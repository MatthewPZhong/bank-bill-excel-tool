# Blindspot Pass

默认执行只读检查。目标是找到足以改变方案或验收范围的遗漏，不是生成一份泛泛的风险词表。

## 扫描流程

1. 明确用户目标、非目标、可见行为和关键不变量。
2. 读取实际入口、调用方、状态存储、输出端、测试和配置。必要时查看历史 diff，但不要用历史意图覆盖当前代码事实。
3. 沿真实数据流检查：输入 -> 规范化 -> 决策 -> 状态/持久化 -> 输出 -> 重试/恢复。
4. 检查以下维度，只报告与当前任务有关的项：
   - 入口与旁路：是否还有未受保护的调用路径
   - 数据和契约：空值、枚举、精度、顺序、兼容版本、序列化
   - 状态生命周期：初始化、复用、清理、重入、跨会话残留
   - 失败模式：部分成功、超时、重试、取消、重复执行
   - 并发和幂等：竞态、重复写、重复导出、唯一键
   - 可观测性：失败是否可见，计数是否能解释，是否存在静默丢弃
   - 测试：核心行为、反例、边界和旧路径保护是否有证据
5. 对高影响未知选择 `BLOCK`、`PROBE` 或 `ASSUME`；能从仓库查证的先查证。

## 证据纪律

每条发现必须区分：

- **事实**：代码、测试、配置或运行结果直接证明
- **推断**：基于事实得出的最可能解释
- **未知**：当前证据不足，仍需验证

每条发现包含：影响、证据位置、最便宜验证方式和处置建议。不要把“理论上可能”写成缺陷；无法说明触发条件和用户影响的候选项应删除或降级。

## 输出格式

按严重度排列：

```markdown
### [等级] 简短标题
- 事实：
- 推断/未知：
- 影响：
- 证据：
- 最便宜验证：
- 处置：BLOCK / PROBE / ASSUME / 已覆盖
```

结尾列出：

1. 会改变方案的存活问题
2. 已被代码或 spec 反证的候选问题
3. 建议补充的验收与测试

若没有实质问题，明确说明未发现会改变方案的盲区，并写出剩余验证边界。
