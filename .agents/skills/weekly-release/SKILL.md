# weekly-release

详细执行步骤的唯一正文是 [references/release-checklist.md](references/release-checklist.md)。本入口不重复维护步骤；开始发布任务时读取该清单，按当前状态执行。

## 触发与范围
- 用于准备发布、接手已完成模块集成的 release、继续 PR 或标签发布、核验发布结果；日常模块开发和普通修复不自动触发。
- 支持“只检查”“准备到 PR”“完成正式发布”等用户明确范围；这些是自然语言任务范围，不是新增的 CLI 参数。仅讨论或制作流程文件，不等于授权执行真实发布。
- 周一是计划发布窗口，不是自动调度；不新增定时任务，不因到期强行发布。提交、推送、合并 PR、升版、标签和对外发布遵守已有明确授权，授权内连续完成。
- spec / TechDoc 的存放与复用仍交给 `versioned-docs`，不在此重新生成需求或技术文档。

## 接手与续做
- 已有 `release/<版本号>` 时核对其基线、实际差异和纳入清单；不重建、不清空，不机械重做已合并分支。
- 已完成事项须用提交、差异、PR 或检查记录核实，再标记完成；没有证据的项目不能仅凭勾选视为通过。
- 默认从清单 B 接手已集成版本；尚未准备分支才执行 A。已有 PR、合并或标签时核实前置条件后，从对应未完成步骤续做。
- 只重做受新增修改、基线推进、失败或证据失效影响的检查，不重跑整套无关流程；明确要求针对最终提交执行的门禁不能用旧提交结果冒充。

## 记录方式
- 清单使用 `[ ]` 待做、`[x]` 已完成；条件不适用写 `N/A + 原因`，阻塞项保留未勾选并注明原因。
- 通用清单保持空白。每轮记录可放到 `changes/<版本号>/release.md` 或现有 PR/Release 记录，复用已有记录，不重复创建。
- 发版后结果写入 PR/Release 或独立记录，不为补勾选改写已发布提交或移动正式标签。最终报告格式与收尾条件见清单 G。
