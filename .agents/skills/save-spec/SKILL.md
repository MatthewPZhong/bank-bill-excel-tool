# save-spec

按目标版本与适用分支管理 spec 和 TechDoc。下列路径均相对项目根目录；本文件统一维护其存放、查找、复用与补齐规则。

## 适用边界
- 仅在任务需要存放、查找复用或补齐 spec / TechDoc 时使用。仅要求阅读、评审或讨论时不主动落盘或补生成文件。
- 按任务补齐相关资料，不把扫描全部版本或变更目录作为固定前置步骤。

## 定位与存放
- **版本定位**：优先使用文件正文或元数据中标明的目标版本号，不用文档修订号或依赖版本代替。文件未注明时先查当前任务的目标版本，再核对 `package.json.version`；下文“当前版本”均指本次任务的目标版本。版本冲突先核实，不因工作区版本不同改写输入文件的版本。
- **分支定位**：同一版本明确拆分为多个开发分支时，按文件中的分支计划及当前任务确定所属分支；不把仓库存在多个分支等同于本版本多分支。版本、分支仍无法确定时按项目根目录 `CODEX.md` 的「未知项的定义与处理」处理，不猜测归属。
- **存放目录**：单分支版本存入 `changes/<版本号>/`；多分支版本存入 `changes/<版本号>/<分支名>/`。缺少版本或分支文件夹时直接新建；提供与生成的文件遵守同一规则。文件名沿用输入或同版本约定，无约定时新生成 `spec.md`、`techdoc.md`。

## 复用与补齐
- **提供即复用**：用户提供 spec、TechDoc 中任一文件，直接存放并使用，不重复生成，也不为统一格式重写。已在目标目录且内容一致的直接复用；同名内容冲突先核对，不擅自覆盖。
- **先查缺失项**：未提供其中任一文件时，先在当前版本的目标目录查找与本任务匹配的对应文件；多分支版本先查所属分支。已有适用文件就直接使用，不因用户未再次提供而重新生成，不把其他分支的同名文件当成本任务文档。
- **复用格式**：确需补齐文件时，在 `changes/<当前版本>/` 内查找同类型文件，复用章节、字段和排版；多分支优先本分支，再参考同版本其他分支。只复用格式，不照搬其他任务的业务内容、版本或完成状态；当前版本没有同类范本时，再查 `changes/templates/`、`docs/templates/`，仍无范本则采用最小必要结构并说明。
- **只补缺失文件**：缺 TechDoc 时依据已有 spec 细化实现方案、模块/文件改动、数据流/接口及测试与验收，迁移、兼容、回滚按需补充；缺 spec 时依据明确的用户需求与已有材料整理，不把技术推断当作已确认需求。两者齐全时直接使用，不再生成另一套。新生成文件注明目标版本及适用分支，引用依据文件，保存到上述目标目录，不以对话摘要代替文件。
- 不擅改输入文件的目标、范围或验收条件；缺口和冲突按项目根目录 `CODEX.md` 的「未知项的定义与处理」处理，需要变更用户提供的 spec 或 TechDoc 时先取得用户明确授权。

## 交付
- 列出实际存放路径、复用或补齐情况及格式参考来源；未解决的缺口或冲突如实说明。
