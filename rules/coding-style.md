# 编码规范

## 命名

- 类 / 类型名：清晰、可搜索、见名知意
- 方法 / 函数名：动词开头，表达行为
- 常量：避免魔法值
- 禁止难懂缩写，除非是约定俗成

## 函数设计

- 单个函数尽量只做一件事
- 避免隐式副作用
- 复杂分支优先拆解为小函数

## 错误处理

- 不吞异常
- 明确区分业务错误、参数错误、系统错误
- 日志中不要泄露敏感信息

## 可维护性

- 优先改最少的代码满足需求
- 新增抽象前先确认是否真的会复用
- 修改公共能力时，说明影响面

## 提交前检查

- 能否运行最小验证
- 能否通过项目已有 lint / test / build
- 是否同步更新相关文档和注释
