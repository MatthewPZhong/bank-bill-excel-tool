## 1. 用户明确提出的需求

在“拆分字段”页面的“值”及其下拉框下方新增一行：

1. 左侧为复选框，右侧紧接文字“按行拆分”。
2. 勾选后，“字段”和“值”的下拉框均被禁用。
3. 勾选后，“按行拆分”右侧出现输入框，输入框右侧显示文字“行”。

保留这三个原始要求，不改名为“按数量拆分”，不将复选框改为下拉框或单选按钮。

## 3. 页面布局

### 3.1 未勾选

```text
选择拆分字段

字段     [ 原有字段下拉框                 ▼ ]
值       [ 原有值多选下拉框               ▼ ]

□ 按行拆分

□ 需要拆分成多个文件              [取消] [完成]
```

### 3.2 已勾选

```text
选择拆分字段

字段     [ 原选择保留，禁用               ▼ ]
值       [ 原选择保留，禁用               ▼ ]

☑ 按行拆分  [ 请输入行数 ] 行

□ 需要拆分成多个文件（禁用）       [取消] [完成]
```

图中的“禁用”用于解释状态，不要求写入下拉框文案；不显示“预计生成 K 个文件”等常规预估提示。行数输入仍默认空白，不预填 1000；文件数量上限 1000 与每份行数 N 是两个不同概念。

新增行位于值控件之后、提示区之前。复选框、文字、输入框和单位在同一行垂直居中，沿用现有弹窗字体、控件高度、间距和禁用色。不得借此给整个工具箱重新定宽高；狭窄窗口通过既有自适应布局避免按钮和输入框被裁切。

输入框与单位在未勾选时均不显示、不占据可聚焦位置。文字“按行拆分”关联复选框，点击文字或聚焦复选框后按空格均可切换；输入框的可访问名称为“每份文件数据行数”。

## 4. 状态与交互

| 状态 | 字段控件 | 值控件 | 行数输入及“行” | 完成按钮 |
|---|---|---|---|---|
| 未勾选，尚未选值 | 沿用原逻辑 | 沿用原逻辑 | 隐藏 | 禁用 |
| 未勾选，字段和值有效 | 沿用原逻辑 | 沿用原逻辑 | 隐藏 | 沿用原逻辑 |
| 已勾选，行数为空或非法 | 禁用 | 禁用 | 显示 | 禁用 |
| 已勾选，行数有效、本次导入计数可用且 R＞0、预计 K 未超限 | 禁用 | 禁用 | 显示 | 可点击；不要求字段和值，最终由主进程校验 |
| 已勾选，可信来源的页面计数显示无数据或预计超限 | 禁用 | 禁用 | 显示并反馈原因 | 禁用；不能绕过主进程复核 |
| 已提交，任务执行中 | 不可修改 | 不可修改 | 不可修改 | 防重复提交，沿用运行态保护 |

### 4.1 勾选

立即关闭可能已展开的值选择浮层，然后禁用字段控件和值按钮；显示行数输入及单位，并把焦点移到输入框。关闭浮层不得取消原有值选择。

按行模式下不再显示“请至少选择一个值”等字段模式提示，也不再检查隐藏的字段条件。不得只把控件变灰，却继续要求用户选择被禁用的字段和值。

### 4.2 取消勾选

恢复原字段与原已选值，重新按字段模式计算“完成”按钮状态。值列表原本为空时继续保持禁用，不能一律启用所有控件。只做模式切换，不触发清空选值的“字段改变”逻辑。

同一弹窗内的行数草稿保留，但字段模式提交不携带这个隐藏参数。

### 4.3 与原多文件分组模式的关系

勾选按行拆分时，原“需要拆分成多个文件”入口禁用。取消按行拆分后恢复此入口的原行为。

原多分组页面维持现状，不在每个分组中新增“按行拆分”。从多分组页取消“需要拆分成多个文件”后，可回到单组页面选择按行模式。原有多分组页最多八组的 UI 限制，不自动套用于按行模式的输出数量。

### 4.4 取消和关闭

沿用原“取消”、右上角关闭和遮罩交互。仅切换勾选、修改数字、取消或关闭弹窗，不创建输出任务，不生成文件。任务提交后沿用现有工具箱执行与关闭策略，不在本次增加一个新的后台任务管理页面。

### 4.5 文件数量校验（不显示常规预估行）

输入合法 N 后，仍使用本次导入返回的 `dataRowCount` 在内部计算 K = ceil(R / N)，用于数量上限和完成按钮状态校验。按用户最新要求，删除常规预计数量及每份行数说明这一行，不创建对应展示节点；行数错误和超限提示保留。

R = 0 时显示“文件中没有可拆分的数据行”。计数缺失或已失效时显示“导入计数不可用，请重新导入文件”，不得把缺失值显示为 0，也不允许基于猜测启动任务。

预计超限时显示第 6.5 节的可操作提示并禁用完成按钮。即使前端计算在上限内，主进程仍须检查 token、源快照、可信 R、K 以及资源预算；不信任 renderer 传入的计数或上限。晚到的导入/计数结果不得覆盖新文件、新 token 的页面。

## 5. 行数校验

输入先去除首尾空白，再校验为十进制数字字符串，转换后必须为大于零的安全整数。允许 `00010`，提交规范化为 `10`；不得使用会将 `10abc` 截成 `10` 的宽松解析。

| 输入 | 处理 |
|---|---|
| 空白 | 完成禁用；用户尝试操作或离开已编辑输入框时提示“请输入每份文件的数据行数” |
| `1`、`1000`、`00010` | 有效；提交整数 1、1000、10 |
| `0`、负数、小数、字母、`10abc`、`1e3`、`1,000` | 无效；提示“请输入大于 0 的整数” |
| 超出安全整数范围的纯数字 | 无效；提示“行数过大，请输入有效范围内的整数” |

前端与主进程必须都校验。输入 N 不等于“每个 Sheet 的物理行上限”；单份文件超过现有 writer 的 Sheet 容量时，沿用 writer 的工作表滚动规则，不能强行写出超限 Sheet，也不能静默修改 N。

## 6. 数据与输出规则

### 6.1 数据行定义

复用 `TOOLBOX_SHEET_STRATEGIES.SPLIT` 的实际数据流：首个参与的非空 Sheet 提供逻辑表头，后续 Sheet 的相同首行表头不作为数据；后续 Sheet 非重复首行按现有续页规则处理。隐藏和深度隐藏 Sheet 继续参与。

有效数据行以现有读取层触发的 `onDataRow` 为准。现有规则跳过的完全无有效值行不计数；有内容的隐藏行仍计数。不得新增去重、排序、金额过滤或按字段过滤。保留各参与 Sheet 的原顺序与每个 Sheet 的原行顺序。

本次不放宽导入阶段既有文件格式、重复表头和续页结构限制。“不要求选择字段和值”不表示允许导入原先就校验失败的文件。

### 6.2 分块

设导入后的有效数据行数为 R、每份行数为 N：

- R > 0 时，输出文件数为 `ceil(R / N)`；每行恰好输出一次。
- 非末份均为 N 条数据，末份为剩余行数；不补空白行。
- R ≤ N 时仍生成一份文件。
- R = 0 时提示“文件中没有可拆分的数据行”，不产生只有表头的输出文件。
- 每份文件包含对应的逻辑表头；writer 发生 Sheet 滚动时，按既有规则补充各 Sheet 表头。

例：2501 条数据、N=1000，输出三份，分别为 1000、1000、501 条数据；表头不计入这些数字。

### 6.3 输出目录和命名

选择一次输出目录，按原始文件名去除扩展名后生成：

```text
流水明细_按行拆分_0001.xlsx
流水明细_按行拆分_0002.xlsx
流水明细_按行拆分_0003.xlsx
```

序号至少四位，超过四位自然扩展，不截断。沿用项目的文件名规范化和目标路径校验。输出格式沿用工具箱现有 XLSX 输出，不新增输出格式选择器。

保存前检查全部计划目标；存在同名文件时沿用现有确认机制，不得静默覆盖。输出不得与输入文件或受保护原件指向同一对象。用户取消目录选择或拒绝覆盖，不生成正式输出。

覆盖许可绑定确认前全部目标的存在状态及身份；确认期间新出现或被替换的目标应拒绝并要求重新操作，不能在确认后重新采集并自动接受。该保护持续到正式发布。

### 6.4 格式保真

复用既有 style-aware 行模型、样式注册和输出 writer，不将 `matchValues` 或字符串数组重新拼装为输出数据。原始值、类型、数字格式、基础单元格样式、行属性及布局基准的既有保真能力不得退化。

对既有不支持或仅部分保留的复杂对象，继续使用现有检测、警告和失败规则；本次不把“复用既有格式保真”写成对所有 Excel 对象的新增无损承诺。不得吞掉 writer 的降级提示。

### 6.5 输出数量保护与提前检查

`MAX_ROW_SPLIT_FILES = 1000` 为本稿推荐的首版保护值，须通过上限测试后才能作为已支持容量发布；不能将“写入常量”当作容量验证。

主进程先根据可信 R 与合法 N 计算 K，再检查 K，**通过后才构造 K 个输出路径、完整任务计划和生成任务**。K > 1000 时禁止调用 rows 生成执行器，不创建保真缓存，不生成任何输出。既有导入上下文、拒绝日志不属于此处禁止创建的“生成任务”。

超限时提供最小建议行数：`N_min = ceil(R / 1000)`。示例：R=250000、N=100，预计 2500 份，提示：

> 预计生成 2500 个文件，最多支持 1000 个，请将每份行数调整为至少 250 行。

上限内不等于无条件忽略磁盘、路径长度或消息大小。计划和结果的 IPC 预算也必须提前校验；超预算时以明确原因拒绝，不能截断列表、少生成文件或静默改变 N。预算建议与待测配置见 TechDoc §6.5，不把材料中未给出的字节数伪装成已验证限制。

在合法输入、路径与资源均满足已明确预算的验收环境，K=9 和 K=1000 都必须成功。旧八分组限制或旧路由能力不构成这两个成功用例的免责理由。

## 7. 异常、任务与发布

### 7.1 独立后台任务，复用现有入口与发布体系

按行模式通过现有公开 `toolbox:split:export` 入口进入，内部使用新增的 `toolbox:split-rows` 后台任务合同。它不是将 rows 伪装为原字段多分组任务；输入校验、资源策略、执行器、输出校验与恢复关联都必须登记。

普通文件和大文件的 rows 生成均在后台执行，调用同一个生成核心；不在主进程同步生成普通文件，不在 Worker 失败后回退主进程重跑。原字段模式以及导入扫描的既有路由不因本次顺手改变。

一次按行拆分是一个逻辑任务，输入与全部输出成组关联；不为 K 个文件分别创建 K 个业务任务，不新增存档中心业务状态。内部调度、生成和发布子步骤仍可沿用既有任务体系。

### 7.2 固定的首版执行路径

```text
主进程校验与上限检查
  → 独立 rows 后台任务
  → 写入任务私有保真缓存，封存并核对行数/引用完整性
  → 只创建一个活动输出 writer，顺序生成第 1…K 份
  → 每份提交、校验、释放后，才创建下一份 writer
  → 全部文件及汇总一致性校验通过
  → 交给既有 Publisher 发布
  → 任务/存档结算与结果反馈
```

这里“每份提交”仅指提交到任务私有生成目录，不是发布到用户选择的正式目录。首版不再保留“异步拉取读取”与“落盘缓存”二选一。

缓存须保存现有保真合同需要的原始值与类型、样式引用及其可解析资源、表头和连续行序号；不能把所有内容转为字符串。增加的临时磁盘占用与 I/O 必须纳入预算和实测，不承诺固定提速或固定内存占用。

### 7.3 失败与反馈

导入后源文件发生变化，应拒绝基于旧计数导出并提示重新导入。缓存封存后的行数与可信 R 不一致，不能重算 K 后继续执行旧计划，必须在发布前失败。

第 j 份生成或校验失败时，正式发布调用次数必须为 0；已经校验的前 j−1 份仍只是临时产物。正式发布一旦开始，中断、回滚和恢复按既有 journal 与恢复协议处理，不声称多个文件在文件系统层面天然原子，也不由生成器擅自删除正式目标。

成功提示列明文件数量、总数据行数、每份实际数据行数、保存路径及现有格式警告。结果与警告须在消息预算内完整表达合同规定的信息，禁止悄悄省略失败份数。错误和取消沿用既有反馈风格；测试状态、待恢复与最终成功必须区分。

长结果列表在内容区滚动，保留完整文件信息与末尾警告；确认按钮始终可见，可点击返回工具箱。

后台资源准入失败须区分总配额不足与临时占用：若任务所需资源超过平台固定总配额，立即拒绝，不进行注定无法满足的排队；临时占用继续按原有有界队列等待，超时后提示稍后重试。两类错误均以中文显示，并保留错误码、申请资源、总预算、当前占用与可用额度，明确本次尚未开始生成拆分文件。总配额低于所需值时提示释放资源后重启应用；不自动重跑、不降低 rows 的资源预约或跳过资源管理。失败后的正式目标、用户源文件保护和临时目录清理沿用原约定。

## 实施资源补充

CSV/XLS 沿用会物化源表的 reader，因此本模式在创建任务前对这两种源格式设定 64 MiB 读取预算，超出时提示先转换为 XLSX；XLSX 继续流式读取。其他缓存、样式、磁盘和消息预算、测量环境及未完成平台验收见 [实施记录](implementation-notes.md)。这些预算可能使 K 未超限的极宽或高样式文件仍被拒绝，拒绝发生在正式发布之前。
