## 3. 新发现：R05 · P2 · 冻结的输出父目录身份没有传给 Publisher

**位置：`src/main.js:21088–21091`。** 关联 `publishToolboxArtifacts`（同文件约 `20453–20471`）以及 `toolbox-row-split/service.js` 的发布编排。

**文档依据：** TechDoc §5.1 要求冻结全部目标及父目录身份，并要求确认到正式写入之间的变化不能自动接受；Spec §6.3 要求目标保护持续到正式发布。

### 触发与影响

1. 源文件位于输出目录之外，计划输出两份，两个目标均不存在。
2. 完成准备流程，冻结 FilePlan，TaskLifecycle 的 `assertFilePlanFresh` 校验通过。
3. 在后续等待 `beforeStart` / `startFileTask`、尚未创建 generation 目录时，外部进程将选中的输出目录重命名，并在原路径创建新目录。
4. Main 在新目录创建真实的 `.toolbox-rows-*`，完成生成和发布。

冻结的父目录身份已能识别变化，但 rows 传给 Publisher 的目标项只有 `targetPath`，公共 wrapper 仅补 `expectedTargetSnapshot`，没有传递 `filePlan.outputs[i].targetParentIdentity`。由于目标文件仍不存在，文件级快照检查通过，发布没有拒绝已经替换的父目录。

**实测结果：** `assertFilePlanFresh(oldPlan)` 已报 `ARCHIVE_TARGET_PARENT_CHANGED`；继续调用真实 Main execute 却返回 `success`，两份 XLSX 写入新目录，原选中目录仍为空。本轮复现记录中的父目录 inode 从 `111030196` 变为 `111030198`。该场景影响输出目录归属保护；未将其夸大为已复现已有文件被覆盖。

**对照结果：** 仅在测试调用侧补传冻结的 `expectedTargetParentIdentity`，相同场景返回 `TOOLBOX_PUBLICATION_TARGET_PARENT_CHANGED`，正式发布被拒绝。

### 建议修复及复验

将每个冻结输出项的 `targetParentIdentity` 作为 `expectedTargetParentIdentity` 传入既有 Publisher，并沿用其身份检查及 journal 合同；不能在发布前重新采集当前目录身份来代替原确认身份。

补充回归：在生命周期预检通过后、生成前替换输出父目录，以及发布前目录身份变化，均应拒绝正式发布；目录身份不变的正常路径仍应成功。

**复现边界：** probe 使用真实 Main prepare/execute、公共发布 wrapper、生成器和 Worker Publisher；系统对话框、后台调度及归档结算为替身。保持生产 generation 目录布局；没有通过迁移临时产物构造不可达状态。未运行完整业务 Main 或完整 TaskLifecycle 桌面流程。

证据：[复现脚本](evidence/review-2026-09-18-r2/parent-identity-probe.js)、[复现输出](evidence/review-2026-09-18-r2/parent-identity-result.txt)、[对照脚本](evidence/review-2026-09-18-r2/parent-identity-control.js)、[对照输出](evidence/review-2026-09-18-r2/parent-identity-control-result.txt)。脚本保留当时的隔离快照路径，异地执行需先调整路径。
