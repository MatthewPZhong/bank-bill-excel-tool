## 1. 用户明确要求

**REQ-01 — 移除提示。** 点击存档中心批次的删除按钮后，从删除确认提示中移除完整句子：

> 该操作不会删除原始文件和用户已另存的副本。

**REQ-02 — 删除必须实际完成。** 删除批次动作执行完成后，该批次对应的信息和原始文件彻底删除，不能仅隐藏批次、删除关联记录或登记一个将来的清理任务便宣告完成。

**REQ-03 — 正确的功能归属。** 修改存档中心统一批次删除功能，不按 `moduleId === 'toolbox'` 限定。工具箱只是该中心的一类批次来源。

功能启动时的授权为创建指定开发分支、执行 save-spec 并开始迭代实现；当时不包含发布操作。后续整版发布授权与结果由 release 流程单独记录。

## 2. 当前实现与本次差异

在 `v3.2.8` 基线中，提示已定位到 `src/renderer.js` 的 `confirmArchiveBatchDelete()`；它调用统一存档 API，而不是工具箱的合表或拆表处理入口。[R1]

已有删除链路会删除批次与文件关联，登记 `archive_cleanup_jobs`，清理目录化存档文件和最后引用释放后的 Blob；失败会返回 `partial` / `deleted-cleanup-pending`。因此不能把当前系统描述成“从不删除物理文件”。[R2][R3][R4]

| 项目 | 已核实的当前事实 | 本次目标或设计 |
| --- | --- | --- |
| 确认提示 | 含用户指定要删除的句子 | 全部存档批次统一移除，不只改工具箱 |
| 批次元数据 | Repository 已执行实际删除 | 保持实际删除，并核查批次详情、关联与缓存的完整收口 |
| 存档物理文件 | 已清理目录化文件和释放的 Blob | 核验目标清单完整性，补齐遗漏的已知归属文件 |
| 源路径释放 | `_releaseSourcePaths()` 是尽力释放回调，异常会被吸收 | 不能把该回调执行过当成原始文件删除完成的证据 |
| 部分失败 | Controller 和 renderer 已存在部分失败反馈 | 明确“删除未完成”，提供可持续定位的重试状态 |
| 删除保护 | 已有运行、锁定、业务引用、恢复保护 | 保留；不得通过 force 绕过 |
| 自动到期清理 | 与主动删除复用 `_deleteBatchUnlocked()` | 不因本次人工删除调整而自动获得新的外部文件删除权限 |

源码只证明当前上述行为。**尚未核实所有模块的外部原路径、受管暂存路径和 `sourcePath` 的完整映射，不能声称现有系统已经删除或一定保留了所有外部原文件。**[R5]

## 3. 术语与原始文件边界

### 3.1 必须区分的对象

| 对象 | 本文含义 |
| --- | --- |
| 批次信息 | 存档中心中的批次记录、详情、文件关联、该批次专属存档元数据与可回收的专属关联信息；不等于各业务模块的全部原始业务数据 |
| 存档内原件 | 应用存档区保存的原始输入内容及该批次对应的目录文件、底层内容文件 |
| 外部导入原文件 | 用户导入时实际选中的文件，例如桌面、下载目录或共享盘上的文件；它与存档副本可能是不同的物理文件 |
| 受管暂存文件 | 应用为任务持有的输入快照、中间文件或只读打开副本；是否属于本批次必须有所有权记录 |
| 用户另存副本 | 用户通过另存、复制等方式独立保存的文件；删除旧提示句不等于授权删除这些文件 |
| 共享 Blob | 以内容摘要寻址、仍可被其他批次引用的底层存档内容文件 |

### 3.2 D-01：外部导入原路径是否属于删除范围

**状态：已确认（2026-09-11）。** 用户选择：仅删除存档中心保存的原件及可确认归属的受管文件。

- 存档内原始输入、输出归档、独占 Blob 和有持久归属证据的受管文件纳入删除。
- 桌面、下载目录、共享盘等外部导入原文件、外部输出和用户另存副本不属于本次删除范围。`sourcePath` 不赋予删除权限。
- 所有主动删除计划固定 `sourcePolicy: managed-only`；确认文案使用“存档中心保存的原始文件”。
- 旧任务、自动到期清理和恢复流程不扩大原授权范围。

### 3.3 “彻底删除”的完成定义

本稿设计采用以下应用层定义：目标批次不再能作为正常批次访问；约定范围内的文件路径及独占内容已完成文件系统删除；应用不提供恢复按钮；重试或旧任务不能自动重建该批次。

不承诺磁盘取证级擦除，不清除操作系统备份、云盘版本历史或用户独立备份，也不承诺 SQLite 文件的字节级清零。共享内容仍被其他有效批次使用时，只释放本批次引用；这不等于允许保留本批次独占文件。

## 4. 范围与非目标

### 4.1 本次范围

存档中心中所有批次的用户主动单批次删除：确认弹窗、统一调用链、删除目标清单、物理清理、失败反馈、重试收口、列表和详情刷新、共享引用保护、删除后防重建。

成功、失败、取消或存档不完整批次均按实际状态和归属检查处理。不是只有成功批次才能删除，也不是失败批次可以绕过运行/恢复/业务引用保护。

### 4.2 不在本次范围内

不新增批量删除，不改变业务算法，不连带删除其他关联批次，不删除模板、配置或整个业务数据库，不修改各模块自己的“删除导入数据/删除月份”等业务动作，不调整保留天数及维护触发时机，不新增云端清除或用户另存副本清除，不自动执行发版。

自动到期清理继续沿用已经授权的清理范围。共用的安全修复可以复用，但不能静默把主动删除新增的外部原文件策略传播给到期清理。

## 5. 删除与保留矩阵

以下为 D-01 确认后的实现约束。

| 对象 | 处理规则 | 完成判据/保护 |
| --- | --- | --- |
| 目标批次记录、详情、文件关联 | 删除 | 按批次 ID 查询不可作为正常批次访问 |
| 该批次专属的存档关系与可回收元数据 | 清理 | 不留下指向已删除对象的正常可用入口；共享关系只摘除目标一端 |
| 存档内原始输入文件 | 删除 | 已登记目标路径不存在 |
| 该批次的输出存档文件 | 删除 | 删除的是应用保存的存档，不据此删除外部输出目录中的用户文件 |
| 独占 Blob | 删除 | 删除时重新核实无有效引用，并确认目标身份 |
| 其他批次仍引用的 Blob | 保留 | 另一批次仍能正常读取；本批次引用已经释放 |
| 有归属证据的只读副本、暂存文件 | 清理可释放的目标 | 不全目录清空，不触及其他任务持有文件 |
| 外部导入原文件 | 不删除 | D-01 已确认仅清理存档中心原件和已确认归属的受管文件 |
| 用户另存副本、其他批次文件、未知同名文件 | 不删除 | 路径和内容不变 |
| 正常业务数据库中的有效数据、业务引用锁 | 不级联删除 | 引用未解除时拒绝删除批次，而非自动解绑业务数据 |
| 发号游标、必要发行事实、防重放标记 | 保留必要控制字段 | 不复用批次号，不重建已删批次；不将完整业务内容塞入删除标记 |
| 未完成清理计划与失败详情 | 暂时保留 | 可定位、可重试；完成后清除多余路径和业务信息 |

## 6. 功能要求

### ARC-DEL-01 — 确认文案

移除 REQ-01 中的完整句子，不换一个同义“不会删除原始文件”的句子重新放回弹窗。保留确认与取消。

本稿建议最终文案：

```text
确定永久删除批次 {批次号} 吗？
该批次信息及存档中心保存的原始文件将一并删除，删除后无法恢复。
```

按钮为【永久删除】【取消】。文案已按 D-01 的受管文件范围固定。

批次号须继续安全转义。不得在点击图标时就删除；只有本次有效确认后才开始破坏性步骤。

### ARC-DEL-02 — 取消与执行状态

取消、关闭尚未确认的弹窗或 Escape 均不删除信息和文件。预检查可以只读，不得通过“准备删除”提前释放引用。

执行期间防止重复提交，显示【删除中…】或等价状态。提交删除后不提供暗示能回滚文件的取消按钮；窗口关闭或重启不能让清理证据丢失。

### ARC-DEL-03 — 服务端授权和保护

渲染端仅提交批次标识及服务端生成的确认凭证（采用预检查方案时），不得传入任意磁盘删除路径、模块伪装或 force 开关。主进程按真实批次状态重新检查运行、锁定、业务持有、恢复和存储维护状态。

当前活动任务、恢复任务或有效业务数据仍依赖目标文件时，拒绝删除并说明原因。不能为了删掉一个存档批次自动删除其他批次或解除业务引用。

以下状态属于恢复依赖，必须在只读预检查及数据库删除事务提交前重新检查，不能只看批次终态、当前存档根是否明确或维护锁是否释放：

- **迁移 journal 未收口：** 包括切换存档根前失败并留下恢复记录，以及切换成功后旧根清理失败的 `cleanup-pending`。拒绝发起新删除，保留批次与文件，先由既有迁移恢复完成两端状态和残留清理。此方案不把单次批次删除扩展为自行删除新旧两根；已提交的删除计划仍按原范围在原根恢复完成，再允许新迁移。升级前已同时存在的迁移 journal 与删除计划按 TechDoc 的专门顺序收口，不机械套用新请求门禁造成互等；两类记录均收口前不能报告完整成功。
- **目标批次仍有未 ACK 的 terminal-owner intent：** 任务已成功、失败或取消，不代表 outbox 通知及 `afterTerminal` 后处理已完成。先通过既有 owner 恢复路径完成终态后处理与确认，再允许删除。预检查不得顺带执行恢复、丢弃通知或写入 ACK；不能把批次 `not-found` 当成通知已安全完成。

确认弹窗打开后，上述任一状态发生变化都须使本次删除重新校验；校验与提交之间应受既有协调机制保护，不能依据弹窗前的旧快照继续删除。

### ARC-DEL-04 — 删除记录与文件共同收口

删除前保留足以继续执行的持久清理计划。数据库变更和该计划应原子提交；物理清理在本次请求中执行并等待结果。

“任务已登记”“元数据已删”“UI 卡片已消失”都不等于完整成功。不能只调 `fs.rm(sourcePath)`，也不能以目录存在就认定其中所有内容都属于该批次。

### ARC-DEL-05 — 严格成功条件

本稿拟新增明确的完成字段，例如 `fullyDeleted`。只有同时满足下列条件才显示“存档批次及对应原始文件已永久删除”：

1. 批次业务展示信息及约定的专属关联已删除。
2. 已确认删除范围内的全部目标均已删除、已安全确认不存在，或是明确允许保留的其他批次共享内容。
3. 无未完成的删除项；清理计划已经完成收口。
4. 防重放控制已生效，普通访问不能重建该批次；没有被删除动作遗留的 owner 终态后处理或未 ACK 通知阻断恢复与启动。

目标归属未知、源文件被替换或仍存在未完成项时，不得把该需求标为通过。

### ARC-DEL-06 — 部分失败可见、可重试

删除前校验失败：保留批次和文件，显示具体原因。

已经发生部分删除：显示“删除未完成：部分文件尚未清理，请解除占用或检查权限后重试”等实际原因，不显示绿色成功。批次记录即使已经删除，存档中心也应通过轻量未完成提示/明细保留该任务的状态和【重试清理】入口；不得重建业务批次来承载失败状态。

重试应只处理允许继续的目标，且重新校验文件身份与引用。不得将同路径后来新建的文件当作旧文件删除。已删除文件不要求恢复，数据库回滚也不能被描述成物理文件自动恢复。

### ARC-DEL-07 — 缺失文件、离线目录与未知文件

只有存储根可访问、归属验证完成时，目标文件已经不存在才按幂等完成处理。存储盘离线、共享目录不可达或权限错误不能当作“文件已删除”。

未知文件和缺失归属证据的历史临时文件不得猜测删除；记录可解释的阻止/待人工核定状态。未知文件不能被伪装成已清理对象。

### ARC-DEL-08 — 删除后的界面和统计

清空已删除批次的选中状态、详情和可用操作；刷新列表、文件总大小、运行次数和关联任务显示。异步旧响应不得重新填回被删除的详情。

不调整现有统计口径：文件总大小不是实际磁盘回收字节数；共享内容存在时两者可以不同。批次序号不倒退、不复用；不通过重新排列其他批次弥补删除产生的编号空缺。[R4][R7]

### ARC-DEL-09 — 历史数据、重启与并发

覆盖新旧批次、存档不完整批次、无可用原路径证据的历史批次、删除后重新进入、删除中断后重启、同批次重复提交，以及另一批次重新引用相同 Blob 的情况。

旧清理计划不得因升级而自动获得外部原文件删除权限。用户手动删除一个批次，不等于同意后台扩大清理范围。

恢复安全不止要求“批次不复活”。对旧版本已删除 owner 的遗留通知和删除后迟到通知，必须先验证完整 owner、batch、issuance 身份及耐久终态/后处理证据，再按 TechDoc 的安全路径收口；不得仅凭删除标记、批次不存在或一次 `finishFileTask()` 失败直接丢弃通知。必要后处理必须保留且可恢复，收口后 outbox 不得持续阻断启动；身份无法匹配、证据不足或后处理尚未完成时保留通知，并显示可定位的恢复阻塞原因，不伪造 ACK。

## 7. 交互流程

```text
进入存档中心 → 选择批次 → 点击删除
  → 只读预检查范围及迁移 journal / owner 恢复依赖 → 显示确认弹窗
      取消：返回，不改变数据和文件
      确认：重新校验状态、凭证、文件身份及上述恢复依赖
        不允许删除：保留批次并提示原因
        允许删除：原子登记清理计划、删除批次业务展示信息
          → 本次调用执行实际文件清理
              全部完成：明确成功 → 刷新列表、详情、统计
              部分失败：明确未完成 → 保留清理状态 → 安全重试
```

上述流程已在本功能实施；预检查接口、清理重试与后续修复记录见 [implementation-notes.md](implementation-notes.md)，实际验证范围见 [validation.md](validation.md)。

## 8. 验收矩阵

所有测试仅使用专用临时目录、测试文件与测试数据库，不连接用户真实工作文件。

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| AT-01 | 不同来源模块的批次确认弹窗 | 指定句子均不出现；不是仅工具箱生效 |
| AT-02 | 取消、关闭未确认弹窗 | 数据库、引用、文件、清理计划均不变 |
| AT-03 | 普通批次完整删除 | 元数据与所有约定独占文件真实不存在；明确完整成功 |
| AT-04 | 同一批次多个输入、输出 | 全部目标覆盖，不仅删除首个或 ready 文件 |
| AT-05 | 用户另存文件、外部输出文件、同名不同路径文件 | 未获授权者不删除 |
| AT-06 | 两批次共享 Blob | 删一个不破坏另一个；最后有效引用释放后可回收 |
| AT-07 | 活动、锁定、业务引用、恢复中 | 拒绝删除；不清理实际文件 |
| AT-08 | 文件占用、权限不足 | 不报完整成功；任务状态持久存在且可重试 |
| AT-09 | 原路径文件修改、替换或同内容重新创建 | 不误删新对象；身份冲突明确可见 |
| AT-10 | 文件已缺失/存储盘离线 | 前者在可验证条件下幂等；后者不能假成功 |
| AT-11 | 路径穿越、符号链接/目录联接、伪造批次 ID | 越界目标不删除；服务端验证生效 |
| AT-12 | 数据库提交失败 | 批次/引用/清理计划一致；不先盲删文件 |
| AT-13 | 提交后、清理中、完成响应前退出 | 重启可安全恢复；不重建批次，不丢清理证据 |
| AT-14 | 旧 outbox、新版 `version: 1` 的 `file-batch` owner、迟到通知及重新执行旧操作；成功/失败/取消终态仍有未 ACK intent、后处理失败；身份不匹配或证据不足 | 只读预检与提交前重校验均阻止未收口 owner 的新删除；先恢复 `afterTerminal` 并 ACK 后才能删除。旧版已删 owner 及迟到通知须验证完整身份和耐久终态/后处理证据，不能以 `not-found` 或删除标记直接 ACK；后处理不丢失、不重复生效，已删批次不复活、号码不复用，合法通知安全恢复后 outbox `remaining = 0` 且初始化成功。身份不匹配、证据不足或后处理未完成时保留通知并明确阻塞，不能为清零伪造 ACK |
| AT-15 | 重复点击/重复请求 | 不重复释放引用，不生成互相冲突的清理计划 |
| AT-16 | 删除后列表、关联任务、详情、统计 | 无陈旧入口、无错误回填；逻辑大小与磁盘空间不混淆 |
| AT-17 | 自动到期清理 | 保持原授权范围，不自动删除外部原文件 |
| AT-18 | 存储迁移与删除并发；切换前失败遗留 journal；切换后旧根清理失败、迁移已返回且维护锁已释放的 `cleanup-pending`；预检后新增迁移依赖 | 预检与提交前重校验都拒绝未收口迁移期间的新删除，批次和文件保持不变；不能因当前根明确、锁已释放而放行。先完成既有迁移恢复，再删除并检查两端真实文件，不遗留目标独占原件却返回 `fullyDeleted = true`；已有删除计划按原范围安全恢复；升级前已有 pre-switch journal 与 cleanup job 的重叠夹具按 TechDoc 专门顺序收口，各阶段中断重启不互等、不提前完成、不扩权 |
| AT-19 | 原本失败/取消/存档不完整批次 | 能按真实清单清理，不吞掉源文件清理失败 |
| AT-20 | 已知归属只读/暂存文件、未知文件 | 只删可确认对象，未知文件不误删 |
| AT-21 | 旧 cleanup job 与旧元数据升级 | 不扩大旧任务授权；升级幂等 |
| AT-22 | 待重试 Blob 被新批次引用 | 重试重新查询引用，不使用过期释放清单盲删 |
| AT-23 | 模块业务数据仍有效 | 不级联清空业务数据库；必要时删除被引用保护阻止 |
| AT-24 | D-01 最终确认范围 | 包含外部原文件时验证可信身份、依赖和实际删除；仅存档内原件时外部文件不变，文案与范围一致 |
