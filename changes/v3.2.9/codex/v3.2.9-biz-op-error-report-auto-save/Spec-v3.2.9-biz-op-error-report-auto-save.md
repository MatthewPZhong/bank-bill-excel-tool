## 1. 背景与当前实现

以下为基线代码事实，不是新增需求：

- 当前区间页面由 `src/renderer-biz-op-v327.js` 控制。它会在获得 `reportRef` 后显示【导出错误报告】，并通过 `exportObject('ERRORS', reportRef)` 发起手动导出。[S2]
- 任务取消不是单一静态按钮：同一个按钮在导入时显示为【取消导入】，普通任务时显示为【取消当前操作】，在任务弹窗中还可能显示为【取消】。按钮会随忙碌状态动态移动。[S2]
- 主进程已经有 `ERRORS` 类型的 XLSX 导出流程，包含诊断来源校验、受管导出任务、文件发布以及归档处理。内部 `reportRef` 指向诊断数据，不等于用户可直接打开的 XLSX 文件。[S3][S4]
- 应用的现有存储根目录由 `src/main.js` 的 `getStorageRoot()` 决定；当前实现为系统“文档”目录下的 `网银账单生成小助手`。现有错误目录按生成日期分层。[S5]

因此，本次不是“把按钮隐藏一下”，也不是“把内部诊断文件移动出去”，而是将既有错误报告的用户手动导出步骤改为主进程自动执行。

## 2. 目标与非目标

### 2.1 目标

1. 本模块不再向用户提供手动【导出错误报告】入口。
2. 本模块不再向用户提供用于中止**已经提交的任务**的【取消操作】及其同义按钮。
3. 产生本次操作的可用错误诊断时，自动生成并保存原格式 XLSX 错误报告到现有 `error-reports` 目录，不弹出“另存为”。
4. 用户能区分业务操作结果与报告保存结果；保存失败不能被伪装成保存成功，也不能吞掉原始业务错误。

### 2.2 非目标

本次不修改核对算法、金额与币种口径、日期规则、输入版本替换规则、结果表字段或错误报告字段；不启用或迁移其他模块的后台执行平台；不调整存档中心的通用策略；不新增报告管理页、保存按钮、取消按钮或配置开关。

本次不取消系统文件对话框、日期选择、删除确认等**任务提交前**的取消/返回行为，也不删除后端用于应用退出、窗口销毁、故障收尾的取消和恢复能力。

本期不新增跨启动的“未开始报告补导”调度系统，不承诺应用被强制结束时仍能完成尚未启动的报告保存。已经进入导出任务的发布/归档恢复继续遵循现有机制。异常中断与磁盘故障必须如实提示，不得通过绕过保护机制满足“自动保存”。

## 4. 功能需求

### FR-01 删除手动错误报告入口

删除本模块页面中【导出错误报告】按钮的创建、显示控制、事件绑定及仅服务于该按钮的页面状态。包括初始状态、失败状态、重复进入模块和弹窗状态；不能仅通过 CSS 隐藏。

页面不再因为收到 `reportRef` 而显示按钮，也不再由 renderer 发起 `ERRORS` 报告的保存位置选择。普通 OP、流水、结果原表及差异结果表的导出入口继续保留。

删除后不得留下仅为该按钮保留的空白工具栏。现有【重试恢复】仍可按原状态规则显示。

### FR-02 删除执行中的任务取消入口

删除执行期间的【取消操作】【取消当前操作】【取消导入】，以及动态插入任务弹窗、实际调用任务取消接口的【取消】按钮。

不得全局按按钮文字删除：日期选择、删除确认中的【取消】是不同语义，必须保留。系统文件选择和另存为对话框中的原生“取消”也不变。

执行中保留防重复提交、控件禁用、状态提示、必要的关闭保护。任务结束后恢复控件状态和合理焦点。导入按钮保留在原布局中，禁用即可，不再用“取消导入”替换。

本需求针对本模块实际可达界面。实施时检查兼容/回退入口；如仍有同一模块的相同任务按钮，做定点处理，不改变 mode/legacy 路由，不影响其他模块的取消功能。

### FR-03 自动保存的触发范围

主进程以**本次导入任务实际产生、完成校验且可读取的诊断**为依据触发自动保存。当前基线的结构化 XLSX 错误诊断来自导入链路；本期不擅自把所有预检提示或任意运行异常都转成新的报告类型。[S3][S4]

| 情况 | 预期行为 |
| --- | --- |
| 本次导入被拒绝，并有可用的错误诊断 | 自动保存一次 XLSX 错误报告 |
| 导入抛出异常，但恢复后能取得本任务已经封存的错误诊断 | 仍自动保存，不因异常返回路径丢失诊断关联 |
| 成功导入，只有内部空诊断 | 不生成对外空错误报告 |
| 用户取消文件选择，未提交导入任务 | 不生成错误报告 |
| 仅有缺失日期/数据等预检提示，没有结构化诊断 | 保留原提示，不伪造 XLSX |
| 诊断未生成、未封存、已不可用或归属校验失败 | 明确提示没有可用报告，不使用上一任务的诊断代替 |
| 恢复未完成，不满足安全导出条件 | 不绕过门禁；提示当前未保存及阻断原因 |
| 应用退出/窗口销毁导致后端取消 | 遵循现有取消、载体关闭与恢复约束，不强行启动导出 |

**不能把 `reportRef` 非空或错误样本数量大于零当作唯一触发判断。** 文件级错误、扫描不完整和样本截断需要保留真实说明；零条已收集样本不必然等于“没有错误”。同样，只有内部空诊断也不应产生空报告。

### FR-04 保存目录与文件命名

保存到主进程现有存储根目录下：

```text
<getStorageRoot()>/error-reports/YYYY-MM-DD/
```

按当前基线，实际对应：

```text
<系统文档目录>/网银账单生成小助手/error-reports/YYYY-MM-DD/
```

`YYYY-MM-DD` 为报告创建时的**本地生成日期**，不是 OP 数据账期。沿用现有日期子目录，不把文件平铺到 `error-reports` 根目录，也不另建项目目录下的同名文件夹。

建议文件名固定为：

```text
业务OP导入错误报告-YYYYMMDD-HHMMSS-UUID.xlsx
```

目录不存在时自动创建。同秒多个独立失败任务产生不同文件，不覆盖旧报告。路径和文件名由 Main 生成；renderer 不传入任意保存路径，文件名不拼接用户原文件路径。

### FR-05 报告格式与真实性

复用既有 `ERRORS` XLSX 的字段、工作表组织、样本与说明规则，不用 TXT 或原始 JSONL 替代。继续保留既有样本上限、截断信息、扫描完整性和错误计数精确性；样本行数不能被误标为全部错误数量。[S3][S4]

只有既有发布流程确认报告已发布且目标文件可验证时，才提示“已自动保存”。仅创建了目录、内部 `reportRef`、暂存文件或导出任务，不算保存成功。

报告自动保存不改变导入是否成功，不提交原本应拒绝的输入数据，也不重跑业务写入。

### FR-06 保存结果反馈

错误摘要和报告反馈同时可见；本模块原有状态区和当前任务弹窗可用于展示。不新增手动报告导出按钮，不强制自动打开文件或目录。

| 保存结果 | 展示要求 |
| --- | --- |
| 已保存 | 原业务失败摘要 + “错误报告已自动保存至 error-reports/日期/文件名.xlsx” |
| 已保存，归档或清理未完成 | 明确文件已保存，同时说明仍有归档/收尾未决 |
| 确认未保存 | 原业务失败摘要 + 自动保存失败/受阻原因，提示检查目录权限、磁盘或任务记录 |
| 发布结果待恢复核验 | 明确“保存状态待恢复核验”，不能说已成功，也不能认定文件一定不存在 |
| 没有可用诊断 | 原业务错误保留，说明“本次未生成可用的错误报告” |

展示的是经过主进程构造的相对位置。需要避免长文件名被完全截断到无法查看/复制；具体使用换行或既有详情展示方式，不新增一套报告管理界面。不得泄露内部数据库、staging 路径、原始堆栈或完整业务行。

### FR-07 重复调用与后续操作

同一有效 IPC 请求以 sender、requestId 及请求参数关联。完成身份与参数校验后，先查验现有请求缓存，再对新请求执行启用/恢复门禁；同 ID 改参仍拒绝。导入恢复或报告收尾使 `recoveryReady=false` 期间，相同 sender、requestId 及参数的并发重放必须复用同一个请求 promise，不重复导入、不重复生成报告。

请求完成后，即使缓存结果为 `cleanupPending=true`，相同请求的有效重放也返回原业务结果、`errorReport`（如有）与 `cleanupPending`，不被新请求门禁替换。该保证限于当前进程和现有请求缓存有效期；缓存重放不承诺跨启动去重，也不实时重新查询恢复或发布状态。

新的、用户主动发起的导入属于新操作，仍须通过原启用/恢复门禁；即使输入文件相同，产生新的错误报告也不视为重复覆盖问题。

本次导入、恢复、自动保存与必要收尾期间，页面保持忙碌。保存完成或明确失败后再恢复交互。下一次任务不得展示上一任务的保存位置。

### FR-08 保存失败与恢复边界

无权限、磁盘已满、目标不可用等错误要明确反馈；报告保存失败不得覆盖原业务 `status`、`code`、摘要，不得产生“导入完成”的假提示。

保留本任务的可用内部诊断和现有恢复证据，不能因为移除了手动导出按钮就提前删除诊断。已发布但归档未完成的报告，按原有流程收尾，不以新导入覆盖旧任务。

本期不新增“保证自动补导”的承诺或隐藏队列。已经进入导出任务的异常由原恢复流程核验；未开始的保存因门禁或文件系统失败而结束时，明确说明未完成，保留证据，用户排除原因后可重新发起导入。

| AC-16 | 页面仅收到受限元数据，不收到内部绝对路径、任意文件权限或业务行 |
| AC-17 | 普通 OP/流水/结果表导出、原核对逻辑、模式路由与其他模块功能保持原行为 |

## 7. 设计默认与已冻结边界

本次按以下边界设计，无需为按钮文案等已明确细节重复询问用户：

- `error-reports` 指现有应用目录，并保留按日分层；不是仓库目录。
- 删除的是任务执行取消入口；确认框取消与系统对话框取消保留。
- 报告继续采用现有 XLSX 格式；不改变核对规则和报告列契约。

- 当前用户已授权建分支、save-spec 与实现验证；提交、push、合并和发布仍不在本次授权范围。
