# Spec — 映射关系管理迭代：特征值设置入口、默认选中与新分隔符，「启用」列去竖线

> status: in-progress
> created: 2026-11-24
> 目标版本：v3.2.22（暂定，发版时按 weekly-release 调整）
> 适用分支：`feat/feature-value-settings`
> 分支基线：正式标签 `v3.2.21`（`0e996340`）
> 依据：2026-11-24 用户需求（网银账单生成模块 · 特征值管理、映射关系管理）及同日确认的一项决策
> 格式来源：`changes/v3.2.21/feat/mapping-logic-feature-layout/spec.md`

## 1. 背景

1. 【特征值管理】按钮在映射字段选「字段筛选特征值」后才出现在该行，入口分散；用户要求集中到「个性化映射设置」。
2. 特征值管理弹窗打开时下拉框为空白，需要再选一次才能看到已有特征值。
3. 分隔符缺少 `-`、`_`、`$`。
4. v3.2.21 加的「启用」列两侧竖线不需要。

## 2. 已确认决策

| 编号 | 决策 | 来源 |
| --- | --- | --- |
| D1 | 「个性化映射设置 → 按字段区分发生额」下方新增一行文本「特征值设置」，右侧按钮【管理】打开特征值管理（原【特征值管理】） | 用户，2026-11-24 |
| D2 | 映射字段 = 字段筛选特征值时，行内不再出现【特征值管理】，只留「选择特征值」+ 下拉框 | 用户，2026-11-24 |
| D3 | 拆分/合并账单映射关系设置弹窗同样去掉行内【特征值管理】，不另设入口；特征值只在主弹窗「特征值设置 →【管理】」维护，拆分弹窗只选用 | 用户，2026-11-24 |
| D4 | 特征值管理弹窗的「特征值」下拉默认空白；已有特征值时默认选中最早新增的特征值 | 用户，2026-11-24 |
| D5 | 分隔符新增 `-`、`_`、`$` | 用户，2026-11-24 |
| D6 | 映射关系管理「启用」列两侧的竖线去掉 | 用户，2026-11-24 |

## 3. 规则

### 3.1 入口（D1～D3）

- 「特征值设置」不是映射行：不写 `data-template-field`，保存映射时不收集；不受拆分/合并互斥与「按字段区分发生额」互斥影响，【管理】始终可用。载荷没有「按字段区分发生额」（旧载荷）时不渲染。
- 行高与勾选行一致（编辑区最小高度 36px），【管理】与上方【维护发生额映射关系】左对齐。
- 拆分弹窗不再接收 `getMainFeatureFilterUsage` / `onFeatureFiltersChange`；打开时拿主弹窗当前特征值列表，只供「选择特征值」选用。主弹窗【管理】删除特征值时，删除保护仍计入拆分映射草稿（「字段（拆分/合并映射）」）。

### 3.2 特征值管理弹窗（D4）

- 「最早新增」= 列表第一项：新增追加在末尾，`normalizeFeatureFilterList` 保序，下拉框顺序即新增顺序。
- 打开时与删除成功后应用默认选中：列表非空则选中第一项并回显其条件；为空则空白、设置区隐藏。
- 未改动判断按控件值：回显已有特征值后记下设置区各控件的值（快照），【保存】时控件值与快照完全一致即直接关闭、不写库。不与库中原文比较——单行输入框会去掉模板包带入的名称换行，无法回显的值显示为空，与原文比较会把“未动”误判为改动并改写数据。依据：默认选中后「打开 → 保存」不应产生写入；筛选字段已被模板【更新】删除的旧特征值未改动时，不因前端表头校验拦住关闭（后端对未改动的已有特征值本就不按表头校验）。有改动时校验与保存不变。
  - 特征值名未编辑（与快照一致）而改了其他条件时，提交库中原名，不因输入框去掉换行而改名；保存失败后快照保留，重试时同样沿用原名。
  - 任一次保存或删除失败（含 busy、已写库但同步模板库文件失败等结果不确定的情况）后，之后的【保存】一律提交、不再按快照跳过，避免界面与库不一致时把“恢复原值”或“切到别项再选回”当成未改动跳过。此时控件与快照一致或「特征值」选空白的，按界面所示的列表原样提交（由后端对照库中现值校验，不按前端表头拦下已删除的筛选字段，也不经单行输入框改写名称、样例中的换行）；有改动的照常校验后提交。
  - 该标记在关闭后从同一主弹窗重开【管理】时由主弹窗带入；保存或删除成功后列表以后端回包为准，标记清除，恢复按快照判断。用户手册在“未改动只关闭”旁注明失败后【保存】会重新提交。
  - 主弹窗的特征值列表只在成功回包后更新；删除已写库但回包失败时，从同一主弹窗重开【管理】提交的列表仍含已删除项，后端按未知 id 拒绝。该提示改为“请关闭映射关系管理后重新打开，再在「特征值设置」点击【管理】”（从模板管理重开映射关系管理会重读库中列表）。
- 筛选字段已不在表头时按字面列名补「X（已删除）」选项并标红，以 `__FIXED__:` 开头的列名同样标出（`ensureStaleFieldOption` 的 `literal` 选项，不按映射内部存储值跳过）。

### 3.3 分隔符（D5）

- 存储键名：`hyphen`（`-`）、`underscore`（`_`）、`$` 为 `dollar`；按字符串拆分（`$` 不作正则）。后端 `feature-filter.js` 与渲染端 `configuration.js` 同口径。
- 兼容：只前向兼容，未单独提升模板包版本。旧版本的实际行为：
  - 同一数据库回退：旧版本不认识新分隔符，是否拒绝生成取决于旧版实际生效的映射能否识别并校验该特征值，模板包版本保护不到这种场景。
    - 多数路径拒绝：映射直接选「字段筛选特征值」并经旧版生成前检查的，v3.2.18～v3.2.21 报「不支持的分隔符」；只经「逻辑取值」候补引用的（v3.2.21 新增的候补类型），v3.2.21 同样报不支持的分隔符，v3.2.19～v3.2.20 不认识特征值候补、先报「映射字段不存在」（`TEMPLATE_MAPPING_FIELD_MISSING`）。
    - v3.2.16～v3.2.17：经旧版主映射规范化的路径把映射存的特征值 id 当成源列名（v3.2.18 起即如此，与本次无关），不拒绝，该字段为空或取同名列的值；开启拆分/合并、不复用且拆分映射直接选用特征值时，旧版读不到单条规则、报「尚未设置筛选条件」拒绝生成。
    - 也有不拒绝的路径：旧版生成前检查只覆盖部分映射时（如开启拆分/合并后只检查拆分映射），未被检查的引用不会因新分隔符拒绝，可能静默留空。
    - 因此用户手册提示：用了新分隔符的模板请在 v3.2.22 及以上版本生成账单。
  - 旧版特征值管理里分隔符下拉框没有对应选项、显示为空，旧版也没有“未改动不写库”：在旧版选中该特征值后点【保存】，即使没做任何编辑，整表校验通过时会按“不拆分”写回、规则被改变；同模板还有其他特征值用了新分隔符时，整表校验报「不支持的分隔符」，整次保存被拒绝、都不写回。用户手册在分隔符说明旁提示：在旧版本里查看这类特征值请点【取消】或关闭。
  - 模板包导入：先按整包版本判断，再逐模板校验。包版本按 `resolveTemplateBundleVersion` 取所用功能的最高版本（逻辑取值候补含特征值或费用账单字段映射特殊处理 v9；费用账单、两类过滤、重复账单过滤或逻辑取值 v8；仅映射选用特征值 v7；否则 v6/v5）。接收方能读的最高版本：v3.2.17 为 v6，v3.2.18 为 v7，v3.2.19～v3.2.20 为 v8，v3.2.21 为 v9；包版本高于接收方时整包拒绝。只有接收方支持该包版本时才逐条规范化包内特征值，新键名报「不支持的分隔符」，该模板被跳过、其他模板照常导入。
  - v3.2.17 及更早：只读单数 `featureFilter`，忽略 `featureFilters` 列表；有映射选用特征值的包至少为 v7，整包拒绝；没有映射选用时列表被整体忽略，这与分隔符无关（v3.2.18 起即如此）。

### 3.4 「启用」列（D6）

- 去掉首列单元格 `::after` 竖线及起止行样式（`mapping-enable-span-start/-end` 不再添加）；「启用」列头、勾选框居中位置、行高不变。

## 4. 非目标

- 不改特征值的匹配规则、id 分配、删除保护、模板包版本与生成链路。
- 不改映射关系管理其他行的布局。

## 5. 验收

- 主弹窗「按字段区分发生额」下方为「特征值设置」【管理】，点击打开特征值管理；映射行与拆分弹窗均无【特征值管理】。
- 特征值管理打开时：有特征值则选中最早新增的一项并回显；无特征值为空白；删除后回到剩余最早的一项；未改动【保存】不写库。
- 分隔符下拉含 `-`、`_`、`$`，保存后按所选分隔符拆段取值并导出。
- 「启用」列无竖线，勾选框位置与行高不变。
- 验证：`tests/unit/backend/file-service/feature-filter.test.js`、`scripts/integration/statement-feature-filter.js`（⑧）、`scripts/renderer-lifecycle/fixtures/configuration-dialogs.js` 相关用例。
