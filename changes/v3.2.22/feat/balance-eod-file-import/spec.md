## 1. 背景

| 需求 | 现状 | 问题 |

| 核对上一账单日余额 | 【导入余额文件】只在普通「补录上一账单日余额」弹窗出现 | 已有种子但首日对不上时只能手输 |

## 3. 功能规则

### 3.1 导入余额文件（D1–D4、D6）

- **入口**：普通「补录上一账单日余额」与「核对上一账单日余额」两种弹窗的左下角。断档补录、余额不一致确认、人工补录替换确认不出现。
- **待匹配账号**：
  - 普通补录：当前分组首个账单日之前没有任何种子的全部账号（同 v3.2.17）；
  - 核对：当前核对账号（当前账单日期取提示）排第一，再加本分组缺种子的账号（银行账号 + 币种去重）。
- **文件**（D7、D8，R28 起）：只接受 xlsx——扩展名不是 `.xlsx` 或内容不是 xlsx（ZIP 包）时提示「余额文件须为 xlsx 格式（清结算系统导出的「银行原始日终余额信息」），请在 Excel 中打开并另存为 xlsx 后重新导入」，不读取（此前接受的 xls、csv 及按内容判断格式的各项口径一并停用）。读第一个工作表（Excel 的第一个标签）；该表隐藏时提示「余额文件的第一个工作表是隐藏的，请把余额所在的工作表取消隐藏并移到第一个后重新导入」。读取前按原始字节核对结构白名单，不符合时提示「无法核对余额文件的工作表内容，请在 Excel 中打开并另存为 xlsx 后重新导入」，不导入：
  - 部件：根关系、工作簿与工作簿关系、第一张工作表、共享字符串、样式表。工作簿只有一个，根关系指向的工作簿、工作簿关系指向的共享字符串与样式表，与读取库按内容类型取的部件相同；工作簿的标签数、第一个标签名、日期系统（含扩展里的 `workbookPr`）与读取库读出的一致。
  - 写法：UTF-8 编码、XML 1.0 字符；除开头的 XML 声明外没有处理指令、注释、CDATA、DTD；标签内只用空格与换行分隔；命名空间只在根元素、扩展列表的 `<ext>` 与 `mc:AlternateContent` 中声明，用到的前缀都已声明；只用五个预定义实体，字符引用只出现在 `<t>`、`<v>`、`<f>` 的文本中。
  - 读取用到的元素（工作表数据、行、单元格、合并范围、列样式、条件格式、维度；数字格式、单元格格式、差异格式；共享字符串项；工作表标签、工作簿属性；关系）：在扩展列表外须在主命名空间、父元素为规定的元素、不在 `mc:AlternateContent` 中、个数符合（如工作表数据恰好一个、合并范围表至多一个）；扩展列表中只允许条件格式、差异格式、数字格式、工作簿属性等几种，`<xm:sqref>` 为规范写法（大写单元格引用、单个空格分隔）。属性名只含字母数字（关系只认 `Id`、`Type`、`Target`、`TargetMode`，其他元素首字母小写），小写后不重复（读取库按小写名称与下划线前的部分另存别名），带前缀的只认 `r:id`、`x14ac:dyDescent`、`xr:uid`；序号、开关与单元格引用类属性为规范写法；关系不得指向外部。
  - 白名单只看结构，不限定保存软件：随包 `assets` 下 27 个与本机 80 个由 Excel、WPS、Apache POI、读取库保存的 xlsx 均能通过。下文 R17–R27 的逐项核对（公式缓存、合并范围、条件格式、样式继承等）保留为第二层。
  - 只读一次文件字节，结构核对、原值、显示文本、日期系统与行号都取自这一份字节；读取范围为工作表声明的范围（dimension）与实际有单元格的范围的并集（R19 起：有的导出工具追加行后不更新声明的范围，Excel 照常显示）；只转换有内容的行与有内容的列（R21 起：远端带样式的空白格会把有效范围撑到 16384 列，不按全宽展开；R23 起跨列合并的标题（如 `A1:XFD1`）只在有内容的列上标记被遮住的格，没有内容的列不转换；R24 起数组公式的结果区域同样只核对有内容的列，宽数组区域不逐列展开；R25 起区域索引只建在有单元格的列上），「行号」为原表物理行号。前 10 个非空行（只有读不出原值的单元格的行也算非空）内需有一行同时包含 6 个取值列名（trim 后精确匹配），否则提示「余额文件缺少列：…」并列出需要的列。「余额来源」「余额获取方式」可选，缺失时显示为空；这两列的格读不出原值时显示「读不出（原因）」，不显示读取库读出的空串、FALSE 等，不影响该行参与匹配与选择；R26 起这两列按银行账户号同口径核对显示格式（生效的数字格式、条件格式可能改变显示时显示「读不出（单元格的数字格式或条件格式可能改变显示的内容，无法确认）」——同账号同日多个余额时用户靠它区分，不显示可能与 Excel 不同的文本）。其他列忽略。
- **解析**：同 v3.2.17——银行账户号去首尾空格，数字单元格只在不超过 15 位整数时采用；超过 15 位或带小数的数字（Excel 只保留 15 位有效数字）、拿不到显示文本的数字、没有计算结果的公式、无法识别的数值在 Excel 中看得到账号却无法确认原值，跳过又可能让该账号退回更早一天的余额，整个文件不导入，提示「余额文件第 N 行的银行账户号…，无法确认属于哪个账号，请把银行账户号改为文本或修正后重新导入」（R24 起，此前按无效行跳过；Excel 错误值、被跨列合并遮住的格在 Excel 中也看不到账号，仍按无效行跳过）。银行账户号显示的内容可能与原值不同时整个文件不导入（R23 / R24 起）：显示文本与原值不同（如 `000000` 格式把 123 显示为 000123、自定义格式的文本段把文本 1 显示为 HK1；此前按无效行跳过），单元格实际生效的数字格式不是常规 / `0` / 文本（含读取库不应用的继承行样式（customFormat）、列样式与命名样式的格式；继承规则不判断，单元格没有自身样式时样式 0、行样式、列样式都须为这三种），或被带数字格式的条件格式覆盖（按条件格式的区域逐格；纵向合并的格只按首格核对，被遮住的格自身残留的格式不影响显示，R25 起；R27 起条件格式块与列样式（`<cols>`）按 XML 元素识别，结束标签带空白（`</conditionalFormatting >`）、自闭合的块不漏读，条件格式块不在 sheetData 之后或结构无法解析时按全部格处理，列样式无法确认时所有格按可能改变显示处理）——读取库给的显示文本不应用条件格式与继承的格式，Excel 可能显示成另一个账号，跳过该行又可能让该账号退回更早一天的余额，提示「余额文件中银行账户号显示的内容可能与原值不同（单元格的数字格式或条件格式），无法确认属于哪个账号，请把银行账户号改为常规或文本格式后重新导入」。R28 起（D9）按表头所在行以下每个有值的格核对（含空文本、只有空白的文本：带文本段格式时 Excel 会显示成另一个账号），币种、银行名、开户地同口径，整个文件不导入，提示「余额文件中{列名}显示的内容可能与原值不同（单元格的数字格式或条件格式），无法确认余额属于哪个账号，请把{列名}改为常规或文本格式后重新导入」。样式表无法核对（UTF-16 等非 UTF-8 编码、CDATA / DTD、注释没有结束）时所有格按可能改变显示处理；样式表与关系文件中的注释不算（R24 起：注释里的 `<dxf/>` 会使差异格式的序号错位）；差异格式表不止一个或有 `<dxf>` 以外的内容、条件格式的 dxfId 指向差异格式表里没有的项（R27 起）时按条件格式带数字格式处理；工作簿没有样式表部件（可选部件）时按常规格式处理，单元格引用不存在的样式时按可能改变显示处理（R27 起，此前整份按无法核对拒绝；账单查重同口径）；条件格式的 dxfId 不是纯数字（如字符引用 `&#48;`）时同样按带数字格式处理；自定义格式只取 `<numFmts>` 中的定义（差异格式 `<dxf>` 里同号的 numFmt 不覆盖单元格的格式），`<numFmts>`、`<cellXfs>`、`<cellStyleXfs>` 任一出现多次，或格式编号 / 样式序号（numFmtId、xfId）不是纯数字时所有格按可能改变显示处理（R25 起）；`<numFmts>`、`<cellXfs>`、`<cellStyleXfs>`、`<dxfs>` 只认主命名空间的直接子元素（R26 起：声明为 mc:Ignorable 的 `<extra:dxf/>`、`<extra:xf/>` 等扩展元素 Excel 忽略，按局部名称计入会让样式与差异格式的序号错位），表内有其他元素、嵌套同名元素、在扩展列表 `<extLst>` 以外声明命名空间，或样式表根元素不在主命名空间时同样按无法核对处理；账单日期：数字单元格按工作簿日期系统换算序列号（日期系统无法确认时读不出）；文本只接受四位年份在前的写法（`2026-09-30`、`2026/9/30`、`2026.9.30`、`2026年9月30日`，可带时间）与有效的 8 位 YYYYMMDD（D10，R28 起）——日在前或月在前（如 `03/02/2026`、`30/09/2026`）、两位年份（如 `30/09/26`、`26年9月30日`）、不是有效 YYYYMMDD 的 8 位数字（如 `01102026`）按读不出处理，原因为「无法确认年、月、日的顺序」（Excel 按系统的区域设置可能读成另一天）；其他文本（如 `Sep 30, 2026`、纯数字文本）原因为「无法识别为日期」；期末余额允许千分位，但文本带逗号时只接受分组正确的写法（`1,234.56`；`12,34`、`1,23,456` 等可能是十进制逗号或其他分组，去掉逗号会放大金额，按「无法识别为金额」读不出处理，R18 起），`0` 有效；账号为空、日期或金额无效的行跳过并计数（取值列为空、只有参考列有内容的残缺行同样计数；取值列与参考列都为空的行不计）；其中账号可识别的行可能就是该账号当天的余额行，另按读不出处理（账单日期 / 期末余额读不出，原因为「为空」「无法识别为日期」「无法确认年、月、日的顺序」「无法识别为金额」），匹配时该账号不退回更早一天（规则见下条）；币种为空的行同样按币种读不出处理。银行名、开户地、币种去首尾空格。
- **匹配**（每个待匹配账号）：
  - 取 银行账户号 相同、币种 / 银行名 / 开户地 不区分大小写相同、`账单日期 < 当前账单日期` 的行中日期最新的一天：
    - 该日只有一个余额（按分去重）→ 来自文件，预填日期与余额（取该日首行原值）；
    - 该日有多个不同余额 → 待选择，弹出「选择余额」（见下）；
  - 账号 + 币种在文件中存在，但银行名 / 开户地都对不上 → 需手工录入，原因写明文件里的银行名 / 开户地（最多列 3 组）与本组的银行名 / 开户地；
  - 没有早于当前账单日期的行 → 需手工录入「文件中没有该账号早于 {当前账单日期} 的余额」；
  - 文件中没有该账号 + 币种 → 需手工录入「文件中没有该账号」。
  - 币种、银行名、开户地存成数字等非文本的格时一律按读不出处理（「开户地读不出（单元格不是文本，无法确认显示的内容）」），不当作另一开户地而排除该行、退回更早一天的余额（R22 起；R23 起不再按显示文本放行：读取库给的显示文本不应用条件格式，常规格式的 1 在 Excel 中也可能显示为 001）。文本格同样可能被格式改变显示（R24 起）：显示文本与原值不同（「单元格显示的内容与原值不同」），时按读不出处理；按银行账户号的口径（生效的数字格式、条件格式）可能改变显示时，R28 起整个文件不导入（D9，见「解析」）。常规格式的数字仍按读不出处理。
  - 「文件中有没有该账号」「银行名 / 开户地是否一致」按可读的身份字段（账号、币种、银行名、开户地）判断，期末余额或日期读不出的行也算；余额能否采用只看所有字段都可读的行（如唯一一行在当前账单日、期末余额读不出 → 「文件中没有该账号早于 … 的余额」，不报「文件中没有该账号」）。读不出的银行名 / 开户地不算对不上；银行名 / 开户地为空、本组的不为空时按读不出（为空）处理（可能是同一开户地漏填或没读到，不当作另一开户地而退回更早一天；本组的也为空时照常按空值比较，R19 起）。
  - 读不出原值的单元格（读取库会读成空串等）：Excel 错误值（#N/A 等）、没有计算结果的公式（文本公式读出空串、布尔公式与没有值的错误公式，与没有缓存结果无法区分，一并算；数组公式结果区域里读取库没有建单元格的格同样算，只看区域内有内容的行；xlsx 另按工作表 XML 原文识别带公式却没有缓存值的格，如写成空 `<f t="shared" si="0"></f>` 有注释（读取库会解析注释里的行），或工作表数据（`<sheetData>`）不是规范写法（R19 起：读取库按正则切分行与单元格，与 Excel 的 XML 解析有多处不同，如 `<c` 后接换行时整格漏读、数值格 `<v>20,50</v>` 读成 20；只接受标签名后紧接空格 / `/` / `>`、属性的 `=` 前后没有空白（R20 起）、结束标签没有空白、没有 CDATA 与非预定义实体、`<row>` / `<c>` 都带 r 且行号递增、单元格引用的行与所在行一致且列递增、`<c>` 只含至多一个 `<f>` / `<v>` / `<is>`、`<v>` 除 `xml:space="preserve"` 外不带属性、`<v>` 按单元格类型是完整字面值的写法（单元格类型不含日期 `t="d"`：读取库按本机时区换算 ISO 日期，与 Excel XML 结构解析，读取库按正则切分，自闭合的 `<si/>` 会使后面各项的下标整体错位，把账号 A 的格读成账号 B；读取库读文本格时先解开字符引用再按 UTF-8 解码，`&#39321;&#28207;`「香港」等非 ASCII 的字符引用与 `_xHHHH_` 转义读成乱码，最新一行因银行名对不上被排除；内联文本直接的 `<t>` 与 `<r>` 并存时取值不明确，同样无法核对），Excel 与常见导出工具写出的文件都满足；R25 起工作表根元素 `<worksheet>` 与 `<sheetData>` 须在 SpreadsheetML 主命名空间（过渡或严格写法），`<sheetData>` 内的元素只用绑定到主命名空间的前缀（富文本属性 `<rPr>` Excel 中打开并另存为 xlsx 后重新导入」，不导入）、跨列合并单元格中首格以外的列（合并范围取读取库读出的与 xlsx 工作表原文中的并集，读取库会漏掉单引号写法的 `ref`；R26 起工作表原文只取根元素 `<worksheet>` 的直接子元素 `<mergeCells>` 下主命名空间的 `<mergeCell>`（R27 起按父元素核对：放在声明为 mc:Ignorable N 行）开户地读不出（Excel 错误值 #N/A），无法确认该账号的余额，请手工填写」（不退回更早一天）。银行账户号为 Excel 错误值、被跨列合并遮住时无法归属，按无效行跳过并计数；没有计算结果的公式、无法确认原值的数字、显示可能与原值不同时整个文件不导入（见「解析」）。
  - 纵向合并单元格：Excel 整块显示首格的值，同列后续行一律按首格读取（如两天共用一个合并的开户地或账号；被遮住的格里残留的旧值不用，首格读不出时后续行同样读不出）。
  - 核对账号：文件里最近一天早于该账号当前已有的最近余额日期（按导入时的种子记录取，与重算同口径）→ 需手工录入「文件中该账号最近的余额在 X，早于已有的 Y 余额，导入后仍按已有余额核对，请手工填写」；确认视图该行日期不得早于 Y（输入框下限与提示；读取已有余额失败时提示文件损坏，不带种子文件路径），保存前主进程预检按当时的种子记录再核一次，更早的日期拒绝「上一账单日日期不能早于已有余额的日期 Y（更早的余额不会用于本次核对）」，不写入不会被采用的历史余额。
- **选择余额弹窗**：有待选择账号时先弹出，标题「选择余额」。按账号分组，每组列出该日全部行：期末余额、余额来源、余额获取方式、账单日期、银行名、开户地、币种、银行账户号（及文件行号），单选；默认不选。用于比较的期末余额、余额来源、余额获取方式紧跟「选择」列，窗口放大到 150% 时不必横向滚动即可看到。
  - 【确认】：每组都须选一行，否则在常驻按钮栏提示还有几个账号未选择，正文滚到第一个未选的账号并聚焦；之后每次选择都同步更新剩余数，选齐后提示隐藏；选定后该账号按所选行的日期与余额预填，来源标「已选择」，进入「余额确认」视图。
  - 【取消】或关闭：放弃本次导入，回到导入前的视图，不写任何种子。
- **余额确认、连续保存、账号核对、返回、留痕**：沿用 v3.2.17 §3.1。确认清单内的普通缺种子账号与核对账号都可连续保存；保存后主进程的下一个提示仍是本分组、清单内、尚未保存的账号（普通补录或核对）就继续，其余情况（断档、余额不一致、人工补录替换、覆盖确认、清单外账号、校验失败、报错或完成）停下交给原有流程。导入日志增记银行名 / 开户地与待选择账号数；日志中的文件名、模板名、银行名 / 开户地按待匹配账号与长数字脱敏，界面仍显示原名。
- 余额按文件原值保存为人工补录，不扣回余额附加值（同 v3.2.17 D2）。

### 3.2 去掉账号顺序固定（D5）

- 大账号确认页不再显示「多账号账单导入解析模式」下拉与「记住顺序」；每次多账号导入都按账号顺序不固定口径手动选择（不含无交易空段）。「单个账号匹多个文件」不再与记住顺序互斥。
- 主进程不再读取已保存的模式与顺序，不再按记住的顺序自动分配大账号，也不再弹「记住顺序不匹配」提示；选择结果按不固定口径校验与执行。
- 原表只有表头、没有任何数据行的文件（按映射时记下的原表数据行数判断：表头以下的非空行，在读取器遇到汇总行截断、截掉模板表头范围以外的列之前统计，所以只有汇总行、只有范围外的列有值，或只有 Excel 错误值（读取库读成空串，按原表单元格计入）也算有数据；工作表声明的有效范围（xlsx 的 dimension 等）以外仍有内容的行同样计入（R20 起：有的导出工具追加行后不更新声明的范围，读取器只读到声明范围为止，不把这类文件判为只有表头；账单读取本身仍按声明范围，见 backlog））不占分配位置（选择窗口与分配执行同一口径），直接识别大账号时也不参与识别（其余文件照常识别，生成仍用完整文件清单）；有数据行但没有借贷金额的文件（如只有余额行）、原表有数据但处理后没有输出的文件（「过滤账单」全部过滤、拆分合并零输出等，生成后照常给出原有提示）不算只有表头，沿用原口径。需要识别或分配大账号的导入（指定模板与按文件名映射：MerchantId 映射为多大账号或「自己输入」，或候选大账号多于一个），若全部文件都只有表头，在混合模式检查、直接识别与手动选择之前报「导入文件中没有账号存在交易数据」（指定模板为多大账号映射而没有候选大账号时，生成走原路径校验大账号、用不到映射结果，这里不映射整批，只按同一读取口径与文件变更检查逐文件探测原表，见到第一份有数据的文件即停止）（v3.2.21 及以前会让用户为空文件选择账号、误报未识别到大账号，或继续生成空明细）；预检阶段的这一拒绝按未开始导入处理，保留上一批的导出与补录入口。MerchantId 取自文件列、候选大账号不超过一个的模板不变。
- 用户数据目录里已有的 `big-account-modes/`、`big-account-orders/` 文件不删除、不再读取。
- 模板包：导出不再带 `bigAccountMode`、`bigAccountOrderConfig`；导入旧模板包时忽略这两项，不报错。模板数据里的 `fixedAssignments` 字段保留（模板契约不变）。
- 删除对应 IPC 与 Preload 接口（`bigAccount.loadMode / saveMode / loadOrder / saveOrder`）。

## 4. 非目标

- 批量一次写入多个账号的种子（仍逐个账号沿用现有写入与重算）。
- 覆盖确认后自动续保存清单内其余账号（沿用 v3.2.17：停下交给原有流程）。
- 扣回余额附加值。
- 按模板文件当前版本动态识别余额文件列名（D6 为结构参考）。
- 清理用户磁盘上残留的大账号模式 / 顺序文件；dormant 的 statement-worker 契约里的固定模式字段（见 backlog）。

## 5. 验收标准

- 两个账号缺种子，文件含其中一个账号多日余额（含当前账单日及之后的行）：确认视图预填早于当前账单日期最近一天的余额，另一个标需手工录入并写明原因；确认后依次写入人工种子并生成余额账单。
- 核对弹窗出现【导入余额文件】；导入后确认视图首行为核对账号，确认后按文件余额写入种子（日期与已有种子相同时先弹覆盖确认）。
- 同账号同日多条不同余额：弹出选择余额，显示余额来源与余额获取方式；未选全不能确认；取消后不进入确认视图、不写种子；选定后确认视图按所选行预填。
- 同账号同日多条相同余额：不弹选择，直接取。
- 账号与币种相同但银行名或开户地不同：不匹配，标需手工录入并写明文件中的银行名 / 开户地。
- 旧 4 列余额账单格式：提示缺少列。
- 余额文件只接受 xlsx：csv、xls 等扩展名，或扩展名为 `.xlsx` 但内容不是 xlsx 时提示另存为 xlsx；第一张表隐藏、结构不符合白名单时不导入；随包与本机样本 xlsx 全部能通过白名单（D7、D8）。
- 身份列带数字格式或被条件格式覆盖时整个文件不导入；日在前、两位年份的文本日期按读不出处理（D9、D10）。
- 大账号确认页无模式下拉与记住顺序；残留的 fixed 模式与记住顺序文件不再触发自动分配，仍进入手动选择；旧模板包（带 `bigAccountMode: 'fixed'`）导入成功。
- 设置 → 模板文件列出「银行原始日终余额信息」，可另存为。
