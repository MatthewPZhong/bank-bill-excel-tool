# Spec：工具箱合表 / 按字段拆分的确认前冻结与发布前核对（B57、B58）

> status: done
> created: 2026-11-23
> 目标版本：v3.2.22（暂定，发版时按 weekly-release 调整）
> 适用分支：`fix/toolbox-publication-freshness`
> 分支基线：正式标签 `v3.2.21`（`0e996340`）
> 依据：`knowledge/backlog.md` B57、B58 的关闭条件；2026-11-23 用户选定本轮修复范围；Codex 审查（2026-11-23 第一轮）
> 参照实现：按行拆分 `src/main-process/toolbox-row-split/service.js` `prepareRows`（确认前冻结、确认后核对）

## 1. 背景

| 编号 | 问题 |
| --- | --- |
| B57（P1） | 按字段多文件拆分在「覆盖全部」确认之后才形成 FilePlan：确认弹窗等待期间外部新建的目标、或被替换的已列出目标，会被当作合法目标覆盖 |
| B58-T3（P2） | FilePlan 冻结后源文件被替换，合表 / 单值 / 多文件拆分仍从原路径读新内容并正式发布，随后输入归档因 `ARCHIVE_SOURCE_CHANGED` 失败，正式输出缺少相符的输入归档 |
| B58-T4（P2） | 发布包装层只补目标文件快照，合表与单值 / 多文件拆分未把冻结的父目录身份交给发布器，目标目录被同路径替换后仍发布成功 |

## 2. 决策

| 编号 | 决策 |
| --- | --- |
| D1 | 多文件拆分在目录选定、非普通文件预检之后立即 `normalizeFilePlanV1` 冻结全部目标（含尚不存在的）与源文件；按冻结快照的 `targetSnapshot.exists` 列出冲突再弹「覆盖全部」；确认后 `assertFilePlanFresh`，确认期间的新建 / 替换报 `ARCHIVE_TARGET_CHANGED` 并取消，不覆盖任何文件。没有冲突、不弹确认时冻结刚核对过全部目标且其后没有等待，不再重复同步核对（高延迟网络盘上避免阻塞其他 IPC，Codex 第七轮 P2）。`prepared.filePlan` 就是确认前冻结的计划，契约层（`ipc-task-contract.js`）直接沿用，生命周期在执行前再核对一次 |
| D2 | 合表、单值拆分在保存框返回后同样立即冻结（系统保存框自带覆盖确认，冻结点与其相邻）。三种都先只冻结目标（目标快照与父目录身份，`freezeToolboxFilePlanTargetsFirst`），再访问输入（别名检查、输入快照）；完整计划沿用先冻结的输出证据、不重新采样（`normalizeFilePlanV1` 新增可选参数 `reuseFrozenOutputsOf`：只接受本进程登记过的冻结计划，按冻结输出的下标逐项核对声明、拒绝空槽，路径、角色、来源操作及显式给出的文件名与 artifactKey 须与冻结值一致，省略文件名时沿用冻结值；冻结项本身带预先生成的产物证据时不沿用），返回给执行阶段的计划携带的就是用户确认时的目标版本，父目录身份的可靠性也按首次冻结（首次不可靠时之后只核对路径，首次可靠时之后核对 dev / ino）；之后按冻结的证据核对当前磁盘（`assertFilePlanFresh`），不一致报 `ARCHIVE_TARGET_CHANGED`。别名检查或完整计划规范化失败时（如目标被建成文件夹）先核对目标，目标变了、或系统错误指向输出路径与其任一级上级目录（目录被移走后又移回；按工具箱既有的路径别名规则 `normalizeTargetAliasKey` 比较：macOS 不区分大小写与 Unicode 组合 / 分解形式，Windows 不区分大小写；字面路径未命中时按解析后的真实路径再比，错误经指向输出目录的目录链接报出时同样归为目标变化，Codex 第八轮 P3）时报目标变化（中文提示），否则原样抛出输入本身的错误。合并多个文件或输入在网络盘上时，遍历输入期间外部新建或替换的目标不被当作用户已确认覆盖的版本（Codex 第一轮 P1、第二轮 P2、P3，第三轮 P1、P3，第四轮 P2、P3，第五轮 P3 ×2，第六轮 P3 ×3，第七轮 P3，第八轮 P3） |
| D3 | 发布包装层 `publishToolboxArtifacts` 带冻结 FilePlan 时：目标须与计划输出逐一对应（数量、路径一致，按计划输出的下标逐项核对，数组空槽也拒绝，Codex 第八轮 P3）；父目录身份统一从计划输出取出交给发布器复核（目录被同路径替换即 `TOOLBOX_PUBLICATION_TARGET_PARENT_CHANGED`；文件系统给不出可靠的目录身份（dev / ino 为 0 或冻结期间不稳定，`identityReliable: false`）时按 [v3.2.3 TechDoc](../../../v3.2.3/techdoc.md) 第 265 行「既有 action 不得因 Windows 能力未知被误伤」退回路径核对，不设 `requireTargetParentIdentity`，与按行拆分相同）；发布前再核对一次计划的全部输入（`assertFilePlanInputsFreshAsync`：与同步核对同一口径，异步访问文件系统，输入在网络盘上断连或高延迟时不阻塞主进程，Codex 第六轮 P2），源文件被替换或改写即拒绝（合表 `ARCHIVE_INPUT_CHANGED`，拆分沿用 `TOOLBOX_SPLIT_READ_CONTEXT_STALE`「拆分源文件在读取后已变化，请重新选择」）；单值拆分零命中、不进入发布时，返回「无匹配行」前同样核对一次输入（普通与大文件通道；后台生成通道在 worker 内生成后已核对），生成期间源文件被替换时报源文件已变化，不把另一版本的结果当作本次筛选结果（Codex 第九轮 P2）。`normalizeFilePlanV1` 的 `reuseFrozenOutputsOf` 只适用于 eager 计划，deferred / none 时拒绝（第九轮 P3）；生成器失败、尚未进入发布时同样先核对输入：前台合表与四条拆分生成器调用（普通、大文件通道）经 `generateToolboxCheckingInputs` 按计划的失效口径报出，后台合表 / 单值拆分的 worker 与多文件拆分的编排在生成失败时按 `ARCHIVE_INPUT_CHANGED` 报出；源文件未变或已取消时保留原错误，避免源文件被换成缺少所选字段的版本时提示用户检查字段名（Codex 第十轮 P2）；改报源文件已变化时保留原错误的暂存保留标志、清理诊断与人工恢复路径，清理失败的暂存文件不被外层删除；后台多文件拆分编排的失败后核对在主进程异步读取（Codex 第十一轮 P2 ×2）。多文件拆分覆盖确认后核对到源文件已变化时清除本次拆分读取会话（目标变化等其他失败保留会话，第十二轮 P3）。生成器失败、源文件同时变化、暂存清理也失败三者叠加时，合表生成器与后台通道改报源文件已变化会丢掉清理诊断与保留标志：2026-11-24 用户决定外部故障叠加类 P2 按残余风险收口，登记 `knowledge/backlog.md` B139（第十二轮 P2 ×2） |
| D4 | 目标文件与父目录的复核仍由发布器在提交时完成，包装层只补发布器不掌握的输入快照；共享发布器（VCC 等也在用）不改 |
| D5 | 不改执行策略登记（G7 registry、mode、production 开关），也不切换后台 / 非后台路径 |

## 3. 行为与边界

- 用户可见变化：确认期间或确认后目标被外部改动、生成期间源文件被替换时，本次导出失败并提示原因，需重新操作；此前会覆盖或发布不一致的输出。
- 只读导出（持仓 / 预付等）同样经过包装层：其计划输入为空，父目录身份随之由发布器复核，只加严。
- 残余窗口：发布前核对输入到发布器提交之间仍有极短窗口，若源文件恰在此时被替换，正式输出已提交而输入归档失败（保留 receipt，按既有「存档接管待重试」处理），与按行拆分现状相同。
- 残余窗口：合表、单值拆分在保存框返回到首次冻结目标之间（毫秒级），外部程序新建的同名文件会被当作已确认覆盖；冻结内部补核对只能缩小窗口。2026-11-24 用户决定按残余风险收口，登记 `knowledge/backlog.md` B138（Codex 第九轮 P1）。
- 源文件「替换后再原样换回」（同 inode、同时间戳）不在快照可检测范围内。
- 目标所在文件系统给不出可靠的目录身份时，父目录被同路径替换无法识别（见 D3），与修复前相同。

  - 合表 / 单值 / 多文件：发布前父目录被同路径替换时发布器拒绝、不结算（以冻结时身份可靠为前提，临时卷给不出可靠身份时跳过）；未变时照常发布、回读正确；

  - 合表 / 单值 / 多文件：完整计划规范化时目录被临时换成有同名文件的另一处、随后换回：计划仍是确认时的目标版本，之后再换过去时核对拒绝、对方文件不变；只有完整计划规范化时父目录身份暂时不可靠：计划带先冻结的可靠身份、照常导出（以本次首次冻结的真实结果判定前提，给不出可靠身份时跳过）；首次冻结不可靠、之后可靠：计划与交给发布器的期望身份都是首次冻结的不可靠身份（发布器在独立 Worker 复核，按不可靠身份只核对路径的行为由 D3 用例覆盖）、照常导出；完整计划规范化时目录（或输出所在子目录的上级）被移走又移回、别名检查时目录被移走：报 `ARCHIVE_TARGET_CHANGED`（中文提示）、不发布（夹具 `duringFullPlanSampling` 只在指定的那次规范化期间注入；第四轮的 12 项、第五轮的上级目录 3 项在各自上一提交的实现上均失败，已验证）；
  - 合表选两份源文件、只在生成后替换第二份：`ARCHIVE_INPUT_CHANGED`、不发布不结算（发布前只核对第一份时失败，已验证）；不区分大小写的卷上输出目录与输入所在目录大小写不同、或只差 Unicode 组合形式（macOS，第七轮；按大小写折叠比较时失败，已验证）、规范化期间被移走又移回：报目标变化；多文件拆分只有弹出覆盖确认时才在确认后核对整份计划（第七轮，确认后无条件核对时失败，已验证）；发布目标少一个、顺序调换或有空槽时在调用共享发布器前拒绝、不结算（第七、八轮；逐项核对改回遍历目标数组时空槽失败，已验证）；输入经指向输出目录的目录链接读取、规范化期间输出目录被移走又移回：报目标变化（第八轮，不按真实路径再比时失败，已验证）；单值拆分（普通与大文件通道）生成期间源文件被替换为不含所选值的版本：报源文件已变化、不报「无匹配行」（第九轮，零命中前不核对输入时失败，已验证）；`reuseFrozenOutputsOf` 用于 deferred / none 计划时拒绝（第九轮，不拒绝时失败，已验证）；生成器报错时：合表、单值 / 多文件拆分（普通与大文件通道）生成期间源文件被替换报源文件已变化、不报找不到字段，源文件未变时保留原错误，均不发布；后台单值拆分 worker 生成期间源文件被换成缺少所选字段的版本、后台多文件拆分编排生成失败时报 `ARCHIVE_INPUT_CHANGED`（第十轮，三处核对各自去掉时失败，已验证）；源文件未变时原样透传注入错误的错误码与消息（第十一轮，改为通用错误时失败，已验证）；合表、单值、多文件拆分的生成器清理失败且源文件被替换：报源文件已变化、只附清理诊断、暂存文件保留（第十一轮，不保留标志或诊断时失败，已验证）；后台多文件拆分失败后的核对不同步访问源文件（第十一轮，改用同步读取时失败，已验证）；覆盖确认期间源文件被改写：报源文件已变化并清除拆分读取会话，目标变化时不清除（第十二轮，不清除或一律清除时失败，已验证）；后台多文件拆分源文件未变时还原 Worker 经协议回传的具体错误码与消息、后台单值拆分保留生成器的缺字段原错误（第十二轮，不还原 Worker 错误时失败，已验证）；`assertFilePlanInputsFreshAsync` 不同步访问文件系统、口径与同步核对一致；
