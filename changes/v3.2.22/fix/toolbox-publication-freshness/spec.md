## 1. 背景

| 编号 | 问题 |
| --- | --- |
| B57（P1） | 按字段多文件拆分在「覆盖全部」确认之后才形成 FilePlan：确认弹窗等待期间外部新建的目标、或被替换的已列出目标，会被当作合法目标覆盖 |
| B58-T3（P2） | FilePlan 冻结后源文件被替换，合表 / 单值 / 多文件拆分仍从原路径读新内容并正式发布，随后输入归档因 `ARCHIVE_SOURCE_CHANGED` 失败，正式输出缺少相符的输入归档 |
| B58-T4（P2） | 发布包装层只补目标文件快照，合表与单值 / 多文件拆分未把冻结的父目录身份交给发布器，目标目录被同路径替换后仍发布成功 |

## 2. 决策

| 编号 | 决策 |
| --- | --- |
| D1 | 多文件拆分在目录选定、非普通文件预检之后立即 `normalizeFilePlanV1` 冻结全部目标（含尚不存在的）与源文件；按冻结快照的 `targetSnapshot.exists` 列出冲突再弹「覆盖全部」；确认后 `assertFilePlanFresh`，确认期间的新建 / 替换报 `ARCHIVE_TARGET_CHANGED` 并取消，不覆盖任何文件。`prepared.filePlan` 就是确认前冻结的计划，契约层（`ipc-task-contract.js`）直接沿用，生命周期在执行前再核对一次 |
| D2 | 合表、单值拆分在保存框返回后同样立即冻结（系统保存框自带覆盖确认，冻结点与其相邻）。三种都先只冻结目标（目标快照与父目录身份，`freezeToolboxFilePlanTargetsFirst`），再访问输入（别名检查、输入快照）；完整计划规范化时会重新采样目标，之后要求完整计划里每个目标的证据与先冻结的一致（目标快照相同；父目录身份按首次冻结的可靠性比较：首次不可靠时只核对路径，首次可靠时须仍可靠且 dev / ino 相同），再按先冻结的证据核对当前磁盘（`assertFilePlanFresh`），任一不一致报 `ARCHIVE_TARGET_CHANGED`。这样返回给执行阶段的计划携带的就是用户确认时的目标证据：重新采样时目录被临时换成另一处、随后换回，或只有第二次采样的身份暂时不可靠，都报目标变化。别名检查或完整计划规范化失败时（如目标被建成文件夹、目录被移走）同样先核对目标，目标变了报目标变化（中文提示），否则原样抛出输入本身的错误。合并多个文件或输入在网络盘上时，遍历输入期间外部新建或替换的目标不被当作用户已确认覆盖的版本（Codex 第一轮 P1、第二轮 P2、P3，第三轮 P1、P3） |
| D3 | 发布包装层 `publishToolboxArtifacts` 带冻结 FilePlan 时：目标须与计划输出逐一对应（数量、路径一致）；父目录身份统一从计划输出取出交给发布器复核（目录被同路径替换即 `TOOLBOX_PUBLICATION_TARGET_PARENT_CHANGED`；文件系统给不出可靠的目录身份（dev / ino 为 0 或冻结期间不稳定，`identityReliable: false`）时按 [v3.2.3 TechDoc](../../../v3.2.3/techdoc.md) 第 265 行「既有 action 不得因 Windows 能力未知被误伤」退回路径核对，不设 `requireTargetParentIdentity`，与按行拆分相同）；发布前再核对一次计划输入，源文件被替换或改写即拒绝（合表 `ARCHIVE_INPUT_CHANGED`，拆分沿用 `TOOLBOX_SPLIT_READ_CONTEXT_STALE`「拆分源文件在读取后已变化，请重新选择」） |
| D4 | 目标文件与父目录的复核仍由发布器在提交时完成，包装层只补发布器不掌握的输入快照；共享发布器（VCC 等也在用）不改 |
| D5 | 不改执行策略登记（G7 registry、mode、production 开关），也不切换后台 / 非后台路径 |

## 3. 行为与边界

- 用户可见变化：确认期间或确认后目标被外部改动、生成期间源文件被替换时，本次导出失败并提示原因，需重新操作；此前会覆盖或发布不一致的输出。
- 只读导出（持仓 / 预付等）同样经过包装层：其计划输入为空，父目录身份随之由发布器复核，只加严。
- 残余窗口：发布前核对输入到发布器提交之间仍有极短窗口，若源文件恰在此时被替换，正式输出已提交而输入归档失败（保留 receipt，按既有「存档接管待重试」处理），与按行拆分现状相同。
- 源文件「替换后再原样换回」（同 inode、同时间戳）不在快照可检测范围内。
- 目标所在文件系统给不出可靠的目录身份时，父目录被同路径替换无法识别（见 D3），与修复前相同。

## 4. 验收

- 单测 `tests/unit/main-process/toolbox-publication-freshness.test.js`（39 项，夹具 `tests/helpers/toolbox-main-handlers.js`，执行 Main 原始 prepare / execute 与真实发布器）：
  - 多文件拆分确认期间新建 / 替换目标时拒绝、原内容保留、冲突只列冻结时已存在的目标；确认后沿用同一计划，prepare 之后新建目标由生命周期核对拒绝；
  - 合表、单值拆分保存框返回即冻结；合表 / 单值 / 多文件在访问输入期间目标被新建或替换时拒绝、不覆盖对方文件（换回上一提交的 `main.js` 时这 6 项失败，已验证）；
  - 合表 / 单值 / 多文件：父目录身份首次采样不可靠、之后恢复时照常导出；访问输入期间目标被建成文件夹时报 `ARCHIVE_TARGET_CHANGED`（换回上一提交的 `main.js` 时这 6 项失败，已验证）；
  - 合表 / 单值 / 多文件：发布前父目录被同路径替换时发布器拒绝、不结算（以冻结时身份可靠为前提，临时卷给不出可靠身份时跳过）；未变时照常发布、回读正确；
  - 合表 / 单值：受控模拟目录身份一直不可靠时，同路径替换的目录只核对路径、照常发布（D3）。多文件拆分的暂存目录在目标目录内，替换目录即移走暂存产物，不适用此场景；
  - 合表 / 单值 / 多文件：完整计划采样时目录被临时换成有同名文件的另一处、随后换回，只有完整计划采样时父目录身份暂时不可靠，别名检查时目标目录被移走：均报 `ARCHIVE_TARGET_CHANGED`、不发布（夹具 `duringFullPlanSampling` 只在第二次采样期间注入；换回上一提交的 `main.js` 时这 9 项失败，已验证）；
  - 合表 / 单值 / 多文件：生成前、生成后源文件被替换时不发布。
  - 换回 v3.2.21 的 `main.js` 时 13 项失败（已验证）。
- 集成 `scripts/integration/toolbox-publication-freshness.js`（11 项；目录替换的 3 项在临时卷给不出可靠目录身份时打印 SKIP，不计入通过数与总数）：CSV 源 → 正式 xlsx 回读的同类场景；合表 / 单值 / 多文件各一项接真实 `TaskLifecycle` 与临时归档库，生成后源文件被替换时任务终态 failed、输入与输出归档项均为 failed、无 outbox 与发布 receipt。
