# Spec：网银按文件名映射多模板导入失败时还原输出、种子与会话（B45）

> status: done
> created: 2026-11-23
> 目标版本：v3.2.22（暂定，发版时按 weekly-release 调整）
> 适用分支：`fix/statement-multi-template-rollback`
> 分支基线：正式标签 `v3.2.21`（`0e996340`）
> 依据：`knowledge/backlog.md` B45 的关闭条件；2026-11-23 用户选定本轮修复范围；Codex 审查（2026-11-23 第一、二轮）

## 1. 背景

`main.js` `generateMultiTemplateGroupFiles`（按文件名映射、多模板分组生成）在业务校验全部通过后：先按 `replacePaths` 删除旧会话条目，再逐组写出明细 / 余额（直接写入 `exports/<今天>/`，与旧文件同名即覆盖）并立即写余额种子，最后合并汇总文件。写出或合并中途失败（如 Windows 上文件被 Excel 占用）时导入显示失败，但旧会话条目已删（后续「导出全部」漏掉被覆盖的账单）、前组的同名输出与种子已被失败批次替换。

## 2. 决策

| 编号 | 决策 | 依据 |
| --- | --- | --- |
| D1 | 旧会话条目在全部组写出与合并都成功后才替换 | B45 关闭条件 |
| D2 | 写出期间失败时回滚（补偿），不改为「先暂存再发布」：写出经写出记录（`statement-output-rollback.js` `write(filePath, writeFn)`）执行，每个路径首次写入前记下原状态（已存在的复制原内容到系统临时目录下的批次目录，不存在的记为新建）；任一组或合并失败时按逆序还原——原有文件原地写回、新建的删除——再抛出错误 | 同批后组需读取前组刚写入的余额种子（种子按日期链接计算）。推迟写种子会改变同批语义；暂存输出需改动生成、合并、会话缓存的全部路径引用。回滚只在写出边界加记录，现有语义不变。偏离 backlog「输出先暂存再发布」字样 |
| D3 | 记录范围：各组明细 / 余额文件、明细与余额汇总文件、余额种子文件（`generateStatementFiles` 新增 `writeOutput` 参数，三处写出都经它执行）。传入 `writeOutput` 时，余额文件与种子的写出异常原样抛出、整批回滚，不再转成「余额生成失败」告警继续提交；同时传入的 `checkOutputTarget` 在首次读取本组余额种子前检查种子路径，是文件夹等非普通文件时同样整批回滚。补录、断档、余额不一致、替换补录等待确认的业务告警与种子内容读取失败的告警不变 | 这些是该流程全部的磁盘副作用；否则后组余额写出失败或种子路径不安全时前组的新种子留在盘上、余额汇总缺组（Codex 第一轮 P1、第二轮 P1）。单模板导入不传，行为不变 |
| D4 | 原地写回：分块复制、以截断方式打开目标，不换文件（人工补录保护按种子文件 dev + ino 识别文件，`getBalanceSeedFileIdentity`）；不把整份文件读入主进程。当前内容与备份一致时不写回（如被 Excel 占用、写出时根本没打开的文件，写回会再次撞上占用并误报还原失败） | `balance-seed-store.js` 现有约定；Codex 第一轮 P2、P3 |
| D5 | 按文件身份记录：同一文件经不同路径写入（不区分大小写的文件系统上大小写不同的种子路径、硬链接）按 dev + ino 合并为一条，只保留首份备份。每次写完记下文件身份（dev + ino + 大小 + 修改时间）；同一文件再次写入前核对，被其他程序改动过即停止（`STATEMENT_OUTPUT_CHANGED_EXTERNALLY`）。回滚时：写完后被其他程序替换或修改的文件不覆盖、不删除；写出回调抛错时，本批只原地改写文件，路径上换成另一个文件的属于其他程序，导入前不存在、本批也没写成过的路径上出现的文件无法确认归属（可能是写到一半的本批文件，也可能是其他程序新建的），都不覆盖、不删除，与无法还原的文件一起交给人工 | 回滚只认路径会覆盖或删除外部文件（Codex 第一轮 P2、第二轮 P1 ×2、P2） |
| D6 | 路径上是符号链接、文件夹等非普通文件时在写出前拒绝（`STATEMENT_OUTPUT_TARGET_UNSAFE`，只给所在目录），由调用方回滚前组 | 写出会跟随链接改写别处的文件，回滚无法还原（Codex 第一轮 P2） |
| D7 | 首次记下每个文件时即把「原路径 ↔ 备份文件」追加到批次目录的「写出记录.txt」。还原不完整：备份目录只保留未还原文件的备份，写入「恢复清单.txt」（原路径 ↔ 备份文件 ↔ 处理方式 ↔ 原因），清单写不出（如临时卷已满）时以写出记录代替；改报业务错误 `STATEMENT_OUTPUT_ROLLBACK_INCOMPLETE`，消息（界面状态框只显示消息）给出未能还原的数量与清单位置，报错文件另列原失败原因与分类数量；系统异常的堆栈尽力写入日志；活动日志只记数量与清单位置。写日志失败不影响抛出该错误 | 资金口径的可审计性；内部文件名含完整账号，不写入报错文件与活动日志（Codex 第一轮 P2 ×3、第二轮 P2 ×3） |
| D8 | 写出期间的系统异常（如文件被占用）且本批已完整还原时，两个导入入口（直接导入、完成大账号选择）按未生效的导入返回（`preservesSession`）：只弹窗提示「已还原为导入前的状态，请关闭占用的文件后重新导入」，不清空上一批的导出缓存，界面保留上一批的状态框与导出按钮。不生成报错文件、不替换上一批可导出的报错文件（异常堆栈可能含内部文件名中的账号）；异常尽力写入日志文件，活动日志只记错误代码，写不出不影响返回。写出阶段的业务校验失败（已在写出前整批预检，极少）仍按普通失败处理，以便列出明细、导出报错文件 | 旧会话条目与磁盘都已还原，再清空上一批的导出入口与之不符（Codex 第一轮 P2、第二轮 P2 ×2） |

## 3. 行为与边界

- 用户可见：写出中途因文件被占用等系统异常失败时，弹窗提示已还原，上一批的导出文件、余额种子、会话与导出按钮保持导入前状态，关闭占用的文件后重新导入即可；成功时行为不变。
- 业务校验失败（收支同时有值、账单日期无效、渠道余额方式冲突等）在任何写出之前拦下，行为不变。
- 生成全程为同步调用，回滚完成前不会处理其他 IPC，不会与其他写种子的操作交错。
- 「本次运行里见过的人工补录」（内存）不另行回滚：确认替换写入后会去掉对应日期，种子还原后下次生成读盘时按当前人工补录重新记下（`indexManualBalanceSeeds`）；已确认的替换键仍在会话确认集合中，重试时按已确认处理，与修复前同一批次成功时一致。
- 残余风险：
  - 进程在批次中途退出（崩溃、断电）时无法还原，与修复前相同；系统临时目录里会留下备份目录（含账单数据与写出记录），由系统回收。
  - 导入前不存在的文件在写到一半时失败（如磁盘已满）会因无法确认归属而留给人工，按恢复清单删除即可。
  - 执行阶段开始时会清掉上一批的待补录提示（既有行为）。若上一批正等补录、又覆盖导入且写出失败，界面仍显示上一批的补录入口，点击时提示已失效，需重新导入上一批。
  - 外部程序在本批写出与下一次写出之间改动同一文件、且大小与修改时间都不变时无法识别（文件系统时间精度内）。
- 单模板导入、补录后重算、「导出全部」不在本次范围。

## 4. 验收

- 集成 `scripts/integration/statement-channel.js` Step⑳（同一银行段两个模板、共用一份种子文件；`appendLog` 用不抛错的桩，余额写出失败若被转成告警会继续提交）：
  - 首次导入第二组明细写出被占用（EBUSY）：第一组新写的明细、余额删除，种子文件内容与文件身份还原，旧会话条目不替换；
  - 重试成功：写出两组与两份汇总，旧会话条目替换一次；
  - 覆盖导入时余额汇总合并写到一半失败（目标已截断）：余额汇总逐字节还原，已覆盖的同名明细、余额、明细汇总与种子还原为上次内容；
  - 覆盖导入时第二组余额文件写出被占用：整批还原（去掉 D3 的上抛时 9 项失败，已验证）；
  - 第二组业务校验失败（收支同时有值）：写出前拦下，输出与种子不变；
  - 再次重试成功：同名同数、内容更新，旧会话条目每次成功各替换一次；
  - 第二组种子写到一半失败（一笔新余额已写入、下一笔时磁盘已满）：异常原样传出，种子字节与文件身份还原，会话不提交；重试后余额按链计算；
  - 第二组的余额种子路径是文件夹：首次读取前拦下、整批还原（去掉 `checkOutputTarget` 时 3 项失败，已验证）；
  - 同一账户跨组的余额链（C 组 09-01、D 组 09-02 同为 M009/USD）：后组余额写出失败后种子只剩期初；重试后两天余额与种子按链计算（110、130）；
  - 真实会话（statement-session 实现）：上一批导入后覆盖导入同名文件且写出失败，会话条目、批次、当前批次与导出缓存不变；重试后旧条目各替换一次，只剩本次的条目与批次。
- 集成 Step⑳b（真实 `createErrorResult`）：导入入口对已完整还原的系统异常返回 `preservesSession`、不清空上一批的导出缓存、不替换上一批的报错文件，写日志失败也照常返回；还原不完整时界面消息给出数量与恢复清单位置；未经回滚的异常与写出阶段的业务校验失败仍按失败的导入处理。
- 单测 `tests/unit/main-process/statement-output-rollback.test.js`（11 项）：原地还原（inode 不变）、新建删除、同一路径只记首次状态、写到一半截断后分块写回（大于一个复制块）、被占用未写入的文件不写回、写完后被外部替换或修改的文件不处理并写恢复清单、同一文件经不同路径写入按文件身份合并、两次写之间被外部改动即停止、写出回调抛错时区分本批与其他程序的文件、清单写不出时以写出记录代替、符号链接与文件夹在写出前拒绝、`failBatch` 的标记与还原不完整错误（消息给出数量与清单位置，明细不含文件路径）。
- 加载 `generateMultiTemplateGroupFiles` 的既有夹具补注入 `createStatementOutputJournal`，原用例照常通过。
