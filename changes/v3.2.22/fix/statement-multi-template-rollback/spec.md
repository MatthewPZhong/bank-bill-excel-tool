# Spec：网银按文件名映射多模板导入失败时还原输出、种子与会话（B45）

> status: done
> created: 2026-11-23
> 目标版本：v3.2.22（暂定，发版时按 weekly-release 调整）
> 适用分支：`fix/statement-multi-template-rollback`
> 分支基线：正式标签 `v3.2.21`（`0e996340`）
> 依据：`knowledge/backlog.md` B45 的关闭条件；2026-11-23 用户选定本轮修复范围

## 1. 背景

`main.js` `generateMultiTemplateGroupFiles`（按文件名映射、多模板分组生成）在业务校验全部通过后：先按 `replacePaths` 删除旧会话条目，再逐组写出明细 / 余额（直接写入 `exports/<今天>/`，与旧文件同名即覆盖）并立即写余额种子，最后合并汇总文件。写出或合并中途失败（如 Windows 上文件被 Excel 占用）时导入显示失败，但旧会话条目已删（后续「导出全部」漏掉被覆盖的账单）、前组的同名输出与种子已被失败批次替换。

## 2. 决策

| 编号 | 决策 | 依据 |
| --- | --- | --- |
| D1 | 旧会话条目在全部组写出与合并都成功后才替换 | B45 关闭条件 |
| D2 | 写出期间失败时回滚（补偿），不改为「先暂存再发布」：每个路径首次写入前记下原状态（已存在的复制原内容到系统临时目录下的批次目录，不存在的记为新建）；任一组或合并失败时按逆序还原——原有文件按原内容原地写回（保留文件身份），新建的删除——再原样抛出原错误 | 同批后组需读取前组刚写入的余额种子（种子按日期链接计算）。推迟写种子会改变同批语义；暂存输出需改动生成、合并、会话缓存的全部路径引用。回滚只在写出边界加记录，现有语义不变。偏离 backlog「输出先暂存再发布」字样 |
| D3 | 记录范围：各组明细 / 余额文件、明细与余额汇总文件、余额种子文件（`statement-generation.js` `generateStatementFiles` 新增 `beforeOutputWrite` 钩子，写出前调用） | 这些是该流程全部的磁盘副作用；会话、上次导出缓存只在成功后更新 |
| D4 | 种子文件原地写回：人工补录保护按种子文件 dev + ino 识别文件（`getBalanceSeedFileIdentity`），种子写入本就原地覆盖，还原保持同一身份 | `balance-seed-store.js` 现有约定 |
| D5 | 还原失败不覆盖原错误：未能还原的路径附在原错误明细后，写错误日志并保留备份目录位置，便于人工恢复 | 资金口径的可审计性 |

## 3. 行为与边界

- 用户可见：写出中途失败时导入仍显示失败，但此前的导出文件、余额种子与会话保持导入前状态，重新导入即可；成功时行为不变。
- 业务校验失败（收支同时有值、账单日期无效、渠道余额方式冲突等）在任何写出之前拦下，行为不变。
- 生成全程为同步调用，回滚完成前不会处理其他 IPC，不会与其他写种子的操作交错。
- 「本次运行里见过的人工补录」（内存）不另行回滚：确认替换写入后会去掉对应日期，种子还原后下次生成读盘时按当前人工补录重新记下（`indexManualBalanceSeeds`）；已确认的替换键仍在会话确认集合中，重试时按已确认处理，与修复前同一批次成功时一致。
- 残余风险：进程在批次中途退出（崩溃、断电）时无法还原，与修复前相同；系统临时目录里会留下备份目录（含账单数据），由系统回收。
- 单模板导入、补录后重算、「导出全部」不在本次范围。

## 4. 验收

- 集成 `scripts/integration/statement-channel.js` Step⑳（同一银行段两个模板、共用一份种子文件）：
  - 首次导入第二组明细写出被占用（EBUSY）：第一组新写的明细、余额删除，种子文件内容与文件身份还原，旧会话条目不替换；
  - 重试成功：写出两组与两份汇总，旧会话条目替换一次；
  - 覆盖导入时余额汇总合并失败：已覆盖的同名明细、余额、明细汇总与种子还原为上次内容；
  - 第二组业务校验失败（收支同时有值）：写出前拦下，输出与种子不变；
  - 再次重试成功：同名同数、内容更新，旧会话条目每次成功各替换一次。
  - 换回 v3.2.21 的 `main.js` 与 `statement-generation.js` 时 8 项失败（已验证）。
- 单测 `tests/unit/main-process/statement-output-rollback.test.js`：原地还原（inode 不变）、新建删除、同一路径只记首次状态、还原失败保留备份、非普通文件不处理。
- 加载 `generateMultiTemplateGroupFiles` 的既有夹具补注入 `createStatementOutputJournal`，原用例照常通过。
- `npm run release-check` 通过。

## 5. 人工复核（资金口径）

- 余额种子回滚涉及余额链：建议在 Windows 上用实际银行模板按「打开某个导出文件后再覆盖导入」复现一次，确认失败后 `balance-seeds/<银行>.json` 与导入前一致、重试后余额正确。
