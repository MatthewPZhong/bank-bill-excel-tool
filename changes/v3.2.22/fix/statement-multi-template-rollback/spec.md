# Spec：网银按文件名映射多模板导入失败时还原输出、种子与会话（B45）

> status: done
> created: 2026-11-23
> 目标版本：v3.2.22（暂定，发版时按 weekly-release 调整）
> 适用分支：`fix/statement-multi-template-rollback`
> 分支基线：正式标签 `v3.2.21`（`0e996340`）
> 依据：`knowledge/backlog.md` B45 的关闭条件；2026-11-23 用户选定本轮修复范围；Codex 审查（2026-11-23 第一至五轮）；2026-11-23 用户决定外部程序并发改动的竞态、磁盘写满导致归档终态也写不进时的恢复指引按残余风险收口，种子目录本身是链接时沿用既有行为

## 1. 背景

`main.js` `generateMultiTemplateGroupFiles`（按文件名映射、多模板分组生成）在业务校验全部通过后：先按 `replacePaths` 删除旧会话条目，再逐组写出明细 / 余额（直接写入 `exports/<今天>/`，与旧文件同名即覆盖）并立即写余额种子，最后合并汇总文件。写出或合并中途失败（如 Windows 上文件被 Excel 占用）时导入显示失败，但旧会话条目已删（后续「导出全部」漏掉被覆盖的账单）、前组的同名输出与种子已被失败批次替换。

## 2. 决策

| 编号 | 决策 | 依据 |
| --- | --- | --- |
| D1 | 旧会话条目在全部组写出与合并都成功后才替换 | B45 关闭条件 |
| D2 | 写出期间失败时回滚（补偿），不改为「先暂存再发布」：写出经写出记录（`statement-output-rollback.js` `write(filePath, writeFn)`）执行，每个路径首次写入前记下原状态（已存在的复制原内容到系统临时目录下的批次目录，不存在的记为新建）；任一组或合并失败时按逆序还原——原有文件原地写回、新建的删除——再抛出错误 | 同批后组需读取前组刚写入的余额种子（种子按日期链接计算）。推迟写种子会改变同批语义；暂存输出需改动生成、合并、会话缓存的全部路径引用。回滚只在写出边界加记录，现有语义不变。偏离 backlog「输出先暂存再发布」字样 |
| D3 | 记录范围：各组明细 / 余额文件、明细与余额汇总文件、余额种子文件（`generateStatementFiles` 新增 `writeOutput` 参数，三处写出都经它执行）。传入 `writeOutput` 时，余额文件与种子的写出异常原样抛出、整批回滚，不再转成「余额生成失败」告警继续提交；同时传入的 `checkOutputTarget` 在首次读取本组余额种子前检查种子路径，是文件夹等非普通文件时同样整批回滚。种子逐笔写入（每笔重读、重写同一份 JSON），每笔都单独经写出记录执行：写前核对身份，前一笔写成后种子被其他程序替换时不再写下一笔。补录、断档、余额不一致、替换补录等待确认的业务告警与种子内容读取失败的告警不变：逐笔写种子前重读种子失败、余额模板不可读（`FILE_READ`，发生在本次写入之前；写出器读余额模板时的原生读取异常也在读取处归为「余额账单模板不可读」，单模板导入因此同样给出该告警，不再只报「系统异常已写入日志」；这一归类只在账单生成传入 `reportTemplateReadFailure` 时生效，新开账户、月度余额等共用写出器的调用方保留原生错误与原有的系统异常处理，Codex 第十轮 P2）；首次读取种子前的路径检查只有确认是文件夹、快捷方式等不安全目标时才整批回滚，检查本身失败（如目录没有遍历权限 `EACCES`，此时尚未写种子）与原流程一样按「余额生成失败」处理本组余额、保留明细（Codex 第十一轮 P2）；该系统错误的消息带种子文件路径（文件名可能是完整账号），写日志前只保留错误码（Codex 第十二轮 P2）与初次读取失败同样按「余额生成失败」告警提交，此前已写出的本组余额文件与已写入的种子笔数保留（与单模板导入相同），不整批回滚；写出记录据此撤销本次的写入登记（路径上的文件与写前一致时：首次登记的撤销登记并删除备份，之后再写时重新记下；此前写成过的回到上次写后的状态），回滚时不把它当作写到一半的文件去读取或写回（Codex 第八轮 P1） | 这些是该流程全部的磁盘副作用；否则后组余额写出失败或种子路径不安全时前组的新种子留在盘上、余额汇总缺组（Codex 第一轮 P1、第二轮 P1）。同一读取错误不因发生时机不同而清掉上一批的导出入口（Codex 第六轮 P2、第七轮 P2）。单模板导入不传，行为不变 |
| D4 | 原地写回：分块复制，以不截断方式打开目标、在同一文件描述符上核对身份（dev + ino，写完后的大小与修改时间），备份成功打开后再截断、按位置写回，核对与写回针对同一个文件，不换文件；截断后写回失败时在同一描述符上记下失败后的文件状态，经别名重试时仍认作本批文件（不误判为被其他程序修改）；写回后再核对路径仍指向写回的文件，否则不算还原、保留备份（人工补录保护按种子文件 dev + ino 识别文件，`getBalanceSeedFileIdentity`）；不把整份文件读入主进程。当前内容与备份一致时不写回（如被 Excel 占用、写出时根本没打开的文件，写回会再次撞上占用并误报还原失败）；比较时两边按同一逻辑分块读满再比较（读取可能未到末尾就返回较少字节，Codex 第七轮 P2） | `balance-seed-store.js` 现有约定；Codex 第一轮 P2、P3，第三轮 P1（核对与截断分开打开时，中间被替换的文件会被截断覆盖），第四轮 P2 ×2，第六轮 P2 |
| D5 | 按文件身份记录：同一文件经不同路径写入（不区分大小写的文件系统上大小写不同的种子路径、硬链接）按 dev + ino 合并为一条，只保留首份备份。每次写完记下文件身份（dev + ino + 大小 + 修改时间）；同一文件再次写入前核对，被其他程序改动过即停止（`STATEMENT_OUTPUT_CHANGED_EXTERNALLY`）。回滚时：写完后被其他程序替换或修改的文件不覆盖、不删除；写出回调抛错时，本批只原地改写文件，路径上换成另一个文件的属于其他程序，导入前不存在、本批也没写成过的路径上出现的文件无法确认归属（可能是写到一半的本批文件，也可能是其他程序新建的），都不覆盖、不删除，与无法还原的文件一起交给人工。补充（第三轮）：已知文件（原有文件、本批写成过的文件）写后按路径查到的文件编号须与写前相同（本批只原地改写），不同说明写出期间被替换，停止生成、回滚时留给人工；原有文件在回滚时已不在路径上（被移走或删除）的不在原路径新建，保留备份交给人工；经别名路径写过的同一文件记下每个路径（同时登记到写出记录），回滚时别名已指向另一个文件的列入恢复清单、保留备份，主路径没能写回而别名仍指向原文件时经别名写回；写完后路径上没有普通文件（新输出被移走等）即停止生成；文件系统不提供文件编号（ino 为 0）时按系统解析出的真实路径区分（`realpathSync.native`：不区分大小写的卷上还原实际大小写、短文件名还原为长文件名），大小写不同的同一种子仍合并为一条、只保留首份备份，解析失败时退回字面路径；此时原有文件另有硬链接（`nlink > 1`）的，真实路径不能把各链接归为同一文件，在首次改写前拒绝（`STATEMENT_OUTPUT_TARGET_UNSAFE`）。补充（第六轮）：主路径写回失败、随后经别名写回同一文件的，复核此前失败的路径仍指向原文件且内容与备份一致后不再列入恢复清单 | 回滚只认路径会覆盖或删除外部文件（Codex 第一轮 P2、第二轮 P1 ×2、P2，第三轮 P1、P2 ×3，第四轮 P1、P2 ×2，第五轮 P2，第六轮 P2 ×2） |
| D6 | 路径上是符号链接、文件夹等非普通文件时在写出前拒绝（`STATEMENT_OUTPUT_TARGET_UNSAFE`，只给所在目录），由调用方回滚前组 | 写出会跟随链接改写别处的文件，回滚无法还原（Codex 第一轮 P2） |
| D7 | 首次记下每个文件时即把「原路径 ↔ 备份文件」追加到批次目录的「写出记录.txt」：表头说明它不是失败清单（列出本批全部写入尝试，含已还原的），条目写「写前已有文件」或「写前不存在（不代表路径上现在的文件由本批创建）」；恢复清单写不出、以写出记录代替时，消息改为「恢复清单未能写出，请按写出记录逐个核对」，与正式清单区分（Codex 第八轮 P2）。写前不存在的路径只在本批曾写成该文件（记下过文件身份）时计为「本次新建」、给出删除指引；没有这一证据时（如写出回调抛错、回滚时检查路径又报 `EIO`），摘要与清单按「写前不存在且归属待核对」处理，原因保留系统错误码。原有文件的备份已不可用（被删除或移走）、目标仍在时单独标注「原内容备份已不可用，路径上仍是本批写出的内容」，不报「原有文件被移走」、不指引用不存在的备份重建。报错文件先写不带 `.txt` 的临时文件，写入与关闭都成功后才以正式名称发布（硬链接不覆盖已有报告，不支持硬链接的卷确认目标不存在后改名），写到一半失败、临时文件又删不掉时不留下外观正常的残缺报告（Codex 第十轮 P2 ×2、P3）；临时名只在目录内唯一、不含模板名与步骤名，正式名恰在文件名长度上限时不因临时名超长而写不出（Codex 第十一轮 P2）；同名报告追加 `-2` 等序号时按字节从基本名末尾缩短，正式名不超过 255 个 UTF-8 字节（Codex 第十二轮 P2）。首次登记时记下备份大小，主路径与硬链接别名写回前、比较内容与复核「已还原」时都核对（已打开的）备份大小，备份被截短时不截断目标、不按内容一致报已还原、不撤销其他路径的失败记录，按「备份不可用」交给人工；写回字节数与备份时不符时报错（Codex 第十一、十二轮 P1 ⚠️ 资金红线）。已还原文件的备份删除改为显式有限重试（非递归 `rmSync` 不按 `maxRetries` 重试，第十二轮 P3）。本批成功或全部还原后删除批次目录（含账单原内容），短暂占用时有限重试，仍失败时活动日志以 warning 留痕、只记目录位置（Codex 第八轮 P2）。恢复清单先写临时文件、完整写成后再改为正式名称，写到一半失败时不留下残缺的正式清单；写前不存在、写出回调抛错后路径上出现的文件在清单与摘要中标为「写前不存在且归属待核对」，不计入「本次新建」；部分回滚时已还原文件的备份删除失败会有限重试，仍失败时在恢复清单中单列「已自动还原、可直接删除」（Codex 第九轮 P2、P3 ×2）。还原不完整：备份目录只保留未还原文件的备份，写入「恢复清单.txt」（原路径 ↔ 备份文件 ↔ 原因 ↔ 处理方式；处理方式按原因给出：路径已被其他程序改动或替换的先保留现状、另存后与备份核对，已是快捷方式或文件夹的不要直接覆盖或删除，原有文件被移走的确认去向后再决定是否重建，归属不明的核对后再删，只有确认仍是原文件时才直接用备份覆盖，Codex 第七轮 P2），清单写不出（如临时卷已满）时以写出记录代替；改报业务错误 `STATEMENT_OUTPUT_ROLLBACK_INCOMPLETE`，消息（界面状态框只显示消息）给出未能还原的数量与清单位置，报错文件另列原失败原因与分类数量；系统异常的堆栈尽力写入日志（去掉异常消息，只留错误名、代码、系统调用与调用栈：Node 文件异常的消息带完整路径）；活动日志只记数量与清单位置。写日志失败不影响抛出该错误。两个导入入口把该错误交给 `createRollbackIncompleteErrorResult`，报错文件名、上下文与活动日志都用固定名称「按文件名映射模板」（完成大账号选择入口原用首个匹配模板的真实名称，可能含完整账号；该入口进入多模板分组生成后的任何错误——还原不完整、导出位置不安全、组内业务校验失败（其上下文带该组模板的真实名称，最后以固定名称覆盖）、系统异常——都用固定名称；直接导入入口同样以固定名称覆盖错误上下文中的模板名，Codex 第七、八、九轮 P2）：报错文件尽力写入，写不出（数据目录已满或只读，正是还原失败的常见原因）时仍返回原消息（数量与恢复清单位置）并标 `errorReportReady: false`，不让写报错文件的异常盖掉恢复指引，也不替换上一批的报错文件。报错文件只新建、不覆盖（`writeErrorReport`：同一秒同名时依次加 -2、-3……，写到一半或关闭时失败都删掉新文件，同一描述符只关闭一次），上一份报告的内容不受本次写失败影响 | 资金口径的可审计性；内部文件名含完整账号，不写入报错文件、活动日志与日志文件（Codex 第一轮 P2 ×3、第二轮 P2 ×3、第三轮 P1、第五轮 P2、第六轮 P2、P3） |
| D8 | 写出期间的系统异常（如文件被占用）且本批已完整还原时，两个导入入口（直接导入、完成大账号选择）按未生效的导入返回（`preservesSession`）：只弹窗提示「已还原为导入前的状态，请关闭占用的文件后重新导入」，不清空上一批的导出缓存，界面保留上一批的状态框与导出按钮。不生成报错文件、不替换上一批可导出的报错文件（异常堆栈可能含内部文件名中的账号）；异常尽力写入日志文件（同 D7 去掉异常消息），活动日志只记错误代码，写不出不影响返回。写出阶段的业务校验失败（已在写出前整批预检，极少）仍按普通失败处理，以便列出明细、导出报错文件 | 旧会话条目与磁盘都已还原，再清空上一批的导出入口与之不符（Codex 第一轮 P2、第二轮 P2 ×2） |

## 3. 行为与边界

- 用户可见：写出中途因文件被占用等系统异常失败时，弹窗提示已还原，上一批的导出文件、余额种子、会话与导出按钮保持导入前状态，关闭占用的文件后重新导入即可；成功时行为不变。
- 业务校验失败（收支同时有值、账单日期无效、渠道余额方式冲突等）在任何写出之前拦下，行为不变。
- 生成全程为同步调用，回滚完成前不会处理其他 IPC，不会与其他写种子的操作交错。
- 「本次运行里见过的人工补录」（内存）不另行回滚：确认替换写入后会去掉对应日期，种子还原后下次生成读盘时按当前人工补录重新记下（`indexManualBalanceSeeds`）；已确认的替换键仍在会话确认集合中，重试时按已确认处理，与修复前同一批次成功时一致。
- 残余风险：
  - 进程在批次中途退出（崩溃、断电）时无法还原，与修复前相同；系统临时目录里会留下备份目录（含账单数据与写出记录），由系统回收。
  - 导入前不存在的文件在写到一半时失败（如磁盘已满）会因无法确认归属而留给人工，按恢复清单删除即可。
  - 执行阶段开始时会清掉上一批的待补录提示（既有行为）。若上一批正等补录、又覆盖导入且写出失败，界面仍显示上一批的补录入口，点击时提示已失效，需重新导入上一批。
  - 外部程序在本批写出与下一次写出之间改动同一文件、且大小与修改时间都不变时无法识别（文件系统时间精度内）。
  - 本批新建的文件首次写成到记下身份之间（同一同步调用内的极短窗口）被替换无法识别；还原时在同一描述符上核对后，其他程序仍可能同时写同一文件（文件系统不提供强制锁），与修复前相同。
  - 其他程序给本批新建的文件另建的硬链接不处理（回滚只删除本批写过的路径）。
  - 外部程序（同步盘等）在本批写出或回滚的同一时刻并发改动同一文件（2026-11-23 用户决定按残余风险收口，登记 `knowledge/backlog.md` B136）：写出回调失败时无法区分本批写坏了文件还是外部程序原地改了它（按本批的处理，用备份写回）；写出器按路径打开并截断，核对身份前可能截断外部刚换进来的文件（写后核对会停止生成并交给人工，但对方被截断的内容没有备份）；删除本批新建的文件时，核对与删除之间路径可能被替换。修复需把明细、余额、汇总、种子四类写出器改为经核对过身份的文件描述符写入、删除改为先移到隔离路径核对后再删。
  - 磁盘写满等原因使回滚不完整、且存档中心随后写任务终态与恢复意图也失败时（2026-11-23 用户决定按残余风险收口，登记 `knowledge/backlog.md` B137）：共享的归档生命周期抛出归档错误，界面只看到该错误，看不到未还原数量与恢复清单位置；恢复清单与写出记录仍在系统临时目录的 `statement-rollback-*` 目录里。修复需让共享 IPC 入口在业务已返回错误结果、终态写入随后失败时保留业务结果（影响所有任务）。
