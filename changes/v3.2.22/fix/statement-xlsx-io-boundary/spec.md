## 1. 背景

| 编号 | 问题 | 资金口径 |
| --- | --- | --- |
| B133（P1） | 手工改写过结构的 XLSX，长数字还原时取到的原文可能来自读取库实际没读的工作表或行，流水号与金额血缘错位 | 是（交易标识血缘） |
| B113（P3） | 明细写出时，文本中形如 `_xHHHH_` 的字面值被当作 OOXML 转义改写（`FEE_x0041_` 读回为 `FEEA`）；U+FFFE / U+FFFF / 未配对代理项写出后工作表无法解析或变成「�」 | 是（标识可能变成同一个值） |
| B132（P4） | 大账号配置重复校验、大账号选择弹窗按 `MerchantId@@币种` 原样拼键，含 `@@` 的不同账户会同键 | 否（极端输入） |

## 2. 决策

| D1 | workbook.xml、工作簿关系文件或目标工作表 XML 含内容带尖括号（`<`、`>`）或未闭合的注释 / CDATA，或标签内出现空格、回车、换行以外的空白（制表符等）时，整张表不还原长数字，按既有「长数字无法核对原值」提示，照常生成。内容不含尖括号的注释、CDATA 里没有标签，两边读到的结构相同：注释按 XML 语义去掉后照常还原（与 v3.2.21 相同，还原前仍核对原文与读取库的值相等），检查标签内空白时也不把注释、CDATA 正文当作标签。判断标签范围时跳过引号内的属性值（属性值里的 `>` 不是标签结尾） | B133 关闭条件；沿用 v3.2.21 D2「无法还原照常生成并提示」；属性值含 `>` 时原判断提前结束标签、漏掉其后的制表符（Codex 第一轮 P2）；一律不还原会让只含普通注释的文件只剩近似值，近似值继而参与账户映射、预处理过滤与大账号识别（Codex 第三轮 P1 ×2、P2） |

## 3. 规则

### 3.1 长数字还原的可核对前提（B133）

- 读取库（SheetJS）不跳过 XML 注释：注释里的 `<sheet>`、关系、`<row>`、`<c>` 都会被解析，后出现的覆盖先出现的。本模块按有效内容定位，两边可能读到不同的表或行。
- 读取库只把空格、回车、换行当作标签名的结束，认不出 `<Relationship\t…>` 这类标签，会放弃关系文件、改按物理序号读表；本模块的正则认得出，按关系定位。
- 注释、CDATA 内容不含尖括号时没有可被读取库当作标签的内容，两边结构相同，照常还原（D1）。
- 上述写法（注释掉的标签、标签内制表符等）Excel、WPS 与银行系统都不会生成。出现时不尝试与读取库对齐，整张表不还原（D1）。此时长数字只剩近似值，与二进制 .xls 等既有无法核对的来源一样，按 v3.2.21 口径提示后照常生成：近似值仍可能参与账户映射、预处理过滤（见 §5）。
- 同一判断也作用于开启「重复账单过滤」时的工作表原文核对：该表不参与按原文查重（宁可漏判，与原有「无法核对工作表原文」一致）。

### 3.2 写出边界（B113）

- 转义只作用于字符串单元格（含表头、余额模板原有文本），数值、日期、布尔单元格不变。
- 读回（Excel、WPS、读取库）得到原文，控制字符的既有 `_xHHHH_` 编码不受影响；`_x0041` 后接回车的情形随之解决。
- 拒绝（D3）发生在任何文件写出之前，不留下部分文件。
- 余额记录的取值来自明细行（已预检）与模板名拆出的银行名称、所在地；模板名由界面输入，不在写出前预检，若仍含这类字符，余额写出边界兜底拒绝，按既有「余额生成失败」告警处理，明细已写出。
- 读取库只能正确还原 U+0080 以下的 `_xHHHH_` 转义（`_x00E9_` 读成「�」），随程序发布的余额账单模板不含更高的转义（单测确认）。

### 3.3 已知边界

- 转义后单元格 XML 变长：原文接近 32767 个字符且含 `_xHHHH` 时，读取库写出会因超长拒绝（极端情况，不另处理）。
- 本分支只改网银账单生成的写出路径。工具箱 / VCC 的 `src/backend/xlsx/excel-text.js` `encodeExcelStXstring` 已转义完整的 `_xHHHH_`，但 `_xHHHH` 后紧跟控制字符时仍会被改写（实测）；单据对账 `recon-id-fix-io.js` 等其他写出路径未逐个核实，一并登记 B134。
- 写出边界的兜底报错只列行号与列名，不带输出文件名（内部文件名可能含账号）。

## 5. 人工复核（资金口径）

- B133：确认实际使用的银行 XLSX 均由 Excel、WPS 或银行系统直接导出；复核此前用手工改写过 XML 的文件导出的流水号（关闭条件要求，需人工处理）。
- D6（⚠️ 资金红线）：此前用二进制 .xls 或原文无法核对的 XLSX、且账户信息行的账号为超过 15 位的数字时，自动识别可能按近似值命中了另一个维护账号；建议按原始账单复核这类文件的大账号归属。修复后这类文件不再自动识别：只维护一个大账号时报未识别并说明原因，多个时在选择窗口中由用户指定。
- D1 残余（⚠️ 资金红线）：含注释掉的标签、标签内制表符等手工改写的 XLSX，以及二进制 .xls 等既有无法核对的来源，交易行里超过 15 位的数字仍按读取库的近似值参与账户映射（回填清算账号、币种）与预处理过滤，只在导出行给出「长数字无法核对原值」提示（v3.2.21 既有口径，2026-11-23 用户决定本轮不改）；登记 `knowledge/backlog.md` B135。
- B113：此前明细中含 `_xHHHH_` 字面值的流水号、参考号已被改写，若有依赖这些标识的对账结果，需按原始账单人工核对。
- D4b 残余（⚠️ 资金口径）：链接表的非流式读取（多工作表等，SheetJS）对跨富文本片段拼成的转义先拼接再还原、对公式字符串里的非 ASCII 转义还原后按 UTF-8 再解码（读成「�」），不同原值可能读成同一个键；这是 v3.2.21 起的既有行为，本分支只让流式读取在这些情形下拒绝，登记 `knowledge/backlog.md` B134。
- D4b（⚠️ 资金口径）：链接表流式导入改为还原 `_xHHHH_` 后，此前经流式路径入库、标识含转义文本（`_x005F_`、`_x000D_` 等）的记录，再次导入时键会变为还原后的文本，可能与旧记录不再按同一键更新；建议导入前在链接表中检索含 `_x` 的 BizId 等标识并人工核对。
