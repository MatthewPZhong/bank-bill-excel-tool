## 1. 背景

| 编号 | 问题 | 资金口径 |
| --- | --- | --- |
| B133（P1） | 手工改写过结构的 XLSX，长数字还原时取到的原文可能来自读取库实际没读的工作表或行，流水号与金额血缘错位 | 是（交易标识血缘） |
| B113（P3） | 明细写出时，文本中形如 `_xHHHH_` 的字面值被当作 OOXML 转义改写（`FEE_x0041_` 读回为 `FEEA`）；U+FFFE / U+FFFF / 未配对代理项写出后工作表无法解析或变成「�」 | 是（标识可能变成同一个值） |

## 2. 决策

| 编号 | 决策 | 依据 |
| --- | --- | --- |
| D1 | workbook.xml、工作簿关系文件或目标工作表 XML 含注释（`<!--`），或标签内出现空格、回车、换行以外的空白（制表符等）时，整张表不还原长数字，按既有「长数字无法核对原值」提示，照常生成 | B133 关闭条件；沿用 v3.2.21 D2「无法还原照常生成并提示」 |
| D2 | 在 XLSX 写出边界把文本中「`_` 后接 `x` + 4 位十六进制」的下划线写成 `_x005F_`，内存中的行数据不变；覆盖单组明细 / 余额写出（`writers.js`）与多组明细合并写出（`main.js` `mergeGeneratedXlsxFiles`） | B113 关闭条件；`_x005F_` 是 OOXML 对下划线本身的转义 |
| D3 | 写进明细的文本含 U+FFFE、U+FFFF 或未配对代理项时整份拒绝：网银映射阶段按「源文件第 N 行写进『字段』列」列出；写出边界再按输出的行号与列名兜底（余额、新开账户等其他调用方） | B113 关闭条件「明确拒绝或报错列出源行与列」 |
| D4 | 移除 v3.2.21 为费用账单「字段映射特殊处理」加的临时拒绝（`hasWorksheetEscapeLikeText` 及渲染端同口径校验）：这类值现在可原样写出、读回 | B113 补充说明「修复写出边界后应移除该拒绝」 |
| D5 | 大账号重复校验与选择弹窗的勾选 / 预填 / 顺序键改用结构化键（`JSON.stringify([大账号, 币种])`）；这些键不落库，无需兼容旧值 | B132 关闭条件 |

## 3. 规则

### 3.1 长数字还原的可核对前提（B133）

- 读取库（SheetJS）不跳过 XML 注释：注释里的 `<sheet>`、关系、`<row>`、`<c>` 都会被解析，后出现的覆盖先出现的。本模块按有效内容定位，两边可能读到不同的表或行。
- 读取库只把空格、回车、换行当作标签名的结束，认不出 `<Relationship\t…>` 这类标签，会放弃关系文件、改按物理序号读表；本模块的正则认得出，按关系定位。
- 上述写法 Excel、WPS 与银行系统都不会生成。出现时不尝试与读取库对齐，整张表不还原（D1）。
- 同一判断也作用于开启「重复账单过滤」时的工作表原文核对：该表不参与按原文查重（宁可漏判，与原有「无法核对工作表原文」一致）。

### 3.2 写出边界（B113）

- 转义只作用于字符串单元格（含表头、余额模板原有文本），数值、日期、布尔单元格不变。
- 读回（Excel、WPS、读取库）得到原文，控制字符的既有 `_xHHHH_` 编码不受影响；`_x0041` 后接回车的情形随之解决。
- 拒绝（D3）发生在任何文件写出之前，不留下部分文件。

### 3.3 已知边界

- 转义后单元格 XML 变长：原文接近 32767 个字符且含 `_xHHHH` 时，读取库写出会因超长拒绝（极端情况，不另处理）。
- 本分支只改网银账单生成的写出路径。工具箱 / VCC 的 `src/backend/xlsx/excel-text.js` `encodeExcelStXstring` 已转义完整的 `_xHHHH_`，但 `_xHHHH` 后紧跟控制字符时仍会被改写（实测）；单据对账 `recon-id-fix-io.js` 等其他写出路径未逐个核实，一并登记 B134。
- 写出边界的兜底报错只列行号与列名，不带输出文件名（内部文件名可能含账号）。

## 4. 验收

- 单测：
  - `statement-long-number-source-text.test.js`：注释在单元格内、关系文件含注释、关系标签用制表符分隔并互换目标、工作表同一坐标有注释掉的旧行，均不还原并提示；修复前这四个用例均失败（已验证）。
  - `writers-worksheet-text.test.js`：明细与余额写出读回含 `_xHHHH_` 的文本原样保留、行数据不被改写；非法字符拒绝并列出行列、不留文件。
  - `statement-balance-gap.test.js`：多组明细合并后 `_xHHHH_` 原样保留。
  - `bill-split-fee-field-mapping.test.js`：费用行固定文本与源列取值中的 `_xHHHH_` 不再拒绝。
  - `statement-currency-big-account.test.js`：`A@@B / USD` 与 `A / B@@USD` 不判重复，同账户同币种仍判重复；旧键下失败（已验证）。
- 集成 `statement-bill-split-fee-bill.js`：真实 CSV 生成→写出→读回，主映射与费用行的 `_xHHHH_`（含与 CRLF 相连）原样保留；主映射取值含 U+FFFF 时拒绝并列出源行与列、不写出明细。去掉转义时 3 项失败（已验证）。
- 渲染生命周期：`legacy-dialogs`（含 `@@` 账户勾选序号与取消互不串号）、`configuration-dialogs`（固定文本含 `_xHHHH_` 不再报错）。
- `npm run release-check` 通过。

## 5. 人工复核（资金口径）

- B133：确认实际使用的银行 XLSX 均由 Excel、WPS 或银行系统直接导出；复核此前用手工改写过 XML 的文件导出的流水号（关闭条件要求，需人工处理）。
- B113：此前明细中含 `_xHHHH_` 字面值的流水号、参考号已被改写，若有依赖这些标识的对账结果，需按原始账单人工核对。
