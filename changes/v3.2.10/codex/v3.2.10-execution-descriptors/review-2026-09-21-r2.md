### R2 · P3：无 dispatch hook 的非生产关闭观察回退 — 已关闭

修复落点：[contract.js:300](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/tmp/worktrees/v3210-execution-descriptors/src/main-process/execution-descriptors/contract.js:300)、[runtime.js:78](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/tmp/worktrees/v3210-execution-descriptors/src/main-process/background-execution/runtime.js:78)、[supervisor.js:321](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/tmp/worktrees/v3210-execution-descriptors/src/main-process/background-execution/supervisor.js:321)。对应 G7-AC-02、G7-AC-05。

compiler 新增按 action 查询真实 hook 或 null 的接口，Supervisor 在每次任务开始时读取并固定该 action 的 hook，随后沿用原生产检查与派发时序。上轮“始终存在的聚合函数”不再被误当成该 action 已具备派发授权。

已确认四类兼容与授权边界：

| 情形 | 当前行为 |
| --- | --- |
| nonproduction，无 BizOP authority、无通用 hook | 到达测试 adapter，恢复上轮 P3 的旧行为 |
| 已批准启用的 production action，自身无 hook | 在建 job、准入和 worker 创建前拒绝；不会被 production-disabled 提前检查掩盖 |
| 已注入 BizOP authority，但其他 closure action 无自身/通用 hook | composition 显式保留原拒绝函数；非生产也拒绝，没有扩大成 no-op |
| 有本域 hook、通用 hook 或 hook 抛错 | 本域优先；先 await hook 再进入 adapter；真实授权错误继续传播 |

另外对新 getter 增补独立机制探针：另一个 action 有 hook 不能代当前 action 授权；getter 每任务只调用一次，任务开始后改变返回函数不影响在途任务；等待 hook 期间取消时先保持 carrier `UNKNOWN`，原 hook 结束后才进入 `NOT_CREATED`。该探针最终 0 worker、0 active lease，shutdown 无 errors 或 leaked transports。

修复过程中曾出现混合 BizOP 场景被误放行的中间版本；本次复审的是补修后的最终快照。原 `biz-op-v327.test.js` 拒绝断言没有被放宽，本轮完整运行该文件并通过，没有使用中间版错误期望作为关闭依据。

证据：[独立 getter/取消探针](review-2026-09-21-r2-evidence/getter-lifecycle.cjs)、[三个探针结果](review-2026-09-21-r2-evidence/getter-lifecycle-output.json)。这些探针使用真实 composition/runtime/Supervisor 和受控 adapter，不等同于真实 worker 故障终止验收。
