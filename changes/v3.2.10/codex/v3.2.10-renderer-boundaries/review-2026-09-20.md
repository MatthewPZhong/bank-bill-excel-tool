## 2. 发现

### R01 · P1 · VCC 业务 OP 离页后展示旧账期，保存采用新扫描的数据

**位置：**[vcc-op-calc.js:144](../../../../src/renderer/controllers/vcc-op-calc.js:144)，关联 [F2 构建与保存](../../../../src/renderer/controllers/vcc-op-calc.js:221)、[重新进入](../../../../src/renderer/controllers/vcc-op-calc.js:316)。违反 Spec §4、G3-AC-09 / 13。

`scan` 会替换 Main 的 compute snapshot。扫描结果因离页 generation 过期而被第 147 行直接丢弃时，Renderer 仍保留上一批的 `scanned/yearMonth/totals`。重新进入只查已保存月份，未重新核对本次可保存会话，却继续启用「开始运行」。F2 展示旧值，提交仅传 `beginOp`；[Main 的 save handler](../../../../src/main.js:15438) 与 [session.saveRun](../../../../src/main-process/vcc-op-calc-session.js:399) 使用新的 compute snapshot。

复现采用真实 controller、modal host/bridge、真实 XLSX streaming reader、真实 VCC session 和内存 SQLite；弹窗内容由受控工厂记录：

1. A.xlsx 的账期为 `2026-07`，发生额 `10.00`，完成 F1 确认和统计。
2. 重新扫描 B.xlsx：账期 `2026-08`，发生额 `900.00`；延迟扫描回包，在等待时离页。
3. B 在 Main 已完成，交付回包后返回该模块。Run 按钮仍可用，F2 展示 `2026-07 / 10.00`。
4. 按这个展示输入期初 OP `100.00`，实际落库为 `2026-08 / begin_op=100.00 / total_amount=900.00 / end_op=1000.00`。

这证明用户确认的账期/发生额与实际保存来源可以错位。尚无证据说明真实业务数据已经受到影响。基线不会因导航丢弃 B 的 F1；本次新增的 stale-return 路径跳过该确认而直接恢复 A 的 F2。基线另有取消确认的弱点，不据此否定本次新增路径。

**修复方向：**重新扫描导致 Main 会话变化时先失效旧可保存状态；区分“不能更新旧页面”与“必须记录业务结算”，重入只能恢复与 Main 对应、已确认的来源。不得把 Renderer 的旧金额直接传回覆盖 Main 的事实来源。

**证据：**[复现脚本](review-2026-09-20-evidence/review-vcc-stale-cache-real.cjs)、[实际 SQLite 输出](review-2026-09-20-evidence/review-vcc-stale-cache-real-output.json)。两个合成 XLSX 所在临时目录已清理，SQLite 为 `:memory:` 且已关闭。

**⚠️ 资金红线，请人工复核。** 修复验收需核对“界面确认账期 / 输入期初 / Main snapshot / 落库月份与金额”四者一致。当前自动探针不能替代该财务流程的人工核对。

### R02 · P1 · 默认设置中的存档入口直接触发 ReferenceError

**位置：**[app-settings.js:550](../../../../src/renderer/dialogs/app-settings.js:550)。违反 G3-AC-13 / 17。

`getArchiveCenterApi()` 的 `const api = archiveCenterApi || api.archiveCenter` 遮蔽外层注入的 `api`。生产[设置按钮](../../../../src/renderer.js:1753)调用无参数工厂，`archiveCenterApi` 为空，右侧访问尚未初始化的局部变量，抛出 `Cannot access 'api' before initialization`。虽然 root 正确注入了 archiveCenter，默认读取路径无法使用它。

真实 Electron 工厂复现：打开设置，点击「存档」，列表 API 调用数为 **0**，页面显示 `批次列表加载失败：Cannot access 'api' before initialization`；相同依赖通过显式 `archiveCenterApi` override 传入时，调用数为 **1** 且正常。由该 helper 访问的统计、保留期和批次操作也受影响。

基线为 `archiveCenterApi || window.desktopApi?.archiveCenter`，属于本次提取时引入的回归。现有 app-settings fixture 显式传入 override，未覆盖正式入口的默认参数。

**修复方向：**避免局部名称遮蔽，使用外层窄 API；增加“正常依赖注入、无 preview override”的工厂入口测试。

**证据：**[Electron 探针](review-2026-09-20-evidence/review-modal-probe.cjs)、[ARCHIVE_DEFAULT_PROBE 输出](review-2026-09-20-evidence/review-modal-probe-output.log)。未对真实存档目录进行操作。

### R03 · P2 · ReconID 操作结束后场景下拉仍被 busy 状态锁住

**位置：**[recon-id-fix.js:49](../../../../src/renderer/controllers/recon-id-fix.js:49)。违反 Spec §4、G3-AC-13。

`render()` 以 `disabled ||= busy` 更新场景下拉。操作开始把它设成 true，结束将 `busy=false` 后再次 render，结果仍是 true。与其他按钮不同，这个下拉没有先重算正常状态。导入、运行、导出正常收尾只刷新 session，直到重新进入页面或触发场景列表 reload 才恢复。

探针中初始 `disabled=false`，执行实际 controller 的一次成功导出后为 `true`。同一 finally 路径也覆盖错误、取消，用户会无法换场景继续操作。

**修复方向：**每次从 busy、类别和可选场景等当前事实完整计算 disabled。补充成功、失败、取消后控件恢复的行为断言。

**证据：**[R3 探针](review-2026-09-20-evidence/renderer-boundaries-r3-review-probes.test.js)、[失败断言日志](review-2026-09-20-evidence/r3-review-probes.log)。

### R04 · P2 · BizOP 后台导入离页后丢失最终反馈

**位置：**[renderer-biz-op-v327.js:102](../../../../src/renderer-biz-op-v327.js:102)，关联 [状态重读](../../../../src/renderer-biz-op-v327.js:488)。违反 Spec §4、G3-AC-09 / 13。

顶层导入没有弹窗，运行期间允许离页。`perform()` 在结果返回或抛错时，因为 `taskCurrent()` 不成立直接丢弃结算，只记 `needsRefresh`。重新进入的 `status()` 只恢复模块可用状态；`hasTaskFeedback` 已被设成 true，原有的“正在等待后台处理”因而一直保留。

真实 controller 的行为探针让后台返回 `{status:'error', message:'测试导入失败，文件没有保存'}`。返回模块后状态文本仍为「导入文件，正在等待后台处理…」，但 `busy=false`、导入按钮已启用，导入调用次数仍为 1。用户看不到实际失败或错误报告反馈，可能误判任务仍在执行。基线没有这一 generation 丢弃分支。

**修复方向：**领域状态保存后台最终成功/失败/取消与错误报告信息，只有 DOM 写入受页面代次限制；返回时呈现已结算反馈。

**证据：**[复现脚本](review-2026-09-20-evidence/review-bizop-background-feedback.cjs)、[前后状态](review-2026-09-20-evidence/review-bizop-background-feedback-output.json)。此项使用模拟 DOM 和可控 API，未启动真实导入。

### R05 · P2 · 隐藏页面结果已失效，返回后仍显示旧“已导出”

**位置：**[bank-statement.js:680](../../../../src/renderer/controllers/bank-statement.js:680)，同类 [recon-id-fix.js:51](../../../../src/renderer/controllers/recon-id-fix.js:51)。违反 Spec §5、G3-AC-15。

确定失效通知在隐藏状态下先清内存 result/export，随后 render 因 inactive 返回。重新进入时 render 和状态重读都使用 `updateStatus:false`；`lostResult` 又依据已经清掉的内存结果计算为 false，导致旧导出反馈一直留在 DOM。

两个方向分别复现：先使两域结果完成并已导出，离开 bank 后在 ReconID 场景管理批删再返回 bank；反向隐藏 ReconID 也一样。Main 两侧结果均为 false，导出按钮已禁用，但页面分别仍显示 `已导出：bank-output.xlsx` 或 `已导出 — 主文件 recon-output.xlsx`。这是反馈与 Main 事实不一致；探针没有发现此时仍能通过按钮导出过期结果。

**修复方向：**保留待重绘/反馈已失效标记，下一次 enter 按 Main 事实清旧反馈。不要仅从已清空的结果反推是否发生过失效。

**证据：**[R3 探针](review-2026-09-20-evidence/renderer-boundaries-r3-review-probes.test.js)、[两方向失败日志](review-2026-09-20-evidence/r3-review-probes.log)。使用真实 Main handler/SQLite harness、真实 command service/router/controllers，`writerBoundaryTrusted:false` 与生产相同。

### R06 · P2 · 部分已承诺迁移的写入弹窗仍绕过 busy 关闭协议

**位置：**[功能收纳保存回调](../../../../src/renderer-dialogs.js:1454)、[拆分账单行数确认](../../../../src/renderer/dialogs/configuration.js:4437)。违反 Spec §3.2、TechDoc §3.4、G3-AC-03 / 14。

两处真实生产工厂没有把写入状态完整接入宿主：

- 功能收纳只有按钮级 `committing`，未注册 `canClose`。保存等待时公共根替换仍返回 `opened`；旧保存成功后执行无目标 `closeModal()`，把后来打开的告警也关闭。
- 拆分账单份数从两份减为一份，确认回调无同步提交锁。延迟保存时连续点击确认产生 **2 次** `saveBillSplitRowCount`；按钮未 disabled，父 handle 的 `close()` 返回 `closed`，写入中父子栈被清掉。

**分类说明：**按钮级锁、裸 closeModal 和缺少双击保护在基线已有。这是本分支 R1 所要求的全生产入口治理尚未闭合，不能称为新引入的业务双击缺陷。节点已经统一交给宿主，并不等于每个业务写入的关闭资格已经正确迁移。

**修复方向：**将 busy 映射为对应 handle 的 `canClose`，同步锁定提交，异步结算只操作原 handle；保留正常保存完成后关闭本层的行为。补确认写入中根替换、导航、父层关闭和双击的组合测试。

**证据：**[真实 Electron 工厂探针](review-2026-09-20-evidence/review-modal-probe.cjs)、[BILL_SPLIT_PROBE / CABINET_PROBE](review-2026-09-20-evidence/review-modal-probe-output.log)。可控 API 只记录调用，未修改实际模板配置。
