## 2. R3-01 闭合证据

原问题是：将「按字段区分发生额」从“是”改为空，清空规则成功、随后元数据保存失败，窗口仍使用已删除的规则缓存。

当前 [saveAmountConfiguration](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/tmp/worktrees/v3210-renderer-boundaries/src/renderer/dialogs/configuration.js:4576) 将阶段结果和恢复读取放在同一 `runWrite` 内：首阶段只有明确成功才继续一次元数据写；任一阶段失败且原窗口有效时，重读规则和元数据。结算时先恢复旧控件状态，再按实际配置同步缓存、入口和互斥资格。原错误继续显示，不自动重复业务写。

使用同一份独立真实工厂探针，对原 byField 序列做了前后对照：

| 观察项 | R3 修前 | R4 当前 |
| --- | --- | --- |
| API 序列 | `rules → meta` | `rules → meta → read` |
| 规则存储 | 已清空 | 已清空 |
| 规则管理入口 | 仍显示 | 隐藏 |
| 正负号选择 | 仍禁用 | 恢复可用 |
| 再次进入规则编辑 | 仍带“入金／出金”旧规则 | 重新启用时为空规则 |
| 错误反馈 | 显示元数据失败 | 保留同一失败反馈 |

证据：[独立探针](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/tmp/worktrees/v3210-renderer-boundaries/changes/v3.2.10/codex/v3.2.10-renderer-boundaries/review-2026-09-21-r4-evidence/review-modal-r4-probe.cjs)、[R3 对照输出](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/tmp/worktrees/v3210-renderer-boundaries/changes/v3.2.10/codex/v3.2.10-renderer-boundaries/review-2026-09-21-r4-evidence/review-modal-r4-before-output.log)、[R4 输出](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/tmp/worktrees/v3210-renderer-boundaries/changes/v3.2.10/codex/v3.2.10-renderer-boundaries/review-2026-09-21-r4-evidence/review-modal-r4-probe-output.log)。本轮使用修复后应满足的正确行为断言；没有把旧探针“缺陷存在即通过”的退出码当成闭合依据。

独立矩阵为两个入口各 11 种情况，共 22 项，覆盖：

- 首阶段 failed / reject / cancelled：不续发元数据，只读取事实；未提交时原规则仍可编辑。
- 第二阶段 failed / reject / cancelled：确认规则已清空，接纳实际旧元数据，不复活旧规则。
- 第一或第二阶段已提交后 failed / reject：以重读值反映已落地事实，原错误仍保留。
- 两阶段正常成功：仅执行两条业务写，没有多余恢复读取；所有情形均断言调用次数和顺序，确认无自动重试。

矩阵实际打开规则编辑器核对值，闭合不只依靠按钮样式。signed 在已有按字段规则时本来禁用；相关矩阵以合成 `change` 覆盖其内部相邻分支，不能将其描述为该初始状态下可自然点击的用户流程。

[Main 配置读取](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/tmp/worktrees/v3210-renderer-boundaries/src/main.js:8903) 返回实际规则与元数据；两条保存仍独立提交，数据库写后模板库同步可能返回错误。当前恢复方式没有把 failed/reject 当作回滚，也没有新增事务、补偿或自动重试。后端与 Main 本轮未改；第三轮内存 SQLite 独立提交探针是历史证据，本轮仅重新核对代码合同，没有把它计作本轮新执行。
