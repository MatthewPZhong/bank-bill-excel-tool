## 1. 背景

拆分/合并账单把一行原始账单拆成多份输出行。部分银行把手续费等费用与交易放在同一行，需要拆出一份只有支出的「费用账单」，其发生额要由若干列计算得出（如 手续费 + 邮电费）。现有配置只能把某一列直接映射为 Debit Amount，不能计算。

## 3. 功能规则

### 3.1 文案范围（D1）

- 只改拆分/合并账单弹窗内的三处文字，以及拆分语境下的两条互斥报错、模板【更新】失效引用说明中的「按正负号拆分的发生额」。
- 主映射弹窗中「按正负号拆分的发生额」「按字段区分发生额」是映射行的存储键，不改。
- 副区域「按字段取发生额」右侧的【发生额映射关系管理】按钮需求未提及，保持原文字。

### 3.2 费用账单列（D2）

| 操作 | 规则 |
| --- | --- |
| 勾选某行 | 立即写入模板；其他行自动取消勾选；该行 Credit Amount 下拉框置灰并清空（已存的映射保留，生成时不读取） |
| 取消勾选 | 立即写入模板；模板不再有费用账单行；该行恢复已存的 Credit Amount 映射 |
| 合并组内的行 | 与该行其他控件一致，勾选框禁用 |

- 费用标记存在拆分行上，删除行、减少份数时随行移动或一起删除。
- 费用账单行置灰的 Credit（及启用特殊取值后置灰的 Debit）只在界面上显示为空，已存的映射保留、【完成】照原样保存；取消费用账单或关闭特殊取值后原映射恢复。生成时不读取被置灰的映射，也不要求这些列仍在源文件或模板表头中。
- 「Credit 与 Debit 不能同列」只比实际生效的映射：费用行的 Debit 可以选停用的 Credit 所在列。取消费用账单时，若保留的 Credit 与 Debit 同列，清空 Credit，避免同一列既记收入又记支出。
- 费用账单配置的保存（费用行、特殊取值、公式）失败时，按重读到的已保存配置显示并保留失败提示（可能已落库、只是模板库文件同步失败）；重读也失败时提示关闭重开，本窗口暂停配置写入。
- 已完成（只读）的行也可直接勾选，不需要先点【编辑】。

### 3.3 费用账单发生额特殊取值逻辑（D3）

- 位于「发生额取值设置」第三行：文本 + 勾选框 + 【设置】（勾选后显示）。
- 勾选状态立即写入模板。没有费用账单行时勾选框置灰，并提示先在表格中勾选费用账单；已保存的勾选和公式保留，但不生效。
- 勾选后费用账单行的 Debit Amount 下拉框置灰并清空。
- 与「按正负号取发生额」「按字段取发生额」不互斥：这两项照常作用于其他行。

### 3.4 公式设置弹窗（D4）

- 标题「费用账单发生额设置」；打开时回显已保存的公式。
- 左下拉框选项为模板表头（同表格其他下拉框）；右下拉框为 加 / 减 / 乘 / 除 / 运算结束。
- 一行最多 6 个下拉框（3 组），第 7 个起换行，换行后与第一个下拉框左对齐。
- 【保存】校验：至少一组；每组的字段和运算符都已选择；只有最后一组且最后一组必须是「运算结束」。两个下拉框都为空白的组保存时忽略。校验通过后写入模板并关闭。
- 【取消】/×：关闭，不保存。

### 3.5 计算口径（D5–D8）

- 只作用于已完成（completed）的费用账单行，且需启用特殊取值逻辑。
- 运算字段按单元格原值带正负号参与计算（去除千分位、货币符号等，同「按正负号取发生额」的取值口径）；空白或无法识别的值按 0。
- 先乘除后加减，同级从左到右。
- 非 0 除以 0：该文件报错，不生成，并列出源文件行号（账单自带的合计行不计入）；0 ÷ 0（如该行运算字段都为空）按 0。
- 按十进制精确计算（不经浮点，数值单元格按其十进制取值，含 1e-7 这类指数形式），结果取绝对值，四舍五入保留 2 位（1.005 → 1.01、10000.005 → 10000.01）。
- 结果为 0 时沿用现有规则：Credit、Debit 都为 0 的拆分行不输出。
- 启用特殊取值、存在已完成的费用账单行但公式缺失或无效：拒绝生成并提示设置公式。
- 公式引用的字段不在源文件表头中：拒绝生成（同其他拆分字段）；模板【更新】删掉公式字段时，失效引用列表包含「费用账单发生额公式」。

### 3.6 费用账单行的取值优先级（D10）

| 情况 | Credit Amount | Debit Amount |
| --- | --- | --- |
| 启用特殊取值且公式有效 | 空 | 公式结果（优先于「按正负号/按字段取发生额」和行级 Debit 映射） |
| 未启用特殊取值 | 空（不论行级映射还是副区域规则算出收入） | 原逻辑（副区域规则或行级 Debit 映射） |

- 之后的户名 / 卡号按收支方向分配、合并组净额计算不变。

### 3.7 模板包与模板库

- 拆分行带「费用账单」标记，拆分配置带「特殊取值逻辑」勾选状态与公式，随模板包导出、导入与模板库文件同步。
- 任一模板标了费用账单或勾选了特殊取值逻辑时，模板包写 v8，v3.2.18 及更早版本读到整包拒绝（否则会静默输出不同的金额）；都未用到时版本号沿用原规则。

## 4. 验收

- 文案按 D1 显示；主映射弹窗不变。
- 费用账单勾选唯一，勾选行 Credit 置灰；启用特殊取值后该行 Debit 置灰；关闭重开后状态保留。
- 公式弹窗按 D4 布局；第 7 个下拉框换行；校验提示按 §3.4；【取消】不写入。
- 生成结果：费用账单行 Debit = 公式结果（先乘除后加减、取绝对值、2 位小数），Credit 为空；其他行不受影响；除数为 0、公式缺失、字段缺失时拒绝生成。
- 模板包往返后配置一致，用到时写 v8。
- 旧库启动自动补列，重复启动无副作用。

## 5. 非目标

- 不改主映射弹窗的发生额配置项与其存储键。
- 不支持括号、常量或多个费用账单行。
- 不修复模板包导出时丢失「指定账单实现功能」序号的既有问题（登记到 `knowledge/backlog.md`）。

## 6. 迭代二：「账单拆分合并设置」与根据字段值过滤账单（2026-11-17）

### 6.1 背景

同一份网银原始账单里只有一部分需要拆分。按字段值设置过滤规则：命中规则的源行走拆分/合并映射，其余行走模板主映射，两部分按源行顺序合在一起输出明细和余额账单。

### 6.2 已确认决策

| 编号 | 决策 | 来源 |
| --- | --- | --- |
| R1 | 映射关系管理分组标题「账单拆分合并管理」改为「账单拆分合并设置」（只改映射弹窗；历史文档不改，USER_GUIDE 发版时同步） | 用户，2026-11-17 |
| R2 | 分组第三行「根据字段值过滤账单」，勾选框在文字右侧，勾选后显示【过滤规则设置】；开关存为映射行（勾选 `是`，未勾 `''`） | 用户，2026-11-17 |
| R3 | 开启拆分且勾选过滤时，解除拆分对主映射 Currency / Credit / Debit / 按正负号 / 按字段区分 的互斥，供未命中的行使用；主映射内三选一照常 | 用户，2026-11-17 |
| R4 | 过滤规则弹窗组件构成参考 场景管理 → 银行对账单赋值自身 → 账单类型；文本「过滤规则」；右下【保存】在左、【取消】在右 | 用户，2026-11-17 |
| R5 | 命中口径：同一规则内的条件全部满足、任一规则满足即命中 | 用户，2026-11-17 |
| R6 | 规则随映射关系管理【保存】一起落库：规则弹窗【保存】只校验并暂存、回到映射关系管理，不提示「已暂存」；【返回】放弃时一并丢弃 | 用户，2026-11-17 |
| R7 | 开启过滤时，命中行拆分出的币种也按币种映射表规范化，与主映射行同一口径（避免同一币种输出成「人民币」与 CNY、余额按币种拆成两组） | 用户，2026-11-17（对账专项审查后确认） |

### 6.3 界面

- 「根据字段值过滤账单」只在勾选「拆分/合并明细账单」时可用；未勾选拆分时勾选框与按钮置灰、提示先勾选拆分，已存的勾选与规则保留但不生效。
- 勾选过滤后主映射的 Currency、Credit / Debit、按正负号、按字段区分发生额恢复可编辑（不清空已填值）；取消过滤（拆分仍勾选）时恢复原互斥并清空这几行（【返回】可放弃）。
- 【过滤规则设置】弹窗：标题「过滤规则设置」；正文左侧「过滤规则」（ⓘ 说明命中口径），右侧为「规则 #N」分组（组头【删除该规则】）；每个条件为 字段下拉（模板表头）+ 运算符下拉 + 值输入框 + × + 新增（在下方插入条件）；底部「+ 新增过滤规则」。
  - 运算符：等于 / 不等于 / 包含 / 不包含 / 空值 / 非空值 / 开头为；空值、非空值时隐藏值输入框。迭代三起追加字段运算（§7.3），本弹窗与原始账单预处理共用。
  - 删到规则的最后一个条件时保留一个空白条件；整条规则用【删除该规则】删除，删除后序号重排。
  - 规则字段已不在模板表头（模板【更新】后）时显示「（已删除）」并保留原值，保存模板时由主进程拒绝。
  - 【保存】校验：至少一条规则；每个条件的字段必选，空值 / 非空值以外的运算符必须填值；字段与值都为空的条件、没有条件的规则忽略；值去首尾空白。
  - 【取消】/ ×：不改暂存的规则。

### 6.4 保存与生成

- 映射【保存】：开启拆分且勾选过滤时，主映射必须设置一种发生额（直接映射 / 按正负号 / 按字段区分，三者只能选一种），且至少一条有效规则、字段在模板表头中；MerchantId 为「原始账单仅有币种无账户号」时，Currency 照不拆分时的要求映射到币种列。未生效时规则只规范化保存（保留草稿）。
- 主映射与拆分映射的特征值：过滤开启且不复用模块映射时，两套映射所选特征值都须有效；未命中提示只记该行所走映射用到的特征值。
- 生成：
  - 比较口径：单元格去首尾空白后按文本比较，区分大小写，不做数值换算（`100` 与 `100.00` 不相等）。
  - 命中的源行按拆分/合并配置展开（复用或不复用模块映射同原规则），未命中的行按主映射输出；两者在同一次逐行处理中按源行顺序输出，之后的明细过滤、余额计算不变。
  - 币种（R7）：命中行只取拆分行配置的币种列，单元格为空时不回落到主映射币种；取到的值按币种映射表规范化（与主映射同一口径，MerchantId 按币种取大账号时不做模糊匹配），无法识别时保留原值并记「币种未匹配」提示（同一源行同一列只记一次）。开启过滤时即使主映射未配 Currency 也加载币种映射表。
  - 合计行在两条路径各自按原规则识别。
  - 勾选过滤但规则缺失或无效：拒绝生成并提示设置规则；规则字段不在源文件表头：拒绝生成（`映射字段不存在`）；模板【更新】删掉规则字段时，生成前的失效引用列出「根据字段值过滤账单 · 过滤规则 #N 第 M 个条件」，未勾选时标为未启用。
  - 「拆分无输出」提示只统计命中的行；「按字段区分发生额未命中」提示只统计走主映射的行。
- 存储：`template_bill_split_meta.row_filter_rules_json`（启动补列、幂等），形状 `[{ seq, conditions: [{ field, op, value }] }]`；与映射同一事务写入。
- 模板包：规则随拆分配置导出导入并同步模板库文件；勾选过滤或有规则时写 v8（与费用账单共用，v3.2.18 及更早版本整包拒绝）。

### 6.5 验收

- 分组标题为「账单拆分合并设置」；第三行勾选框与按钮按 §6.3 显示与置灰，勾选后主映射解除互斥。
- 过滤规则弹窗按 §6.3 布局（日 / 夜间）、校验与暂存；【保存】映射时规则随请求提交，【返回】不提交。
- 生成：命中行拆分、未命中行按主映射，按源行顺序合并；未勾选过滤时全部行拆分（原行为）；规则缺失、字段缺失时拒绝生成。
- 旧库启动补列，重复启动无副作用；模板包往返后规则与生成结果一致，用到时写 v8。

### 6.6 非目标

- 不支持数值大小比较、正则或忽略大小写的匹配。
- 未开启过滤的拆分模板，拆分行币种仍取源单元格原值（不改既有输出）；收付均为 0 的拆分行静默丢弃的既有行为不变。

## 7. 迭代三：原始账单预处理与字段运算（2026-11-17）

### 7.1 背景

部分网银原始账单混有非真实账单的行，需要按某个或某些字段的值、或字段之间的关系做条件判断，过滤出真正的网银原始账单。预处理完成后得到「原始账单加工表」，用于明细 / 余额账单的生成。

### 7.2 已确认决策

| 编号 | 决策 | 来源 |
| --- | --- | --- |
| P1 | 映射关系管理新增分组「原始账单预处理」，位于「个性化映射设置」上方；行「过滤账单」+ 勾选框，勾选后右侧显示【规则设置】 | 用户，2026-11-17 |
| P2 | 【规则设置】弹窗标题「过滤规则设置」，组件同 §6.3 过滤规则弹窗 | 用户，2026-11-17 |
| P3 | 命中任一规则的源行**保留**进入原始账单加工表，未命中的行丢弃，不参与明细 / 余额生成 | 用户，2026-11-17 |
| P4 | 原始账单加工表只是生成时的内存中间表，不导出文件 | 用户，2026-11-17 |

**比较口径**
- 每个源行按「整行表头 + 整行单元格去首尾空白后的文本」比较：包括模板表头范围以外的列（模板只需与源表头的一段连续列匹配即可导入，模板没取的列如交易流水号不同也不算重复）；行尾空白单元格不影响；表头不同的文件之间不会判为重复。含多个分段（重复表头）的文件，每行用其所属分段的整行表头比较。整行按 Excel 物理列对齐（记录首个非空单元格的绝对列号，工作表有效范围的起始列不同不影响比较）。Excel 错误值（`#N/A` 等）按类型比较，与空白、任何文本（含同文字的文本）都不相同。以下无法证明整行相同的行不参与查重（保留）：工作表声明的有效范围（`!ref`）以外仍有值的行（读取时取不到这些列）；CSV 中有不能按 UTF-8 解码的字节、单元格含替换字符的行（不同原文可能解出同一字符）。含公式的行（含数组公式范围内的行）同样不参与查重（保留）：读取库读不出文件里是否真有缓存结果（没有缓存时数值公式读成空、文本公式读成空串、布尔公式读成 false），无法证明读到的就是 Excel 的计算结果，宁可漏判。XLSX 是否含公式按工作表 XML 原文判断（含公式元素的行、共享 / 数组公式引用范围内的行都不参与），不依赖读取库是否在单元格上给出公式：共享公式的从属单元格可以写成空的 `<f t="shared" si="0"></f>`，读取库读成空白；找不到工作表原文时整张表不参与。文本型工作簿（扩展名为 `.xls` / `.xlsx` 的 HTML 表格、制表符文本等）读取时会把单元格文本推断成数值 / 日期 / 布尔值（`00001` 与 `1`、`1,000` 与 `1000` 读成同一个值），查重按不推断类型再读一次的原文比较（普通映射仍用推断后的值）；两次读取结构不一致时整张表不参与。HTML 表格的单元格文本还会去掉内部标签与标签两侧的空白（`REF <b>A</b>` 与 `REFA` 读成同一文本），另按与读取库相同的切行规则从原始字节取每行的原始标记（含 `<tr>` 开始标签与所在的 `<thead>` / `<tbody>` / `<tfoot>` 开始标签：它们的 class / style 可以决定单元格的数字格式）附在指纹上；样式表按行位置（`:nth-child` 等）设置数字格式、引用外部样式表（`<link rel="stylesheet">`、`@import`，实际生效的样式不在文件里）、或表格各行之间有注释（含 Office 条件注释 `<!--[if gte mso 9]>…<![endif]-->`，读取库删除、Excel 按条件显示）时整张表不参与，原始标记完全相同的行才可能判为重复；切出的行对不上时整张表不参与；带 Excel 公式属性（`x:fmla`，读取库不当作公式、只读到计算结果）的行不参与；HTML 行摘要另含表格各行以外的文档原文（未删注释的原文：BOM、`<head>` 中声明的字符编码与样式表——样式可以写在 `<style><!-- … --></style>` 里、`<table>` 开始标签、表格之后的内容），这些上下文不同的文件不互判重复：同样的字节在不同编码下是不同的文字，样式表里的 `mso-number-format` 可以把同一个值显示成不同的文本。工作簿使用 1904 日期系统时每行另附日期系统标记：同一日期序号在两种日期系统下是不同的日期，不与 1900 日期系统的文件互判重复。XLSX / XLS 中带非常规数字格式的单元格按「类型 + 值 + 格式代码」比较（XLS 没有原文行摘要，常规格式的值也按「类型 + 值」比较：布尔值 `TRUE` 与文本 `true` 不同）（数字格式可以给同一个值加上不同的显示文本，如 123 显示为 `TX-A-0123`、`TX-B-0123`）；XLSX 带数字格式的条件格式（含 x14 扩展）覆盖的行不参与；XLS 含 Excel 2007 起的条件格式记录（CondFmt12 / CF12 / CFEx，读取库不解析、可以改数字格式）时整张表不参与。按区间排除（条件格式、公式范围、纵向合并）时只标记区间内有内容的行。文本型工作簿与 CSV 中 Excel 会按公式计算的文本（以 `=`、`@` 开头，或以 `+`、`-` 开头但不是普通带符号数字，如 `="TX-"&ROW()`、`+ROW()`）值未知，该行不参与；普通带符号数值（`-1,234.56`、科学计数法 `-1.2E-4`）与只有正负号的占位（`-`）照常比较。纵向合并单元格（合并区域跨多行）的从属行不参与：只有首行存值，其余行的该格为空但实际属于同一值（如合并的流水号标识一笔交易及其费用行）。CSV（`.csv`）每行另附该行原文的摘要：导入解析器宽松（如吞掉未加引号字段中间的引号，`SALE 2" X"` 与 `SALE 2 X` 读成同一文本），原文完全相同的行才可能判为重复。含替换字符（U+FFFD）的单元格（不论本次解码是否有损、不论文件格式，XLSX / XLS 中的同样处理：文件里的替换字符可能是上游解码丢失后写入的）、分隔符文本中含换行的单元格（读取库把引号字段内的 CRLF 改成 LF）值未知，该行不参与。分隔符文本每行另附文件的解码方式：读取库对带 UTF-8 BOM 的文件按 UTF-8 解码、否则逐字节读，不同字节的两个文件可以读成同一文本（无 BOM 的 `café` 与带 BOM 的 `cafÃ©`），解码方式不同的文件不互判重复；逐字节读时替换字符读成 `ï¿½`，同样按替换字符处理。只核对能正向识别的 HTML 表格（按文档根元素区分：根元素为 `Workbook` 的是 Excel 2003 XML；HTML 可以声明 SpreadsheetML 命名空间）与分隔符文本（首行含制表符、逗号、分号或竖线，或以 `sep=` 声明分隔符）两种文本格式，其他（Excel 2003 XML、SYLK、DIF、SocialCalc、固定宽度文本、含 NUL 字节的二进制格式等）整张表不参与。XLSX 每行另按工作表 XML 原文比较：各单元格的列号、类型、原始 XML（共享字符串换成该项 `<si>` 原始 XML 的摘要，每项只算一次，不按引用次数复制原文）与实际数字格式（单元格自身的样式，没有时继承行样式、再继承列样式；样式自身的格式、其所属命名样式 `cellStyleXfs` 的格式与选择标志 `applyNumberFormat` 都计入；自定义格式按格式代码，格式代码按完整属性读取——引号内可以有 `>`，如 `[>0]"A-"000`）的摘要附在指纹上，样式表读不到时整张表不参与，引用的样式不存在或格式代码读不到时该行不参与；原文行须与读到的行一一对应（有 `<row>` 省略行号或行号重复时整张表不参与，单元格省略位置或个数与读到的不同时该行不参与；只有核对到原文摘要的行参与，原文写法未识别等没有核对到的行一律不参与），原文完全相同的行才可能判为重复——读取库会把超过 15 位有效数字的数值舍入（`9007199254740992` 与 `9007199254740993`）、把字符引用读错等，同一值的不同写法按不同处理（宁可漏判）；找不到工作表或共享字符串原文时整张表不参与。不做数值换算：xlsx 数值 `100` 与 csv 文本 `100.00` 不相等。
- 只有会导出为明细行的源行参与比较，与明细导出共用同一判定（`isDetailExportAmountRow`：Credit / Debit 恰有一个不为空或 0，不能解析的金额如 `100.` 照常导出、照常参与）；合计行、空行、多账户分段文件中的账号说明行等不参与。
- 账户号取该源行全部输出行的 MerchantId + 币种（拆分行可能有多组，按二元组排序后整体比较，账户号中的任何字符都不影响拆分）；账期取首个输出行的 BillDate。
- 同一组须源行内容、账户号、账期都相同：同一源内容在不同模板下解析出不同账期时不算重复。账期（BillDate）为空的源行不参与（两个未知账期不能证明是同一账期），导出行为不变。
- 任一输出行没有账户号（MerchantId 为空）的源行无法证明账户相同，不参与查重（保留、不删）。任一输出行（拆分出的某一笔也算）收、支同时有值的源行生成时须报错，不参与查重（删除会掩盖报错，且结果随文件顺序变化）。币种为空照常参与，同余额按（账户号, 币种）分组的口径。
- 被「过滤账单」去掉的行不参与。

**生成流程**
- 读表、过滤账单、映射、大账号识别 / 分配都在完整数据上完成后扫描；有重复时暂停，返回 `duplicate-review`，不生成、不写入导入会话、不动已缓存的导出。
- 指定模板导入勾选查重时，为跨文件查重在预检阶段先映射全部文件（没有重复时这些条目随预检直接进入任务）。所有导入在预检映射前记下配置：指定模板记该模板（含同渠道模板）的配置指纹；按文件名映射时文件命中哪个模板取决于全部模板的表头，记模板目录快照（全部模板的记录与映射行，只读数据库），命中的模板另在映射后记配置指纹——等待复核、等待选择大账号的上下文同样带上目录快照，新增、删除或修改任一模板即要求重新导入。预检放行后在业务入口使用这些条目前再核对（任务开始前的批次预留、证据采集期间配置仍可能被保存），变化时按未开始返回（还没有改动会话与输出，界面只提示、保留上一批的导出与补录入口），变化时提示「导入期间模板、渠道或账户映射已修改，请重新导入文件」：各路径（查重预映射、按记住的顺序分配大账号、单账户识别、按文件名映射等）都可能复用预检映射的条目，不按旧配置生成；按记住的顺序自动分配大账号、确认重复账单后生成失败（如收支同时有值）时照常报错，不降级为重新选择大账号；多大账号模板未选定大账号时与未勾选时同一口径拒绝（不生成账户为空的明细）。预检阶段映射 / 校验失败不在预检拦截，执行阶段重新映射并按原路径报错，照常可导出含逐行明细的报错文件。
- 暂停发生在导入的预检阶段（与大账号选择相同），不开后台任务、不归档。需要选择大账号的导入，先完成大账号选择再扫描。
- 【确认】：用同一导入通道续跑，生成前按同一口径重新扫描，结果须与弹窗展示的一致（摘要含文件顺序、行号、内容指纹、账户号与账期），不一致时拒绝生成（`DUPLICATE_ROWS_REVIEW_STALE`，提示重新导入）；重新扫描时指纹缺失或重复已消失也按不一致拒绝。一致时删除各组首行以外的源行的全部输出行（含拆分出的多行）及这些行的提示，再生成明细 / 余额。
- 【确认】续跑在业务入口按 ID 核对并消费待确认上下文：同一确认的两个请求即使都已获准开始，第二个也按未开始返回，不会重复写入会话。
- 【确认】提交中提醒窗口锁定：不能关闭、取消、切换页面或被其他弹窗替换；结果只在原窗口仍在最上层时续接（错误、补录 / 断档确认替换原窗口）。
- 【取消】/ ×：清除待确认状态，返回主页面，不生成；状态框、导入会话与已生成的导出保持不变（上一批待补录余额时仍可点击状态框继续，同大账号选择窗口的 ×）。被切换页面、其他根弹窗替换等方式关闭时同样清除待确认状态（释放预映射数据）；【确认】没有成功时（可能未进入执行，如等待期间源文件被移动）也按同一上下文清除，已执行时为空操作。
- 等待确认期间删除模板或渠道：待确认的复核作废，【确认】时提示重新导入，不按已删除的模板配置生成。
- 需要先选择大账号的导入：暂存选择时记下映射条目时的配置指纹（不论是否勾选查重；配置指纹另含大账号固定模式与记住的顺序），完成选择时先核对（预检时核对一次，任务开始前再核对一次）（等待选择期间改了配置，如启用 / 关闭查重、改金额映射，须重新导入），再决定是否查重；复核沿用这份指纹。
- 【确认】或完成大账号选择时未开始生成就被拒绝（续跑前核对失败、源文件在确认期间变化、任务未获准入或未能开始、IPC 在开始前抛错；续跑请求在预检阶段的任何拒绝都由主进程标记 `preservesSession`，如枚举文件不可用，不靠界面的错误码清单推断；完成大账号选择时「选择无效」除外，保留选择窗口重新选择）：只弹提示，状态框、导出按钮与上一批的补录入口保持不变，同时释放待确认数据（大账号选择一并释放）。复核失效（摘要不一致）是执行阶段的结果，返回值带 `DUPLICATE_ROWS_REVIEW_STALE`。【确认】或完成大账号选择时 IPC 抛错：主进程只在开始执行时取走待确认数据（大账号选择同理），界面按 contextId 释放成功即证明没有开始生成（按上述未开始处理）；释放不到（如生成后归档终态写入失败）时无法确认是否已生成，按普通导入失败处理（不保留上一批的导出与补录入口），提示核对生成结果。
- 等待确认期间修改了参与模板的配置（映射、渠道归属、账户映射、拆分/合并元数据等）：暂停时记下各参与模板及其同渠道兄弟模板（按文件名映射时它们的大账号也参与选择）的配置指纹（含生成实际使用的配置），【确认】续跑前核对，变化即拒绝并清除待确认，提示重新导入（不把旧明细与新配置混用）。
- 跨文件重复时记下被删行的保留方文件。之后只覆盖去重关系的一端都会出错（只覆盖保留方会让去除的交易丢失；只覆盖去除方会把去除的交易带回来重复入账）：选择文件后即拦下，提示把相关文件一起重新导入（一起导入时重新查重）。去重关系可以连成链（A 保留了 B 的行、B 又保留了 C 的行），按通过去重关系（含间接）相连的整组判断，一次列出整组文件，按提示一起导入即可放行，不会沿关系链来回提示。这是未开始的导入，界面只弹提示，状态框、导出按钮与补录入口保持不变；提示含文件名，不写入活动日志。
- 同一批选择了内容完全相同的整文件（改名副本）时，先走既有的整文件重复提示（在行级查重之前，选择覆盖时只保留后选的文件），不进入行级复核：整文件提示能保证整份副本不重复入账，包括行级查重无法证明相同而保留的行（含公式、没有账户号等），比行级复核更保守。行级复核只处理整文件提示之后仍保留的文件。
- 未开始导入的拒绝提示（如只覆盖去重关系的一端）返回时另一个弹窗正在提交、提示无法打开，或返回时用户已离开账单页面：保留这条提示（提示含文件名，状态框会写入活动日志，只显示不含文件名的等待文案），状态框提示「本次导入未开始，请点击“导入文件”查看原因」，再点时弹出原提示，不重新导入、不写入活动日志。
- 离开账单页面期间返回的等待确认（含重复账单提醒、大账号选择、大账号顺序不匹配），或返回时另一个弹窗正在提交、提醒窗口无法打开，都只提示「导入等待确认」并保留结果，用户再点「导入文件」继续（不重新选文件）；导入确认与导出选择分别保存，互不覆盖；同时保留上一批的补录入口；用户继续某项时，若状态框仍是这条等待提示：另一项仍在等待则换成它的等待提示，没有其他待办才恢复原反馈（之后取消也不丢上一批的可用操作）；等待期间已有新反馈（如完成了补录）则保留新反馈。
- 查重只在同一生成组（同一模板，或同一渠道的各子模板；即同一份输出明细、同一条余额链）内进行，不同生成组的相同行不互判重复（照常各自生成，与未开启时一致）。跨组去除是把交易从一家银行的账单挪到另一家，不是去除重复，还会让某组被整组去空、该组之前生成的余额失去明细依据（覆盖导入后旧的计算余额仍被沿用）。（2026-11-18 审查中按保守口径收窄 U2 的「一次导入的全部文件」，用户已于 2026-11-18 确认。）
- 删除在映射之后进行，分段账号识别与大账号分配不受影响。之后补录余额、导出全部均基于删除后的明细，不从源文件重读。

**展示与可审计**
- 行号是 Excel 中的物理行号：工作表有效范围不从第 1 行开始（前几行完全为空）时也按物理行号显示、删除与记录（同时修正各类逐行提示的行号）。
- 提醒弹窗按行封顶，每次最多列出 1000 行（依次列出各组，最后一组可能只列出前面的行并注明其余行数）；超出时说明总组数、总行数，并在表格下方列出全部去除的行号（每个文件一行，行号压缩成区间，如「第 3、5-9 行」），确认前在弹窗内即可核对任意一行。
- 活动日志记录「发现重复账单，等待确认」「已确认过滤重复账单」「已取消导入（重复账单）」。前两条都写完整的去除行号清单（同上）；另附文件、行号、账户号、账期明细样例，最多 200 行，另记总行数。日志持久化在磁盘，不写文件名（文件名可能含账户号），以文件序号（本次导入的文件顺序）、行号、组号定位；账户号只留末 4 位（4 位及以下全部隐去）；币种只写 3 位字母的币种代码，其他值记为「未识别币种」；弹窗核对时显示原文件名、账户号与币种。复核失效（摘要不一致）按告警级别记录。
- 开启查重但有行无法核对原文（含公式、编码有损、格式无法核对等，这些行保留、不参与查重）时，生成提示附「N 行无法核对原文，未参与重复账单过滤」，活动日志同记（同批还需处理余额时也另记一条），避免误以为已全部查重。
- 生成提示附「已去除重复账单行 N 行」；同批还需处理余额（补录、断档、余额不一致、补录替换）时，该提示一样附上；补录余额后重新生成（含按文件名映射逐个账户补录）的提示按本次范围的会话条目统计，同样附上。

**模板包**：勾选时写 v8（旧版本会忽略开关、静默输出重复行）。模板【更新】不把开关值当作源字段引用。

### 8.4 映射字段「逻辑取值」

**界面**
- 「逻辑取值」只出现在与「需要拼接字段」相同的行（Balance、MerchantId、Currency、个性化映射字段除外），位于「需要拼接字段」上方。
- 选中后下拉框右侧显示【设置】；弹窗标题「逻辑取值」，正文左侧「候补字段取值」+ Tips 悬停说明，右侧为带序号的模板字段单选下拉框，首行【新增】在末尾追加，其余行【删除】；默认两个。字段已不在模板表头时显示「（已删除）」。
- 【保存】（左）校验：至少选择 2 个字段、不可重复；空白下拉框忽略；校验通过后暂存，随映射【保存】提交；【取消】（右）/ × 不改暂存；映射【返回】放弃。
- 映射【保存】前选了「逻辑取值」但未设置候补字段时提示「请点击【设置】选择候补字段」。开启拆分/合并等互斥规则清空该行映射时，同步隐藏【设置】与候补预览（保存只按当前映射值）。模板表头有一列叫「逻辑取值」时，只有该行原本就保存为直接取该列（旧版本的映射）才保持不设置候补字段；新选「逻辑取值」一律须设置候补字段，不因表头同名放行。
- 拆分/合并账单映射弹窗不提供该值；从模块映射导入时，主映射中的「逻辑取值」行留空并提示；只有旧版直接引用名为「逻辑取值」的源列的映射照常复制，判据与主映射保存相同：没有候补字段（空，或只有一个同名列本身）、该行打开映射弹窗时已保存为这种直接引用、且模板表头确有这一列（刚选「逻辑取值」尚未设置候补字段的行不复制）。

**存储**：映射行 `mappedField='逻辑取值'`、`mappedFields` 为有序候补字段（不新增列）。升级时一次性迁移（`app_settings` 标记只执行一次）：旧库里 `mapped_field` 为「逻辑取值」且有多个字段的映射行（主映射与拆分映射）是旧式按序拼接（首个源字段恰好叫「逻辑取值」），还原为需要拼接字段；单字段 / 无字段的直接映射不动。与「需要拼接字段」「字段筛选特征值」相同，「逻辑取值」作为映射模式的保留字识别：源文件中名为「逻辑取值」的列不能再直接映射（与这两项现有选项同口径，按名称冲突几乎不会出现，不另做区分）。

**保存校验**：候补字段 ≥2、不重复、都在模板表头中；不允许用于 Balance、MerchantId、Currency 与个性化映射字段；拆分映射中出现（带候补字段）时拒绝保存，模板包导入时包含这种拆分映射、或候补字段重复的模板整条跳过（与映射保存入口同一校验，不写入界面无法创建的配置）；拆分映射直接引用名为「逻辑取值」的源列（没有候补字段）的旧配置照常保存与导入。是否为旧版本的直接引用按去重前的原值判断：候补为空、或只有一个同名列本身；多项（含两个同名列）都按逻辑取值处理。两种旧写法生成时都按源列名直接读取（不转成内部 token），按源字段名判断的逻辑（如根据发生额做映射的户名）与旧版本一致。启用拆分/合并但复用模块字段的映射关系时，拆分映射不参与生成，其中失效的旧引用不阻断生成。

**生成**：按序号取第一个去首尾空白后非空的单元格；逻辑取值在生成时用以 NUL 开头的内部标记传递（不落库），真实列名不会与它相同：旧模板直接映射的列名即使形如 `__LOGIC_VALUE__:[…]` 也照旧直接读该列，新配置的逻辑取值也不会被同名列覆盖；全部为空输出空；之后按目标字段照常规范化。候补字段不在源文件表头中时拒绝生成（`映射字段不存在`）。只有 `__LOGIC_VALUE__:` 前缀加非空字段名数组才按逻辑取值处理，其他以该前缀开头的映射值按普通源字段读取（旧模板兼容）。已存映射为「逻辑取值」却没有候补字段（v3.2.18 及更早直接映射名为「逻辑取值」的源列即为此形态）：模板表头有该列时照旧按该列读取（保存、模板包导入都按直接映射该列原样保留，不升模板包版本），没有时拒绝生成并提示在【设置】中重新选择，不把该字段（如发生额）静默变成空。模板【更新】删掉候补字段时，失效引用列出该映射。

**模板包**：用到时写 v8（旧版本会当作需要拼接字段，静默输出不同的值）。读 v7 及更早的包时，`mappedField` 为「逻辑取值」的多字段映射是旧式按序拼接（首个字段恰好是名为「逻辑取值」的源列），还原为需要拼接字段；单字段 / 无字段的是直接映射该列，原样保留。

### 8.5 验收

- 「原始账单预处理」显示「过滤账单」「重复账单过滤」两行；后者无按钮，勾选随【保存】落库、重开回显。
- 勾选后：同一文件内与跨文件的重复行（账户相同）弹窗列出；账户不同、表头不同、被过滤掉的行不列出；【确认】后每组只保留首行，明细 / 余额行数与金额按去重后计算；【取消】不生成、不改会话；无重复时不弹窗；未勾选时生成结果与之前一致。
- 「逻辑取值」位于「需要拼接字段」上方，【设置】弹窗按 U9 布局（日 / 夜间），默认两个下拉框；生成按 U10 取值；缺字段拒绝生成。
- 模板包用到任一功能时写 v8，往返后配置与生成结果一致。

### 8.6 非目标

- 不跨导入批次查重：分别两次导入的文件在「导出全部」中不互查（`knowledge/backlog.md` B102）。
- 回退到 v3.2.18 及更早安装包时，数据库中的「逻辑取值」映射会被旧版当作需要拼接字段（B103，待人工复核与发版说明）。
- 不支持用户按组选择保留哪一行；不导出原始账单加工表或重复行明细文件。
- 「逻辑取值」不进拆分/合并账单映射；候补不支持固定值、特征值；`0` 不视为空。
- `statement-worker/session-state.js`（仅单测使用、生产未接入）不接入两项功能。
