## 1. 背景

拆分/合并账单把一行原始账单拆成多份输出行。部分银行把手续费等费用与交易放在同一行，需要拆出一份只有支出的「费用账单」，其发生额要由若干列计算得出（如 手续费 + 邮电费）。现有配置只能把某一列直接映射为 Debit Amount，不能计算。

## 3. 功能规则

### 3.1 文案范围（D1）

- 只改拆分/合并账单弹窗内的三处文字，以及拆分语境下的两条互斥报错、模板【更新】失效引用说明中的「按正负号拆分的发生额」。
- 主映射弹窗中「按正负号拆分的发生额」「按字段区分发生额」是映射行的存储键，不改。
- 副区域「按字段取发生额」右侧的【发生额映射关系管理】按钮需求未提及，保持原文字。

### 3.2 费用账单列（D2）

| 操作 | 规则 |
| --- | --- |
| 勾选某行 | 立即写入模板；其他行自动取消勾选；该行 Credit Amount 下拉框置灰并清空（已存的映射保留，生成时不读取） |
| 取消勾选 | 立即写入模板；模板不再有费用账单行；该行恢复已存的 Credit Amount 映射 |
| 合并组内的行 | 与该行其他控件一致，勾选框禁用 |

- 费用标记存在拆分行上，删除行、减少份数时随行移动或一起删除。
- 费用账单行置灰的 Credit（及启用特殊取值后置灰的 Debit）只在界面上显示为空，已存的映射保留、【完成】照原样保存；取消费用账单或关闭特殊取值后原映射恢复。生成时不读取被置灰的映射，也不要求这些列仍在源文件或模板表头中。
- 「Credit 与 Debit 不能同列」只比实际生效的映射：费用行的 Debit 可以选停用的 Credit 所在列。取消费用账单时，若保留的 Credit 与 Debit 同列，清空 Credit，避免同一列既记收入又记支出。
- 费用账单配置的保存（费用行、特殊取值、公式）失败时，按重读到的已保存配置显示并保留失败提示（可能已落库、只是模板库文件同步失败）；重读也失败时提示关闭重开，本窗口暂停配置写入。
- 已完成（只读）的行也可直接勾选，不需要先点【编辑】。

### 3.3 费用账单发生额特殊取值逻辑（D3）

- 位于「发生额取值设置」第三行：文本 + 勾选框 + 【设置】（勾选后显示）。
- 勾选状态立即写入模板。没有费用账单行时勾选框置灰，并提示先在表格中勾选费用账单；已保存的勾选和公式保留，但不生效。
- 勾选后费用账单行的 Debit Amount 下拉框置灰并清空。
- 与「按正负号取发生额」「按字段取发生额」不互斥：这两项照常作用于其他行。

### 3.4 公式设置弹窗（D4）

- 标题「费用账单发生额设置」；打开时回显已保存的公式。
- 左下拉框选项为模板表头（同表格其他下拉框）；右下拉框为 加 / 减 / 乘 / 除 / 运算结束。
- 一行最多 6 个下拉框（3 组），第 7 个起换行，换行后与第一个下拉框左对齐。
- 【保存】校验：至少一组；每组的字段和运算符都已选择；只有最后一组且最后一组必须是「运算结束」。两个下拉框都为空白的组保存时忽略。校验通过后写入模板并关闭。
- 【取消】/×：关闭，不保存。

### 3.5 计算口径（D5–D8）

- 只作用于已完成（completed）的费用账单行，且需启用特殊取值逻辑。
- 运算字段按单元格原值带正负号参与计算（去除千分位、货币符号等，同「按正负号取发生额」的取值口径）；空白或无法识别的值按 0。
- 先乘除后加减，同级从左到右。
- 非 0 除以 0：该文件报错，不生成，并列出源文件行号（账单自带的合计行不计入）；0 ÷ 0（如该行运算字段都为空）按 0。
- 按十进制精确计算（不经浮点，数值单元格按其十进制取值，含 1e-7 这类指数形式），结果取绝对值，四舍五入保留 2 位（1.005 → 1.01、10000.005 → 10000.01）。
- 结果为 0 时沿用现有规则：Credit、Debit 都为 0 的拆分行不输出。
- 启用特殊取值、存在已完成的费用账单行但公式缺失或无效：拒绝生成并提示设置公式。
- 公式引用的字段不在源文件表头中：拒绝生成（同其他拆分字段）；模板【更新】删掉公式字段时，失效引用列表包含「费用账单发生额公式」。

### 3.6 费用账单行的取值优先级（D10）

| 情况 | Credit Amount | Debit Amount |
| --- | --- | --- |
| 启用特殊取值且公式有效 | 空 | 公式结果（优先于「按正负号/按字段取发生额」和行级 Debit 映射） |
| 未启用特殊取值 | 空（不论行级映射还是副区域规则算出收入） | 原逻辑（副区域规则或行级 Debit 映射） |

- 之后的户名 / 卡号按收支方向分配、合并组净额计算不变。

### 3.7 模板包与模板库

- 拆分行带「费用账单」标记，拆分配置带「特殊取值逻辑」勾选状态与公式，随模板包导出、导入与模板库文件同步。
- 任一模板标了费用账单或勾选了特殊取值逻辑时，模板包写 v8，v3.2.18 及更早版本读到整包拒绝（否则会静默输出不同的金额）；都未用到时版本号沿用原规则。

## 4. 验收

- 文案按 D1 显示；主映射弹窗不变。
- 费用账单勾选唯一，勾选行 Credit 置灰；启用特殊取值后该行 Debit 置灰；关闭重开后状态保留。
- 公式弹窗按 D4 布局；第 7 个下拉框换行；校验提示按 §3.4；【取消】不写入。
- 生成结果：费用账单行 Debit = 公式结果（先乘除后加减、取绝对值、2 位小数），Credit 为空；其他行不受影响；除数为 0、公式缺失、字段缺失时拒绝生成。
- 模板包往返后配置一致，用到时写 v8。
- 旧库启动自动补列，重复启动无副作用。

## 5. 非目标

- 不改主映射弹窗的发生额配置项与其存储键。
- 不支持括号、常量或多个费用账单行。
- 不修复模板包导出时丢失「指定账单实现功能」序号的既有问题（登记到 `knowledge/backlog.md`）。

## 6. 迭代二：「账单拆分合并设置」与根据字段值过滤账单（2026-11-17）

### 6.1 背景

同一份网银原始账单里只有一部分需要拆分。按字段值设置过滤规则：命中规则的源行走拆分/合并映射，其余行走模板主映射，两部分按源行顺序合在一起输出明细和余额账单。

### 6.2 已确认决策

| 编号 | 决策 | 来源 |
| --- | --- | --- |
| R1 | 映射关系管理分组标题「账单拆分合并管理」改为「账单拆分合并设置」（只改映射弹窗；历史文档不改，USER_GUIDE 发版时同步） | 用户，2026-11-17 |
| R2 | 分组第三行「根据字段值过滤账单」，勾选框在文字右侧，勾选后显示【过滤规则设置】；开关存为映射行（勾选 `是`，未勾 `''`） | 用户，2026-11-17 |
| R3 | 开启拆分且勾选过滤时，解除拆分对主映射 Currency / Credit / Debit / 按正负号 / 按字段区分 的互斥，供未命中的行使用；主映射内三选一照常 | 用户，2026-11-17 |
| R4 | 过滤规则弹窗组件构成参考 场景管理 → 银行对账单赋值自身 → 账单类型；文本「过滤规则」；右下【保存】在左、【取消】在右 | 用户，2026-11-17 |
| R5 | 命中口径：同一规则内的条件全部满足、任一规则满足即命中 | 用户，2026-11-17 |
| R6 | 规则随映射关系管理【保存】一起落库：规则弹窗【保存】只校验并暂存、回到映射关系管理，不提示「已暂存」；【返回】放弃时一并丢弃 | 用户，2026-11-17 |
| R7 | 开启过滤时，命中行拆分出的币种也按币种映射表规范化，与主映射行同一口径（避免同一币种输出成「人民币」与 CNY、余额按币种拆成两组） | 用户，2026-11-17（对账专项审查后确认） |

### 6.3 界面

- 「根据字段值过滤账单」只在勾选「拆分/合并明细账单」时可用；未勾选拆分时勾选框与按钮置灰、提示先勾选拆分，已存的勾选与规则保留但不生效。
- 勾选过滤后主映射的 Currency、Credit / Debit、按正负号、按字段区分发生额恢复可编辑（不清空已填值）；取消过滤（拆分仍勾选）时恢复原互斥并清空这几行（【返回】可放弃）。
- 【过滤规则设置】弹窗：标题「过滤规则设置」；正文左侧「过滤规则」（ⓘ 说明命中口径），右侧为「规则 #N」分组（组头【删除该规则】）；每个条件为 字段下拉（模板表头）+ 运算符下拉 + 值输入框 + × + 新增（在下方插入条件）；底部「+ 新增过滤规则」。
  - 运算符：等于 / 不等于 / 包含 / 不包含 / 空值 / 非空值 / 开头为；空值、非空值时隐藏值输入框。迭代三起追加字段运算（§7.3），本弹窗与原始账单预处理共用。
  - 删到规则的最后一个条件时保留一个空白条件；整条规则用【删除该规则】删除，删除后序号重排。
  - 规则字段已不在模板表头（模板【更新】后）时显示「（已删除）」并保留原值，保存模板时由主进程拒绝。
  - 【保存】校验：至少一条规则；每个条件的字段必选，空值 / 非空值以外的运算符必须填值；字段与值都为空的条件、没有条件的规则忽略；值去首尾空白。
  - 【取消】/ ×：不改暂存的规则。

### 6.4 保存与生成

- 映射【保存】：开启拆分且勾选过滤时，主映射必须设置一种发生额（直接映射 / 按正负号 / 按字段区分，三者只能选一种），且至少一条有效规则、字段在模板表头中；MerchantId 为「原始账单仅有币种无账户号」时，Currency 照不拆分时的要求映射到币种列。未生效时规则只规范化保存（保留草稿）。
- 主映射与拆分映射的特征值：过滤开启且不复用模块映射时，两套映射所选特征值都须有效；未命中提示只记该行所走映射用到的特征值。
- 生成：
  - 比较口径：单元格去首尾空白后按文本比较，区分大小写，不做数值换算（`100` 与 `100.00` 不相等）。
  - 命中的源行按拆分/合并配置展开（复用或不复用模块映射同原规则），未命中的行按主映射输出；两者在同一次逐行处理中按源行顺序输出，之后的明细过滤、余额计算不变。
  - 币种（R7）：命中行只取拆分行配置的币种列，单元格为空时不回落到主映射币种；取到的值按币种映射表规范化（与主映射同一口径，MerchantId 按币种取大账号时不做模糊匹配），无法识别时保留原值并记「币种未匹配」提示（同一源行同一列只记一次）。开启过滤时即使主映射未配 Currency 也加载币种映射表。
  - 合计行在两条路径各自按原规则识别。
  - 勾选过滤但规则缺失或无效：拒绝生成并提示设置规则；规则字段不在源文件表头：拒绝生成（`映射字段不存在`）；模板【更新】删掉规则字段时，生成前的失效引用列出「根据字段值过滤账单 · 过滤规则 #N 第 M 个条件」，未勾选时标为未启用。
  - 「拆分无输出」提示只统计命中的行；「按字段区分发生额未命中」提示只统计走主映射的行。
- 存储：`template_bill_split_meta.row_filter_rules_json`（启动补列、幂等），形状 `[{ seq, conditions: [{ field, op, value }] }]`；与映射同一事务写入。
- 模板包：规则随拆分配置导出导入并同步模板库文件；勾选过滤或有规则时写 v8（与费用账单共用，v3.2.18 及更早版本整包拒绝）。

### 6.5 验收

- 分组标题为「账单拆分合并设置」；第三行勾选框与按钮按 §6.3 显示与置灰，勾选后主映射解除互斥。
- 过滤规则弹窗按 §6.3 布局（日 / 夜间）、校验与暂存；【保存】映射时规则随请求提交，【返回】不提交。
- 生成：命中行拆分、未命中行按主映射，按源行顺序合并；未勾选过滤时全部行拆分（原行为）；规则缺失、字段缺失时拒绝生成。
- 旧库启动补列，重复启动无副作用；模板包往返后规则与生成结果一致，用到时写 v8。

### 6.6 非目标

- 不支持数值大小比较、正则或忽略大小写的匹配。
- 未开启过滤的拆分模板，拆分行币种仍取源单元格原值（不改既有输出）；收付均为 0 的拆分行静默丢弃的既有行为不变。

## 7. 迭代三：原始账单预处理与字段运算（2026-11-17）

### 7.1 背景

部分网银原始账单混有非真实账单的行，需要按某个或某些字段的值、或字段之间的关系做条件判断，过滤出真正的网银原始账单。预处理完成后得到「原始账单加工表」，用于明细 / 余额账单的生成。

### 7.2 已确认决策

| 编号 | 决策 | 来源 |
| --- | --- | --- |
| P1 | 映射关系管理新增分组「原始账单预处理」，位于「个性化映射设置」上方；行「过滤账单」+ 勾选框，勾选后右侧显示【规则设置】 | 用户，2026-11-17 |
| P2 | 【规则设置】弹窗标题「过滤规则设置」，组件同 §6.3 过滤规则弹窗 | 用户，2026-11-17 |
| P3 | 命中任一规则的源行**保留**进入原始账单加工表，未命中的行丢弃，不参与明细 / 余额生成 | 用户，2026-11-17 |
| P4 | 原始账单加工表只是生成时的内存中间表，不导出文件 | 用户，2026-11-17 |
| P5 | 过滤规则组件新增运算 等于（字段）/ 不等于（字段）/ 包含（字段）/ 不包含（字段），同步到 §6「根据字段值过滤账单」；选这四种时值输入框换成单选下拉框，选项为模板字段 | 用户，2026-11-17 |
| P6 | 被比较字段的单元格为空时：包含（字段）不命中、不包含（字段）命中；等于 / 不等于（字段）按去首尾空白后的文本比较，两边都空算相等 | 用户，2026-11-17 |

### 7.3 界面

- 「过滤账单」与拆分/合并无关，始终可用；勾选状态存为映射行（`templateField='过滤账单'`，勾选 `是`、未勾 `''`）。
- 规则弹窗同 §6.3（分组、条件、【删除该规则】、【保存】在左、【取消】/× 不改暂存），tooltip 说明命中的账单保留为原始账单加工表。
- 字段运算：值位置为模板表头单选下拉框（占位「请选择比较字段」）；比较字段已不在模板表头时显示「（已删除）」并保留原值。在字段运算与其他运算之间切换时清空值。
- 【保存】校验：字段运算须选择比较字段（「请选择比较字段」），其余同 §6.3。规则弹窗【保存】只暂存，随映射关系管理【保存】提交；映射【返回】放弃（同 R6）。
- 运算符下拉框加宽，避免「不包含（字段）」截断（两个过滤规则弹窗共用）。

### 7.4 保存与存储

- 映射【保存】：勾选「过滤账单」时须至少一条有效规则，条件字段与比较字段须在模板表头中；未勾选时规则只规范化保存（保留草稿）。
- 存储：`templates.preprocess_row_filter_rules_json`（启动补列、幂等），形状同 §6.4；与映射同一事务写入。模板包覆盖导入（表头被覆盖）时清空。
- 模板包：条目带 `preprocessRowFilterRules`，开关在 `mappings` 中；勾选或有规则时写 v8（v8 为本分支新增、尚未发布，不另升版本；v3.2.18 及更早整包拒绝）。

### 7.5 生成

- 生成配置：勾选时下发规则；规则缺失或无效拒绝生成（`PREPROCESS_ROW_FILTER_MISSING`，提示在【规则设置】中设置）。
- 读表后、任何映射之前过滤：只保留命中规则的数据行（表头保留），之后的主映射、§6 根据字段值过滤账单、拆分/合并、合计行识别、各项提示统计都基于加工表；报错与行元数据中的行号仍为源文件物理行号。
- 字段（含比较字段）不在源文件表头：拒绝生成（`映射字段不存在`）。模板【更新】删掉规则字段时，失效引用列出「原始账单预处理 · 过滤规则 #N 第 M 个条件（比较字段）← 字段」；未勾选时标为未启用。§6 的规则同样列出比较字段。
- 行数可观测：明细结果带 `preprocessRowFilterStats { totalRows, keptRows }`；某文件读到数据行但没有一行命中时，生成后提示「以下文件经原始账单预处理过滤后没有账单行，请检查过滤规则」（不阻断生成）。
- 余额：余额只按保留的行计算与逐日校验；被过滤掉的行若影响了银行余额列，按既有的余额不一致提示处理，不做静默调整。
- 大账号识别的表头前区（`buildBigAccountRecognitionBasis`）读原始行，不受过滤影响。多账户分段文件按上一段最后一笔交易为界在下一段表头前找账号说明行：被过滤掉、但账单日期可识别的行仍算作上一段的交易（`droppedTransactionRowNumbers`），避免其中的本方账号被当成下一段的账号（对账专项审查补充）；BillDate 取特征值时按被过滤行自己的特征值判定日期（Codex 审查补充）。

### 7.6 验收

- 分组「原始账单预处理」在「个性化映射设置」上方；勾选「过滤账单」显示【规则设置】，弹窗标题「过滤规则设置」，运算含四个字段运算且值位置为字段下拉框。
- 规则随映射【保存】提交、【返回】不提交，重开回显；旧库启动补列，重复启动无副作用。
- 生成：只有命中规则的行出现在明细 / 余额中；规则缺失、字段缺失拒绝生成；全部被过滤时提示；模板包往返后规则与生成结果一致，用到时写 v8。
- §6 根据字段值过滤账单可用字段运算，命中口径按 P6。

### 7.7 非目标

- 不导出原始账单加工表文件；不提供命中 / 丢弃行明细预览。
- 不支持数值大小比较、正则或忽略大小写的匹配；字段运算不做数值换算。
- `statement-worker/session-state.js` 的映射路径（仅单测使用、生产未接入，且未下发特征值等配置）不接入预处理过滤。
