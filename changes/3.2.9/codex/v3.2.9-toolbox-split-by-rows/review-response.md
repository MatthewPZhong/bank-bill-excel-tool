## 1. 总体处理

采纳 review 的收敛方向：保留现有界面设计，仅增加预计文件数量；技术首版固定为“独立 rows 后台任务 → 保真任务私有缓存 → 单个活动 writer 顺序输出 → 全部校验后发布”。

v1 保留异步拉取/保真落盘两种可能，实施选择尚未完成；v1 A15 允许超过八份时“明确失败”，不足以证明九份可正常输出。这两处在 v2 改为明确路线与正向成功断言。

本轮只修改独立的 v2 文档，不覆盖 v1，不修改远端或本地项目代码。上述判断基于提供的文档和 review，不声称重新核查了最新仓库。

## 3. 在 review 基础上进一步补充的工程约束

以下 E1–E6 是本轮为了消除实施歧义新增的设计约束，不冒充 review 原文或用户原始需求。

| 编号 | 补充约束 | 目的与边界 |
|---|---|---|
| E1 | 缓存追加本身也不能使用未被等待的异步回调；在后台内同步追加或有界批次同步刷盘。 | 源 onDataRow 不 await 的约束没有因“改写缓存”自动消失；避免未完成写入和错误丢失。 |
| E2 | 缓存保存可独立解析的注册表/资源，而不只是样式编号；源关闭后做保真回放测试。 | 样式引用需要对应实体与生命周期保证；具体既有编码器能否满足仍需验证。 |
| E3 | 计划与公共结果大小在任务前预检，真实 manifest/结果在发布前再次校验。 | 避免文件已发布才发现结果传不回；完整文件列表不能被静默截断。 |
| E4 | 磁盘预算含缓存、全部生成文件、校验峰值、发布副本/备份，并按卷检查。 | 单 writer 只约束活动生成器，不代表只需容纳一份文件或内存恒定。 |
| E5 | 主进程在创建任务前完成 mode→action→policy 分派；后台和主进程校验任务身份/计划/结果。 | 仅增加 Worker op 不足以避免旧八分组合同或旧资源限制。 |
| E6 | 首版不做半缓存或第 j 份续生；发布中断只按既有恢复协议处理；回滚保留在途任务识别。 | 不将生成重试与发布恢复混为一谈，不在未恢复任务上盲目重复生成/覆盖。 |

## 4. 验收不能混淆的四组概念

**提交到 generation 与正式发布不同。** 每份 commitAndValidate 成功后文件仍在任务私有目录；第 j 份失败时 Publisher 调用数必须为 0。

**保护值与已验证容量不同。** 1000 是推荐的产品保护值。需要千份完整生成、校验、发布、结果返回及资源记录，才能在相应测试范围内标记通过。

**正向成功与安全失败不同。** 合法且满足资源预算的九份用例必须成功。资源超限时安全拒绝属于另一个失败用例，不能拿来替代九份正向验收。

**自动化回读与人工打开验收不同。** Windows 操作、Excel 打开与显示、WPS 打开与显示分别留记录；不能由“文件可以解析”推导为这些人工项通过。
