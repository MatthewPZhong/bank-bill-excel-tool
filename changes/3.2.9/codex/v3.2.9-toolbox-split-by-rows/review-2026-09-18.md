## Findings

### R01 · P1 · 覆盖确认期间新出现的文件会被未经确认覆盖

- 位置：`src/main-process/toolbox-row-split/service.js:46–51`；关联 `src/main.js:21045–21053`。
- 依据：Spec §6.3、A31；TechDoc §5.1 的目标检查及同名覆盖许可。
- 原因：预检只收集当时存在的目标。等待覆盖确认后没有冻结或复核此前的目标状态；后续 FilePlan 才采集快照，将期间新出现的文件作为既有可覆盖目标接收。

复现步骤：

1. 输入 2 行数据，每份 1 行，计划生成两个文件。
2. 输出目录中最初只有第 1 个同名目标存在。
3. 确认框只列出第 1 个目标；确认框打开期间，其他进程创建第 2 个同名目标。
4. 用户同意覆盖所列目标，继续按 Main 的顺序创建 FilePlan、生成并发布。

实测真实生成器及 Publisher worker 成功发布两份；`secondWasConfirmed=false`、`secondSnapshotExists=true`、`unconfirmedFileReplacedByXlsx=true`。第二个文件未经确认即被替换。该 probe 使用直接执行器适配 runtime，未启动完整业务 Main。

建议：将确认前所有目标的存在状态及身份绑定到后续 FilePlan；确认期间发生变化应拒绝或重新确认，不能在确认后重新采集并自动接受新目标。

复验要求：原本不存在的目标在确认期间出现，以及已存在目标在确认期间被替换，两种场景均不得未经再次确认覆盖；原有目标内容应保持不变。

证据：[覆盖竞态 probe](evidence/review-2026-09-18/overwrite-probe.js)。

### R02 · P2 · 多文件成功弹窗裁切结果及确认按钮

- 位置：`src/renderer-dialogs.js:12093–12096`。
- 依据：Spec §7.3、A19；TechDoc §4.3。
- 原因：rows 将全部文件明细和警告放入普通 `alert-card`；卡片限制高度且 `overflow:hidden`，内容区不可滚动，确认按钮随内容被推出可见区域。

使用真实 Electron、正式 `index.html` CSS 链及 renderer 工厂，在 1080×800 的 BrowserWindow（内容区高度 772px）注入 rows 成功结果，路径采用 `/Users/test/Downloads/流水明细_按行拆分_0001.xlsx` 形状：

| 文件数 | 实测表现 |
|---|---|
| 1 / 8 | 确认按钮可见 |
| 9 | 卡片底部 y=744，按钮 y=737–773，已部分裁切 |
| 30 | 按钮 y≈2202–2238，完全不可见 |
| 1000 | 按钮 y≈69859–69895，完全不可见 |

后续文件明细及末尾警告无法正常查看，30/1000 份时无法用鼠标点击可见的确认按钮返回。此复现使用 mock API 成功结果，未代替真实 Main 文件对话框验收。

建议：使用可滚动的结果内容区，并保持确认操作区可见；完整保留文件列表与警告，不用截断列表规避布局问题。

复验要求：1/8/9/30/1000 份、长文件路径及有警告场景都能查看末尾内容并正常确认返回。

证据：[几何结果](evidence/review-2026-09-18/ui-result.json)、[截图](evidence/review-2026-09-18/ui-1000.png)、[UI probe](evidence/review-2026-09-18/ui-probe.js)。

### R03 · P3 · 勾选后未聚焦行数输入框

- 位置：`src/renderer-dialogs.js:12363–12367`。
- 依据：Spec §4.1。
- 实测：复选框获取焦点后勾选，输入框虽已显示并启用，`document.activeElement` 仍为 `split-by-rows`。
- 建议：完成状态刷新后，在勾选状态调用行数输入框的 `focus()`。
- 复验要求：鼠标或键盘勾选后可立即输入数字；取消勾选时不聚焦已隐藏输入框。

### R04 · P3 · 三类输入错误提示未按 Spec 区分

- 位置：`src/renderer-dialogs.js:12145–12149`。
- 依据：Spec §5。

| 输入 | 当前提示 | Spec 要求 |
|---|---|---|
| 空白 | 请输入大于 0 的整数 | 请输入每份文件的数据行数 |
| `0` | 请输入大于 0 的安全整数 | 请输入大于 0 的整数 |
| 超出安全整数范围的纯数字 | 请输入大于 0 的安全整数 | 行数过大，请输入有效范围内的整数 |

这些输入均被拒绝，未发现因此放行非法拆分；缺陷是明确约定的提示语义未实现。建议分别处理空白、非正整数和超范围输入，并保留 `00010` 规范化行为。
