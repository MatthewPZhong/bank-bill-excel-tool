## 1. 勘误原因

冻结 baseline 的 `BatchOverlayTransitionV1` 四个 command 只携带 Batch/Task/source 字段，缺少 canonical `actionKey`、persisted legacy `expectedTaskKey` 与 `operationKey`。现有 Task/Batch 行只能权威证明 legacy task identity，不能推导 canonical action identity；但 recovery event DDL 又要求 `action_key / operation_key / task_run_id` 非空，因此 Batch event lineage 缺少可实现的权威来源。

同一 baseline 要求同 `eventId` 的相同 canonical request 返回已提交结果、不同 request 返回 `RECOVERY_EVENT_ID_CONFLICT`，但 event 表只持久 `event_id` 与展开后的 event 列，没有 transition/canonical request hash。共享 event type、不同 evidence 或不同 command 在进程重启后无法可靠区分。
