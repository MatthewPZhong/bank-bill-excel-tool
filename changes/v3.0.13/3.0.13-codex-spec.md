# bank-bill-excel-tool 3.0.13 Codex Spec

## 0. 背景

项目：`MatthewPZhong/bank-bill-excel-tool`

目标版本：`3.0.13`

本次迭代围绕四个用户需求：

1. 所有涉及“导入文件”的模块，点击导入后文件选择框默认进入上一次导入文件所在目录。
2. 网银账单生成模块中，大账号识别不到或识别到但未维护时，必须提示用户，不允许静默取大账号库里的其它账号。
3. 导入中台调拨单后生成调拨对账单时，仅对 `调拨状态 = 付款成功` 的行派生调拨对账单。
4. 银行对账单处理结果表去掉单独的 `异常-人工处理` / `异常-人工判断` sheet，将其 `异常说明` 列移到 `命中场景` sheet 的 `命中明细` 列右侧。

---

## 1. 通用约束

### 1.1 不允许破坏的行为

- 不改变既有 IPC 名称，除非新增 helper IPC；renderer 现有调用应保持兼容。
- 不改变现有导入文件格式识别规则，只给 open dialog 增加 `defaultPath`。
- 不改变银行对账单处理核心回填逻辑、场景命中逻辑、金额匹配逻辑。
- 不改变调拨对账单字段映射，只增加状态过滤。
- 不把 `_rowId`、`_modifiedColumns` 等内部字段写入 Excel 用户可见列。

### 1.2 资金红线

本项目多处逻辑属于资金对账链路。以下改动必须最小化：

- Req2 只能修复“大账号识别/选择”误兜底，不要重写账单生成主流程。
- Req3 只在 `mid-allocation -> fund-transfer-recon` 派生入口过滤 `调拨状态`，不要在下游匹配引擎二次过滤造成口径漂移。
- Req4 只改变 Excel 输出布局，不改变 `manyToManyRows` 的检测器产物和银行行本身。

## 2. Req1：导入文件默认进入上一次导入目录

### 2.1 需求

所有业务导入入口，只要用户打开文件选择框，第二次再点击同类导入时，应默认进入上一次选择的文件所在目录。

取消选择时不更新目录；选择文件后，即使后续业务校验失败，也更新为用户刚选择文件的目录。

多文件选择时，以 `filePaths[0]` 所在目录为准。

如果上一次目录不存在或不可访问，静默回退到 Electron 默认目录，不弹错。

### 2.2 涉及入口

Codex 需要 grep 全仓：

```bash
grep -R "showOpenDialog" -n src
```

并至少覆盖以下 preload 暴露的业务导入入口：

- `desktopApi.bankStatement.import()`
- `desktopApi.bankStatement.batchImport()`
- `desktopApi.bankStatement.importGatewayRecon()`
- `desktopApi.linkedTable.import()`
- `desktopApi.files.importFile(templateId)`
- `desktopApi.templates.importTemplate()`
- `desktopApi.templates.importBundle()`
- `desktopApi.bigAccount.importBankInfo(templateId)`
- `desktopApi.pending.pickFiles()`

### 2.3 推荐实现

在 `src/backend/database/settings-repository.js` 增加轻量 helper，复用现有 `app_settings` 表，无需新增迁移：

```js
const LAST_IMPORT_DIRECTORY_GLOBAL_KEY = 'last_import_directory';
const LAST_IMPORT_DIRECTORY_PREFIX = 'last_import_directory:';

function buildLastImportDirectoryKey(scope) {
  const s = String(scope || '').trim();
  return s ? `${LAST_IMPORT_DIRECTORY_PREFIX}${s}` : LAST_IMPORT_DIRECTORY_GLOBAL_KEY;
}

function getLastImportDirectory(db, scope = '') {
  const scoped = getSetting(db, buildLastImportDirectoryKey(scope));
  if (scoped) return scoped;
  return getSetting(db, LAST_IMPORT_DIRECTORY_GLOBAL_KEY);
}

function setLastImportDirectory(db, scope, directory) {
  const dir = String(directory || '').trim();
  if (!dir) return;
  if (scope) setSetting(db, buildLastImportDirectoryKey(scope), dir);
  setSetting(db, LAST_IMPORT_DIRECTORY_GLOBAL_KEY, dir);
}
```

导出这些 helper。

在 main 进程新增本地 helper，位置可放在 `src/main.js` 或抽到 `src/main-process/import-dialog-state.js`：

```js
function resolveExistingDirectory(dir) {
  if (!dir) return undefined;
  try {
    const resolved = path.resolve(dir);
    return fs.existsSync(resolved) && fs.statSync(resolved).isDirectory()
      ? resolved
      : undefined;
  } catch (_) {
    return undefined;
  }
}

function getImportDialogDefaultPath(scope) {
  return resolveExistingDirectory(settingsRepository.getLastImportDirectory(database.db, scope));
}

function rememberImportDialogDirectory(scope, filePaths) {
  const first = Array.isArray(filePaths) ? filePaths[0] : filePaths;
  if (!first) return;
  settingsRepository.setLastImportDirectory(database.db, scope, path.dirname(first));
}

async function showImportOpenDialog(scope, options) {
  const defaultPath = getImportDialogDefaultPath(scope);
  const result = await dialog.showOpenDialog(mainWindow, {
    ...options,
    ...(defaultPath ? { defaultPath } : {})
  });
  if (!result.canceled && Array.isArray(result.filePaths) && result.filePaths.length > 0) {
    rememberImportDialogDirectory(scope, result.filePaths);
  }
  return result;
}
```

然后把现有 `dialog.showOpenDialog(...)` 替换为 `showImportOpenDialog(scope, options)`。

推荐 scope：

- `statement-generator`
- `bank-statement-process`
- `linked-table`
- `pending-reconciliation`
- `bank-bu-recon`
- `biz-op-recon`
- `vcc-op-calc`
- `acquiring-bill-currency`
- `toolbox`
- `template`
- `big-account`

### 2.4 测试

1. 首次导入无 `defaultPath`。
2. 选择 `/tmp/a/file.xlsx` 后，再次导入同 scope，`showOpenDialog` 收到 `defaultPath=/tmp/a`。

## 3. Req2：网银账单生成大账号识别失败时禁止误取其它账号

### 3.1 问题

当前大账号识别链路在以下场景可能静默误选：

- 文件中识别不到大账号；
- 识别到大账号，但该大账号未在当前模板的大账号库维护；
- 识别结果为空或不唯一，却被后续逻辑兜底成大账号库里的其它账号。

用户要求：无法识别或未维护时必须提示，不允许用错账号继续生成。

### 3.2 Codex 定位指令

先 grep 以下关键词，定位实际自动识别/自动选择分支：

```bash
grep -R "__MULTI_BIG_ACCOUNT__\|selectedBigAccount\|completeBigAccountSelection\|extractBigAccountOrder\|allowManagedMerchantWithoutSelection\|template_big_accounts\|getWithOwn\|groupBigAccountRows" -n src tests
```

重点关注：

- `src/main.js`
- `src/main-process/statement-generation.js`
- `src/backend/file-service.js`
- `src/main-process/statement-session.js`
- `src/backend/database/template-repository.js`
- `src/backend/database/utils.js`
- 相关 renderer 大账号选择弹窗逻辑

### 3.3 行为规则

新增纯函数，建议命名：

```js
resolveRecognizedBigAccount({
  extractedMerchantId,
  extractedCurrency,
  maintainedBigAccounts,
  sourceFileName
})
```

返回：

```js
{ status: 'ok', selectedBigAccount }
{ status: 'needs-selection', candidates, message }
{ status: 'failed', code, message, detailLines }
```

规则：

1. `extractedMerchantId` 归一化后为空：
   - 返回 `failed`。
   - code: `BIG_ACCOUNT_NOT_RECOGNIZED`。
   - 文案：`未识别到大账号，请检查导入文件或先在“维护大账号”中维护后重新导入。`
   - 不允许 fallback 到 `maintainedBigAccounts[0]`。

2. `extractedMerchantId` 非空，但维护表无同 merchantId：
   - 返回 `failed`。
   - code: `BIG_ACCOUNT_NOT_MAINTAINED`。
   - 文案：`识别到大账号「${id}」，但当前模板的大账号库未维护该账号，请先维护后重新导入。`
   - detailLines 包含文件名、识别值、模板名。

3. 同 merchantId 只有一个维护项：
   - 返回 `ok`，使用该维护项。

4. 同 merchantId 有多个币种：
   - 若 `extractedCurrency` 非空且能唯一匹配币种，返回 `ok`。
   - 若币种无法唯一确定，返回 `needs-selection`，复用现有大账号选择弹窗，让用户选。
   - 不允许自动取第一个。

5. 用户已经在弹窗显式选择 `selectedBigAccount` 时：
   - 保持既有逻辑，不要再次错误拦截。
   - 但可以校验所选项仍存在于当前模板维护列表；不存在则提示重新选择。

### 3.4 接入点

在“自动识别并准备生成文件”的路径中，在调用 `prepareGeneratedFiles` / `generateStatementFiles` 前执行上述校验。

不要在 `buildMappedRows` 中简单拒绝所有未映射 `MerchantId`，因为普通账号映射流程仍可能允许原值透传。本需求只针对“维护大账号 / 自动识别大账号”的误兜底路径。

错误返回应走现有用户侧错误体系，至少包含：

- `status: 'failed'` 或项目当前错误结果约定；
- `step: '识别大账号'`；
- `errorCode: 'BIG_ACCOUNT_NOT_RECOGNIZED' | 'BIG_ACCOUNT_NOT_MAINTAINED'`；
- `message` 用户可读；
- 状态框可见；
- 如项目当前错误报告机制会生成 txt，则继续生成。

### 3.5 测试

新增大账号识别单测：

1. 维护表有 `B002/USD`，文件识别为空：返回失败，不生成文件。
2. 维护表有 `B002/USD`，文件识别为 `A001`：返回失败，不选择 `B002`。
3. 维护表有 `A001/USD`，识别为 `A001`：成功选择 `A001/USD`。
4. 维护表有 `A001/USD`、`A001/EUR`，识别账号为 `A001` 但币种未知：返回 `needs-selection`。
5. 维护表有 `A001/USD`、`A001/EUR`，识别账号 `A001` 且币种 `USD`：成功选择 USD。
6. 用户显式选择 `A001/EUR` 后重新生成：不被识别失败逻辑拦截。

## 5. Req4：银行对账单处理结果去掉异常 sheet，异常说明并入命中场景

### 5.1 当前代码事实

当前 `writeBankStatementOutput` 输出：

- `未命中场景` sheet；
- `命中场景` sheet，第一列为 `命中明细`；
- 如果 `manyToManyRows` 非空，会追加 `异常-人工判断` sheet，表头为 `[异常说明, ...BANK_STATEMENT_FIELDS]`。

用户说的 `异常-人工处理` 与代码当前 `异常-人工判断` 语义相同。本次验收中，两个名称都不应再出现在输出工作簿中。

### 5.2 修改方案

修改 `src/main-process/exceljs-writer.js`。

保留：

```js
const MANY_TO_MANY_NOTE_HEADER = '异常说明';
```

可删除或停止使用：

```js
const SHEET_MANY_TO_MANY_NAME = '异常-人工判断';
function appendManyToManyReviewSheet(...) { ... }
```

在 `writeBankStatementOutput(rows, headers, savePath, unmatchedRows, modifications, paymentOfflinePairs, staleHitNotesByRowId, manyToManyRows)` 中构造 `noteByRowId`：

```js
function buildManyToManyNoteByRowId(manyToManyRows) {
  const map = new Map();
  if (!Array.isArray(manyToManyRows)) return map;
  for (const rv of manyToManyRows) {
    const row = rv && rv.row;
    if (!row) continue;
    const key = row._rowId;
    if (key === undefined || key === null) continue;
    const note = cellToString(rv.note);
    if (!note) continue;
    const prev = map.get(key);
    map.set(key, prev ? `${prev}; ${note}` : note);
  }
  return map;
}
```

命中 sheet 表头从：

```js
const hitHeaders = [HIT_DETAIL_HEADER, ...headers];
```

改为：

```js
const hitHeaders = [HIT_DETAIL_HEADER, MANY_TO_MANY_NOTE_HEADER, ...headers];
```

每行从：

```js
const cells = [detail, ...headers.map((h) => row[h])];
```

改为：

```js
const abnormalNote = manyToManyNoteByRowId.get(row._rowId) || '';
const cells = [detail, abnormalNote, ...headers.map((h) => row[h])];
```

对齐：

```js
r.getCell(1).alignment = { wrapText: false, vertical: 'top' };
r.getCell(2).alignment = { wrapText: false, vertical: 'top' };
```

标黄列偏移从：

```js
r.getCell(colIdx + 2).fill = YELLOW_FILL;
```

改为：

```js
r.getCell(colIdx + 3).fill = YELLOW_FILL;
```

删除这段追加 sheet 的逻辑：

```js
if (Array.isArray(manyToManyRows) && manyToManyRows.length > 0) {
  appendManyToManyReviewSheet(workbook, manyToManyRows);
}
```

Payment 线下调拨核对 3 个 sheet 保持不变；它们仍在命中/未命中 sheet 后追加。

### 5.3 注意事项

- `异常说明` 只对命中场景 sheet 中已有的命中行填值。
- 如果某条 `manyToManyRows` 指向的银行行不在 `rows` 命中行中，不新增额外银行行，避免改变命中行数。
- `命中明细` 的格式和内容不变。
- `异常说明` 空值时保留空列。
- 旧的独立异常 sheet 不再输出。

### 5.4 测试

更新 `exceljs-writer` 单测：

1. `manyToManyRows` 非空时，工作簿不包含 `异常-人工判断` / `异常-人工处理`。
2. `命中场景` sheet 表头第 1 列是 `命中明细`，第 2 列是 `异常说明`，第 3 列开始是原银行表头。
3. 命中行 `_rowId` 匹配 `manyToManyRows[].row._rowId` 时，第 2 列写入 note。
4. 未匹配 note 的命中行第 2 列为空。
5. 被修改字段标黄仍落在正确原字段列，不能错位。
6. Payment 线下调拨核对 3 个 sheet 仍按原逻辑输出。

## 9. 验收标准

1. 任意业务导入入口首次选择某目录文件后，再点同入口导入，文件框默认打开该目录。
2. 取消导入不会覆盖记忆目录。
3. 大账号识别不到时，网银账单生成不会继续生成，不会使用其它维护账号，并显示明确提示。
4. 识别到未维护大账号时，不会使用其它维护账号，并提示用户先维护。
5. 中台调拨单只有 `调拨状态=付款成功` 的源行会派生调拨对账单；每条成功源行仍生成 in/out 两行。
