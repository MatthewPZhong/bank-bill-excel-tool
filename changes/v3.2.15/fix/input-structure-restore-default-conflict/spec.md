## 1. 背景

设置 → 模板文件可以给输入原表导入新版本并启用，也可以【恢复默认】切回内置 V1。同组的表（平盘 5 张链接原始表、银行账单处理 4 张链接表、VCC 财务OP 5 张原表）导入时只靠表头区分来源，所以同组两张表的当前结构不能完全相同。v3.2.14 在导入新版本和启用版本时核对这一点，恢复默认不核对。

审查发现的操作顺序：

1. VCC 充值清退明细启用一个末尾多一列的版本；
2. VCC 费用及换汇明细启用一个与充值清退明细内置表头完全相同的版本（此时充值清退明细的当前版本是第 1 步的版本，核对能通过）；
3. 充值清退明细恢复默认。

之后两张表的当前结构完全相同。VCC 导入的识别器 `classifyHeaderRow` 用 `rules.find()` 取第一个完全匹配，费用及换汇明细的文件会被静默识别为充值清退明细，进入另一套计算分支，属于资金口径风险。

## 2. 已确认决策

| 编号 | 决策 | 来源 |
| --- | --- | --- |
| D1 | 恢复默认会造成同组结构相同时，阻止并提示，用户先调整对方表的当前版本 | 用户，2026-11-05 |
| D2 | VCC 识别器遇到多个完全匹配时拒绝并列出候选，不静默取第一项 | B42 关闭条件 |
| D3 | 核实另外两组识别器遇多重命中时的行为，静默取第一项的同样拒绝 | B42 关闭条件 |

## 3. 功能规则

### 3.1 恢复默认

- 当前版本是用户版本、切回 V1 时，用该表内置结构第 1 个工作表的表头，与同组其他表的当前结构（以及该表的固定对照签名）比较，规则与“启用”相同。
- 有相同的：不切换，返回失败，提示“V1 不能恢复：与「X」当前结构相同，导入时无法区分，请先调整「X」的当前版本”。设置页确认框显示该提示，当前版本不变，不写变更记录。
- “启用后会缺少已被场景使用的取值”的检查仍不适用于恢复默认。
- 当前已经是 V1 时不核对（恢复默认按钮本就不可用；直接调用时按原逻辑返回未变化）。

### 3.2 VCC 来源识别

- 一行表头与多张原表的当前结构都完全相同时，该 Sheet 判为结构错误：错误码 `vcc-sheet-header-ambiguous`，不给出来源类型。
  - 提示：“表头与「A」、「B」的当前结构完全相同，无法确定来源；请在 设置 → 模板文件 调整其中一张表的当前版本”。
  - 明细逐行列出每个候选是内置结构还是当前版本几。
- 与其他结构错误相同：整个导入计划不能提交，不入库。
- 只有一个完全匹配时行为不变。内置五类原表的表头两两不同，全部内置时不会触发。

### 3.3 其他同组识别器（核实结论，不改代码）

| 组 | 识别入口 | 多个完全匹配时 |
| --- | --- | --- |
| 平盘链接原始表 | `position-reconciliation/readers.js` `detectSourceSheet`；导入 Worker `xlsx-reader.js`、`xls-reader.js` `locatePositionBusinessSheet` | 收集全部匹配，超过一个抛 `position-source-ambiguous` |
| 银行账单处理链接表 | `table-type-detector.js`（同一 sheet 多签名精确命中 → `ambiguous`）；`main.js` 导入入口 | 返回 `ambiguous`，提示“表头同时命中多张链接表，无法唯一判定” |

另外按各表必用列核算：在现有内置结构下，只有 VCC 充值清退明细与费用及换汇明细这一对能走到“恢复默认后结构相同”（一方的必用列都包含在另一方的内置表头里）；另外两组受必用列限制走不到。3.1 的核对对三组通用。

## 4. 非目标

- 不检测、不修正 v3.2.14 期间已形成的相同结构状态；该状态下导入由 3.2 拒绝，用户按提示调整。
- 不回溯已导入的数据。若用户在 v3.2.14 按第 1 节顺序操作后导入过费用及换汇明细，其分类与计算结果须人工复核（见 PR #246 待办）。

## 5. 验收标准

- 按第 1 节顺序操作，第 3 步被阻止并显示提示，两张表当前版本不变；对方先恢复默认后，本表可以恢复默认。
- 第 2 步之后，按充值清退内置表头导出的文件唯一识别为费用及换汇明细。
- 两张表当前结构相同的状态下，该文件预检为结构错误、不给出来源类型，提交计划报 `vcc-sheet-header-ambiguous`，不入库。
- 全部内置时，五类原表各自正常识别。

## 6. 数据与资金影响

- 不改表结构、不改迁移、不改金额计算。
- 来源识别从“静默取第一项”改为“拒绝”：消除一类把费用及换汇明细计入充值清退的错误分类，代价是这种配置下需要用户先调整模板版本。
- ⚠️ 资金口径：v3.2.14 期间可能已有的错误分类须人工复核（第 4 节）。
