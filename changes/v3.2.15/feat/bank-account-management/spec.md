## 1. 背景

用户需求（2026-11-05）：

> 网银账单生成模板和平盘对账处理模板都会涉及银行账户的管理，做一个统一管理的页面，之后其他功能模块要用到银行账户时就来这里调用。
>
> 设置新增栏「账户管理」：页面左上角显示“清结算系统账户管理”，右侧有渠道及单选下拉框，渠道默认值为空白，渠道为空白时页面显示所有账户信息。页面左下角有按钮【导入银行账户信息】，其右侧有按钮【导出】，点击【导出】可另存为当前的银行账户表原表。

## 4. 功能规则

### 4.1 页面

- 设置弹窗左栏新增「账户管理」，位于「模板文件」之后、「外观设置」之前。
- 顶部一行：左侧标题“清结算系统账户管理”，右侧“渠道”及单选下拉框。下拉第一项为空白（默认），其后为当前账户表 `银行/通道简称` 的去重非空值。
- 标题下方显示当前账户表概况：原文件名、账户行数、导入时间、识别结构版本。未导入时显示“尚未导入银行账户信息”。
- 表格列为导入时结构的全部列，横向滚动；每页 200 行，翻页。渠道为空白时显示全部行；选中渠道时只显示该渠道的行。`银行/通道简称` 为空的行只在空白（全部）时显示。
- 左下角【导入银行账户信息】，其右侧【导出】。未导入时【导出】不可用。确认写入期间确认框与设置弹窗都不能关闭；预检期间关闭设置弹窗时，迟到的预检结果被丢弃。

### 4.2 导入

1. 选择一个 `.xlsx` / `.xls` 文件（单选，导入目录按 `bank-accounts` 单独记忆）。
2. 预检：
   - 文件不超过 20 MiB。
   - 表头识别结构取「设置 → 模板文件 → 清结算银行账户表」当前版本（与平盘共用）。当前版本不可用时中止，提示恢复默认或重新导入。
   - 逐个工作表比较第 1 行表头（去首尾空格、去掉末尾空列），与当前结构完全一致的工作表必须恰好一个。没有一致的：失败，列出与当前结构的逐列差异，并提示到「设置 → 模板文件」导入新版本；多个一致：失败，列出这些工作表。
   - 当前结构必须包含 `银行/通道简称`。
   - 全部非空数据行入库（含注销、非正常、不参与对账的行）；没有数据行时失败，已有账户表不变。
3. 预检通过后确认：“清结算银行账户表将整份替换：X 行 → Y 行（N 个渠道）”。取消则丢弃本次预检。
4. 确认后写入：先把原文件写入 `{userData}/bank-accounts/`，再在一个事务内替换主库中的账户表元数据与全部账户行，最后删除旧原文件。任一步失败时旧账户表保持不变。
5. 预检之后账户表已被替换（如另一窗口已导入）：确认时提示已变化，需重新导入。

### 4.3 导出

- 另存为最近一次导入的原文件，文件名默认为导入时的原文件名，扩展名不变。
- 保存前核对原文件的 SHA-256；不一致或缺失时提示重新导入，不导出。
- 不允许覆盖账户管理自己保存的原文件；先写同目录临时文件再替换，失败时不截断已有文件。

### 4.4 对外只读接口

账户管理服务向主进程其他模块提供只读查询（本期无调用方）：

- `getSnapshotMeta()`：当前账户表元数据（文件名、行数、表头、导入时间、结构版本），未导入时为 `null`。
- `listAccounts({ channel })`：按表头组成的账户行对象，可按 `银行/通道简称` 筛选。

各模块接入时自行决定筛选口径（如维护大账号的“正常 + 参与对账”、平盘的“正常”），并在各自 spec 中定义。

### 4.5 模板文件

- 「清结算银行账户表」的使用模块增加「账户管理 · 导入识别结构」，与平盘共用一份结构。
- 该结构的必用列增加 `银行/通道简称`（平盘自身读取的必用列不变）。导入不含此列的新版本时，模板文件预检不通过。

## 5. 非目标

- 不改维护大账号、平盘的导入与筛选口径，不把它们切换为读取账户管理。
- 不做按渠道合并导入、账户的手工增删改、历史版本。
- 不做账户管理与网银“渠道”、对账模块 `channels` 表的对应。
- 不把账户管理的导入登记到存档中心：原文件由账户管理自己保存并可另存（与模板文件导入一致）。

| A4 | 账户表属于“轻量、长期、稳态”的主数据，存主库（不属于 run 级批量数据）；原文件存 `{userData}/bank-accounts/<sha256>.<扩展名>` |

## 7. 验收标准

- 设置弹窗出现「账户管理」栏，位置、标题、渠道下拉、左下两个按钮符合 §4.1。
- 导入与当前结构一致的账户表：确认后表格显示全部行；渠道下拉列出去重值，选中后只显示该渠道的行，切回空白显示全部。
- 表头不一致、多个工作表一致、无数据行、文件超限、结构不可用：导入失败并给出原因，已有账户表不变。
- 再次导入：确认文案显示新旧行数，确认后整份替换；取消时不变。
- 【导出】另存的文件与最近一次导入的原文件字节一致；未导入时不可用；原文件被改动时拒绝导出。
- 重启应用后账户表、渠道列表与导出仍可用；迁移重复执行无变化。
- 模板文件中「清结算银行账户表」的使用模块含账户管理；导入缺 `银行/通道简称` 的新版本时预检不通过。
- 维护大账号、平盘的导入行为与 v3.2.14 一致。

## 8. 数据与兼容影响

- 新增主库表 `bank_account_snapshot`、`bank_account_rows`，仅新增，幂等；回退到 v3.2.14 时这两张表与 `{userData}/bank-accounts/` 被忽略，不影响其他功能。
- 本期不改变任何金额、匹配、余额或导出口径，不触发对账专项审查；后续模块接入时按各自 spec 审查。

### 9.2 偏离与说明

- 解析在主进程用 SheetJS 同步完成（与维护大账号导入一致），文件上限 20 MiB；接近上限的文件解析期间界面可能短暂无响应。账户表通常远小于此，暂不放入 Worker。
- 平盘与账户管理共用一份识别结构；由于平盘对表头也要求完全一致，两者对同一份文件的识别结果相同。
- 确认写入失败（预检失效、账户表已变化、保存或写库失败）时，后端已消耗本次预检，确认框关闭并提示重新导入，不在原框内重试。
