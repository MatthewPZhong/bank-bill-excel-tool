# Spec — v3.2.15 更新说明：按“上一个版本 → 当前版本”显示并分页

> status: in-progress
> created: 2026-11-05
> updated: 2026-11-05
> 目标版本：v3.2.15
> 适用分支：`feat/release-notes-range`
> 分支创建基线：`v3.2.14` 正式标签 → `245bae04`
> 前序规格：[v3.2.14 升级后首次启动弹出更新说明](../../../v3.2.14/feat/release-notes-on-upgrade/spec.md)。本文取代其中 4.1 第 1 条的老用户基线、4.2 第 6 条与 D3 的设置入口范围、第 5 节“不推断本功能上线前的实际旧版本”；其余规则不变。

## 1. 背景

用户反馈（2026-11-05）：从 3.2.12 升级到 3.2.14 后，重启软件显示的更新说明只有 3.2.14，缺了 3.2.13。

用户需求（2026-11-05）：设置里的版本更新按钮，点击后弹出的页面需显示用户上一个版本到最新版本的更新内容；内容过多时，页面下侧新增【上一页】【下一页】按钮。

## 2. 代码现状（基线 `v3.2.14` / `245bae04`）

| 位置 | 当前行为 | 与本次的关系 |
| --- | --- | --- |
| `src/main-process/release-notes/service.js` `resolveStartupReleaseNotes` | 主库已存在但没有确认记录（v3.2.14 之前的版本）时，以 `LEGACY_BASELINE_VERSION = 3.2.13` 为基线，取 (3.2.13, 当前]，3.2.13 本身不显示 | 3.2.12 升到 3.2.14 只看到 3.2.14 的原因；改为从 3.2.13（含）起 |
| `app_settings.release_notes_acknowledged_version` | 只记录已确认到的版本，不记录升级前的版本 | 新增“最近一次升级”记录 |
| 设置「版本管理」【查看本版更新说明】（`app-settings.js` → `ui.openReleaseNotes` → `openCurrentReleaseNotes`） | 只显示当前版本一条 | 改为显示最近一次升级的区间 |
| 更新说明弹窗（`src/renderer/dialogs/release-notes.js`） | 全部版本在正文里依次排列，过长时滚动 | 改为分页 |

| 编号 | 决策 |

## 4. 功能规则

### 4.1 版本记录

- 保留 `release_notes_acknowledged_version`，含义不变。
- `app_settings` 新键 `release_notes_last_upgrade`，值为 JSON `{ "fromVersion": "X.Y.Z" | null, "toVersion": "X.Y.Z" }`，表示最近一次升级：从哪个版本升到哪个版本。`fromVersion` 为 `null` 表示从 v3.2.14 之前的版本升级上来、具体版本未知。
- 两个键在同一事务内写入：
  - 用户确认启动弹窗时，写入确认版本和本次升级区间；
  - 升级区间内没有说明条目、启动时直接确认的，同样写入本次升级区间。
- 全新安装只写确认版本，不写升级记录。降级、同版本重启都不改记录。
- 读取时校验：两个版本号都须是正式版本号，且 `fromVersion` 低于 `toVersion`；不合格时视为没有记录。

### 4.2 启动判定（取代前序 4.1 第 1 条中老用户的基线）

| 情形 | 待显示区间 | 首行文字 | 确认后写入的升级记录 |
| --- | --- | --- | --- |
| 有确认记录 R，当前版本 C 高于 R | (R, C] | 已从 vR 更新到 vC | `{ R, C }` |
| 没有确认记录，主库已存在（v3.2.14 之前的版本升级） | [3.2.13, C] | 已更新到 vC | `{ null, C }` |
| 全新安装、同版本、降级、开发版 / 预发布号 | 不弹，规则同前序 | — | 不写 |

区间内没有说明条目时不弹，直接写入确认版本和升级记录。

### 4.3 设置入口（取代前序 4.2 第 6 条）

- 按钮文字改为【查看更新说明】，在设置之上打开同款弹窗，不改变确认记录。
- 显示内容按以下顺序确定：
  1. 本次启动有待显示的更新说明（尚未确认）：显示同一区间。
  2. 升级记录的 `toVersion` 等于当前版本：`fromVersion` 有值时显示 (fromVersion, C]，首行“已从 vX 更新到 vC”；为 `null` 时显示 [3.2.13, C]，首行“已更新到 vC”。
  3. 其他情况（全新安装、降级后、记录无效）：只显示当前版本，首行“当前版本 vC”。
- 没有可显示的条目时显示“本版暂无更新说明”，不显示首行。

### 4.4 分页（启动弹窗与设置入口相同）

- 每页 1 个版本，第 1 页是最新版本，依次往旧翻。
- 只有 1 个版本时不显示翻页控件。2 个及以上时，底部左侧显示【上一页】“第 i/n 页”【下一页】，右侧保留【知道了】；在第 1 页时【上一页】置灰，在最后一页时【下一页】置灰。翻页后正文回到顶部。
- 翻页不算确认。【知道了】、×、Esc 的确认规则和点击背景不关闭的规则不变。

## 5. 非目标

- 不补写 3.2.13 之前版本的说明（D3）；从更早版本升级的用户，区间内没有条目的版本不显示。
- 不从活动日志等来源推断老用户的实际旧版本（D2 已确定按 3.2.13 起显示）。
- 已在 v3.2.14 确认过说明的用户，确认时 v3.2.14 不记录升级来源，本版不补回；他们升级到 v3.2.15 后按 4.2 第一行处理。
- 不新增 IPC：数据仍随 `app:get-info` 的 `releaseNotes` 下发。

## 6. 验收标准

- 3.2.12 的老用户（主库已存在、没有确认记录）升级到 3.2.15：弹出 3.2.15、3.2.14、3.2.13 三页，首行“已更新到 v3.2.15”；确认后写入 `{ null, 3.2.15 }`，设置入口显示同样三页。
- 记录 3.2.14 的用户升级到 3.2.16：弹出 (3.2.14, 3.2.16]，确认后写入 `{ 3.2.14, 3.2.16 }`；重启不再弹，设置入口仍显示这一区间。
- 全新安装：不弹，设置入口只显示当前版本。
- 降级：不弹，不改记录；设置入口只显示当前版本。
- 升级记录损坏或不合格：按没有记录处理，不报错。
- 翻页：按钮置灰、页码、单个版本不显示翻页控件、翻页不确认，均符合 4.4。
- 设置入口打开、翻页、关闭都不改变确认记录。

## 7. 数据与兼容影响

- 只新增一个 `app_settings` 键，不新增表、不改迁移；不涉及账单、对账、金额或币种。
- 降级到 v3.2.14 时旧代码不读新键；再升级回来时按确认记录判断，新键仍可用于设置入口。
