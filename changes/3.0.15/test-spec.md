# 3.0.15 Test Spec — 重复入金匹配

> status: implementation merged via PR #88; human release gates pending
> created: 2026-07-14
> source of truth: `changes/3.0.15/spec.md`（AC-01 ～ AC-27）
> release gate: 自动化完整通过 + 资金人工复核签字

## 1. 测试目标

- 核心业务逻辑：锁定银行 46 列 + 单据 26 列双文件、BizId、精确金额、七元组、严格 1+2、全月份 MPT 唯一匹配、单据唯一匹配、身份字段一致和两 sheet 映射。
- 边界条件：空值、空格、大小写、高精度金额、负零、长数字、0/多候选、同 ID、跨组复用、纯 Inbound、忽略 FundType、零结果及 Excel 上限。
- 错误路径：导入硬失败、方向金额非法、MPT 原始结构损坏、侧库/快照异常、写盘失败、用户取消及进程重启。
- 回归范围：标准银行 reader、MPT INBOUND 持久批次、前置资金对账、模块开关、数据库迁移、发布导出和既有 smoke。
- 守恒目标：每条相关银行行恰有一种 disposition；每条自动使用的 MPT 候选全局唯一且可追溯。

## 2. 测试分层

- 单元测试：金额与文本规范化、BizId 校验、结构化分组键、分组计数、MPT 候选集合、全局复用图、身份一致、原因顺序、守恒、writer 映射、store/repository 生命周期。
- 集成测试：银行+单据双文件原子导入 → 当前周期侧库 → 全月份 MPT 查询 → 运行快照 → 两 sheet 导出；覆盖 MPT 批次替换/删除与启动清理。
- E2E / smoke：Electron IPC、按钮 enable/disable、进度、另存为取消/成功、模块默认关闭和前置资金对账回归。
- 手工验证：Windows Excel/WPS 视觉、真实脱敏多月份数据性能、全月份边界、资金血缘与结果抽样。

## 5. 不测项与原因

- `MPT_CHANNEL_OTHERS`：3.0.16 范围；本版仅测仍被拒绝及提示版本正确。
- 临时银行对账单：3.0.16 范围；本版没有对应输入/状态。
- 缺渠道账单：3.0.16 范围；本版只回归现有“缺网关账单”。
- 自动发送邮件：未实现；只验证邮件模板 sheet。
- 多文件银行合并和非标准表头兼容：明确非目标，测试应验证拒绝而非兼容。
- 生产真实敏感数据进入自动化 fixture：出于隐私不使用；由业务方在受控环境以脱敏真实样本人工复核。

## 6. 执行顺序

1. 先写金额、分组、全局复用、BizId、MPT 查询和 writer 的失败用例（Red）。
2. 实现最小纯算法切片，使 P0-08 ～ P0-34 逐组 Green。
3. 实现侧库、run mirror、启动清理和 snapshot，使 P0-02/07/37 ～ P0-42 Green。
4. 接通 IPC/UI 和原子导出，使 P0-01/35、P1-01/05/06/08 Green。
5. 跑既有前置资金对账、数据库和文件读取回归。
6. 跑完整 unit → integration → smoke → release-check；不得只以 focused tests 作为完成证据。
7. 执行真实规模性能/视觉探针，记录结果和阈值。
8. 由资金业务负责人完成 §8 人工复核并签字，最后才允许发布。
