## 1. Goal / Context / Constraints / Done when

- Goal：C2「银行对账单赋值自身」支持等于、包含；提取大账号顺序时发现明确识别但未维护的大账号，提醒后结束整批导入。
- Context：C2 对账字段目前仅相等；账户映射已经识别出的账号可能在维护列表匹配阶段丢失为 null。
- Constraints：包含方向为左侧包含右侧；新增账号阻断只在点击【提取大账号顺序】时触发；手动选择、完全未识别提示、多币种提示和历史生成结果保留。
- Done when：配置、执行、确认详情一致；旧配置默认操作符及比较方式兼容，命中结果变化边界明确；全批检查不漏已绑定或空分段；确认后旧导入上下文失效且本批无生成；自动化检查与人工验收状态分别记录。

## 2. 对账字段操作符

作用域限定 `category=offset-bill-mark`。每条对账字段显示：左侧账单类型、左侧字段、单选操作符、右侧账单类型、右侧字段。

| 项目 | 规则 |
| --- | --- |
| 枚举 | 等于、包含 |
| 新行及旧配置缺省值 | 等于 |
| 多条字段 | AND，全满足才配对 |
| 每条字段的取值方向 | 依据该条自身的 leftType / rightType 选择当前配对中的行；同一类型对可正反向混用 |
| 等于 | 保持既有字符串／金额数值比较 |
| 包含 | 两侧按现有单元格规范化转字符串、去首尾空白；区分大小写；左侧包含右侧 |
| 包含空值 | 任一侧为空不命中；0 不是空 |
| 包含方式 | 字面子串；完整相等也命中；不使用正则、数值换算或反向包含 |

示例：`ABC123 包含 123` 命中；`123 包含 ABC123`、`ABC123 包含 abc`、任意值包含空均不命中。

例如第一条为「类型 1.Currency 等于类型 2.Currency」，第二条为「类型 2.CustomerRef 包含类型 1.CustomerRef」，第二条必须计算类型 2 包含类型 1；类型 1 为 `ABC123`、类型 2 为 `123` 时不命中、不赋值、不锁定。交换这两条 AND 条件的顺序不改变该配对的比较结果。

候选配对仍由第一条字段的两个类型建立；后续条件可引用其中任一类型。条件引用当前配对之外的类型时，该配对不命中，不借用其他类型行。两侧是同一类型时保留既有左右候选行语义，不新增三方配对。

操作符贯通新增、编辑、复制、查看、确认详情、保存及场景导入导出。旧配置缺少 op 时默认等于；显式非法 op 拒绝保存，执行时返回配置错误。原有多候选告警、跳过、锁定、赋值、修改记录和标黄规则保留。`reconFields=[]` 继续沿用无条件赋值。

多候选必须按完整候选关系判定：一对多左行的全部命中仍计入右侧的多对一检查。仅当配对双方各自只有一个候选时，才可赋值并锁定双方。交叉歧义分别报告一对多／多对一，不赋值、不锁定相关配对；同场景中的独立合法配对继续执行。对于同一类型对，交换 AND 条件顺序不得改变最终修改与锁定对象；告警中的一对多／多对一名称仍随当前左右角色确定。

## 3. 提取大账号顺序时检查维护情况

适用于界面 `MerchantId=自己输入` 的模板及其兼容存储表示。用户进入选择窗口并点击【提取大账号顺序】时，对本批全部文件及账号分段检查，包括已手动绑定、未参与此次提取、已识别并保留在冻结证据中的空交易分段。存在未维护账号时不应用部分提取结果。

沿用原文件账号识别及账户映射链路，在维护列表匹配之前保留真实 MerchantId。维护范围采用当前选择窗口的大账号列表，主子模板及文件名匹配模式继续沿用当前汇总范围。MerchantId 转字符串并 trim 后精确比较，不通过子串判定存在；账号存在但有多个币种视为已维护。

完全无法识别大账号时继续显示原提取失败提醒，确认后可返回手动选择；不从任意数字单元格猜测账号。未点击提取或未触发未维护错误时，现有手动选择流程继续可用。

提醒文案：

```text
大账号「M002」未维护，请先维护后重新导入。
点击【确认】后将结束本次整批导入。
```

多个账号一次列全，并显示文件及分段位置；同账号可合并展示但不得遗漏来源位置。用户确认后调用现有取消接口清除当前选择上下文，关闭提醒和选择窗口，结束整批导入。本批不生成明细／余额文件、不保存账号顺序，保留此前成功导入的批次与结果。维护后重新导入。

提取与完成提交互斥；取消失败可重试，但不得恢复本次完成导入按钮。按钮只消费冻结识别证据，不重新读取文件。

## 4. 验收标准

| 编号 | 标准 |
| --- | --- |
| AC-01 | 对账字段只有等于、包含两个选项且单选，新增默认等于。 |
| AC-02 | 保存、重读、复制、确认详情及 bundle 往返保留 op。 |
| AC-03 | 包含方向、空值、大小写、0 及字面比较符合规则；逐条类型绑定，反向条件不误命中或漏匹配，同一类型对的条件换序不改变比较结果。 |
| AC-04 | 旧配置缺少 op 时默认等于，保留字符串／金额比较方式；逐条字段来源按本版修正的类型方向执行。 |
| AC-05 | AND、多候选、赋值、锁定和审计输出符合既有语义；交叉候选完整计数，歧义不赋值／不锁定，条件换序不改变修改与锁定对象，独立合法配对仍执行。 |
| AC-06 | 显示明确识别但未维护的大账号原值。 |
| AC-07 | 已绑定／未参与提取／空分段中的未维护账号也阻断整批。 |
| AC-08 | 确认取消后上下文失效，本批无生成，历史结果保留。 |
| AC-09 | 完全未识别、已维护多币种及正常手动选择继续可用。 |
| AC-10 | 维护后重导成功；提取和完成互斥，无重复请求。 |

## 5. 兼容与交付

不新增数据库表或批量迁移；旧配置读取时补默认。含「包含」的场景在降版前须停用或改回等于，防止旧引擎忽略操作符。更新版本元数据、CHANGELOG、VERSION_FEATURE_HISTORY、USER_GUIDE。

逐条类型绑定同样适用于「等于」：原先采用反向类型且左右字段名不同的旧条件，将按界面配置修正取值来源，命中结果可能改变。此类场景需纳入人工复核；字符串和金额数值比较方式保持原样。

完成定向回归、release-check、scan:vars、check:vars。涉及资金匹配与账号归属，需用脱敏样本人工核对包含命中、识别原值、分段和整批取消；自动测试不替代人工验收，状态在实施记录中单列。
