# bank-bill-excel-tool 3.0.17 Spec

> 目标版本：`3.0.17`
> 状态：implemented（自动化验证完成，资金人工复核待完成）
> 更新时间：2026-07-16
> 适用仓库：`bank-bill-excel-tool`

## 0. 迭代目标

3.0.17 只交付两项功能：

1. 「中台退款订单回填」增加可选的银行打款流水号模糊匹配。
2. 工具箱「拆分文件」增加最多 8 组的一次扫描、多文件原子导出。

本版不实现 `MPT_CHANNEL_OTHERS`，不新增数据库表或迁移，不包含 PR、合并、tag 或 GitHub Release。

## 1. 退款流水号模糊匹配

### 1.1 配置与页面

- 「中台退款订单回填」自带场景管理页左下角增加勾选框 `银行打款流水号模糊匹配`。
- 配置键为 `bankPaymentSerialFuzzyMatchEnabled`，默认 `false`；旧配置缺字段时按 `false`。
- 配置随场景持久化及导入导出；保存以完整 `config` 浅合并，仅覆盖本字段，不丢失场景分桶字段。
- 修改配置后沿用现有机制使旧运行结果失效。
- 未勾选时，退款回填结果与 3.0.16 旧流程保持一致。

### 1.2 执行顺序与适用行

- 既有 S1-S4 全部先执行，新规则最后执行。
- 新规则只处理旧流程最终结论为 `未能关联到任何退款订单` 的普通未命中银行行。
- 不推翻多候选、日期异常、数据错误或其它既有人工结论。
- 被新规则救回的银行行从人工 sheet 移除，仍满足每条银行行只有一个最终去向。

### 1.3 候选条件

银行行和退款订单须同时满足：

```text
trim(bank.MerchantId) = trim(refund.银行大账号)
trim(bank.Currency) = trim(refund.币种)
trim(refund.银行打款流水号) 非空
trim(refund.银行打款流水号) = trim(bank.ChannelOrderNo)
  OR trim(refund.银行打款流水号) = trim(bank.CustomerRef)
abs(abs(bank.Credit Amount - bank.Debit Amount) - refund.退款金额) < 10
```

- 文本比较大小写敏感。
- 金额使用精确十进制字符串运算，不使用 JavaScript 浮点数；非法金额不得按零处理。
- 金额差等于 `10` 不命中。
- 银行与退款订单必须双向严格 1:1；一对多或多对一均进入人工介入，不抢占、不取最小差额。

### 1.4 输出

- 成功行进入现有回填模板，`命中类型=模糊命中`。
- `匹配命中详情` 固定为：
  `银行对账单ChannelOrderNo/CustomerRef等于退款订单的银行打款流水号，金额差额={实际计算结果}`。
- 标黄字段包含实际参与匹配且存在于模板中的流水号、金额、大账号和币种字段。
- 模糊匹配失败或候选冲突的行保留人工结论，并提供可定位原因。

## 2. 多文件拆分

### 2.1 页面与分组

- 「选择拆分字段」页左下角增加 `需要拆分成多个文件`，默认不勾选。
- 未勾选时保留现有单分组、单另存为请求和返回契约。
- 勾选后每组由 `文件N / 文件名 / 字段 / 值` 构成，使用稳定三列网格；三个标签右边和三个控件起止位置对齐。
- `新增` 最多追加至 8 组；至少保留 1 组，支持删除并连续重编号。
- 新组文件名和值为空，字段继承上一组；每组状态独立，切换字段只清空本组值。

### 2.2 校验

- 每组必须有非空文件名、有效字段和至少一个值。
- 文件名按主名处理，统一补且只保留一个 `.xlsx` 后缀。
- 包含 Windows 非法字符、尾部空格/句点、系统保留名，或规范化后大小写不敏感重复的文件名，阻止导出并定位分组。
- 分组允许重叠，同一源行可进入多个输出；零命中分组仍生成只有表头的合法 Excel。

### 2.3 IPC 契约

旧请求和返回保持不变。新增请求：

```js
{
  sourceFilePath,
  mode: 'multiple',
  groups: [{ fileName, field, values }]
}
```

成功返回：

```js
{
  status: 'success',
  files: [{ filePath, fileName, matchedCount }]
}
```

### 2.4 读取、写入与发布

- 多文件模式只选择一次输出目录。
- 目标冲突时一次列出并确认 `覆盖全部`；取消后不写任何文件。
- 普通 XLSX、大文件 worker、多 sheet XLSX、CSV/XLS 均只扫描源数据一次，并并行判断最多 8 个过滤器。
- 每个文件保留源行顺序和现有格式语义。
- 所有结果先写批次临时目录，再批量发布；任一生成或发布失败时删除本批新文件、恢复被覆盖文件并清理临时文件，不留下部分结果。
- 目标路径不是普通文件时在创建临时批次前拒绝。若操作系统持续阻止原文件恢复，错误结果必须列出保留的备份路径，并保留该临时恢复目录，禁止 finally 删除唯一可恢复副本。

## 3. 兼容与可观测性

- 退款开关关闭时不改变旧退款结果；旧场景配置无需迁移。
- 工具箱旧单文件 IPC、另存为流程、读取格式和返回字段不变。
- 多文件成功反馈展示每个文件名与命中行数；失败反馈包含失败阶段，不把部分结果表述为成功。
- 退款匹配保持银行行与退款订单的唯一消费、去向守恒和可审计金额差。

## 4. 资金红线

- 流水号、大账号、币种、精确金额差或 1:1 判定错误都可能造成错误退款回填。
- 发布前必须使用真实脱敏退款样本逐笔确认新增模糊命中的流水号、金额差、大账号和币种；自动测试不能替代人工复核。
