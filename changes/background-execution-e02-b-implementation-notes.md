> Normative contract remains the merged, self-contained, frozen package at

## Baseline

- Goal/spec: Implement E02-B ResourceGovernor, AdmissionQueue, ServiceHost resource handshake, Supervisor admission, and existing nested topology accounting without wiring product actions.
- Initial plan: Build strict resource-vector and queue primitives first, then the specialized Governor facade, ServiceHost two-phase adoption, and finally Supervisor/adapter integration.
- Done when: All lease kinds, FIFO/aging/cancel/timeout/downgrade, tentative adoption and atomic replacement, crash/close cleanup, Supervisor pre-spawn admission, and compound accounting have reproducible tests; full repository gates pass.

## Reviewer Round 6 Preflight

- Goal: Make cooperative ServiceHost closure drain every service resource through the frozen wire handshake before `executor:close`, while treating a genuine fatal terminal as an internal-cleanup boundary rather than an incomplete graceful trace.
- Context: The Host currently releases tentative/adopted reservations internally and then sends `executor:close`, so a close ACK can be reported as graceful even though the emitted trace violates the contract rule that close starts only after resource release/release-ack. The offline validator correctly enforces graceful completeness but also reports missing adoption/release messages after a valid fatal executor terminal.
- Constraints: Reuse the existing `resource:revoke -> resource:release -> resource:release-ack` and `executor:close -> executor:close-ack` operations, generation control registry, Host Promise rejection, and Supervisor shutdown error report; add no wire fields, public methods, terminal enum, or automatic force fallback; preserve strict identity/duplicate checks before fatal and reject every post-terminal message.
- Done when: Pending admissions abort and settle, tentative/adopted resources drain serially under one absolute close deadline, close is sent only after Host resource maps/claims are empty, any timeout/send failure/raw crash settles bounded and is reported non-graceful, explicit force remains internal fail-closed cleanup, fatal sequences suppress only missing-tail obligations, and all targeted/full gates pass.

## Decisions

| 决定 | 原因与证据 | 放弃的方案 | 影响 |
| --- | --- | --- | --- |
| `CODEX-TECHDOC.md` §7.1 specialized Governor methods and `createServiceHost()` are the only exports added through `background-execution/index.js` | Package manifest marks Platform Contract/E00/Schemas normative and CODEX docs as implementation inputs; the specialized surface mechanically covers the generic E00 primitive | Export generic `requestLease`, AdmissionQueue, or version-document aliases | Generic queue/lease mutation stays package-private and can change without creating parallel public contracts |
| All resource vectors are exact five-key, non-negative safe-integer objects; Worker dynamic vectors are separately normalized from exact three-key values with both carrier slots set to zero | Contract and Protocol Schema freeze two distinct vector domains | Accept partial/defaulted vectors or silently coerce strings/floats | Invalid or overflowing accounting fails closed before queueing |
| No arbitrary partial grant | A smaller memory/CPU grant cannot safely represent a Worker-estimated candidate footprint | Grant any vector less than requested because the Protocol Schema permits it structurally | Only compound `downgrade-to-single` may reduce requested topology |
| A service-held BaseLease is referenced by a service compound request and charged once; a job compound request owns the full base+phase+children topology | Preserves the unique-root formula while satisfying the service requirement to hold BaseLease before nested parser admission | Count the service base twice or omit it from active topology diagnostics | Governor tracks full topology separately from incremental usage contribution |
| Same-service policies derive a conservative service profile | `serviceKey` is the static route identity and a service accepts at most one business command; fixture control policies agree for each key | Choose whichever action first starts the service | Base vector is the component-wise maximum; dynamic limits come from the current full `jobRef.actionKey` policy |
| Admission backlog is one priority/FIFO/aging boundary for every request, including `lowMemoryBehavior='reject'` | A fitting or reject-mode arrival must not bypass an older selected request; otherwise resource pressure changes ordering semantics | Fast-path new requests while an older request is queued | New requests use the immediate path only when the queue is empty; absolute deadlines are rechecked before each drain callback |
| Parent leases carry explicit reverse dependencies from queued, tentative, and active compound/replacement reservations | Incremental accounting is safe only while the referenced Base/Persistent lease remains active | Rely on callers to avoid releasing a referenced parent | Parent release fails with `RESOURCE_DEPENDENCY_ACTIVE`; every reject/abort/timeout/pre-grant failure completes dependency cleanup before rejection is observable to the caller |
| Service owner identity is claimed from request acceptance through tentative adoption, and resource mutation is serialized per generation | Duplicate owners and adopt-vs-detach races otherwise permit two live reservations or ACK of a released candidate | Check only adopted reservations or depend on event-loop ordering | Pending/tentative/adopted ownership is exclusive; adoption revalidates generation, job route, claim, current replacement, and active candidate before ACK |
| Policy freeze rejects incompatible actions sharing one `serviceKey` | Service process executable and capabilities are service identity, not a first-start-wins action choice | Select the entry of whichever action starts first | The frozen resolved entry descriptor, service capability binding when registered, carrier, and service control configuration must be deeply equal |
| E02-A construction without a Governor remains valid only for simple job-lifetime execution | The E02-A public factory predates E02-B resource wiring | Make `resourceGovernor` mandatory for every Supervisor | Service/compound paths fail before spawn; simple job-only execution keeps its prior path without adding a compatibility alias |
| Persistent reservation replacement uses a service-stable Governor identity while retaining the full current `jobRef` | A resident service-state owner survives normal job detach and may be revised by a later action/operation; generic Governor callers still need exact explicit identity checks | Treat a temporary job action/operation as the persistent reservation identity | Host maps action identity to `service:${serviceKey}` with nullable operation identity; wire request/adopt/release routes remain checked against the current full job reference |
| Tentative replacements cannot serve as replacement parents | Atomic replacement does not publish the candidate until adoption; a chained candidate would otherwise bypass the single-current-reservation invariant | Permit a chain and try to topologically adopt it later | Acquire and adopt both require a parent with no upstream active dependency; each link must publish before the next request |
| Ready/adoption timers are wakeups for absolute deadlines | A delayed event-loop timer cannot make a late ready/adopt event valid | Treat timer callback order as the deadline authority | Handlers recheck `now() >= deadlineAt`; adoption deadline begins at lease grant and all timeout values stay within the JavaScript timer-safe domain |
| BaseLease closure may be deferred behind an external CompoundLease dependency | Host cannot release a service root before Supervisor-owned incremental topology, but removing the service record must not orphan the root | Clear the Host BaseLease reference after a blocked release | A package-private Governor deferred-release registry completes exactly once when the final reverse dependency releases; Host keeps its reference until release is proven |
| Service generation ownership is tracked as package-private metadata keyed by Host job-transport identity | Pre-dispatch failure of a job attached to an existing generation must not destroy persistent service state, while the public transport shape must remain unchanged | Force-terminate every service transport for any non-terminal spawn failure or add a new enumerable public field | Supervisor terminates a generation created for that open, but only detaches from an existing generation; a pre-open Host snapshot closes the narrow cancellation window before transport assignment |
| Schema-valid Host state/matrix violations use a dedicated protocol error type | Unknown/stale reservation, owner, revision, or job-route events are Worker protocol violations, while raw adapter failures are not | Classify every Host callback failure as `adapter-error` | Supervisor maps `ServiceHostProtocolError` to canonical `protocol-error` without adding it to the package public facade |
| Offline owner claims mirror the runtime request-to-terminal interval | Two initial requests for the same service/type/owner must not both reach grant before adoption | Claim identity only after adopt-ack | Request claims owner identity; reject or tentative revoke releases it; adoption transitions it to the active reservation and release removes it |
| Supervisor takes ownership of an awaited admission lease only after rechecking terminal, abort, and cleanup state | Synchronous Governor diagnostics can cancel an execution after grant commit but before the awaiting continuation receives the lease | Push every resolved lease unconditionally and rely on later cleanup | A late grant is released immediately, while one unified pre-transport `finally` settles transport assignment so terminal cleanup cannot wait in a cycle |
| Replacement publication has a second narrow delivery-protection boundary | Initial tentative delivery protection cannot cover the later atomic switch; `resource-replaced` diagnostics run before the replacement Promise is observable | Let diagnostics release the newly current reservation or adopt a candidate from its initial grant callback | Early candidate adoption fails before mutation, and release during replacement publication returns false until the published lease is deliverable |
| Internal generation cleanup may defer an adopted reservation release, while Worker-requested release of an old replacement parent is a protocol error | A candidate can commit its Governor dependency before Host registers the tentative grant; cleanup must not orphan either resource, but wire release is an invalid state transition | Reclassify all dependency failures as protocol errors or ignore cleanup release failure | Force-close/crash registers a package-private deferred release; wire release receives no ACK, closes through `ServiceHostProtocolError`, and internal resource failures keep their original classification |
| Offline service resource validation is an explicit per-request FSM | Map presence alone accepts duplicate/conflicting responses and revoke-then-adopt sequences that runtime rejects | Add isolated duplicate checks without a transition model | Requested, granted/rejected, adopted, acked, tentative/active revoked, released, release-acked, and replaced states enforce response exclusivity and identity continuity while preserving both frozen revoke paths |
| Supervisor normalizes shutdown duration before changing acceptance or closing dependencies | E02-A accepts every finite non-negative number, while Host and JavaScript timers require bounded integer delays | Pass the public duration directly to Host or reject previously accepted fractional/large durations | Fractional durations round up, long waits use timer-safe chunks, Host receives a clamped duration, and any normalization failure occurs before lifecycle mutation |
| Every Governor operation that takes a parent lease crosses one delivery-complete gate | A committed lease is not yet caller-owned while synchronous diagnostics run; allowing it to become a compound/replacement parent during that interval can make the delivered outer lease already consumed or chained | Protect only direct release/adopt and add call-site-specific checks | Dependency creation and revalidation reject delivery-protected Base/Persistent parents, and replacement adoption revalidates both old and candidate before switching |
| Host retains immutable replacement linkage from accepted request through grant/adoption | An old reservation is already dependency-protected while its replacement waits in admission, before a tentative grant exists | Inspect only `tentativeGrants` or let Governor return an internal dependency error | Wire release checks live pending and tentative replacements before Governor mutation and maps the violation to canonical `protocol-error`; internal cleanup keeps resource-error semantics |
| Offline validation owns generation-wide correlation tombstones and an explicit service lifecycle | Correlation IDs are one-exchange identities and service messages are ordered across the whole generation, not reset when a resource request terminates | Treat each request/control map independently and infer lifecycle only from message presence | New exchanges claim control IDs once, replies exactly echo their initiating command, grant/reservation IDs never reappear, and lifecycle follows `new -> initialized -> ready -> closing -> closed|failed`; a fatal transition from closing does not require an impossible later close ACK |
| Runtime Host owns one control-exchange registry per service generation | Recording only inbound IDs misses Main tombstones, while a Host-global ID set incorrectly forbids contract-valid reuse by a later generation | Add Main IDs to the old inbound-only set or retain Host-global control generation | Main new exchanges claim before raw send; Worker exchanges and Main responses transition only through their exact operation/job/resource identity; settled entries remain tombstones until generation close; `ready` remains a distinct Worker exchange and revoke remains live through release-ack |
| Cooperative service close has a resource-drain phase before executor close | Frozen valid traces and the contract validator require every adopted reservation to complete release/release-ack before `executor:close`; internal release cannot be represented as a graceful wire trace | Internally release reservations and still accept close-ack, or automatically retry as force while returning success | One absolute deadline covers pending-admission cleanup, insertion-ordered tentative/adopted revoke exchanges, outstanding timeout-revoke completion, and close-ack. Any interruption rejects and is reported non-graceful before fail-closed internal cleanup |
| Control exchanges expose package-private completion without discarding tombstones | A tentative adoption-timeout revoke may remain live after Main has reclaimed its local lease; a later graceful close must wait for the exact release/release-ack instead of bypassing it | Track only graceful-close revokes or delete the earlier live exchange | Every live exchange can settle/reject its waiter while the registry entry remains generation-scoped; response identity and exact echo rules are unchanged |
| Offline fatal completion is state-specific, not a relaxed graceful validator | `executor:error` terminates the generation and transfers unfinished resource ownership to Host cleanup, whereas `executor:close` is valid only after the full resource handshake | Suppress all completeness errors whenever any terminal appears | Only a valid fatal transition marks unfinished request states `terminal-cleanup`; earlier transition/identity errors remain, post-terminal messages remain invalid, and graceful close still rejects pending/revoked/release-awaiting-ack resources |
| Normal job detach uses an outcome-aware adopted-resource matrix | Persistent service-state and an adopt-acked interaction token published by the first accepted `job:done` are service-scoped; phase extensions plus error/cancel/unpublished/late interaction resources remain job-scoped | Revoke every non-persistent reservation, or retain every adopted interaction regardless of terminal outcome/publication ordering | The job remains routable while its exact job-scoped reject/revoke/release/release-ack obligations drain; only the two service-scoped survivor classes outlive `jobs.delete`. Later null-ref or exact saved-jobRef release consumes the token, while service close/crash drains any survivor |
| Zero-millisecond normal detach has an exact no-obligation fast path | Wrapping an already-empty drain in a deadline at `now()` makes a valid empty/persistent/published-token detach fail before useful work; a real wire obligation cannot be completed after a zero deadline | Treat zero as a positive minimum, or skip cleanup even when job-scoped resources exist | Under the generation resource-mutation queue, Host atomically checks pending admission, tentative grant, non-retained adopted reservation, live revoke waiter, and incomplete Main revoke exchange. If none exist it deletes the route without installing a timer; otherwise it fails closed and closes the generation non-gracefully. Init/adoption/revoke/service-close deadlines are unchanged |
