# Spec - v3.0.22 设置页内存档中心

> status: release-ready（PR #97 已合入 `main`；最终发布前门禁通过）
> updated: 2026-07-21
> branch: `codex/v3.0.22-archive-center`
> prototype: `changes/3.0.22/archive-center-settings-prototype.html`

## 1. 目标

在现有“设置”弹窗内新增“存档中心”，保存 11 个主模块在本次启动周期内可证明来源的业务输入文件，以及对应批次第一次成功生成的结果文件。

存档用于查找和复制文件，不提供恢复业务、重新运行、编辑或替换原文件能力。

## 2. 已确认规则

1. 存档中心不新增主模块；设置页左侧导航固定为“自动更新 / 存档中心”，每次打开默认进入自动更新。
2. 有运行按钮的模块，仅运行成功后建批次；只导入不运行不存档，失败或取消运行不建批次。
3. 无运行按钮的模块，在成功生成内部结果文件时建批次。
4. 只保存业务输入和该批次第一次成功结果；后续另存、重复导出、聚合导出和历史重导不追加。
5. 链接表、临时 MPT 成功导入作为所属主模块的独立输入批次，不重复塞入之后每个运行批次。
6. 文件内容按 SHA-256 全局物理去重；同一文件可以在多个批次保留逻辑引用，但物理只存一份。
7. 存档失败不改变业务返回、运行结果或正常导出；用户收到通知。一般失败可在存档中心重试；若文件在业务完成后已发生变化，则禁止把变化后的内容冒充原结果，须重新执行业务生成新批次。
8. 默认保留 90 天，可选 30/90/180/365 天或永久；锁定批次不自动清理。
9. 手动删除需二次确认；锁定批次必须先解锁；删除存档不删除原始输入、正常业务输出或另存副本。
10. 网银账单模板可设置“不存档”；本次生成实际使用的任一模板命中排除时，整个批次跳过。

## 3. 范围

### 3.1 归档内容

- 用户实际选择并在当前启动周期成功导入的业务数据文件。
- 成功运行或成功生成后，与该批次关联的第一次结果文件集合。
- 原文件名、输入/输出方向、来源动作、模块、批次时间、状态、保留期和锁定状态等轻量元数据。

### 3.2 永久排除

- 错误报告、失败明细、修复错误数据和校验错误工作簿。
- 模板文件、模板/场景配置包、规则、映射、设置和枚举文件。
- 工具箱合并/拆分的输入与输出。
- 日志、数据库、side DB、缓存、临时文件、更新包和存档中心自身文件。
- Pending/银行 BU 聚合结果、业务 OP 日期区间结果及其它历史重导结果。
- v3.0.22 之前的输入、运行和输出。

### 3.3 当前版本边界

- 输入路径及运行绑定只在当前应用启动周期内维护，不持久化跨重启的导入凭据。
- 升级前已落库、或本次启动前已持久化的数据源不按文件名猜测，也不补档。
- 重启后从历史运行记录发起的单次导出，没有当前周期活动批次时不建立仅含输出的批次。
- 若一次成功运行没有本次启动周期可证明的输入或结果文件，则不创建空批次。
- 归档重试只重读原记录中的源路径，不提供重新选择源文件入口。
- 保留期设置只影响之后新建的批次，不批量追溯修改既有批次。
- 自动清理在存档服务启动时执行；长时间不重启的软件在下次启动时清理到期批次。

## 4. 设置页

### 4.1 信息架构

- 左侧导航：自动更新、存档中心。
- 自动更新页面保留 v3.0.18 的全部状态、开关、检查和重启升级行为。
- 存档中心不是 `MODULES` 或 `ALL_MODULE_IDS` 成员，不出现在模块切换和模块收纳中。

### 4.2 存档浏览

- 默认日期为本机当天；支持按日期、11 个主模块和批次号筛选。
- 左侧显示批次列表；右侧显示批次信息和文件列表。
- 文件显示方向、原文件名、大小和存档状态。
- 已完成文件支持“打开只读副本”和“另存为”。
- 失败批次支持重试；批次支持锁定/解锁和永久删除。
- 存档设置显示唯一物理占用、逻辑大小、批次数、文件引用数、固定存储路径、默认保留期和网银模板排除策略。

## 5. 批次与模块矩阵

可见批次号为 `{MODULE_CODE}-{YYYYMMDD}-{NNN}`。流水按模块代码和本地日期独立递增，删除后不复用。

| 主模块 | CODE | 建批节点 | 输入 | 第一次结果 |
|---|---|---|---|---|
| 网银账单生成 | `STATEMENT` | 普通账单最终生成成功；月度余额装配成功 | 普通账单本次源文件；月度余额无外部输入 | 明细/余额实际生成文件；月度余额文件 |
| 新开账户余额账单生成 | `NEWACCOUNT` | 生成成功 | 无文件输入 | 余额账单文件 |
| 月度Pending数据核对 | `PENDING` | 对账成功 | 本次启动导入的上下月及移除核对文件 | 首次单 run 差异文件 |
| 资金对账数据处理 | `FUNDRECON` | 对账成功；由该页面发起的网关修复成功 | 本次银行/退款文件，或网关修复输入文件 | 首次主结果、命中报告、清理/回填结果等白名单文件 |
| 对账单修复 | `RECONFIX` | 从本模块发起的修复成功 | 本次修复文件 | 首次主结果与未匹配结果 |
| 月度银行对账单BU回填校验 | `BANKBU` | 对账成功 | 本次月份的 Pending 与银行文件 | 首次单 run 差异文件 |
| 业务OP数据核对 | `BIZOP` | 对账成功 | 本次日期的 OP 与流水文件 | 首次单日期结果 |
| 收单单据币种校验 | `ACQUIRING` | 运行成功 | 本次月份流水/单据文件 | 运行内生成的差异/报告文件 |
| VCC业务OP计算 | `VCCOP` | 保存计算结果成功 | 本次流水文件 | 无文件结果 |
| 前置资金对账 | `PREFUND` | 对账成功 | 本次银行账单 | 首次按渠道结果集合 |
| 重复入金匹配 | `DUPINBOUND` | 匹配成功 | 本次银行账单和单据对账单 | 首次邮件结果工作簿 |

独立输入批次：

- “资金对账数据处理 -> 链接表管理”成功文件使用 `LINKED` 批次代码，模块仍归“资金对账数据处理”。
- “前置资金对账 -> 临时链接表”成功 MPT 文件使用 `PREFUNDTEMP` 批次代码，模块仍归“前置资金对账”。
- 临时 MPT 修复批次与正式前置资金对账批次使用不同内部活动域，不能抢占正式结果。

## 6. 首次结果绑定

- 运行批次在内存中同时按模块归档类型和稳定 run key 记录。
- 延迟导出按非空 run key 精确查找批次；显式 run key 未找到时不得回退到“最新批次”，也不允许跨模块共享“最新批次”。
- 同批次第一次成功结果完成登记后，后续结果事件直接忽略。
- 只有归档白名单内的业务 IPC 才建立运行上下文；其它 IPC 不捕获参数，也不进入归档后台队列。
- 一次结果包含多个文件时，全部文件属于同一首次结果集合；其中部分复制失败时，批次为不完整，重试原失败文件，不允许后续导出替换。
- 资金对账页面复用 `recon-id-fix:run` 时显式传 `originModuleId=bank-statement-process`；专用修复页面传 `recon-id-fix`，导出沿用运行时来源。
- 月度余额装配使用独立批次，但不覆盖普通网银账单等待余额补录的活动批次。
- 临时 MPT 错误修复按源文件与结果的原始下标绑定成功项；不同目录中的同名文件不得互相冒充成功。

## 7. 存储与数据库

存储根：

```text
{Documents}/网银账单生成小助手/存档中心/
├─ blobs/sha256/{前2位}/{64位sha256}
├─ .staging/
└─ .readonly/
```

主库新增轻量表：

- `archive_batches`：模块、批次号、日期流水、业务状态、存档状态、锁定、到期日和错误摘要。
- `archive_batch_sequences`：按模块代码和本地日期保存不可回退的最后流水号；删除最高批次后也不复用号码。
- `archive_artifacts`：批次内逻辑文件、原文件名、方向、角色、源路径、重试状态和 Blob 引用。
- `archive_blobs`：SHA-256、大小和相对物理路径。

业务成功返回时先记录候选文件的大小、修改时间、状态变更时间和文件标识；后台复制前再次核对，文件已变化则记录 `ARCHIVE_SOURCE_CHANGED`，不存入错误字节。文件以流式读取计算 SHA-256，并先写同文件系统临时文件；完成后原子发布。相同 SHA-256 和大小复用既有 Blob。主库不保存文件字节或业务数据行。

同一批次的全部 artifact 元数据必须在首个文件开始复制前登记完成。这样正常退出或复制中断后，启动一致性检查仍能找到整批未完成文件。

## 8. 生命周期

- 创建新批次时冻结当前默认保留期；永久批次的到期日为空。
- 启动清理只选择未锁定且已过到期日的批次。
- 删除批次先移除逻辑引用；只有最后一个引用被删除时才删除物理 Blob。
- 启动一致性检查清理 staging/只读副本/孤儿文件，并把中断或丢失 Blob 的逻辑文件改为可重试失败状态。
- “打开”先生成独立只读副本，不直接暴露 Blob 路径；“另存为”复制 Blob 到用户选择位置。
- 正常退出和升级重启会等待后台存档队列排空；超过 5 秒只记录慢退出告警，不放弃尚未完成的存档任务。

## 9. 失败隔离与可观测性

- 业务 handler 先按原契约返回，文件复制在串行后台队列执行。
- 归档目录不可写、源文件丢失、磁盘错误或元数据错误均不得改写业务返回和业务文件。
- 归档失败通过桌面通知和活动日志提示“业务已成功，但存档失败”；日志不记录源文件绝对路径或表格内容。
- 文件在业务成功后、后台复制前被覆盖或替换时，批次显示不完整且不提供无效重试；用户须重新执行原业务。其它已登记但未完成的文件在异常中断后由下次启动转为失败并可重试。

## 10. 验收标准

1. 设置页双导航、自动更新零回归，存档中心不成为第 12 个主模块。
2. 11 个模块的触发、输入、首次结果和排除出口均有策略测试。
3. 链接表/临时 MPT 与所属正式运行批次不串批。
4. SHA-256 去重、共享引用删除、失败重试、启动修复、保留期和锁定均有真实 SQLite + 临时文件测试。
5. 归档异常不改变业务返回；后台队列不保留大体量业务结果对象。
6. 设置页在 `1240x860` 和最小 `1080x760` 不重叠、不截断。
7. `npm run release-check`、`npm run scan:vars`、`npm run check:vars -- --include-minor` 和启动性能检查通过。
8. ⚠️ 资金红线：人工抽查各模块样本的源文件与存档 Blob SHA-256 相同、结果文件与存档 Blob SHA-256 相同；自动测试不能替代该抽查。
9. 显式历史 run key、同名临时 MPT、月度余额活动批次和排队期间源文件变化均有反例测试，且整批文件在首个字节复制前已全部登记。

## 11. 明确不做

- 跨重启持久化输入 receipt 或 run/result 绑定。
- 失败/取消运行也建立审计批次。
- 云同步、加密、压缩、权限账号体系或自定义存储路径。
- 从存档恢复数据、重新导入、重新运行、预览 Excel 内容、全文搜索或文件名搜索。
- 扫描和补录旧版本历史文件。
- 修改任何金额、币种、匹配、回填、Excel 内容或既有业务保存路径。
