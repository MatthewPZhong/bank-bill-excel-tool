## 1. 背景

### 1.1 为什么要做

用户的 Windows 工作电脑长期可用内存不足 1 GiB，业务 OP 校验和工具箱按行拆分经常无法启动。本次要让经过验证的文件和完整处理流程能够在低内存环境运行，而不是简单降低检查数字、把失败转移到处理过程中。

用户已认可的方向：保留现有 SQLite 落盘、流式行处理和单 writer；同时修改准入规则与实际工作集；不改变对账数据语义和受支持的表格保真规则。两轮 review 补充的前置扫描、共享字符串、发布、错误报告和恢复均纳入本次方案。

### 1.2 业务价值与边界

在资源可以容纳经过验证的执行档位时，用户能够完成“选择文件—处理—校验—发布”的完整流程；关闭外部占用内存的程序后可以直接重试，不因本应用启动时采样过低而必须重启。

低内存不等于无限内存：资源确实不足、文件复杂度超过已验证档位或磁盘不足时，应明确停止／等待；不得偷减数据、精度或校验。本文不承诺任意文件都能在某个固定可用内存数字下成功。

## 2. 代码现状（必须有出处）

| 编号 | 固定基线中的事实 | 对本次的意义 |
| --- | --- | --- |
| F01 | 两个功能相关 policy 的阶段申请为 1 GiB；公共预算默认扣除 2 GiB，在 runtime 创建时确定。[S03](baseline-evidence.md#s03) [S04](baseline-evidence.md#s04) | 任务申请与平台预算必须一起改。 |
| F02 | 在总物理内存 8 GiB、没有其他配额占用的算例中，采样可用内存达到 3 GiB 才有 1 GiB 后台预算。[S03](baseline-evidence.md#s03) | “被拒绝”不能等同于“文件实际需要 1 GiB”。 |
| F03 | `toolbox:split:read` 在导出模式判断前扫描字段去重值；普通路径使用无界累加器。[S05](baseline-evidence.md#s05) [S06](baseline-evidence.md#s06) | 从选文件开始降低工作集，不能只改 rows worker。 |
| F04 | 工具箱 XLSX 共享字符串默认全量进入数组；输入 styles/theme 也先读取为字符串。[S07](baseline-evidence.md#s07) | worksheet 逐行扫描不代表完整 reader 有界。 |
| F05 | 按行拆分已有保真 SQLite 缓存和顺序单 writer；回放样式又全部进入内存。[S09](baseline-evidence.md#s09) | 复用架构，改输入与缓存回放，不重写拆分算法。 |
| F06 | writer 将提交与回读校验放在同一方法，校验前对象未释放；输出样式 XML 有完整读取。[S10](baseline-evidence.md#s10) | 测量并控制 writer／回读叠加峰值。 |
| F07 | OP 发布观察与恢复另有 `EXPORT_IO_RESOURCES` 的 1 GiB；自动错误报告最终验证也用它。[S11](baseline-evidence.md#s11) | policy 外的独立租约一并调整。 |
| F08 | 旧大文件扫描 dispatcher 的 V8 老生代上限为 4096 MiB；收到结果后调用 terminate 但未等待退出即结算 promise。[S15](baseline-evidence.md#s15) | 上限不是预分配量；低内存扫描不能原样照搬该载体配置和释放时机。 |
| F09 | 容量脚本注入 8 GiB 空闲内存；采样晚于字段扫描，且包含测试验证器读回的开销。[S16](baseline-evidence.md#s16) | 不能用它证明完整流程在真实低内存 Windows 上可用。 |

以上确认的是代码路径和风险点，不是用户机器的 OOM 发生位置。尚未测得各阶段真实峰值、最低可用档位或性能提升比例。

## 3. 目标

### 3.1 必做

G01：取消两个目标链路“所有阶段统一申请 1 GiB”的做法；使用经验证的阶段执行档。

G02：保留稳定资源账本，并增加实际批准前的系统可用内存检查；低内存档通过统一入口与其他重型工作协调。

G03：按行拆分覆盖基础扫描、XLSX 共享字符串、输入样式、保真缓存、输出、回读、发布和失败清理。

G04：业务 OP 覆盖导入、计算、各类导出、自动错误报告、发布验证、恢复观察及恢复继续执行。

G05：获批配置真正约束 reader、缓存、SQLite 连接合计、writer 和验证器；申请额度与执行设置不能脱节。

G06：结果语义不变，安全发布、数据血缘、取消、实际载体退出和恢复所有权不倒退。

### 3.2 可后续做

在证据充分后再增加更细粒度的租约缩减、更多资源档、其他模块低内存适配，以及更广泛的 CSV/XLS 流式改造。这些不是本次关闭问题的必要条件。

### 3.3 明确不做

不重写对账算法；不启用旧 BizOP 回退路径；不升级 Electron／表格依赖来替代问题修复；不添加用户手工填写 MiB 的设置；不修改系统页面文件或关闭用户其他程序；不降低保真范围换取成功；不改变输入／输出保留期限、深色模式、VCC 按主体导出或其他 v3.2.11 分支需求。

本次业务 OP 指 `biz-op-v327` 的业务 OP 校验，不是 VCC 财务 OP，也不是 VCC 业务计算。

## 4. 功能点

### 4.1 P01：自动执行档与准入

**输入：** Main 已校验的动作／阶段、源文件元信息、当前可信资源状态。

**输出：** 正常档或低内存档的获批结果，或有原因的等待／拒绝。用户只看到阶段、执行模式及必要反馈，不填写资源参数。

**行为：** 固定硬上限和实时可用内存分别检查；已批准配额只在固定账本扣除。无法证明其他重型工作后续增长有界时，不在其仍运行期间批准新的低内存重型工作。只对静态人工验收清单明确批准且配置摘要匹配的目标阶段启用普通／低内存档。启用不再要求源码、安装包、精确运行时版本或各档压力报告摘要；每次运行仍检查实际内存、资源配额和活动覆盖。

**验收：** AC01—AC05。各数值及选择规则以 TechDoc §三为准；实验参数不得被当作已验证最低配置。

### 4.2 P02：从选择文件开始的按行拆分扫描

**本方案采用的交互决策：** 不要求用户在选文件前新增一个配置步骤。生产入口先执行基础扫描；字段去重值只有在用户明确使用按字段拆分时才补扫。该设计是本次方案选定的实现口径，不是基线已有行为。

基础扫描只返回必要表头、有效数据行数、源文件身份和读取 token，不收集所有字段去重值。它仍可以逐行检查整份文件，不能用压缩大小、Sheet dimension 或抽样替代准确计数。

字段值“尚未请求／加载中／完成／失败”分别表示，不以空集合冒充已扫描。保留默认首字段选择，但默认选中、打开视图和字段 `change` 均不自动补扫；首次点击当前字段的“值”选择入口（包括键盘激活）才加载该字段。未请求及可重试失败时入口可操作，不能沿用“值数组为空就禁用”的判断；加载成功后才区分真正空列与有可选值。

单列文件不需切换字段即可加载。多文件分组遵守相同入口约定：每组绑定自身字段和请求代次，不把一个分组的值或选中项写入另一分组；相同源／字段可以共享有界缓存及去重请求。补扫中、失败或尚未请求时，不允许对应字段分组提交；按行路径不依赖字段值加载成功。切换到 rows／取消只撤销本会话不再需要的补扫，迟到响应不能覆盖新状态，不能因此使仍有效的基础读取 token 失效。

普通与大文件路径都受资源边界约束。预扫描保持在 Worker 中执行重型解析；Main 只做文件选择、受控元信息和编排。必须区分以下三类检查，不能把 rows 专属限制提升为公共限制：

| 检查类别 | 适用范围与行为 |
| --- | --- |
| 公共格式／源文件安全检查 | 对公共扫描及各模式执行既有的文件真实性、支持格式、结构和源身份检查；不新增所有模式统一的 64 MiB 上限。 |
| 执行档适用性与资源检查 | 创建 reader 前检查当前格式、规模和工作集能否使用候选档；低档未经验证或不适用时，普通档通过资源准入后仍可执行。没有可安全运行的档位时按真实资源原因等待／拒绝，不冒用 rows 格式错误。 |
| rows 专属 CSV/XLS 源预算 | 保留按行拆分的 64 MiB 限制，只拒绝 rows 模式；Main 的 rows 准备及 rows worker 实际读取前都检查。公共阶段可给出只读的不适用提示，不能据此拒绝按字段拆分。 |

因此，资源允许的普通档不能仅因为 CSV/XLS 超过 64 MiB 就在选择模式前被拒绝。65 MiB CSV 是兼容回归样本，不是对所有同等大小文件的运行保证；按字段拆分的既有业务规则不变。本分支不授权将 64 MiB 统一扩展到全部拆分模式。[S05](baseline-evidence.md#s05) [S09](baseline-evidence.md#s09)

**验收：** AC06—AC09。保留既有有效行、隐藏 Sheet、重复续页表头、空行和重复列名处理规则，不顺便调整业务口径。

### 4.3 P03：XLSX 读取与保真缓存

接入公共共享字符串 provider 的受限内存／落盘能力，传入明确缓存预算与任务私有目录。输入样式解析、源样式注册和回放样式缓存均需纳入峰值；回放不能再无条件恢复完整样式集。

单字符串、单行、XML 元数据等不可拆分对象也必须有资源保护。既有 ZIP/XML 安全限制不因落盘而取消。正确文本解码、样式引用、数值和日期口径保持。

**验收：** AC10—AC12。具体预算盘点不等于所有对象都必须重构；现有有界实现能够通过目标档位证据时可以保留。

### 4.4 P04：按行拆分输出、校验和发布

继续使用 SQLite 保真缓存与一个 writer 顺序生成；每份数据行数仍由用户指定，不因内存压力自动改变。既有输出 `.xlsx`、文件数上限、命名和跨 Sheet 计数规则保持。

writer 积压控制必须有真实可暂停边界。测量提交、样式注册、输出回读与未释放对象的叠加峰值；超出预算时先处理对象生命周期，不能去掉校验。

所有计划产物均验证完成后才进入现有 Publisher。发布中断时依现有 journal／恢复协议处理；不能承诺文件系统上永远不存在中间文件，也不能向用户把未完成产物集报告为整体成功。

**验收：** AC13—AC16。

### 4.5 P05：业务 OP 完整链路

| 阶段 | 需要贯穿的配置与边界 |
| --- | --- |
| 导入 | reader、共享字符串、路由 writer／候选数据、错误采样；不将资源故障误报为某一业务行非法。 |
| 核对计算 | 工作库、输入连接与输出连接的合计缓存、索引／排序、分组与结果中间文件。 |
| 结果／原表／校验表导出 | 源 reader、共享字符串、spool、writer、输出 validator。 |
| 自动错误报告 | 生成、发布、目标校验、归档交接、必要恢复；不只测试“无错误输入”。 |
| 发布及恢复 | policy 外直接 phase lease、借用观察、恢复检查、后续验证；不能保留隐蔽统一 1 GiB 申请。 |

各阶段从相同的资源配置体系获得设置，但可以申请不同额度。重启后的恢复重新采样、重新获取租约；不得复用重启前的物理额度。恢复对象及业务事实继续按原协议核验。

低内存降档不得改变金额精度、差异容差、参与数据范围、错误总计与既有错误样本上限。资源耗尽导致未完整扫描时，不能给出“全部校验通过”或虚构精确错误总数。

**验收：** AC17—AC20。

### 4.6 P06：压力处理、重试与反馈

缓存能够淘汰时才淘汰；输出能够暂停时才等待；不把压力信号当成即时释放保证。持续无法在获批预算内安全运行时，按已有取消／失败及恢复协议停止。发布关键区的压力不绕过其完成或恢复协议。

资源等待具有期限，并在释放、载体退出、用户重试和定时重新采样时复核。不自动重新提交已产生业务副作用的失败任务。

建议状态文案：

| 状态 | 用户反馈 |
| --- | --- |
| 基础扫描 | 正在读取表头与数据行数。 |
| 低内存执行 | 当前使用低内存模式，可能需要更多磁盘读写。 |
| 等待资源 | 正在等待后台资源；本阶段尚未开始。 |
| 资源暂不足 | 当前资源不足以运行该阶段；释放其他程序占用后可直接重试，无需重启本软件。 |
| 输出未发布 | 处理未完成，结果尚未发布；原文件未修改。 |
| 发布结果待核验 | 发布结果仍待核验，请完成恢复后查看；不要重复提交。 |

以上是展示状态，不新增存档中心业务枚举。OP 不重新增加此前删除的【取消操作】或【导出错误报告】按钮。前置扫描的取消只作用于本扫描会话，不授权取消已提交的 OP 写入。

**验收：** AC21—AC24。

### 4.7 完成标准

| AC | 必须通过的结果 |
| --- | --- |
| AC01 | 固定硬上限与实时内存判定分开；没有把可用内存覆写总账本后再次扣配额。 |
| AC02 | 两个目标流程在经验证的低内存档可运行，不再被无条件 1 GiB 阶段申请挡住。 |
| AC03 | 申请与实际批准之间发生内存变化时，使用最终批准前的有效采样。 |
| AC04 | 低内存重型工作不会与未闭合／增长不明的其他重型工作同时获准；不新增资源池绕过旧账本。 |
| AC05 | 其他 action 未经审批不会因公共预算调整被降低门槛或擅自启用；超出自身稳定上限立即拒绝且不占队首，暂时资源不足才有界等待；覆盖 Bcompat=0、低档后继可调度、取消及释放。 |
| AC06 | 从文件选择开始测峰值；按行路径不创建全字段去重集合。 |
| AC07 | 基础计数与实际拆分计数一致，覆盖隐藏页、空行、跨页、重复续页表头。 |
| AC08 | 默认首字段／单列文件首次点击“值”即可加载，未请求入口可操作；空列与失败可区分；多组不同字段、同字段请求去重、重选／切换／迟到响应隔离通过。 |
| AC09 | 前置扫描取消／窗口销毁／worker 异常时先确认退出，再清理自有临时资源并释放额度。 |
| AC10 | 高唯一文本 XLSX 的共享字符串超缓存时落盘，而非继续增长数组。 |
| AC11 | 输入样式、回放样式、输出样式及回读叠加峰值有证据；不靠删样式通过。 |
| AC12 | SST／ZIP／SQLite 构造失败、取消、关闭失败与残留恢复的所有权测试通过。 |
| AC13 | 正常档与低档输出的行数、内容、顺序、拆分边界和受支持样式一致。 |
| AC14 | 宽行和慢磁盘下输出积压受控；只加 setImmediate 或 highWaterMark 不算证据。 |
| AC15 | 计划中全部文件验证后才发布；验证失败、目标变化和发布中断不误报整体成功。 |
| AC16 | 保留每份行数及 1000 份上限；CSV/XLS 的 64 MiB 限制只作用于 rows，普通档资源充足的字段路径不被该限制提前拒绝；覆盖阈值两侧、65 MiB 兼容样本及资源不足分支，不自动改 N、截断值或转换原文件。 |
| AC17 | OP 导入—计算—结果导出／原表导出完整运行，结果与固定语义基线一致。 |
| AC18 | 含错误行、文件错误和错误样本截断的 OP 导入，可完成既有自动报告流程；资源不足时保留真实业务与报告状态。 |
| AC19 | OP 发布观察、目标验证、自动报告和恢复不再单独硬编码统一 1 GiB。 |
| AC20 | 低内存重启恢复、已提交待确认、借用观察和未闭合载体测试通过，无自等待死锁。 |
| AC21 | 关闭外部程序后直接重试可重新判断；队列也能察觉外部内存释放。 |
| AC22 | 内存下降、磁盘满、权限不足、取消和强制退出不损坏原文件，不清除未完成恢复义务。 |
| AC23 | Windows 真实压力场景与注入数字测试分开记录；正常档／低档结果验证器开销单独计量。 |
| AC24 | 本版本生产启用依据为用户对人工验收通过的明确确认，随包记录确认来源／日期与每个 profile 的配置摘要。预算／缓存配置改变后原确认不得自动放行；运行时内存和并发保护持续生效。压力报告保留为诊断材料，不再作为启动资格的必填项。 |

## 5. 影响范围

前端以 `src/renderer/dialogs/toolbox.js` 和实际 Preload 窄 API 为主；业务 OP 保留既有领域控制器及反馈边界。Main 只做接线、源身份和资源所有权，不重新集中领域算法。

后台涉及共享资源准入、Toolbox 前置扫描、公共 XLSX provider 的参数传递、rows 缓存／writer、OP 各阶段及发布恢复。公共模块仍不能反向依赖业务模块；领域只注册真实能力。[S13](baseline-evidence.md#s13) [S14](baseline-evidence.md#s14)

新增的准备阶段 IPC／版本化结果需要同步校验、预览和集成测试。精确字段和 proposed 接口在 TechDoc 中定义；保留的旧调用明确兼容，但生产按行路径不得回退旧全量扫描。

不新增主数据库中的批量业务数据。前置扫描、共享字符串和工作库归原任务／新建扫描会话的私有临时区，不与用户输入输出的“永久保留”设置混为一谈。

## 6. 技术决策

| 决策 | 选择及原因 |
| --- | --- |
| D01 | 固定账本＋实时准入；避免冻结启动可用内存成为目标功能永久容量。 |
| D02 | 先按真实生命周期大阶段使用实测峰值档，不实现 worker 内每个小步骤的动态租约伸缩。 |
| D03 | 首版低档串行，未知增长等待退出；不做基于粗略 RSS 的未来增长预测。 |
| D04 | 基础扫描先行；首次激活当前字段“值”入口才补扫，支持默认首字段、单列及多分组；公共检查不继承 rows 专属大小限制。 |
| D05 | 共享字符串及样式访问优先复用现有公共机制；保留工具箱自己的 Sheet／行／格式适配。 |
| D06 | 当前阶段额度、缓存及余量按用户人工验收确认登记生产清单；配置摘要改变需重新确认。人工确认不等于任意文件／机器的容量保证。 |
| D07 | 正常与低档保持相同业务输出；不采用直接全局调小常量、关闭防护、退回 Main 或自动改变拆分份数。 |
| D08 | 执行配置随可信租约绑定，Renderer 不能指定配额或伪造低档证据。 |

## 7. 数据／状态／安全影响

### 7.1 数据与状态

业务金额、日期区间、归属键、血缘、样式语义、结果／归档状态及发布 journal 不改。新资源／扫描状态是技术状态，不替代业务结算状态。

获批配置仅用于本次执行。需要记录时写入受控诊断／任务私有资料，不能把一个可重用的“跳过准入 token”存入业务计划。旧恢复记录缺少资源字段仍按已知旧格式读取；本次恢复的资源资格另外获得。

### 7.2 安全与所有权

资源许可不是文件删除或发布许可。扫描 token 绑定发起窗口、会话代次和源身份；不允许任意路径读取、跨窗口取消或删除别的任务目录。仅清理能证明属于本会话且已关闭的临时资源。

金额和行契约变化不在本次授权内。诊断只记录阶段、资源、大小、计数、耗时和脱敏身份；不记录资金明细、单元格正文或凭据。

### 7.3 兼容与回滚

临时低档关闭必须与目标阶段准入策略配套，不允许“恢复旧大内存执行但保留低额度准入”。已运行任务继续按照获批配置完成或按原协议恢复，不能运行中替换配置。

发生未完成发布／新私有资料尚未闭合时，不进行破坏性版本回退或删 journal。回滚步骤与持久兼容性见 TechDoc §九。
