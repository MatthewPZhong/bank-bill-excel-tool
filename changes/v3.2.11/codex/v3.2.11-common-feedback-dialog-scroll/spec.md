## 1. 背景

原始问题：前置资金对账处理模块导入链接表后，文件数量较多时，导入结果弹窗底部的“删除错误数据”按钮被遮盖；缺少可用的纵向滚动条，导致无法操作。

进一步核对发现，该入口使用的公共提示／确认工厂，默认正文缺少统一的纵向滚动保护。其他调用这些工厂的长内容反馈也有同类风险；部分入口已经做过局部修复，但覆盖不一致。用户已同意将本次范围扩大为公共提示／确认弹窗修复。

本次目标由“只修前置资金导入反馈”调整为：**以两个公共工厂为边界，统一提供正文滚动和底部操作区保护；前置资金为首要业务验收场景。** 报错、警告、成功汇总和确认提示均可受益，不按消息类型、具体模块或调用方是否传滚动参数来决定是否保护。

这仍是前端可用性修复。不改变业务导入、错误修复、导出、对账、删除范围、状态或文件处置规则，也不升级为所有弹窗的统一重构。

## 2. 代码现状（附出处）

### 2.1 共性布局

`src/renderer-dialogs.js` 中的 `createAlertDialog(message, options)` 与 `createConfirmDialog(options)` 均创建下列结构：[S1]

```text
.modal-card.alert-card
├── .alert-body
│   ├── .alert-icon
│   └── .alert-message
└── .dialog-actions
```

卡片已经具有纵向 flex、`max-height: calc(100vh - 56px)` 与 `overflow: hidden`。公共 `.alert-body` 主要配置排版、间距，没有统一的纵向滚动规则；公共 `.dialog-actions` 没有统一的不可收缩保护。现有长文本换行规则不等于纵向滚动保护。[S2]

**高度上限与裁剪本身不是需要删除的错误规则。** 应补齐正文可收缩、可滚动与操作区保留空间的配套约束，而非移除高度限制，或让整张卡片连同按钮一起滚动。

## 3. 目标

### 3.1 必做

两个公共工厂默认生成带统一布局标记的反馈卡片。正文短时自然展示；正文长时可独立纵向滚动。已有按钮完整可见、可操作，横向空间不足时换行。此能力不依赖每个业务调用点额外传入 `scrollable: true`。

所有调用这两个工厂的生产入口原则上纳入。盘点中若发现包装层覆盖卡片类名或重排正文／操作区，须在保持原业务合同的前提下完成该包装层的兼容，不把它留成未声明例外。

### 3.2 必须保留

保留完整的原有正文生成结果、按钮文案与顺序、危险样式、业务参数、业务回调、日志选项、关闭资格和宿主管理。既有两种局部滚动样式／标记保留兼容，不要求删除才能获得公共保护。

前置资金的修复范围仍来自 `canRepair === true` 且带 `repairToken` 的失败项；不以可见行、滚动位置或文件总数决定修复对象。[S3]

### 3.3 明确不做

不全局修改所有 `.modal-card` 或所有 `.alert-card`；不强制迁移 VCC 等独立弹窗；不改系统原生对话框、表格管理或配置编辑结构。

不新增分页、虚拟列表、导入数量限制或日志平台；不重做错误文案；不改后台内存、SQL、IPC、批次状态、归档、原文件处置、修复 token 或业务并发规则；不顺带升版、提交、推送、开 PR 或发布。

**不通过截断现有正文来修复布局；也不取消原业务已经存在的采样／展示上限。** 例如工具箱已有提示样例上限，仍按原规则生成正文。前置资金原本完整的文件列表继续完整展示，不擅自缩减。

## 4. 功能点与验收

### 4.1 公共入口默认保护

由 `createAlertDialog()`、`createConfirmDialog()` 统一增加专用布局类，推荐名称为 `.feedback-dialog-card`。保留 `.modal-card` 和 `.alert-card`，不修改工厂签名或 overlay 返回形状。

业务调用不必改成新的工厂或新增参数。普通提示、警告、报错、成功汇总、二按钮／三按钮确认框遵循同一布局合同。后续重新创建的反馈自然继承保护，无须逐个修复返回链。

### 4.2 正文滚动与操作区

沿用现有卡片外观和视口约束；正文采用可收缩的单一主要纵向滚动区。支持滚轮、触控板、系统滚动条和键盘滚动，不主动隐藏滚动条，不强行覆盖系统自动隐藏滚动条设置。

操作区是正文的同级正常布局节点，不随正文滚动、不覆盖最后一项。空间不足时按钮按原顺序换行，按钮文字可换行、触达区域不被压扁；不靠全局固定浮层或提高 `z-index` 补救。

业务消息内已有的表格／代码块局部滚动不得被一刀切删除。本次保证外层正文与 footer 的可达性，不为实现“单一主要纵向滚动区”重写所有富文本内容。

### 4.3 键盘与生命周期

正文提供带可访问名称的键盘焦点入口，继续由现有宿主管理 Tab 环与关闭后焦点恢复。**保留既有首次初始焦点，不在构造阶段因新增正文 `tabindex` 抢占第一个按钮／输入控件的焦点。** 技术方案利用当前宿主先安置初始焦点、后执行 `onMount` 的顺序接入正文焦点。[S6]

不新增全局 Enter 快捷键，不自动点击危险按钮；Enter／空格作用于原按钮时仍是原动作，作用于正文时不得变成修复／导出。已有业务 `canClose`、busy、owner、父子栈、日志和关闭回调不变。

### 4.4 验收标准

保留原 AC01–AC09 的主要意图并扩大覆盖；原 AC10 的“其他公共框不命中”改为“独立结构不误伤”，补充 AC11–AC16。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC01 | 前置资金大量文件且有可修复错误 | 首次展示即看到“删除错误数据并重跑／导出错误数据／关闭”；全部按钮在卡片与视口内且可被真实鼠标命中，无需滚到底 |
| AC02 | 所有公共框的长正文 | 正文可滚到最后一项；顶部／中部／底部位置下 footer 稳定且不覆盖正文；卡片本身不再形成第二个主要纵向滚动区 |

| AC08 | 业务副作用边界 | 打开、滚动、resize、关闭不新增修复／导出；关闭不删除；结构／身份错误不因布局变化变成可修复；既有忙碌和重复点击行为不回退 |
| AC09 | 键盘和主题 | 首次初始焦点保持；Tab／Shift+Tab 可到达正文及按钮，焦点可见、不穿透底层；正文滚动不触发业务；深浅主题可读 |

| AC14 | 已有局部保护与包装层 | `.toolbox-split-rows-result`、`.big-account-unmaintained-alert` 与公共规则兼容；已盘点的公共工厂包装层不能覆盖掉保护标记或把 footer 搬进正文而漏修 |

## 5. 影响范围

生产代码重点为 `src/renderer-dialogs.js` 的两个公共工厂及内部布局辅助函数，以及 `src/styles-gemini-extra.css` 的专用选择器。

原则上不改各业务调用方；若盘点发现覆盖类名／重排结构的公共工厂包装层，则仅修正其布局兼容，并在 TechDoc 实施记录列明证据。不能借此重构控制器、模块状态或各领域的消息格式。

## 6. 技术决策
