## 1. 结论

**核心方案可以采用。本次未确认需要阻断实施的设计缺陷。** 保留卡片高度约束，通过两个公共工厂统一标记，让正文收缩并滚动、操作区保留空间，能够解决原始的前置资金长导入结果遮挡按钮问题。隔离 Electron 实验复现了基线缺陷，也验证了附件示意对该问题的改善。

**其他模块确实有同类风险，而且并非全部经过这两个工厂。** 资金对账、工具箱等公共入口会获得本方案的默认保护；另外发现平盘对账“账户映射保存失败”的自建提示框，在长错误消息下同样会遮挡按钮，但按 r2 的明确边界不会被本方案修复。应把这个具体事实补入范围说明，不能把本功能对外描述成“所有模块报错框已修复”。

建议保留当前技术方向，补齐下文两项定稿说明。方案审查通过不表示实现完成、全仓入口已验收或 Windows 验收通过。

## 3. 定稿建议与范围外风险

### OBS-01：补入平盘账户映射自建报错框，明确公共修复后的剩余风险

**分类：已证实的范围外同类风险，非 r2 明确范围内的漏实现，不阻断公共方案。**

文档位置：[Spec §2.2](/Users/pzhong/Downloads/v3.2.11-common-feedback-dialog-scroll-spec.md:42)、[TechDoc §3.2](/Users/pzhong/Downloads/v3.2.11-common-feedback-dialog-scroll-techdoc.md:103)、[TechDoc §8](/Users/pzhong/Downloads/v3.2.11-common-feedback-dialog-scroll-techdoc.md:370)。文档正确指出同名 `.alert-card` 不一定来自公共工厂，但当前代表清单没有这个具体的未保护报错入口。

源码证据：

- [showNestedAlert()](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/src/renderer-position-reconciliation.js:1275) 自行构造 `.modal-card.alert-card → .alert-body / .dialog-actions`，没有调用 `createAlertDialog()` 或 `createConfirmDialog()`，也没有专用滚动类。
- [账户映射保存失败链](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/src/renderer-position-reconciliation.js:1408) 将异常的 `error.message` 或失败结果的 `saved.message` 交给该自建工厂。
- 实验装载实际 Position 控制器，通过既有映射预览入口打开表单，再用虚构失败结果触发实际保存失败回调。即使公共工厂已经临时套用附件方案，该独立框仍没有公共标记：在 `1080×760` 内容区中，卡片底边为 `732px`，确认按钮底边为 `2563.25px`，中心点无法命中，正文 `overflow-y: visible` 且不可纵向滚动。

这证明该布局遇到足够长的错误消息时会复现同类问题；并不证明用户曾在真实业务中收到本实验长度的错误。

建议在 Spec §2.2 补一行：

> 平盘对账 → 账户映射保存失败：独立自建提示框，长错误消息已在隔离实验中复现按钮被裁剪；不经过本次公共工厂，因此本分支默认不覆盖，保留为已知待处理项及负向回归入口。

如果以后决定一并修复，应明确将这一具体入口加入范围及验证矩阵；本轮不自行扩大既定范围，也不要求因此重构所有独立弹窗。

## 5. 已核实的关键技术决策

1. **独立标记的边界合理。** 仅两个工厂添加 `.feedback-dialog-card`，避免直接改变所有 `.modal-card` 或同名 `.alert-card`。这也意味着 OBS-01 这样的独立框不会自动被修复。
2. **焦点顺序的依据正确。** [scheduleFocus()](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/src/renderer/modal-host.js:151) 先同步执行 `focusDefault()`，帧回调仅在当前焦点不在 overlay 内时兜底；[onMounted()](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/src/renderer/modal-host.js:282) 随后运行描述符回调。附件在 `onMount` 才给正文增加 `tabindex`，在本基线能保持首次按钮焦点。实验中 Shift+Tab 可进入正文。
3. **日志合并方案正确。** [registerModal()](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/src/renderer/modal-bridge.js:9) 串接 `onMount`；原 alert 日志回调保留。实验中基线与提案各产生一次日志。
4. **生产 CSS 的测试要求必要且已正确识别。** [现有 reset()](/Users/pzhong/Desktop/Project/bank-bill-excel-tool/scripts/renderer-lifecycle/electron-main.cjs:26) 默认只是 data URL 和实际 Renderer 脚本，不自动加载生产 CSS。不能用现有“真实 DOM”测试替代实际级联与几何验收。
5. **业务语义保护恰当。** UI 滚动不需要改变 repair tokens、删除范围、导出、IPC、side-DB、归档、金额或状态契约。附件保留既有回调与关闭资格的要求符合本次需求。
