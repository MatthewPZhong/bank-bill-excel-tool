## 1. 背景

用户要求移除存档中心点击批次删除按钮后出现的以下提示文案：

> 该批次信息及存档中心保存的原始文件将一并删除，删除后无法恢复。本次涉及 X 个存档文件副本。

本次按“仅移除指定说明文案”解释，不取消删除确认弹窗，不改变永久删除行为，也不增加替代说明。

## 2. 实施前代码基线

实施前实现位于 [`src/renderer/dialogs/app-settings.js`](https://github.com/MatthewPZhong/bank-bill-excel-tool/blob/18b82b4328cf5e00c1b2549d373a5b2f2677215c/src/renderer/dialogs/app-settings.js#L1380-L1485) 的批次删除确认逻辑中。

删除入口先调用 `prepareDeleteBatch(batchId)`；预检成功且存在 `confirmationToken` 后，使用 `createConfirmDialog` 打开确认弹窗。基线中的 `message` 由三个部分组成：确认问题、固定删除说明、根据 `prepared.summary?.fileCount` 生成的可选数量说明。

保持不变的确认问题为：

> 确定永久删除批次 **{批次号}** 吗？

确认按钮为【永久删除】，取消按钮为【取消】。点击确认后调用 `deleteBatch(batchId, prepared.confirmationToken)`；成功、失败及文件清理未完成的反馈分别沿用既有结果处理。以上均见同一固定基线源码。

**证据范围：** 原方案依据上述固定提交的源码；本次建分支再次核对当前本地 `main` 与 `v3.2.10` 指向同一提交，新 worktree 初始干净。本次未纳入主工作区既有未跟踪材料，也不代表已检查其他功能分支的实现。

## 3. 目标

必须移除用户指定的全部说明，包括动态的“本次涉及 X 个存档文件副本。”；同时移除这段说明专属的换行，不留下空白占位。

保留原确认问题、真实批次号、【永久删除】与【取消】按钮，以及现有预检、确认提交、关闭资格、反馈和列表刷新逻辑。

明确不做：取消二次确认、点击批次删除按钮后直接执行删除、将永久删除改为软删除、修改删除范围或数据结构、调整存档保留期限、修改其他模块或其他操作的确认文案。本分支不承担版本号升级或发布动作。

## 4. 功能点

### 功能点 1：删除确认弹窗文案精简

**输入：** 存档中心已有批次，以及通过既有预检取得的删除确认上下文。

**修改前：**

```text
确定永久删除批次 {批次号} 吗？
该批次信息及存档中心保存的原始文件将一并删除，删除后无法恢复。
本次涉及 X 个存档文件副本。

[永久删除]  [取消]
```

数量说明仅在当前实现判定数量可展示时出现。

**修改后：**

```text
确定永久删除批次 {批次号} 吗？

[永久删除]  [取消]
```

以上只表达保留的内容，不要求改变现有按钮排列、样式或弹窗宿主。正文较短时由现有布局自然排版，不为本次需求重设计弹窗。

### 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 删除预检成功，打开确认弹窗 | 保留原确认问题和目标批次号；指定固定说明与动态数量说明均不出现。 |
| AC-02 | 预检数量为 0、1、多份，或未提供数量摘要 | 均不展示文件副本数量；文案变化不影响原预检与确认流程。 |
| AC-03 | 点击【取消】或通过原有允许的方式关闭 | 不调用实际删除接口，不改变批次和文件数据；返回行为沿用现状。 |
| AC-04 | 点击【永久删除】 | 仍使用当前批次的原预检令牌；提交中防重复点击，原按钮忙碌状态和关闭限制不变。 |
| AC-05 | 预检失败、删除失败，或返回文件清理未完成 | 不越过预检或伪报完全成功；原错误提示、未完成反馈和恢复方式保留。 |
| AC-06 | 删除成功、切换浅色/深色主题、重新打开弹窗 | 仍按原逻辑刷新列表和详情；无说明残留或专属空行，批次号安全显示，按钮可见可用。 |

其中 AC-03 至 AC-06 是对既有行为的回归要求，不是新增删除规则。

## 6. 技术决策

采用调用点精简方案：将 `message` 保留为原确认问题，移除仅用于数量说明的 `fileCount` 和 `scopeSummary` 局部变量。详细代码差异见 [TechDoc §三](./techdoc.md#三需求实现)。

不采用全局隐藏样式或修改公共确认组件，以免波及其他弹窗；不删除后端 `summary.fileCount` 字段，也不因其不再展示而移除预检。

## 7. 数据 / 状态 / 安全影响

本次是展示层变化，删除动作的永久性、影响范围、令牌校验、业务状态和清理机制均不变。继续保留 `escapeHtml(batchNumber)`，避免批次号进入 HTML 时失去转义。

主要风险是误删整个确认环节，或将“前端不再展示数量”扩大为删除后端预检合同。按 AC-03 至 AC-05 回归约束。

回滚仅恢复本分支文案与对应测试，不涉及数据库迁移。**回滚文案不能恢复已经按既有流程删除的数据。**
