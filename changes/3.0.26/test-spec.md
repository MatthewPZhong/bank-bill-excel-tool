## 4. R5 `Extra Fee`

两种 R5 来源和多对多审计均覆盖：

| 场景 | 银行数据 | 对手金额 | 预期 |
|---|---|---|---|
| 正手续费 | Debit=100, Fee=5 | 105 | 命中 |
| 负手续费 | Debit=100, Fee=-5 | 95 | 命中 |
| 空手续费 | Debit=100, Fee='' | 100 | 命中 |
| 分位边界 | Debit=100.004, Fee=0.005 | 对应分值 | 按现有转分规则 |
| 相差 1 分 | 合计与对手相差 0.01 | - | 不命中 |
| 合计为 0 | 主金额与负手续费抵消 | 0 | 按公式比较，不重新绝对值 |
| 合计为负 | 负手续费绝对值大于主金额 | 正/负对手金额 | 两者都不命中；对手金额仍按既有规则取绝对值 |
| 科学计数法 | Fee='5e-1' | 含 0.5 | 命中 |
| 非法手续费 | Fee='abc' | 任意 | 退出候选并产生一次 warning |

- 非法手续费行不能阻止其它合法行匹配。
- warning 包含稳定 code、银行 `_rowId`、字段名，并在 message 中显示原始手续费值；同一 `_rowId` 每次运行只告警一次，缺少 `_rowId` 才按对象身份去重。
- 即使所选来源没有对手数据，方向合规的非法手续费银行行仍必须产生 warning。
- 回归同日优先、日期容差、账号/币种/方向隔离、多候选、严格 1:1、同值消费和 `usedBankRowIds`。
- 多对多异常说明必须基于含手续费后的候选关系。
- DBS-Charge 两个步骤分别加入非零 `Extra Fee` 回归：步骤1只与旧 `abs(Credit-Debit)` 金额命中；步骤2也只与旧金额命中，结果须与无手续费字段时一致。
- 错误报告回读确认 `r5-invalid-extra-fee` 的“可能原因”不是“未知错误”，可见消息包含行身份与原始手续费。
