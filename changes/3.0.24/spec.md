## 0. 任务摘要

- Goal：新增「平盘对账数据处理」主页面占位模块，并让 Payment 线下调拨订单回填支持严格隔离的多个大账号。
- Context：主模块必须同时登记 renderer `MODULES` 与设置仓储 `ALL_MODULE_IDS`；Payment 当前用单个 `bigAccount` 同时筛银行 `MerchantId` 和订单 `收款账户（卡号）`。
- Constraints：平盘模块不接业务 IPC、数据库或 Excel；Payment 保留现有字符串配置字段、金额币种日期规则、三轮阶梯和全局 1:1 消费。
- Done when：AC-01～AC-20 通过，全量门禁、主页面缩放检查和重要变量检查完成；多账号真实或脱敏样本仍须人工确认无跨账号回填。

## 2. 平盘对账数据处理前端契约

### 2.1 模块与页面

- `MODULES` 与 `ALL_MODULE_IDS` 同步登记 `position-reconciliation-process`；`DEFAULT_ENABLED_MODULES` 不变。
- 页面复用「对账单修复」两行布局、轨道尺寸和原按钮样式：
  - 第一行左侧：`功能`下拉框 + `开始运行`。
  - 第一行右侧：`对账表管理` + `链接表管理`。
  - 第二行左侧：保留原标签轨道空位，原场景下拉槽位改为`对账配置管理`，其后为`导出文件`；页面不得显示“场景”。
  - 第二行右侧：状态框，初始文本“欢迎使用小助手”。
- 功能枚举固定为：

| value | label |
|---|---|
| `position-fund-nature-check` | 平盘资金性质校验 |
| `position-data-info-backfill` | 平盘数据信息回填 |
| `position-order-writeoff` | 平盘订单销账处理 |

- 默认选中 `position-fund-nature-check`；模块间切换时 DOM 保留本次会话选择，应用重启后恢复默认。
- 五个按钮点击统一调用 `showComingSoon(按钮名)`；不得调用 import/run/export/manager 业务接口，不建立存档批次。
- 按钮视觉固定为：仅`开始运行`使用蓝色主按钮；`对账表管理 / 链接表管理 / 对账配置管理 / 导出文件`使用白色次按钮。`开始运行`与`导出文件`宽度均为 `140px`，不得被父级通用样式撑到 `180px`。

### 2.2 视觉边界

- `对账配置管理` 占原场景 select 的第二列，第一列保留空轨道，避免整行左移。
- 新状态框使用统一 `.status-box-content / .status-spark / .status-box-text` 结构。
- 新模块加入独立 preview、模块收纳测试和主页面 `1240x860` / `1080x760`、100% / 125% / 150% 几何门禁。

## 3. Payment 多大账号契约

### 3.1 输入与持久化

- 输入例：`202782001、202782002`。
- 保存时按 `、` 拆分，每段 trim；以下情况在原弹窗显示错误并阻止保存：
  - 整体为空、首尾顿号、连续顿号或空白段。
  - trim 后存在完全相同的重复账号。
  - 出现英文逗号 `,` 或中文逗号 `，`。
- 大小写不同的账号视为不同值；不去前导零、不做模糊匹配。
- 保存值规范化为账号原序、顿号连接字符串，仍写入 `config.paymentOfflineBackfill.bigAccount`。
- 老配置不含顿号时视为单账号；无数据库迁移。

### 3.2 引擎匹配

- 引擎运行时再次严格解析配置；非法持久化值安全 no-op，并输出 `payment-offline-invalid-big-account-config` warning。
- 订单池只收录 `收款账户（卡号）` 属于账号集合的行；银行池只收录 `MerchantId` 属于账号集合的行。
- 任一匹配对还必须满足 `trim(bank.MerchantId) === trim(mid.收款账户（卡号）)`，区分大小写。
- R1/R2 周桶按账号隔离；R3 全池兜底也必须先满足同账号，禁止跨账号借用候选。
- 多账号共用 `bankChannel` 和 `region`，共用现有银行行/订单行消费集合；配置账号顺序不参与 tie-break。
- 现有金额、币种、日期、周数、网关回填优先、matchedPairs、warning 和 Excel 契约保持不变。

## 4. 非目标

- 不实现平盘对账导入、运行、管理、导出或存档功能。
- 不新增业务 IPC、数据库表、配置持久化或 Excel 模板。
- 不支持每个大账号单独配置银行渠道或地区。
- 不修改 Payment 金额、币种、日期窗口、排序和回填字段。
- 本迭代不包含 PR、合并、tag 或 GitHub Release。

## 5. 验收标准

- AC-01：新模块出现在闲置功能，启用、排序、切换和 current module 持久化正常。
- AC-02：默认启用模块列表不增加新模块，既有用户启用顺序不变。
- AC-03：页面严格显示三个功能枚举、五个按钮和初始状态文案，不显示“场景”。
- AC-04：`对账配置管理` 保持原场景下拉槽位，页面无重叠、截断或水平漂移。
- AC-05：五个按钮只显示占位提示，不触发业务 IPC、文件选择或存档写入。
- AC-06：功能默认第一项，当前会话切换保留，重启恢复默认。
- AC-07：合法单账号和多账号保存为规范化 `bigAccount` 字符串。
- AC-08：首尾/连续顿号、空段、重复账号、`,`、`，` 均阻止保存并保留草稿。
- AC-09：旧单账号配置加载、保存和运行结果不变。
- AC-10：两个账号各自的银行行只匹配同账号订单。
- AC-11：金额、币种、日期完全相同也不得发生跨账号回填。
- AC-12：某账号没有同账号订单时，不借用另一账号订单。
- AC-13：R1、R2 和 R3 三轮均保持账号隔离。
- AC-14：多账号共享原全局 1:1 消费集合，不重复使用银行行或订单行。
- AC-15：账号配置顺序不改变银行顺序、就近排序和候选赢家。
- AC-16：非法持久化配置不匹配任何行，并输出可见配置 warning。
- AC-17：`matchedPairs` 结构、三张核对 sheet 和回填字段不变。
- AC-18：编排器 gating、R5s2 排除集合及主库读取行为不变。
- AC-19：修改行/未命中行守恒及 warning 汇总不回归。
- AC-20：版本文档、重要变量、全量门禁、预览和启动性能检查完成。

## 6. 资金红线
