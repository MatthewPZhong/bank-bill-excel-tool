## 2026-05-26（spec 阶段）

### 起源
用户提出需求："在网银账单生成里引入网银原始账单获取功能，通过对渠道定制化 RPA 方式实现，RPA 功能与软件影刀 RPA 一样，思考下如何实现"。

### 关键决策（用户拍板）

| 决策项 | 选择 | 备选与拒绝原因 |
|--------|------|--------------|
| 试点范围 | **1 家银行先做** | 拒绝"做通用框架后扩渠道"——风险高、价值滞后 |
| 自动化级别 | **半自动**（用户登录 + 程序操作） | 拒绝"无人值守"——凭证存储+短信处理合规雷区 |
| 网银类型 | **工商银行企业网银（Web 端）** | 拒绝桌面客户端 RPA——跨平台、依赖 nut-js 等重依赖 |
| 录制器 | **不做**，开发者写 JSON 脚本 | 拒绝可视化编排——工作量爆炸 |
| 引擎 | **Electron BrowserView**（无新依赖） | 拒绝 Playwright（+200MB） |
| 账单类型 | **仅交易明细流水** | 拒绝 PDF 回单/余额表/月度对账单——MVP 缩小范围 |
| 日期范围默认 | **昨日**（用户可改） | 拒绝"上次抓取至今"——需额外状态 |
| 分支 | **v3.0.0** | 由用户选定；非 v2.1.x（v2.1.x 是维护型） |

### 风险红线（spec §6 / §7 落地）

⚠️ **资金/认证/凭证 三连敏感**

1. 凭证零存储（MVP）
2. partition 强制 `in-memory:`
3. 下载白名单 + 大小限制
4. DevTools 默认关闭
5. 日志/截图脱敏
6. **银行用户协议**需法务 review
7. **真实测试账号**未到位时不能进 Phase 2
