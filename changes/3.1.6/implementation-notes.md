# v3.1.6 Implementation Notes

## Decisions

| ID | Decision | Rationale | Status |
|---|---|---|---|
| D1 | 新增 `changes/3.1.6/spec.md`，不修改已发布的 v3.1.5 spec | 仓库当前版本为 3.1.5，原 `changes/3.1.5/spec.md` 是已发布的 Release 恢复审计记录 | active |
| D2 | 四类原表分别以业务字段作为全历史幂等键 | 用户指定字段；2026-06 样本内均无空值和重复 | active，实施前需完成历史门禁 |
| D3 | 同键同内容跳过，同键异内容阻断，不做静默覆盖 | 避免重复计入，同时防止不同业务事实被导入顺序覆盖 | active |
| D4 | 每个逻辑原表的一次用户导入为原子边界 | 防止大文件、分片、取消或重试留下部分可计算数据 | active |
| D5 | 性能口径为单批多分片合计 500 万行 | 单个 Excel 工作表无法承载 500 万行，真实通道样本也是多分片输入 | active |
| D6 | 幂等跳过保留逐行审计，并关联本次行与已保留行 | 用户需要知道具体幂等了哪些数据；仅有数量无法解释数据去向 | active |
| D7 | 「校验原表」右侧直接展示「导入记录」，每行粒度为父批次 × 原表类型，并以已导入月份账期单选筛选 | 明确入口和记录粒度；多分片合并展示，同时保留失败/回滚审计 | active |
| D8 | 数据状态（未处理/已归档）与导入状态拆为独立字段 | 前者描述账期有效数据集生命周期，后者描述不可改写的单次导入结果；归档不得篡改导入审计 | active |
| D9 | 系统财务OP按「账期 × 正式模板主体」唯一 | 正式模板与真实明细样本均提供「主体」列；同内容可安全重试，异内容必须暴露双方血缘 | active，取代旧文件级主体决定 |
| D10 | 缺少上月归档时使用一次性人工九币种期初 | 禁止默认 0 或拿待校验的系统值反向充当期初；相同内容重试跳过，不同内容禁止改写 | active |
| D11 | 已归档账期全局冻结，不提供撤销或原地重算 | 本月余额是下月期初来源，补数或回写会破坏跨期血缘 | active |
| D12 | 金额最多 2 位小数和 15 位有效数字，超界拒绝且不舍入 | 与 Excel 可安全展示边界一致；系统 OP 使用单元格显示值隔离底层浮点尾差 | active |
| D13 | Pending 币种相等时“是否错币”取 FALSE | 以正式业务 spec 为准；该字段不参与 J:K 金额汇总 | active |
| D14 | 行数守恒增加事务回滚行数 | 原子失败时，已解析但未提升的正常行需要独立且互斥的最终去向 | active |
| D15 | 失败记录需处理说明和显式“保留当前有效数据集”动作 | 解除运行门禁时不能让用户误以为失败数据已修复或已纳入计算 | active |
| D16 | 同文件多张同类型表按歧义拒绝，表头搜索范围统一为前 220 个非空逻辑行 | 防止识别与正式导入选择不同 sheet 或漏掉前置说明行后的真实表头 | active |
| D17 | staging 每 50,000 行提交一次，但完整校验通过前绝不提升为有效事实 | 500 万行事务需控制 WAL 与崩溃恢复成本；已提交 staging 仍是非有效数据 | active |
| D18 | 取消优先通过 worker 控制消息协作收口，120 秒无响应才强制终止 | 协作取消可保存已读取行的逐行回滚审计，同时保留卡死进程的最终退出能力 | active |
| D19 | 本月计算主体集合包含上月已归档主体 | 防止主体当月无明细时被静默丢失；缺本月系统快照必须显式阻断 | active |
| D20 | 父批次开始时预登记全部已识别原表类型 | 取消或前序类型异常时，尚未开始读取的类型也必须有可见、可处理的失败记录 | active |
| D21 | 非预期运行异常在当前进程内立即收口当前批次 | 不等待应用重启；暂存行转回滚、记录转失败并写错误明细，且不影响其他批次 | active |
| D22 | 活动导入批次在数据库层阻断计算和归档 | 覆盖父批次已创建但首条原表记录尚未处理的窗口，避免归档旧 revision | active |
| D23 | 数据删除按「月份账期 × 目标原表」执行，只删除未归档有效事实并作废未归档结果 | 用户确认该口径；已归档冻结、人工期初和历史导入审计均不得被改写 | active |
| D24 | 删除前把有效行/系统快照的对比侧数据固化到导入审计 | 幂等跳过和冲突记录当前通过外键读取被保留数据；直接删除会让历史明细失去对比侧证据 | active |
| D25 | 删除走单 worker 单事务，提交前执行删除数量和残留状态不变量校验 | 百万级删除不能阻塞 Renderer；触发器、未来 schema 漂移或静默忽略不得被误报为完整成功 | active |
| D26 | 数据管理页面标题对齐表格首列，导航对齐页面标题；删除页按 25%/40% 双列及 10px 间距展示账期和目标表 | 用户明确给出各文本、下拉框的对齐锚点和比例口径；仅调整 VCC 页面局部布局，不改变删除行为 | active |
| D27 | 导入账期改用业务OP日期弹窗的横向年月双下拉结构，首次使用不静默预选，按钮顺序为“确定 / 取消” | 用户指定参考结构并要求移除日期下拉；保留原先首次必须明确选账期及 `YYYY-MM` 后端契约 | active |
| D28 | 最近操作账期超出当前年份前后各一年时不回显，恢复为显式选择 | 保持参考弹窗的年份枚举，同时避免浏览器自动选择首个年份造成账期静默漂移 | active |
| D29 | 运行账期弹窗移除可见字段标签，账期下拉框使用内容区宽度的 25% 并直接与标题左侧对齐 | 用户明确指定显示文本、宽度比例和对齐锚点；保留 `aria-label` 及原账期校验，不改变运行契约 | active |
| D30 | 运行账期操作区上边线下移 15px；导入完成只更新主状态框，不再打开导入记录框 | 用户明确指定交互收口；完整导入审计继续持久化并从数据管理查询，硬失败弹框继续保留以避免关键错误被忽略 | active |
| D31 | 系统财务OP只接受资产 `系统财务OP.xlsx` 的 16 列完整表头及原顺序 | 正式模板已经补入；严格契约可防旧横表或近似字段被误识别为资金余额来源 | active |
| D32 | 系统财务OP主体取「主体」、账期取「账单日期」、余额取「财务余额」显示值，目标月业务部门必须为 VCC | 与正式模板和 `财务OP (20).xlsx` 真实样本逐项一致；不再由用户输入覆盖主体 | active |
| D33 | 一个正式系统OP文件可形成多个主体快照，每个主体必须有归一化后唯一且完整的九币种行 | 模板按主体/币种逐行表达；继续沿用「账期 × 主体」快照唯一与冲突语义 | active |
| D34 | 旧 `YYMMOP + 系统行` 横表不再回退识别 | 用户要求严格模板表头；双格式并存会扩大误识别和金额列错取风险 | active，属于兼容性收紧 |
| D35 | 多主体系统OP文件中任一主体失败时，完整主体快照按事务回滚保留 | 文件级原子失败不能让已完整解析主体失去可见去向；原始读取数继续满足快照级守恒 | active |
| D36 | 选文件识别与正式导入二次校验共用模板差异明细，并跨 worker、main、renderer 完整展示 | 文件可能在选择后被替换；二次校验不能退化为无列定位的通用错误 | active |
| D37 | 已有系统快照时，同一失败批次的精确重放仍记幂等跳过，只有异内容快照记冲突 | 同一输入只能有一个最终处置类别；失败批次也不能把已证明相同的事实误报为冲突 | active |
| D38 | 数据管理导出以「账期 × 目标表」读取当前有效事实并生成新工作簿，不承诺还原原上传文件的字节、样式或非业务 sheet | 当前 schema 持久化完整业务表头/行值但未存原文件二进制；明确边界可避免把数据级导出误解为源文件归档下载 | active |
| D39 | 目标表下拉用「校验原表 / 校验表」分组承载类型，不增加第三个选择字段 | 用户指定筛选维度为账期和目标表；分组可在两个字段内消除同名系统OP及表类型歧义 | active |
| D40 | 删除后以独立生命周期列把成功类导入记录展示为「已删除」，原 `status` 不改写 | 满足列表状态口径，同时保留单次导入成功、跳过或失败的审计事实；失败输入未形成有效数据，不误标为被删除 | active |
| D41 | 校验表导出读取有效行中已持久化的主体、统计币种和有符号金额，不在导出时重算 | 保证导出内容与实际参与计算的数据逐行同源，避免导出逻辑与资金计算逻辑漂移 | active |
| D42 | 校验表生成时间使用独立 `generated_at`，只随实际新增有效事实刷新 | `updated_at` 会在归档时变化，直接展示会把状态更新时间误报为生成时间；全量幂等和失败没有生成新事实，不应刷新 | active |
| D43 | 系统财务OP数据库统计继续以主体快照为守恒单元，用户可见计数同时展示九币种原始行数 | 改写数据库计数会破坏既有幂等、冲突和回滚守恒；仅把 `1 快照 = 9 行币种数据` 明确展开即可消除“导漏八行”的误解 | active |
| D44 | 数据管理校验表显示名复用校验表导出定义 | Pending 校验表正式名称不带 `VCC_` 前缀；复用单一定义可避免页面、下拉框和工作簿名称再次漂移 | active |
| D45 | 用户明确授权执行正式收尾和发布收尾 | 最新指令允许生成稳定版技术资产；历史全量唯一性、真实资金逐项复核和 Windows 实机验证仍须按未执行披露，不能被发布状态替代 | active |

## Assumptions

- A1：四类业务键预期跨账期不复用；历史全量扫描通过前不得把该假设当成已证明事实。
- A2：系统财务OP是账期快照，不进入四类明细业务键的全历史唯一范围。
- A3：内容一致性比较排除导入元数据和派生字段，覆盖原表全部业务字段。
- A4：数据管理中的“导出校验原表”是当前有效业务数据导出，不等同于原上传文件下载；原文件样式、公式、隐藏行列和非业务 sheet 不在本次恢复范围内。

## Reconciliation Blindspot Pass

- 主键血缘：原始键、规范化键、来源文件、sheet、行号、批次、账期均要求持久化；不同原表使用独立命名空间。
- 幂等重复：数据库唯一约束、逻辑原表级事务、同键异内容阻断和跨分片测试已写入 spec；系统快照混合精确重放/异内容时分别记跳过/冲突，整批仍失败关闭。
- 守恒与可观测性：导入结果按新增、重复、空键、冲突和其他错误互斥分类；异常须在数据管理可见并可导出。
- 金额币种：严格币种白名单、方向枚举、2 位小数、15 位有效数字和精确十进制聚合；系统 OP 正式 16 列契约、“财务余额”显示值、CNY→CNH 及 Pending 双币种汇总均有边界测试。
- 状态生命周期：未归档计算可重跑并原子替换草稿；归档绑定输入 revision，归档后拒绝新增事实、改写快照、撤销和重算；下月人工期初与上月归档互斥。
- 部分失败：批次内全部已识别类型先登记；非预期异常即时收口当前批次，未开始类型也有失败去向；多主体系统文件的完整主体保留九行回滚血缘；活动导入在计算与归档事务内再次阻断。
- 可观测性：失败导入、同批/跨批冲突、精确重放、事务回滚、期初初始化和归档记录均可在数据管理查询；审计导出保留原表字段和来源定位。
- 删除生命周期：仅允许未归档账期按单一原表删除；事务内同步失效未归档结果、固化幂等对比侧、保留人工期初和导入审计，并以提交前不变量校验防止静默部分删除。月份入口继续由历史导入记录保留。
- 导出生命周期：仅查询确认导出时仍有效的事实；原表读取完整原始列血缘，校验表读取已持久化的主体、币种和有符号金额，不把失败、回滚、幂等跳过或已删除记录混入。系统快照在输出前再次验证正式 16 列和归一化九币种唯一完整。
