# T01：临时 SQLite 工作库与有序读取

结论：PR3 采用临时 SQLite 工作库。来源分片逐一打开，规范化记录同步写入工作库；建立 UTF-8/BINARY 组合键索引后，按游标在 JavaScript 中使用 financial-decimal 精确分组。不使用 SQLite REAL/SUM 处理财务金额。

有序分片归并本身可用，但需要每个活跃 part 保有真实连接和缓存；当分片数增大时，要么连接数随输入增长，要么另建多趟有限扇入归并。临时 SQLite 增加一次复制与临时磁盘，能够将读取连接固定为 1 个、写连接固定为 1 个，沿用公共 writer 的失败/事务控制，避免本期扩建归并框架。

## 小中型真实探针

`scripts/biz-op-v327/compute-route-probe.js` 生成独立临时 SQLite 分片，分别在新的 Electron Node 子进程比较二叉堆有序归并与临时工作库。两者均按 BINARY/UTF-8 比较 BU、账户、币种；样本含 BMP/非 BMP 字符、高精度正负十进制、重复键和入/出方向。每条原始行参与且仅参与一次。

环境：macOS arm64，Electron 36.9.5 / Node 22.19.0。

| 样本 | 路线 | 总耗时 | 复制 / 建索引 | 读取 / 写连接峰值 | 采样 RSS | 新工作库磁盘 |
| --- | --- | --- | --- | --- | --- | --- |
| 10000 行 / 8 分片 | 堆归并 | 44 ms | 0 / 0 ms | 8 / 0 | 70860800 B | 0 |
| 同上 | 临时 SQLite | 48 ms | 22 / 3 ms | 1 / 1 | 71712768 B | 856064 B |
| 100000 行 / 32 分片 | 堆归并 | 479 ms | 0 / 0 ms | 32 / 0 | 93519872 B | 0 |
| 同上 | 临时 SQLite | 459 ms | 198 / 41 ms | 1 / 1 | 90423296 B | 8790016 B |

两档输入分别形成 2500 / 25000 组，原行数量守恒、精确结果摘要相同：

- 10000 行：`46aff7e5655b53ce728c18f4b69ab87e6f1aeb860cb643cd94a704acebc7578c`
- 100000 行：`6b63e0bb0a39a54d0ee6354ee5218af3a58656c959f5796129260a03a61d81bc`

这不是全面性能排名；单次毫秒差异不作为决策依据。主要依据是资源所有权和连接上限可以固定。探针不替代真实 OP/FLOW 来源、描述冲突说明、两端缺失、19 列结果、取消/关闭、目标 400万/1400万规模或 Windows 验收。PR3 必须在同一既有准入 worker 内接通真实输入与说明落盘，不能把探针直接当作成品业务引擎。
