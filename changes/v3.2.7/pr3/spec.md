# PR3 区间计算与独立结果

Goal：实现固定两端 OP 和 `(S,E]` 每日流水的区间核对，保存同 run 的全量、差异及完整来源说明。基线 PR2 `bf196156`，保留生产关闭状态；本地验证、提交后直接推送并创建远端 PR。

Context：E01—E03 已获用户明确批准。T01 已选择临时 SQLite 工作库、BINARY 有序游标、共享精确十进制运算。复用真实 no-file Task、后台线程、关闭观察、读取 pin、Main 目录提交与 E5 恢复 driver。

Constraints：不改共享恢复平台核心，不修改原 E5 包，不触及真实用户数据。数据行不进入 Main/renderer，不使用 SQL REAL/SUM 或 JS 浮点计算金额。任一必需账期缺失阻断；相同流水单号不去重；已覆盖输入不继续作为新运行来源。

Done when：17 组批准样例逐列符合；真实导入到运行、固定清单、重复请求、流水变更、输入覆盖后历史独立、故障恢复及取消有证据；巨大单键和高基数描述保持有界内存；明确目标规模、Windows 与人工验收未执行部分。

## 计算合同

- 键为规范 BU、保留大小写/前导零的文本账户、规范大写币种。UTF-8/BINARY 逐字段排序，键使用结构化编码。
- 流水区间 `(S,E]`；各日必须存在 FLOW head。单键某方向无流水为 0。两端以各自 `end_balance` 核对。
- 流水反推 = 出 − 入；第 14 列 = 终止期末 + 反推；第 15 列 = 起始期末 − 第 14 列。绝对差额大于 0.01 才金额不平，保留原小差额和符号。
- 各端 OP 行数独立统计，任一端至少两行标多个 OP。数学相同余额只取一次；冲突/缺失余额空，其他键继续。
- 描述按 trim、区分大小写、空值单独比较集合。终止优先；选择端同字段多值留空，候选与全部 OP 来源入说明。双端都存在才比较描述变化。
- 19 列及原因组合顺序采用 E5 已批准样例：金额状态，再缺端、余额冲突、多个 OP、描述变化、同端描述冲突。异常说明链接稳定结果行号；详细值分成说明行，不拼接无界 cell。
- 实际 BU、两端及逐日输入身份/版本/来源摘要、原件集合摘要和规则/解析版本固定入指纹。中间 OP、区间外 FLOW 和运行时间不进指纹。
- 结果分片与 NOTES 分片同一 RESULT manifest；业务 rowCount 只计算结果行，说明单独计数。既有未标分片类型的 manifest 保持原语义，新结果明确标 RESULT/NOTES。
- 每条 OP 对应一个 ROW_SOURCE 说明，固定来源账期/版本/原件/源行以及用于解释的余额、三个描述值和 BU；不复制全部原表列。DESCRIPTION_SOURCE 固定逐字段取值、两端候选数及来源端。冲突候选的完整值保存在相应 ROW_SOURCE，多行说明可按业务键和结果行定位；单值超过 8000 UTF-16 单元时拆成连续片段，保留代理对。
- 同一输入若已有可用结果，复用原 run/version；重复不能占版本或改时间。独立 RESULT holds 保护全部固定原件。删除/覆盖输入后全部 19 列、说明和来源身份留在结果载体中。

## 资源与边界

单输入只读连接、单工作库连接、结果写入最多一个连接；每库 16 MiB cache、FILE 临时存储，公共 writer 4096 行/4 MiB 事务。描述集合由磁盘索引处理，JS 仅保留当前键的常量统计。结果/说明按 250000 行或 256 MiB 目标分片，manifest 64 KiB 限制保持；超预算明确失败，不截断发布。

计算按顺序产生说明分片，同时将每个已完成业务键的固定结果暂存为有界单行 JSONL；关闭说明写连接和工作库后，再顺序转写结果分片。这样无需在每个业务键上反复打开两个输出连接；代价是增加一份临时结果和一次顺序复制。临时结果不发布，只有关闭/删除自有临时文件后才封存整个结果对象。

输入预检先完整检查必需日期，随后通过现有 ArchiveService 核验原件；worker 在资源租约内再校验固定原件和分片的实际摘要。临时目录持续监测实际可用空间，最低保留 16 MiB 为失败停止线；它不代表已取得最大规模磁盘预估模型。

同步 SQLite 调用不能被定时器抢占；行循环定期让出 worker 消息循环，取消后仍等待真实载体关闭再释放读取保护。Windows 目录屏障与最终规模/人工门禁不因本阶段测试通过而解除。
