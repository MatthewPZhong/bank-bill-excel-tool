# v3.1.6 Unknowns Preflight 与实施结论

## Task Brief

- Goal：新增「VCC财务OP校验」，完成四类明细和系统财务OP的导入、幂等审计、发生额计算、跨月归档及双 Sheet 导出。
- Context：v3.1.6 spec 已定义业务键、方向公式、数据管理入口和输出模板；仓库已有大表流式读取、十进制金额和旧 VCC 业务 OP 计算能力，但不存在本功能的数据模型。
- Constraints：四类业务键跨文件、批次和账期唯一；单批多分片合计支持 500 万行；金额、主体、币种、账期和每行处置均可追溯；资金口径不得隐式兜底。
- Done when：功能、数据管理和导出可用；行数守恒与原子回滚成立；自动化、真实样本回放、重要变量检查和 self-review 均通过，且无 P3 及以上 Finding。

## 已确认事实

| 事实 | 证据 | 对方案的约束 |
|---|---|---|
| 旧 `VCC业务OP计算` 仅处理 28 列流水并合并币种 | `src/main-process/vcc-op-calc-session.js` | 新功能必须使用独立模块和表，不能复用旧模块的业务语义。 |
| 仓库已有 yauzl 单遍流式 sheet 扫描器 | `src/backend/big-table-import/zip-reader.js`、`row-scanner.js` | 大表导入可复用流式底座，但现有 pipeline 会按整文件缓冲解析结果，不适合保留 49 列原始行。 |
| 当前可访问的四类样本业务键均非空且唯一 | `spec.md` 3.7：2026-06 三类明细 5,018,417 行，2026-05 Pending 28,812 行 | 可按用户指定字段建唯一约束；正式启用仍需历史门禁。 |
| 充值、费用、通道样本金额均可落到分；通道交易金额可为科学计数法 | 只读流式抽样：36,932、300,000、300,000 行 | 金额解析必须支持十进制科学计数法，不能用字符串截取或浮点累计。 |
| 正式 Pending 原表有 48 列且包含主体，原始数据位于第二个 sheet | 正式业务样本“移除归档Pending账单.xlsx”；内置模板已同步为 48 列并通过直接识别测试 | Pending 读取必须按表头定位 sheet，不能固定读取第一个 sheet；内置模板必须与代码契约同步。 |
| 正式系统财务OP模板为 16 列行式表，包含账单日期、主体、业务部门、币种和财务余额 | `assets/VCC财务OP校验/系统财务OP.xlsx`、正式业务样本“财务OP (20).xlsx” | 主体和目标月从正式列读取，财务余额取显示值；旧横表不再作为兼容契约。 |
| Pending 样本公式把币种相等标为 TRUE，与 spec 的“相等为 FALSE”相反 | `VCC_移除归档Pending账单 - 副本.xlsx` 的 V 列公式及 Sheet2 | 布尔展示口径需业务确认；金额汇总本身按两侧币种分别汇总，不依赖该布尔值。 |

| 系统财务OP如何归属主体 | 已知未知 | 高 | 困难 | 正式模板提供「主体」列，结果按主体归档 | RESOLVED | 正式资产、真实行式样本及多主体快照测试 | 按模板「主体」分组，以「账期 × 主体」唯一；同内容跳过、异内容冲突。 |
| 首次使用且无上月应用归档时如何取得期初OP | 已知未知 | 高 | 困难 | spec 禁止隐式默认；样本含历史 OP/系统行 | RESOLVED | 期初初始化与不可改写测试 | 一次性人工录入九币种余额并填写核对说明；不默认 0，不取系统值兜底。 |
| 同月已归档后的重导、撤销和重算权限 | 已知未知 | 高 | 一般 | 归档余额会成为下月输入 | RESOLVED | 全局归档门禁和双来源测试 | 归档后冻结，不提供撤销或重算；精确重放只作幂等跳过。 |
| 金额精度和超 2 位小数处置 | 已知未知 | 高 | 一般 | 当前明细样本可落分，系统文件存在浮点尾差 | RESOLVED | 输入与聚合边界测试 | 最多 2 位小数、15 位有效数字；系统 OP 读显示值；超界拒绝且不舍入。 |
| Pending“是否错币”布尔语义 | 证据冲突 | 中 | 容易 | 文档与样本公式相反 | RESOLVED | 逐行映射测试 | 以正式 spec 为准：币种相等为 FALSE，不等为 TRUE；金额汇总不依赖该列。 |
| 账期来源及跨来源一致性 | 已知未知 | 高 | 一般 | 四类日期字段不同，正式系统文件按账单日期逐行表达 | RESOLVED | 真实样本和日期边界测试 | 导入显式选择账期；充值/费用取 BillDate、通道取账单日期、Pending 取平账账期，系统OP筛选所选月的账单日期。 |
| 既有历史数据是否满足全历史唯一 | 已知未知 | 高 | 困难 | 仅有 2026-06 唯一性证据 | PROBE | 扫描全部可访问历史文件/库 | 无既有本模块表；上线前仍需业务提供完整历史样本并人工复核。 |
| 同键冲突导致整批回滚时如何满足行数守恒 | 盲区 | 中 | 一般 | 原五类处置无法容纳已解析但因原子事务未提交的正常行 | RESOLVED | 损坏分片与同批冲突测试 | 增加“事务回滚行数”，在其他异常中逐行保留。 |
| 取消或前序异常发生在后续原表开始前时，导入记录是否完整 | 盲区 | 中 | 容易 | 延迟创建记录会让已选原表没有可见去向 | RESOLVED | 首类读取前取消测试 | 父批次开始时预登记全部已识别类型，未开始类型也即时收口为失败。 |
| 运行期非预期异常是否必须等待重启恢复 | 盲区 | 中 | 容易 | 仅启动恢复会让记录暂留“导入中”并阻断后续操作 | RESOLVED | SQLite 故障注入与批次隔离测试 | 当前进程立即收口当前批次；启动恢复继续作为强制终止兜底。 |
| 活动导入与计算/归档是否存在状态竞态 | 盲区 | 高 | 一般 | staging 不提升 revision，单靠 UI 锁可能归档旧结果 | RESOLVED | 空父批次计算/归档门禁测试 | 按账期查询活动父批次，在计算和归档事务内失败关闭。 |

除“全部历史数据唯一性扫描和业务人工资金复核”外，实施所需 BLOCK 已按失败关闭原则消除。历史门禁属于上线运营门禁，不由当前可访问的单月样本替代。最终 self-review 已完成，未保留 P3 及以上 Finding。

生产路径真实回放已完成：2026-06 三类明细 19 个分片共 5,018,417 行全部导入；协作取消和 worker 强制终止恢复均保持有效事实为 0；2026-05 Pending 28,812 行及正式 16 列 PPHK 九币种系统OP快照导入成功。详细耗时、内存、磁盘和处置守恒证据见 `spec.md` 6.1 与 `implementation-notes.md`。
