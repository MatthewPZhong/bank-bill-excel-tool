# Spec — 下线四个对账模块

> status: in-progress
> created: 2026-11-16
> 目标版本：v3.2.20（暂定，发版时按 weekly-release 调整）
> 适用分支：`feat/retire-recon-modules`
> 分支基线：v3.2.19 发布合并提交 `466bb6fa`（PR #254 已合入 main，`v3.2.19` 标签应指向该提交）。2026-11-16 自 `v3.2.17`（`a7f268f2`）创建，2026-11-18 先迁到 `v3.2.18`（`41d10180`）并顺延目标版本，同日再迁到 v3.2.19，见 TechDoc §九
> 依据：2026-11-16 用户要求“彻底下线功能模块（删除源代码、相关 CI、release-check 等）”及数据处理决策

## 1. 背景

以下四个模块不再使用，需从产品中彻底移除，并解除它们与保留模块之间的耦合：

| 模块（界面名称） | module id | 说明 |
| --- | --- | --- |
| 业务OP数据核对 | `biz-op-recon` | 旧版（v2.1.3 起）与 v3.2.7 新版（BizOP v327）两代实现一并删除 |
| 月度Pending数据核对 | `pending-reconciliation` | 含规则管理、导入、移除归档导入、对账与导出 |
| 收单单据币种校验 | `acquiring-bill-currency` | 含多 worker 对账、空闲清理与 4 项设置 |
| 月度银行对账单BU回填校验 | `bank-bu-recon` | 读取 Pending 管理数据与银行对账单 |

## 2. 已确认决策

| 编号 | 决策 | 来源 |
| --- | --- | --- |
| D1 | 删除四个模块的源代码、界面入口、测试、集成/冒烟脚本、预览脚本、CI 专项任务与 release-check 接线 | 用户，2026-11-16 |
| D2 | 用户电脑上的历史数据**保留不动**：主库中这些模块的表与设置项、`run-data/` 侧库、Pending 库、归档中心中的归档、模板文件用户版本均不删除、不改写；新版不再读写。回退旧版安装包后数据仍可用 | 用户，2026-11-16 |

## 3. 规则

- 模块切换菜单、设置（含收单单据币种校验的 4 项设置）、模板文件、归档中心不再出现这四个模块。
- 上次停留在已下线模块时，启动后回到默认模块「网银账单生成」。
- 已下线模块的归档不在归档中心显示，也不参与归档保留期自动清理（即不删除）。
- 保留模块（VCC财务OP校验、VCC业务OP计算、重复入金匹配、模板文件「流水对账单」等）的行为与输出不变。
- 升级前异常退出留下的这些模块的未完成记录，不得阻断新版启动，也不得删除用户文件。

## 4. 非目标

- 提供“清理已下线模块数据”入口（登记 backlog，按用户反馈再定）。
- 删除或迁移用户磁盘上的历史数据。
- 修改保留模块的业务口径。

## 5. 验收

- 应用中不再有这四个模块的入口、IPC 与后台任务；保留模块单测、集成、冒烟全部通过；`npm run release-check` 通过。
- 升级兼容：带有四个模块历史数据（主库表与设置、侧库、Pending 库、归档、`current_module` 指向已下线模块）的数据目录，新版启动成功并回到默认模块；这些数据在启动前后内容不变。
- Windows 打包版界面验收登记 backlog。
