## 1. 背景

拆分/合并账单的费用账单行（v3.2.19）只能单独计算发生额，其他字段（摘要、户名等）仍沿用主映射或拆分映射，费用行与交易行输出相同的描述信息。需要为费用账单行单独设置部分字段的取值；同时整理「拆分/合并账单映射关系管理」弹窗的布局与按钮。

## 3. 功能规则

### 3.1 布局与文案（D1–D3、D6）

- 「发生额取值设置」一行内左右两项：左「按正负号取发生额」，右「按字段取发生额」；各自的附属控件（指定账单实现功能、【发生额映射关系管理】）跟随所属项，窗口较窄时整项换行。
- 「费用账单设置」一行内：左「发生额取值特殊处理」+ 勾选框 +【设置】，右「字段映射特殊处理」+ 勾选框 +【设置】。没有费用账单行时两个勾选框都置灰，并提示「请先在上方表格中勾选费用账单」。
- 更名范围：本弹窗标签与生成时的报错文案；历史文档、发版说明不改。
- 底部【确认】（主按钮）在左、【返回】在右。

### 3.2 字段映射特殊处理（D4、D5、F1、F3）

| 操作 | 规则 |
| --- | --- |
| 勾选 / 取消 | 立即写入模板；勾选后显示【设置】；与「发生额取值特殊处理」互不影响 |
| 没有费用账单行 | 勾选框置灰；已保存的勾选与设置保留但不生效 |
| 【设置】弹窗【保存】 | 校验后写入模板（同时视为勾选）并关闭 |
| 【取消】/ × | 关闭，不保存 |

- 模板字段选项：模板目标字段（同「拆分/合并账单映射关系设置」，已排除 Currency、Credit Amount、Debit Amount 与预处理、高级、拆分分组字段）再排除 MerchantId、Balance、BillDate。枚举里恰有与预处理、高级、拆分分组控制项同名的字段时同样不可选；主进程保存与生成校验使用同一可选范围（`filterFeeFieldMappingTemplateFields`），模板包带入的此类覆盖保存与生成时都拒绝。
- 映射字段选项：空白、自己输入、模板表头（不含空名表头，同名表头只列一次：设置只存列名，生成时与主映射同口径取第一列）。名为「自己输入」的表头与「自己输入」选项互不混淆。取自源列的值按文本输出（同主映射）。
- 已保存的取值类型无法识别、或值不是文本（如模板包带入的数字、对象、布尔值；界面与应用导出的模板包都按文本保存，JSON 数字在读包时可能已被舍入，如 `20261119.000000001` 读成 `20261119`、`1.10` 读成 `1.1`，无法确认原文，须以文本重新填写；含未配对 UTF-16 代理项的文本写出 XLSX 时会被替换成「�」、含 XML 1.0 禁止的 `U+FFFE` / `U+FFFF` 时写出的工作表无法解析，同样视为无效；其他控制字符写出时按 `_xHHHH_` 转义，照常接受）时显示为「（无效）」，保存时要求重新选择，不自动改成空白；生成时同样拒绝。规范化把这类行的取值类型记为 `invalid`（缺模板字段、取值为空白但模板字段不是文本的行，以及不是对象的非空项如误包一层的数组、字符串、数字、布尔值，同样记为 `invalid`；`null`、空白文本、空数组按空白行忽略），保证模板包读包、导入、落库、读取多次规范化后坏行仍保留，不被当作空白行丢弃。
- 选项按 DOM 属性赋值，表头中的换行（CRLF）原样保留，保存的列名与表头一致。未编辑的「自己输入」固定值原样保存（单行输入框会去掉换行），编辑后以输入为准。
- 模板【更新】后映射字段已不在表头时显示「（已删除）」并保留原值，保存时拒绝。
- 【保存】校验：「自己输入」的值不超过 32767 个字符（Excel 单元格上限）；至少一行；选了映射字段（或填了值）的行必须选模板字段；模板字段不重复且在可选范围内；选「自己输入」须填写值；选模板文件字段须在模板表头中。两个下拉框都为空白的行忽略（取值为空白时不看残留的值）。
- 存储：`template_bill_split_meta.fee_field_mapping_enabled`、`fee_field_mappings_json`（启动补列、幂等），形状 `[{ templateField, valueType: 'blank' | 'input' | 'field' | 'invalid', value }]`（`invalid` 只表示无法使用的坏行，不能通过保存写入）。

### 3.3 生成（F1）

- 只作用于已完成的费用账单行，且需勾选「字段映射特殊处理」。
- 费用账单行按设置覆盖对应字段：空白 → 空；自己输入 → 固定值；模板文件字段 → 该行源单元格的值（按字面列名读取；实际写出的费用账单行中，取自源列的值（ValueDate 按日期规范化前的源值）含无法写入 Excel 的字符——`U+FFFE`、`U+FFFF` 或未配对代理项——或超过 32767 个字符时，拒绝生成并列出源行、源列与目标字段，不截断、不交付被改写或无法打开的明细；合计行、合并时不作代表行的费用行不写出覆盖值，不因其值拒绝，也不为其解析 ValueDate；ValueDate 在原值校验通过后再规范化）。覆盖值（固定文本与取自源列的值）写出后读回会被改写时拒绝保存 / 生成并列出位置：XLSX 写出边界不转义字面的 `_xHHHH_`（x 与十六进制不分大小写），却把回车等控制字符编码成 `_xHHHH_`，读回时一律按转义还原——字面 `_x0041_`，以及 `_x0041` 后接回车拼成的转义都会被改写；按同一规则模拟写出再读回判断（backlog B113，修复写出边界后移除该拒绝）。ValueDate 与主映射同口径做日期规范化（无法识别时输出空，与主映射一致；工作簿日期系统与带时间的数值日期序号的既有限制同主映射，见 backlog B52）。覆盖在户名 / 卡号按收支方向分配之后进行，设置了的字段以设置为准。
- 未设置的字段、其他拆分行、未命中「根据字段值过滤账单」走主映射的行都不受影响；账户号、币种、发生额、余额、账单日期（BillDate）与系统按模板名生成的 Channel 不能被覆盖（保存时拒绝；模板包导入只规范化，生成时拒绝，不静默生效）。
- 特征值未命中提示按最终输出判断：源行只输出带覆盖的费用账单行时，被覆盖字段与由拆分规则取值的发生额列所用的特征值不记未命中；其他输出行仍用到时照常提示。
- 合并组沿用现规则：合并结果取组内最小序号行的非金额字段，费用账单行恰为该行时覆盖值保留，否则合并结果不含覆盖值。
- 勾选了但设置缺失或无效：拒绝生成，提示在【设置】中保存；映射字段不在源文件表头：拒绝生成（`映射字段不存在`）。设置中的模板字段已不在当前导出字段（枚举表变化）时忽略该行，也不参与生成前的失效引用拦截。
- 模板【更新】删掉映射字段时，失效引用列出「拆分账单 · 字段映射特殊处理 <模板字段> ← <字段>」；未生效时标为未启用。

### 3.4 【确认】/【返回】（D6、F2）

- 打开弹窗时记下当时的拆分配置。【确认】保留修改并关闭。
- 【返回】/ ×：本次打开后没有发出过任何写入时直接关闭；否则把本弹窗管理的配置（拆分行与其费用标记、完成状态、合并组，按字段取发生额规则，按正负号字段与指定账单序号，发生额取值特殊处理与公式，字段映射特殊处理与设置）在一个事务内恢复为打开时的样子，再关闭。不改主映射、拆分映射与「根据字段值过滤账单」规则。按下【返回】/ × 时不提交「指定账单实现功能」序号面板里的选择。
- 前提（2026-11-21 用户确认）：应用单实例、单窗口（只创建一个 `BrowserWindow`，`requestSingleInstanceLock`），弹窗栈同一时间只允许一个行管理窗口，因此同一模板不会有两个行管理窗口同时打开、交替写入。撤销会话的激活、令牌核对按此前提设计：拆分写入不校验会话身份，交叠窗口间「后挂载窗口撤销覆盖先挂载窗口已确认的写入」「激活失败的窗口仍可编辑」不在本前提内处理；将来支持多窗口时须让拆分写入校验活动会话，见 backlog B115。
- 只能恢复主进程签发的快照：打开行管理前读取拆分配置时（`openRestoreSession`），主进程为本次打开签发独立的撤销会话（不取代同模板的其他会话：打开请求可能因低内存屏障乱序执行，迟到的旧请求不能让当前窗口的令牌失效；同一模板的拆分写入与打开时的快照读取在主进程按受理顺序串行（低内存屏障下旧窗口已受理、尚在等待的写入先结算，快照才读取签发，撤销不会删掉打开前已受理的写入；等待屏障的超时从受理时起算，排队不累加等待时间）；每个模板最多保留 8 个会话，超出时丢弃最早签发的未激活会话——已激活的是当前窗口的撤销点，不被迟到的旧打开请求挤掉；行管理窗口挂载时激活本会话（`activateRestoreSession: <restoreToken>`），同模板的其他会话随之作废，同一时间只有最后挂载的窗口能撤销——拆分写入不改模板代次，交叠的两个会话仅靠签名无法区分，作废被取代的会话才能避免先打开的窗口撤销时覆盖后打开窗口已确认的修改；撤销只接受已激活的会话，迟到的打开请求签发、未挂载激活的会话即使属于同一页面也被拒；窗口的写入须等激活成功后才发出（激活回包未到时等待，回包后发出首个写入前重新核对原父 / 子窗，期间被销毁或替换则不再发出），激活失败（会话已被挤掉或 IPC 异常）即在当前栈顶（行管理或已打开的【设置】等子窗）提示「未能建立【返回】的撤销点」并暂停本窗口配置写入，子窗保存再次提示原因，【返回】/ × 只关闭），按本次运行的随机密钥对规范化后的快照、模板代次与会话签名（`restoreToken`）；撤销时核对签名，不一致整体拒绝。行管理窗口释放时（【确认】/【返回】/ ×、被宿主替换、随所属窗口关闭或强制销毁）带本窗口令牌结束会话（`endRestoreSession: <restoreToken>`，只结束该令牌所属的会话、不读取配置，在读取模板之前处理，激活与结束都作为控制操作不受低内存屏障限制；旧窗口迟到的释放不影响此后打开的新窗口），旧令牌随之失效；打开读取返回后没有创建行管理窗口（请求已被更新的请求取代、父层结束或开始写入）时，按回包令牌结束该次读取开启的会话；会话同时绑定签发时的渲染页面（`webContents`），只接受同一页面的恢复请求，该页面销毁或渲染进程退出（崩溃、被终止）时由主进程清理其会话；同一会话内撤销失败可重试。快照因此只能是确实读出过的已保存状态，渲染进程无法改写成正常保存入口不允许的配置；打开时已失效的引用与旧版本留下的配置照原样恢复（指定账单序号含已不存在、非整数的值也原样恢复，无法按数字往返时不签发令牌）。令牌同时绑定模板代次（`templates.updated_at`，本弹窗内的拆分写入不改它）：模板包覆盖导入、更新表头、改名、保存映射后旧令牌失效；应用重启后令牌也失效。撤销时令牌已失效（错误码 `BILL_SPLIT_RESTORE_TOKEN_STALE`）不提示重试，暂停本窗口配置写入，【返回】/ × 只关闭。打开时主进程无法签发令牌（现有配置结构异常）的，不打开行管理，提示无法建立撤销点。恢复复用 `template:save-bill-split-meta`（`restoreSnapshot` + `restoreToken` 载荷，不另增 IPC，避免改动冻结的执行 / 归档策略基线）。
- 主库已恢复、只是随后的模板库文件同步失败：按撤销成功处理，照常关闭并在原父窗口提示「已撤销本次修改；模板库文件同步失败，下次启动或修改模板时会重新同步」（同模板【更新】表头的处理），记 warning 级活动日志（记模板 ID，模板名与原因中模板维护的账号整体只写位数、其余编号只写位数，release 审查），不再重复撤销；撤销在途时原窗口已结束（强制销毁、被替换）则不提示到其他窗口，只记日志。
- 拆分配置的普通保存（`template:save-bill-split-meta`：按正负号 / 指定账单、费用账单行、发生额取值特殊处理、字段映射特殊处理）同样：主库已提交、只是模板库文件同步失败时按已保存返回（`librarySyncFailed`），记 warning 级活动日志，界面按已保存接纳并提示「已保存，本次设置已生效；模板库文件同步失败，下次启动或修改模板时会重新同步」——在行管理上的操作提示到当前栈顶，【设置】子窗的保存在子窗关闭、回到行管理后提示；不再报「保存失败」而让已生效的设置被误认为未保存。
- 恢复失败：提示并留在弹窗，按重读到的已保存配置显示（收起仍打开的序号面板、清空合并账单的待提交序号），可再次【返回】或点【确认】保留；撤销后重读也失败、或令牌失效时，提示关闭后重新打开确认，本窗口暂停配置写入，此后【返回】/ × 只关闭、不再写库。
- 其他保存失败且重读失败而暂停配置写入时（撤销尚未失败），【返回】/ × 仍按打开时的快照撤销，不把已落库的修改当作【确认】保留。

### 3.5 模板包

- 拆分配置带「字段映射特殊处理」勾选状态与设置，随模板包导出、导入与模板库文件同步。
- 任一模板勾选或保存了字段映射特殊处理时写 v9；v3.2.20 及更早版本读到整包拒绝（否则会静默忽略覆盖）。都未用到时版本号沿用原规则。

## 4. 验收

- 布局与文案按 §3.1；两项发生额取值并排、按字段在右；「费用账单设置」在下方；底部【确认】在【返回】左侧。
- 字段映射特殊处理勾选、【设置】弹窗布局与校验按 §3.2；关闭重开后状态保留。
- 生成：费用账单行的设置字段按 §3.3 输出，其他行不变；设置缺失、字段缺失时拒绝生成。
- 【返回】/ × 撤销本次修改，【确认】保留；恢复不影响主映射与过滤规则。
- 模板包往返后字段映射特殊处理配置与生成结果一致，用到时写 v9；旧库启动补列，重复启动无副作用。例外：「指定账单实现功能」的账单序号不随模板包导出（既有限制 B101，本轮不改），用到指定序号的模板往返后取额范围可能不同，须按 B101 人工复核。

## 5. 非目标

- 不支持对普通拆分行或走主映射的行做字段覆盖；不支持特征值、拼接、逻辑取值作为覆盖来源。
- 主映射弹窗的【返回】不撤销本弹窗已【确认】的修改（与现状一致）。
- 【确认】不保存行内未点「完成」的草稿（与原【完成】一致）。
