> status: in-progress
> created: 2026-11-20
> 目标版本：v3.2.21（暂定，发版时按 weekly-release 调整）
> 适用分支：`feat/cross-sheet-backfill`
> 分支基线：正式标签 `v3.2.20`（`08d1fb41`）
> 依据：2026-11-20 用户需求与决策（对话）；样例账单 `Statement (4).xlsx`（不入库）
> 格式来源：`changes/v3.2.21/feat/bill-split-fee-field-mapping/spec.md`

## 1. 背景

部分网银原始账单是一个持续追加的工作簿。以换汇为例：
- 主表（如 `NGN`，第一个 sheet，模板读的就是它）中的换汇行 `ValueDate`、`Currency`、`Channel`、`Channel OrderNo` 都为空，`Transaction Description` 形如 `Trade - $65.45`；
- 同一工作簿的另一个 sheet（如 `USD`）只有买入方向，`Credit Amount` 就是对应的买入金额，并带有日期。

两边一对一。现状：日期为空的行不会被「账单日期无效整份拒绝」拦下（该规则只拦有值但无效的日期），会以空日期进入明细，余额计算时又被跳过。

实现采用的低影响默认：
- 只填空单元格，不覆盖银行原值；
- 存在待回填行，但来源 sheet 或字段缺失时整份拒绝；没有待回填行时不读来源 sheet；
- 只导出至少回填了一行的源文件；
- 「已使用」状态只在单次运行内有效，不入库。

## 3. 功能规则

### 3.1 配置（D3、D4、D7）

「原始账单预处理」分组新增「跨 Sheet 回填」：勾选框，勾选后显示【规则设置】。弹窗配置项：

| 配置项 | 规则 |
| --- | --- |
| 来源 sheet 名 | 文本，必填；按名称精确匹配工作簿中的 sheet |
| 待回填行条件 | 与「过滤账单」同一套条件（同一规则内的条件全部满足，满足任一规则即命中），字段取模板表头，至少一条有效规则 |
| 配对方式 | 按金额 / 按原值 |
| 本表配对字段 | 模板表头下拉 |
| 来源配对字段 | 文本，必填 |
| 来源日期格式 | 自动 / 日在前（dd/mm/yyyy）/ 月在前（mm/dd/yyyy）；只影响文本日期 |
| 回填字段 | 多行「本表字段（模板表头下拉）← 来源字段（文本）」，至少一行；本表字段不能重复 |

**本表字段不能作为回填目标**：主映射中 Credit Amount、Debit Amount、Balance、Currency、MerchantId 所用的源列，以及「按正负号取发生额」的源列（金额、余额由银行原值决定，币种按 3.2 自动补，账户不从来源 sheet 取，D10）。保存和生成时各校验一次，生成时按实际生效的映射（含拆分映射）判断。

存储：模板级 JSON。
```
{ sourceSheetName, rowRules, matchMode: 'amount'|'exact', matchField, sourceMatchField,
  sourceDateOrder: 'auto'|'DMY'|'MDY', backfillFields: [{ targetField, sourceField }] }
```

### 3.2 生成（D1、D2、D5、D6）

1. **顺序**：读主表 → 跨 Sheet 回填 → 过滤账单 → 映射。重复账单过滤的指纹仍按原始单元格计算。
2. **待回填行**：命中「待回填行条件」的数据行。没有待回填行时不读来源 sheet、不做任何改动。
3. **来源行**：来源 sheet 中，「来源配对字段」能取到配对值的数据行，按表头所在行之后的物理顺序排列。
4. **配对值**：
   - **按金额**：单元格为数值时直接取；为文本时识别其中的金额。去掉千分位后只有一个数字就取它；有多个数字时，取紧跟币种符号（`$` `¥` `€` `£` `₦` `₹` 等）或三字母币种代码的那一个；仍不唯一或没有数字时，视为取不到。比较时换算成分（四舍五入到 2 位小数后取整），取绝对值。
   - **按原值**：单元格文本去掉首尾空白后比较，空值视为取不到。
5. **配对**：按主表物理顺序处理待回填行，每行取第一笔还没用过、且配对值相等的来源行，配上后标为已使用。
6. **回填**：对每个回填字段，只在本表单元格为空时写入来源单元格的值。
   - 本表字段是主映射 BillDate 或 ValueDate 所用的源列时，按日期处理：来源值是真 Excel 日期就直接取日期，是文本就按「来源日期格式」解析。解析成功后以 `yyyy-mm-dd` 写入；解析失败则该行按跳过处理（原因：来源日期无法识别）。
7. **币种（D5）**：主映射 Currency 取自源列，且待回填行该列为空时，补成本 sheet 中「非待回填行」该列唯一的非空值（去首尾空白后去重）。没有或不唯一时该行跳过（原因：无法确定本表币种）。Currency 为固定值或由所选大账号决定时不补。
8. **跳过（D1）**：取不到配对值、没有可配的来源行、来源日期无法识别、无法确定币种时，该行在映射前移除，不进入明细与余额。
   - 跳过的行在错误报告中逐行列出：行号、配对值和原因；
   - 导入结果提示「跨 Sheet 回填：N行未配上，已跳过」，与其他提示一起以「请点击状态框导出报错文件」结尾；日期区间提示为「跨 Sheet 回填：N行回填日期不在相邻交易日期之间，请核对」。
9. **日期区间提示（D6）**：回填到 BillDate 源列的日期，与主表中该行之前、之后最近的、日期有效的非待回填行比较，要落在两者之间（含端点，正序、倒序均可）。只有一侧时，按本表首个与最后一个有效日期判断整体顺序，只比较这一侧；无法判断顺序时不提示。不在区间内的照常输出，只在错误报告中提示，不计入跳过。
10. **整份拒绝**：存在待回填行时，以下任一情况拒绝生成，并提示具体 sheet 或字段：来源 sheet 不存在；来源 sheet 中找不到包含来源配对字段与全部来源回填字段的表头行；主表缺少规则用到的字段。
11. **勾选但规则无效**：勾选了「跨 Sheet 回填」但没有有效规则时，拒绝生成（同「过滤账单」）。

### 3.3 导出回填后的原始账单（D8）

- 点【导出明细】成功写出明细后，对导出范围内「至少回填了一行」的源文件，每个导出一份 `<原文件名去扩展名>_回填.xlsx`，与明细在同一目录。同一文件按大账号分段成多个会话条目时只导出一份。目录中已有同名文件（不区分大小写，含本次明细文件）时依次追加 `(1)`、`(2)`，不覆盖。
- **内容**：原工作簿的全部 sheet，只改主表中被回填的单元格（含 3.2 第 7 条补的币种），被跳过的行保持原样。
  - 日期写成 Excel 日期，显示格式跟随模板日期顺序：自动、日在前用 `dd/mm/yyyy`，月在前用 `mm/dd/yyyy`；工作簿为 1904 日期系统时按 1904 换算；
  - 其他字段写来源单元格的值，数值仍为数值；
  - 回填后的文件用同一模板再导入，明细与本次相同，只剩本次也配不上的行仍是待回填行。
- **格式**：xlsx 原文件复制后只改写主表 XML 中的目标单元格（日期单元格以原单元格样式为底只换数字格式），其余部件逐字节不变；非 xlsx 原文件转成 xlsx 写出，只保留值与数字格式，并在提示中说明。
- **拒绝写出该文件**（提示「回填后的原始账单导出失败：<文件名>（原因）」）：目标单元格含公式；主表中找不到补丁行；原工作簿第一个 sheet 已不是导入时的主表。先写临时文件再改名，失败时不留残文件。
- **一致性**：导入时在同一读取守卫内记录原文件的大小与 sha256，随会话条目缓存。
  - 准备导出（登记输出文件）时已变化或不存在的文件不登记输出；执行时再核对一次，已变化的不写出；
  - 两种情况都提示「原始账单在导入后已变化，请重新导入：<文件名>（未导出回填后的原始账单）」。
- **导出编排**：回填文件与明细一起在 archive-center 的 filePlan 中登记为 outputs（同一 sourceOperation），执行后全部 settle，未写出的按缺失处理。单份失败或变化不影响明细与其他文件；各提示用「；」接在导出结果后，并写入活动日志。
- 与明细一样只在本次运行内有效，不跨重启保存。

### 3.4 模板包与模板更新

- 规则随模板包导出、导入。模板包版本：与 `feat/bill-split-fee-field-mapping` 同在 v3.2.21 发布时共用 v9，否则另升一版；本分支先按「用到跨 Sheet 回填时写 v9」实现，合入 release 时核对。
- 模板【更新】删掉规则用到的本表字段时，列为失效引用「原始账单预处理 · 跨 Sheet 回填 …（字段）」；未勾选时标为未启用。来源 sheet 的字段只在生成时校验。

## 4. 验收

- 换汇样例配置为：待回填行「ValueDate 空值」，按金额，`Transaction Description` ↔ `Credit Amount`，来源 `USD`，回填 `ValueDate ← ValueDate`、`Channel ← Channel`。生成后，换汇行输出 BillDate 2026-09-26、Currency NGN、Debit 90000，没有区间提示。
- 导出明细时，同目录生成 `<原文件名>_回填.xlsx`：换汇行 ValueDate 为 Excel 日期、显示 26/09/2026，USD sheet 保留。用同一模板再导入，明细与本次一致。
- 同金额多笔时，按物理顺序一对一配对；追加新行后，已有配对不变；配不上的行跳过，并在报错文件中列出。
- 来源日期为 mm/dd/yyyy 文本、主表为 dd/mm/yyyy 时，回填日期正确（含 `09/10/2026` 这类日 ≤ 12 的情况）。
- 未勾选时，行为与 v3.2.20 完全一致。

## 5. 非目标

- 来源放在另一个文件；主表 sheet 可配置（仍读第一个 sheet）；来源 sheet 自身输出为账单；「已使用」状态跨次持久化。
- 模板级「日期格式」界面入口（另起任务）。

## 6. 风险与人工复核

- 同金额按顺序配对、币种自动补值、日期回填会直接决定交易落在哪一天、哪个账户，属于对账资金红线，需要用真实样本人工复核。
