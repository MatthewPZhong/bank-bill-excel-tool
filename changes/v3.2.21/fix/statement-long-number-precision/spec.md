# Spec — v3.2.21 网银账单生成：长数字按原文读取（B112）

> status: in-progress
> created: 2026-11-20
> 目标版本：v3.2.21（暂定，发版时按 weekly-release 调整）
> 适用分支：`fix/statement-long-number-precision`
> 分支基线：正式标签 `v3.2.20`（`08d1fb41`）
> 依据：`knowledge/backlog.md` B112（登记于 `feat/bill-split-fee-field-mapping`，2026-11-20 补充 CSV 与伪装文件实测）；2026-11-20 用户决策
> 格式来源：`changes/v3.2.21/feat/mapping-logic-feature-layout/spec.md`

## 1. 背景

网银账单生成读取银行文件时，长卡号、流水号等标识会静默变成别的值，按这些标识对账可能匹配不上或错配（资金口径）。2026-11-20 实测有三类来源：

1. xlsx 数值单元格超出安全整数：工作表里写的 `9007199254740993` 读成 `9007199254740992`，19 位卡号末几位变 0。
2. 扩展名为 .xls、内容其实是 CSV / 制表符文本 / HTML 表格的文件（部分网银导出）：读取库把长数字解析成数字后丢精度。加引号或 HTML 标文本格式也一样。日期写成 `20261101`、`2026年11月01日` 时生成成功、静默出错。
3. 真 CSV 中银行用来让 Excel 按文本显示的 `="长数字"`、首尾制表符：明细连同 `=`、制表符一起输出，与 Excel 打开原文件看到的值不同。

## 2. 已确认决策

| 编号 | 决策 | 来源 |
| --- | --- | --- |
| D1 | 能从文件原文还原的长数字按原文输出 | 用户，2026-11-20 |
| D2 | 文件中只有近似值、无法还原的长数字（二进制 .xls、被 Excel 另存过的 xlsx），照常生成，在导入提示中列出 | 用户，2026-11-20 |
| D3 | 真 CSV 的 `="…"` 与首尾制表符一并还原为 Excel 显示的值 | 用户，2026-11-20 |
| D4 | 只改网银账单生成；其他走同一读取函数的模块不改，登记 backlog（B116） | 用户，2026-11-20 |

实现采用的低影响默认：不整体改为按文本读取（会改变 `(100)` 的正负号、百分比、科学计数与 0 开头的值，并让旧模板表头对不上），只替换确实丢了精度的单元格；长数字与 `="…"` 都只在表头以下的数据行还原（读取结果本身不改，另附原文对照）。

## 3. 规则

### 3.1 长数字还原（D1、D2）

- 作用范围：网银账单生成的映射读取与大账号识别读取（同一次生成读到同一个值）。模板导入 / 更新读表头、其他模块不变。
- 映射读取只还原表头以下的数据行；表头定位、重复表头判定按读取库的值，与模板导入读到的表头一致（表头恰为长数字时照常匹配）。
- 大账号识别（导入时识别与生成时的识别依据）同样按读取库的值定位表头，表头以外的行（表头上方的账户信息行等）按原文匹配。
- 发生额、余额取值的列不还原，保持读取库的数值（与修改前一致）：余额按数值计算，明细与余额须是同一个值。只算实际参与计算的字段，与生成时的取值分支一致，列名按各取值点的读法解读（映射值中的固定值不是列；按字段区分发生额的规则字段、逻辑取值的候补字段、特征值的源字段一律按真实列名，即使以内部前缀开头）：
  - 余额取账单余额列时（主映射 Balance 不是「无」或「通过发生额计算」；这两种余额方式下 Balance 映射的源列都不参与计算，作标识时按原文，release 审查）：主映射 Balance（有行用它出余额时：未开拆分、开了「根据字段值过滤账单」或拆分复用模块映射；拆分不复用且不过滤时不算，release 审查）；拆分不复用模块映射时拆分映射的 Balance；
  - 有行走主映射时（未开拆分，或开了「根据字段值过滤账单」）：按字段区分发生额的规则字段、按正负号拆分的字段、Credit / Debit 映射（含逻辑取值的候补字段、特征值的源字段）三者中生效的一种，未生效的不读；
  - 拆分：逐行按实际的发生额分支——费用账单启用公式时取公式字段；被「按正负号拆分」或「按字段区分发生额」指定（或未指定任何行时全部行）取对应字段，费用账单行只有支出，只取支出规则的字段；其余取该行的收入（费用账单行除外）/ 支出字段。
  - 只保存供恢复、不参与计算的映射（如启用费用公式后保留的支出映射）不算，该列作标识时按原文。同一列既参与计算又作标识时按数值。
  - 超出安全整数的发生额、余额按 §3.3 提示。
- 候选单元格：读取库读成数字、是整数且超出安全整数范围（绝对值 ≥ 2^53，此时数字可能已不等于文件里写的值）。没有候选单元格的文件不做任何额外读取。
- 只还原非负数：负数多是发生额，改成文本后按发生额文本处理会丢负号，保持原读取结果（与修改前一致），按 §3.3 提示。
- 按文件实际内容（不看扩展名）还原：

| 实际内容 | 原文来源 | 结果 |
| --- | --- | --- |
| xlsx（含扩展名为 .csv 的 xlsx） | 工作表 XML 中该单元格 `<v>` 的字面值（XML 注释不算；按 workbook.xml 与其关系文件定位工作表，注释里的旧关系、旧 `<sheet>` 不算，同一关系 Id 有多条有效关系、或 `<sheet>` 上不是恰好一个绑定到 OOXML 关系命名空间的「前缀:id」属性（如另带扩展属性 `custom:id`）、任一张表的关系解析不到（读取库会放弃整份关系表、改按物理序号读表），或读取库定位工作表的口径（`xl/` + 去掉 `xl/` 前缀的 Target，依次退到 Target 原样、关系文件目录 + Target）与按关系文件目录解析 Target 落到不同条目，或读取库解析关系文件与 workbook.xml 的口径（不跳过注释、关系只认不带前缀的 `<Relationship>` 且同一 Id 取后一条）与本模块确认的结果不一致（如关系带前缀、注释里的旧关系在后、注释里有 `<sheet>`）时无法确认来源、整张表不还原；未开查重时只按需解压 workbook.xml、其关系文件与目标工作表，压缩包结构不支持按需读取时退回整包解压，release 审查） | 公式单元格（含共享、数组公式）的 `<v>` 是计算结果的缓存、不是录入的原文，不还原；数组公式、模拟运算表等的结果区域（`<f ref="…">`，共享公式的各格自带 `<f>`、不按区域判断）内只有缓存值的其他格同样不还原；区域须是单格或矩形引用（列名统一大写后再解码），写法异常（如多区域）或显式为空时整张表不还原；区域互相重叠时按各区域的并集判断（release 审查）；字面值是非负整数写法时按原文文本输出（去前导 0）；指数写法（Excel 另存的写法）、单元格里有多个 `<v>`、同一位置重复出现（含乱序声明，扫完整张表判断）时无法还原；表中有单元格没有位置属性时（读取库按前一格顺推位置，可能重叠）、单元格引用的行与所在 `<row>` 的行号（没有 r 时按前一行顺推）不一致时（这一格属于哪笔交易有歧义，舍入为同一数值的原文互换也核对不出，release 审查）整张表都不还原 |
| CSV / 制表符文本 / HTML（扩展名为 .xls 等） | 按文本重新读取同一张表的同一位置 | 原文去首尾空白后是非负整数写法时按原文输出；重读结果与原读取范围不一致时无法还原 |
| 二进制 .xls | 文件里存的就是双精度数 | 无法还原 |
| 真 CSV | 本来就按文本读取 | 不涉及 |

- 无法还原的单元格保持原读取结果（与现状一致），生成时提示，见 §3.3。取原文时遇到容量类错误照常按文件过大处理，其他读取失败按无法还原处理，不阻断生成。
- 16 位以内的安全整数、普通金额、日期不受影响。

### 3.2 CSV 的 `="…"` 与制表符（D3）

- 只作用于真 CSV（项目自带的 CSV 解析）的数据行：
  - 整个字段是 `="…"`（未加引号的原文写法，或带引号字段内容为 `="…"`）时取引号内的文本，`""` 还原为 `"`；
  - 去掉首尾制表符。
- 表头定位、重复表头判定仍按原值，旧模板里存成 `=流水号` 的表头照样匹配；表头以上的账户信息行（大账号识别）按原值，沿用现有的精确 / 模糊 / 包含匹配。
- 重复账单过滤的源行指纹仍按原值计算（指纹不变）。
- 不还原未加引号的 `=公式`（如 `=123`、`=A1+1`）。

### 3.3 无法还原的提示（D2）

- 生成时，映射、拆分映射、拆分户名 / 卡号、逻辑取值、特征值、按字段区分发生额等把源单元格写进明细的取值点读到无法还原的长数字时，按源行与源字段记录：
  - 只记写进明细或参与计算的取值：余额方式为「无」或「通过发生额计算」时，Balance 列既不写进明细也不参与计算，这一列（含拆分映射的）读到的长数字不提示，同一源列还写进其他列时只记那些列（release 审查）；按收支方向取的户名 / 账号只在该方向取值时记（拆分底稿中由子行重填的列不读）；收入 / 支出按发生额规则取值时记（不再读 Credit / Debit 映射的源字段），按字段区分发生额只记同一方向首条命中规则的列，拆分子行各自记录、只汇总实际导出（含合并后导出）的子行；合并行的发生额来源汇总组内各子行实际用于发生额的读取，其余字段（户名、卡号、币种等）的来源只跟随代表行；子行用拆分行自己的币种覆盖底稿币种时，不记底稿币种的来源；币种 / 大账号由所选大账号决定时不读源字段；改选大账号后复用已生成的明细、以及手动分配大账号时，只写进被覆盖的币种 / 大账号列的来源随之去掉；目标列最终写出为空时（如长数字映射到日期列、费用账单行覆盖的 ValueDate，规范化后为空）没有近似值写进明细，不记，同一源列还写进其他列或参与发生额时照常记（release 审查）。行内没有无法还原的长数字时不跟踪来源（提示按源字段记下写进的目标列；手动分配只处理导出行都被分配了大账号的源行；拆分子行同样按目标列记下来源，release 审查）；费用账单行中由「字段映射特殊处理」覆盖的户名 / 卡号列不按收支方向读取源列（release 审查）；拆分行不记主映射的试算（发生额取拆分设置；不复用模块映射时主映射底稿不输出）；特征值在被映射取用且筛出值时记（逻辑取值的特征值候补同样在被采用时记，其源列按特征值规则读取的列判断是否为发生额 / 余额列，release 审查），未筛出时字段留空，只有未筛出提示；
  - 只为导出为明细的行提示，与明细导出同一口径：Credit / Debit 两列恰有一列不为空或 0，缺任一列时都导出。
- 导入提示：`N行长数字无法核对原值`。
- 报错文件明细：`以下单元格是超出精度的数值，文件中没有可核对的原值，导出值可能与银行原值不同，请向银行索取该列为文本格式的文件：`，逐行列出 `文件“名称”第N行，源字段“X”，19位数值`（多个文件一起生成时据此区分）。最多列 100 处，超出时末行写 `……等共N处`。不写读到的值：这类列多是卡号、账号，导入提示的明细同时写入活动日志（对账专项审查，隐私）。
- 不阻断生成：按文件名映射分组生成时逐条合并各组告警，告警条数多时不因展开传参出错。
- 「未筛出特征值」「币种未匹配」「账单日期无效」「币种未维护大账号」等写原值的诊断中，按原文还原的长数字只写 `（19位数值）`，不写完整号码（修改前写的是近似值，不新增完整号码的披露）；多列拼接的值中同样只把还原的那一段写成位数；明细中的值不变。提示中的文件名照写（导入日志本来就写源文件路径，脱敏口径见 B117）。
- 余额补录、断档确认等流程返回补录 / 确认结果时不带导入告警，本提示同样不显示：既有行为，B118。

## 4. 兼容

- 大账号识别：长账号由读成近似值、匹配不上，变为按原文精确匹配。若有人为了匹配而把近似值（如 `6222021234567890000`）维护成大账号，升级后该近似值不再匹配，需改成真实账号。
- 生成时的账号桥接候选、「自己输入」模式按桥接得到的清算账号选大账号，均改为精确命中优先于模糊命中（与导入识别 findBigAccountMatchInRows 同一口径）：按原文读取后，完整账号与其较短后缀可能同时命中，不再按账户映射的枚举顺序取。已是文本的账号同样适用（资金口径，人工复核）。
- 文件里只有近似值的长账号参与大账号识别时仍按近似值匹配、不提示：B119。
- 「根据字段值过滤账单」、原始账单预处理过滤、特征值、逻辑取值、按字段区分发生额的条件，按数据行还原后的值比较：原来写成 `=123` 或带制表符才能命中的条件会失效（概率很低，发版说明提示）。
- 多文件同组生成、重复账单复核的预览 / 执行两次读取都按文件内容确定，结果一致。
- 费用账单「字段映射特殊处理」（`feat/bill-split-fee-field-mapping`）取源列走同一取值点，两分支合入 release/v3.2.21 后自动生效，届时在 release 上补一条回归。

## 5. 验收

- §1 三类来源的长数字按原文输出；无法还原的照常生成并在导入提示与报错文件中列出（不含值）。
- `="…"`、首尾制表符在数据行还原，旧模板表头照常匹配；表头恰为长数字时映射与大账号识别照常定位表头。
- 发生额、余额列的明细值与余额计算一致（与修改前相同）。
- 未映射的列、没有输出的行不提示。
- 不传新读取选项的调用方（模板导入表头、其他模块）行为不变；重复账单过滤结果不变。
- B112 关闭：B112 目前登记在 `feat/bill-split-fee-field-mapping` 分支的 backlog，两分支合入 release/v3.2.21 时移到「已完成」。资金口径，合入前人工复核实际使用的银行模板。

## 6. 非目标

- 其他模块的同一读取问题（账户管理旧导入、余额种子导入、关联表导入、资金对账退款来源等）：B116。
- 伪装成 .xls 的文本文件中日期被读成带小数的序号（B52）。
- 千分位写法的长数字、未加引号的 `=公式`、以 0 开头被读成数字的值。
- 文件里已经是科学计数法文本的值（如 CSV 中的 `6.22202E+18`，上游用 Excel 另存时已丢失）：按文本原样输出，不提示。
- 超过 9×10^15 的发生额、余额不按原文计算：保持读取库的数值（含按正负号拆分时再次解析），与修改前一致，按 §3.3 提示。
- 「未筛出特征值」等提示中原本就是文本的原值（真 CSV、文本单元格的卡号）的脱敏：B117。
