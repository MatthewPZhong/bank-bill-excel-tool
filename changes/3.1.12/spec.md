## 0. 目标与非目标

### 0.1 目标

1. 网银账单生成每次生成尝试只在用户最终确认时做一次源文件变化比较。
2. 移除 Windows 正常启动中的全库无界维护和重复恢复工作，初始化完成后再显示主窗口。
3. VCC 财务 OP 对 v3.1.12 后新导入的 CNH 按 CNY 参与业务计算和输出，同时保留原始审计值。
4. 存档位置界面更清晰；变更位置时完整迁移已有存档；存档保洁改为首次进入后后台增量执行。

### 0.2 明确非目标

- 不把任何改动做进或声明为 v3.1.11。
- 不把“确认期源文件变化比较”的一次限制扩展到其他模块。
- 不移除文件读取过程稳定性、会话/任务所有权、重复文件 SHA 或归档 SHA 校验。
- 不迁移、回填、重算或改写 v3.1.12 前的 VCC 历史业务数据、原始审计和幂等哈希。
- 不新增 CNH 输出列；结果仍为九币种。
- 不新增“其他设置”，不实现 WAL 空间限额、WAL 手工清理、空闲清理或退出清理。
- 不在用户从未进入存档中心时执行到期清理或孤儿保洁，也不增加每日/空闲兜底。

## 1. 网银账单源文件校验

### BSF-01 作用范围

仅修改“网银账单生成”模块。其他模块继续遵守各自已有的源文件、安全、会话和归档合同。

### BSF-02 选择时证据

文件选择完成时保存每个源文件的：

- `sizeBytes`
- `mtimeMs`
- `ctimeMs`
- `ino`（运行环境可可靠取得时）

文件身份以规范化绝对路径与上述元数据共同表示；`ino` 缺失时不得因此拒绝正常文件。

### BSF-03 每次生成尝试只比较一次

- 有大账号最终确认弹窗：用户点击【完成】后、业务执行前比较一次。
- 无最终确认弹窗：用户触发导入/生成后、业务执行前比较一次。
- 不在删除重复文件弹窗返回、选择解析后、完整预检后、大账号 `prepare` 或保存顺序时重复比较。

这里的“一次”仅指“选择时元数据”与“最终确认时元数据”的确认期变化比较；不包含 BSF-06 中的其他安全校验。

### BSF-04 大账号顺序证据冻结

大账号顺序提取使用预检读取源文件时冻结的最小证据，不再为了提取顺序重新打开或读取源文件。保存顺序只校验当前会话身份和提交结构，不做物理源文件比较。

### BSF-05 失败行为

源文件缺失、不是普通文件或元数据变化时统一提示：

> 网银明细源文件在确认期间已变化，请重新选择

失败发生在业务执行前：

- 不生成业务输出文件；
- 不提交网银账单会话的成功/完成状态；
- 已为本次尝试建立的内部任务审计允许以失败终态保留，不把“无业务副作用”误定义为“数据库零记录”。

### BSF-06 继续保留的安全合同

- 同一次实际读取开始/结束之间的文件稳定性校验；
- 会话身份、任务身份和所有权校验；
- 重复文件识别 SHA；
- 存档写入及读取 SHA；
- 输出目标快照和发布前文件合同。

上述校验不计入 BSF-03 的“一次确认期变化比较”。

## 2. Windows 启动治理

### STP-01 窗口时序

- 数据库、迁移恢复、存档必要恢复、outbox、VCC 安全门禁和模板同步全部成功后，才创建并显示主窗口。
- 删除产品路径中的加载页、`initPending` 两阶段渲染、初始化进度文案和对应监听。
- 初始化失败时不创建业务窗口，保留原生错误弹窗并退出进程。

### STP-02 SQLite 启动维护

- 将每次启动的无参数 `ANALYZE;` 替换为 `PRAGMA optimize=0x10002;`。
- 不新增直接删除 `-wal` 文件、WAL 限额或 WAL 清理功能。
- SQLite 自身的 WAL 崩溃恢复和 checkpoint 语义保持不变。

### STP-03 必须保留的启动屏障

- migration journal 恢复；
- SQLite/WAL 打开与崩溃恢复；
- Archive outbox 恢复；
- 中断任务和必要 owner 状态恢复；
- 存档根关键目录的所有权/越根安全检查；
- retention 前一次 VCC lineage/hold 安全门禁。

没有待恢复项时，上述检查应为常数级或只与脏记录数量相关，不得无条件遍历全部历史文件。

### STP-04 删除重复 VCC 门禁

Archive outbox 恢复后的 post-outbox hook 保留一次 VCC lineage/hold 核对；删除主初始化链中再次调用的第二遍核对。

### STP-05 单次 VCC 核对性能

v3.1.12 仍保留全量安全语义，但将活动引用计数改为集合查询，并为 `vcc_fin_op_system_snapshots.import_source_id` 增加索引，消除逐来源、逐表 `COUNT` 和系统快照无索引计数。

### STP-06 不阻塞启动的维护

以下操作移至用户首次进入存档中心后的后台维护：

- 到期清理；
- 目录化副本修复；
- 有所有权证据的孤儿保洁；
- 历史文件健康筛查；
- 非关键路径的存档所有权分页核对。

### STP-07 可观测性

只写日志，不新增启动 UI。至少记录以下阶段的开始、结束、耗时和失败：

- 数据库打开与 SQLite/WAL 就绪；
- schema migration 与一次性 VACUUM；
- `PRAGMA optimize`；
- 存档必要恢复；
- outbox；
- VCC lineage/hold 门禁；
- 模板同步；
- 窗口创建、页面加载及 ready-to-show。

### STP-08 Windows 性能验收

- installer 与 portable 使用同一份脱敏数据库副本分别测至少 5 次；
- 3.1.11 与 3.1.12 使用同一机器、同一路径类型、同一供电/杀毒条件；
- 正常、无待恢复项场景以启动中位数为主指标；
- 3.1.12 相比 3.1.11 中位数至少缩短 70%，不设置绝对秒数；
- 一次性 migration/VACUUM 和崩溃恢复另列报告，不混入正常样本。

“约 2.9GB 主库上的全量 `ANALYZE` 是首要原因”属于本迭代已有诊断输入；实现后必须由阶段日志和 Windows 对拍复核，不能只凭代码推断宣告性能门禁通过。

## 3. VCC 财务 OP 币种

### VCC-01 时间边界

仅影响 v3.1.12 后新导入数据。历史数据库行、历史哈希、历史审计和历史结果均不迁移、不回填、不重算。

### VCC-02 输入词法与归一化

- 输入先去除首尾空格；
- 接受已有九币种的标准大写代码，并新增接受标准大写 `CNH`；
- 小写、混合大小写及其他代码继续拒绝；
- 通过词法校验后，业务字段在导入阶段将 `CNH` 归一为 `CNY`。

### VCC-03 覆盖字段

- 非通道明细：`我方币种`；
- 通道明细：按现有业务分支实际选用的 `交易币种`、`清算币种` 或 `结算币种`；
- Pending：`币种`、`流水_币种`；
- 系统财务 OP：`币种`。

未被现有业务分支选中的通道币种列不新增业务校验，也不参与本行规范哈希改写。

### VCC-04 计算和输出

- 普通明细的 CNY/CNH 进入同一个 CNY 分组并合计；
- Pending 两侧的 CNY/CNH 归一后相等，不判为错币；
- 计算结果、校验表、归档派生结果和 Excel 仍为九币种，只显示 CNY，不新增 CNH 列。

### VCC-05 原始审计

原始审计 JSON 保留源文件中的词法值，包括 `CNH`；业务行、分组键和计算字段只保存归一后的 `CNY`。不得为了统一展示而改写原始审计 JSON。

### VCC-06 幂等

新合同的内容哈希使用币种归一后的规范副本，原始审计副本保持不变：

- 同幂等键、其他内容相同且只存在 CNY/CNH 写法差异：幂等跳过；
- 同幂等键、金额或其他内容不同：幂等冲突；
- 新哈希合同升版；旧记录和旧哈希不改，历史兼容读取保持。

### VCC-07 系统财务 OP 主体级失败

同一主体、同一月份同时出现 CNY 和 CNH 时，归一后形成重复 CNY，拒绝该主体；其他完整且无错误的主体继续处理。原始审计保留每行 `sourceCurrency`，规范字段为 CNY。

### VCC-08 资金红线

发布前必须人工抽查各来源类型的：主体、源币种、规范币种、金额、幂等结果、原始审计、分组行数和最终 Excel。自动测试不能替代人工资金复核。

## 4. 存档中心

### ARC-01 布局

- 第一行左侧显示“存档位置”，右侧显示【变更】；
- 第二行显示完整只读路径；
- 长路径允许换行和选择复制，不使用省略号截断。

### ARC-02 变更位置必须迁移数据

保留并强化现有安全迁移状态机：

1. 暂停新存档操作；
2. 完整核验源位置内由应用拥有的文件；
3. 复制到目标位置并逐文件验证；
4. 原子切换数据库中的存档根设置；
5. 最后清理旧位置。

已核实现有 `ArchiveStorageRootManager` 具备 journal、复制校验、设置切换和旧根清理骨架；v3.1.12 的合同是继续迁移已有内容，不允许只切换路径。

### ARC-03 迁移完整性与失败

- 迁移前后逐文件核对 SHA-256；
- 设置切换前任一失败：不切换，旧位置继续作为唯一真相；
- 切换后旧目录清理失败：进入 `cleanup-pending`，新位置保持生效，后续幂等重试清理；
- 迁移开始后不提供取消；
- 磁盘不足、目标不安全、目标冲突或源不完整时拒绝开始/切换。

### ARC-04 未知文件与临时目录

- 陌生手工文件阻止迁移，既不复制也不删除；
- `.staging`、`.readonly` 不作为正式存档内容迁移；
- 没有数据库记录、cleanup journal 或其他应用所有权证据的未知文件，不得作为“孤儿”自动删除。

### ARC-05 每次启动首次进入维护

每次软件进程启动后，用户第一次进入存档中心时：

1. 先加载并显示批次列表；
2. 随后在后台分页执行元数据筛查、到期清理及有所有权证据的孤儿保洁；
3. 成功后本次进程不重复；
4. 失败后不在后台无限重试，用户下次重新进入时允许再试；
5. 完成后刷新列表；若当前选中批次已到期删除，清空选择并明确提示。

列表首屏不得等待维护完成。

### ARC-06 文件指纹

新增内部 `ArchiveFileFingerprint`：

```text
sizeBytes + mtimeMs + ctimeMs + ino（可选）
```

- 新存档在 SHA 验证成功后保存最终文件指纹；
- 已有非空指纹与当前文件相同时跳过 SHA；
- 指纹变化时只对候选文件计算 SHA；
- SHA 相同则刷新该新合同记录的指纹；SHA 不同走现有损坏/修复/失败合同；
- 指纹只是 SHA 筛选器，不是完整性真相。

### ARC-07 历史存档边界

- v3.1.12 前记录的指纹字段保持 `NULL`；
- 不在迁移时批量补建，不在首次进入维护中全量回扫或顺手回填；
- 旧存档只在打开、另存或变更存档位置时按现有规则计算 SHA；
- 旧 Blob 被新批次去重复用时仍保持旧 Blob 指纹为 `NULL`，不以“新引用”名义回填历史物理文件；新建目录化副本可保存自身指纹。

### ARC-08 不进入时不维护

用户本次启动始终不进入存档中心时，不执行到期与孤儿清理；不增加每日或空闲兜底。

## 5. 接口与数据

### API-01 内部对象

- `ArchiveFileFingerprint`：`sizeBytes、mtimeMs、ctimeMs、ino?`。
- 网银大账号预检冻结证据：仅包含文件序号、源行定位、已识别账号/币种及识别结果，不包含整份原始工作簿行。

### API-02 数据库

- `archive_blobs` 增加可空文件指纹字段；
- `archive_artifacts` 的目录化副本增加可空文件指纹字段；
- `vcc_fin_op_system_snapshots(import_source_id, id)` 增加索引；
- schema 迁移幂等，历史行保持 `NULL`；不得通过历史数据改写来伪造新合同。

### API-03 IPC

- 新增“开始本次启动首次进入维护” IPC；调用立即返回，不等待维护结束；
- 新增维护进度/完成/失败事件；
- renderer 在维护完成后刷新列表；
- 移除 `initPending` 与初始化进度监听合同。

## 6. 验收与测试

### TST-01 网银账单
