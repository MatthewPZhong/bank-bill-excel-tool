## 1. 背景与需求

用户原文要点：

- **第 4 条：网银账单生成的导出**
  - 点击【导出明细】后，直接导出当前批次生成的明细账单，即直接弹出文件另存为框。
  - 点击【导出余额】后弹出的页面做以下调整：
    1. 文本「请选择要导出的范围」下移，与左侧圆形图案的中线对齐。
    2. 删除【导出当前批次文件的余额】和【导出所有批次文件的余额】按钮内多余的空白占位，两个按钮并排显示，「当前批次」在左。
    3. 页面右上角新增「×」关闭按钮。
- **第 5 条：模板管理新增【更新】**
  - 背景：渠道侧变更原始账单字段越来越频繁，调整映射关系的次数随之增多。
  - 入口：模板管理执行操作列的【修改】右侧新增【更新】；普通模板的【重命名】左缘与渠道行【重命名】左缘对齐。
  - 流程：
    1. 点击【更新】弹出文件选择框，选择新模板文件后，弹窗显示新旧模板的字段变更，右下角有【更新模板】【返回】。
    2. 点击【更新模板】后弹窗提示成功或失败。
    3. 成功页右下角有【修改映射关系】【返回】，【修改映射关系】在左。

现状：

- **导出**：同一会话导入两次及以上时，【导出明细】和【导出余额】都先弹出范围选择。范围弹窗的两个按钮是上下排列的整宽卡片，按钮内大段留白，也无法关闭（只能选择范围）。
- **模板**：模板只保存表头（`templates.headers_json`）。重新导入同名模板文件会走 `upsertTemplate`，同时清空映射、大账号、固定值、币种大账号和字段筛选，用户需要从头配置。

## 3. 规则

### 3.1 导出

- **【导出明细】**
  - 无论本次运行导入过几批，都直接导出当前批次的明细，弹出另存为框，取消则不导出。
  - 尚未处理的补录/断档提示仍保留在状态框（与原逻辑一致）。
- **【导出余额】**
  - 单批次时直接另存；多批次时弹出范围选择，规则不变，只调整弹窗版式：
    - 提示文字与左侧图标垂直居中。
    - 两个按钮按文字宽度并排居中，文案不变。
    - 右上角 × 关闭：不导出，也不改变状态栏。
  - 导出进行中（另存为框打开或文件写出期间）× 不能关闭弹窗。
- **导出月度余额账单**：模式不受影响。

### 3.2 【更新】入口与字段变更

- **入口**：【更新】位于普通模板行和子模板行的【修改】右侧。各类行执行操作列的首槽等宽：普通模板为【修改】【更新】，渠道为【导入子模板】。因此【重命名】左缘对齐。
- **选择文件**：点击后弹出文件选择框，可选 xlsx/xls/csv，与导入模板一致；取消不弹窗。
- **读取表头**：读取文件第一行非空行作为表头，与导入模板同一规则。
- **字段变更弹窗**（标题「字段变更」）展示以下内容：
  - 来源：模板「X」← 文件「Y」
  - 新增字段（N）、删除字段（N）：以标签列出，没有时显示「无」
  - 字段顺序：仅比较新旧都有的字段的相对顺序，显示「有调整」或「无变化」
  - 受影响的映射（N）：列出所有引用了删除字段的配置项，例如 `Credit Amount ← 交易金额`；当前未启用的配置项（如已关闭的按字段区分发生额、拆分行草稿）标注「（未启用）」
  - 说明：映射关系、大账号、字段筛选与拆分规则均保留
  - 右下角按钮：【更新模板】【返回】。【返回】和 × 回到模板管理，不做任何修改。
- **字段完全相同**：照常显示变更页，并提示「所选文件的表头与当前模板一致，字段无变化。」，【更新模板】置灰。
- **以下情况不显示变更页**，直接显示结果弹窗，只有【返回】：
  - 新表头与其他模板完全相同：提示「该文件的表头与已有模板「X」完全相同，无法更新为重复表头的模板。」
  - 文件无法读取或没有有效表头。

### 3.3 确认更新

- **复核**：点击【更新模板】后，主进程再次校验以下几项，任何一项不通过都提示失败，不写库：
  - 模板仍存在。
  - 当前表头与变更页展示时一致（否则提示「模板在此期间已被修改，请重新点击【更新】」）。
  - 新旧确有变化。
  - 与其他模板不重复。
  - 映射不是旧版方向（`template_field` 存源字段的早期格式）。旧版方向在表头替换后可能无法识别，映射会整体读空，因此提示「该模板的映射关系为旧版格式，请先点【修改】打开映射关系并点【完成】保存一次，再更新模板」。预览时同样检查。
- **写库**：只写 `headers_json`、`source_file_name`、`updated_at`，以读到的原表头作为条件更新，防止并发覆盖。其他表与列不变。
- **写库之后**：
  - 同步模板库文件（`templates/template-library.json`）。
  - 记录活动日志：模板名、源文件、新增/删除字段、顺序、失效映射数量。
  - 结果弹窗：
    - 成功：显示结果文字和失效映射列表；右下角【修改映射关系】【返回】。
    - 失败：显示原因；右下角只有【返回】。
  - 【返回】回到刷新后的模板管理（子模板所在渠道保持展开）。失败时先重新读取模板列表再返回，例如确认期间模板已被删除。
  - 【修改映射关系】打开该模板的「映射关系管理」，与【修改】相同；完成或关闭后回到模板管理。
- **导出缓存**：本次运行已生成的导出缓存不清除，与保存映射一致。

### 3.4 失效映射的拦截与修改

- **拦截时机**：生成账单（导入网银账单、导出所有批次时重新生成）构建模板配置时检查。凡生成时实际会读取的源字段不在模板表头中，就拒绝生成，提示：
  `模板「X」的映射字段不存在：A、B，请在模板管理中修改映射关系后重新导入`
  报错文件逐条列出失效映射。
- **检查范围**：
  - 主映射：含拼接字段、按正负号拆分的发生额、根据发生额做映射的户名/账户号。
  - 启用时才检查的：按字段区分发生额规则；拆分/合并的拆分映射（不复用时）、已完成的拆分行、拆分发生额规则、按正负号拆分字段。
  - 实际生效时才检查的：字段筛选的筛选字段。
- **不受影响**：现有有效模板。这些模板保存映射时已校验字段存在，检查不会触发。
- **映射关系管理中的显示**：
  - 主映射和拆分映射的下拉框里，失效的值显示为「X（已删除）」并标红。
  - 拼接字段面板中，失效字段标为「（已删除）」，可取消勾选。
  - 不改成正确字段就保存时，沿用现有校验报「映射字段不存在」，不会被静默保存为空。

## 4. 风险（需人工复核）

- 列名不变但含义改变的字段无法识别，映射会照常沿用。
- 模板包（导出模板文件）若包含带失效映射的模板：主映射失效时，在其他电脑导入会因映射校验失败被跳过，其余模板照常导入；拆分映射失效时仍会导入（导入路径不校验拆分映射，属既有行为），在那台电脑生成时被拦截。
- 模板包覆盖已有模板时，按包里的表头校验映射（v3.2.18 修正：原先沿用本机旧表头，更新后的模板交接到旧版本机器时会被误跳过）。
- 存量数据中若已有主映射或拆分映射指向表头外字段的模板，过去这类字段静默输出空值，本版起会被拦截。需用真实库副本只读扫描确认（backlog B96）。

## 5. 非目标

- 不提供「按位置自动迁移映射」或「改名字段自动沿用映射」。
- 不修改模板名称（重命名仍用【重命名】）。
- 不改变导出余额范围的业务规则、按钮文案和月度余额导出。
- CHANGELOG、`docs/VERSION_FEATURE_HISTORY.md`、`release-notes.json` 在发版时同步，本分支不改。

## 6. 验收

1. 多批次导入后点【导出明细】直接弹出另存为框，导出内容为当前批次明细。
2. 多批次导入后点【导出余额】，范围弹窗满足以下各项：
   - 文字与图标垂直居中。
   - 两个按钮同行居中，「当前批次」在左。
   - × 可关闭；导出中不能关闭。
3. 模板管理各类行【重命名】左缘对齐（100%/125% 缩放下不换行）；普通模板、子模板有【更新】。
4. 更新流程：
   - 变更页内容正确。
   - 【返回】不改模板。
   - 【更新模板】后映射、大账号等全部保留，表头替换。
   - 成功页【修改映射关系】打开映射弹窗。
5. 有失效映射时生成账单被拦截且提示具体字段；修改映射保存后可正常生成，输出取自新字段。
6. 字段无变化、重复表头、确认期间模板被改/删时均不写库，并提示原因。
7. `npm run release-check` 通过。
