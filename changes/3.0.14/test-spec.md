# 3.0.14 Test Spec

## 1. 命中与异常说明

1. 场景命中且字段从 A 改为 B：进入命中 sheet。
2. 场景命中但字段 A 仍为 A：不执行异常说明检测，进入未命中 sheet。
3. 字段改值且多对多检测有异常说明：进入命中 sheet，改值列标黄，异常说明保留。
4. 字段未改值但原逻辑可生成异常说明：不得进入命中 sheet。
5. 输入总行数等于命中与未命中输出行数之和。

## 2. 前置资金对账主面板

1. 前置模块与 `资金对账数据处理` 使用相同的 row1 + merged-row DOM 骨架、左右列比例和状态框跨行结构。
2. 原 `导入文件 / 导出文件` 槽位分别放 `[对账场景]` 下拉框和 `链接表管理`。
3. 原 `开始运行 / 场景管理 / 链接表管理` 槽位分别放 `导入文件 / 开始运行 / 导出文件`。
4. `对账场景` 文本位于下拉框左侧，不推挤相邻按钮；状态框宽度和高度与资金对账数据处理一致。
5. 本次会话未导入银行文件、未运行且无异常时，即使临时或持久网关数据已存在，状态框仍显示 `欢迎使用小助手`。
6. 主面板按钮和管理弹窗标题均为 `链接表管理`，用户可见文案不再出现 `临时链接表管理` 或 `导入账单文件`；弹窗内的 `导入` 仍调用既有 MPT 导入处理函数。

## 3. MPT 解析

1. INBOUND `.txt`、`.gz` 各成功一份。
2. OUTBOUND `.txt`、`.gz` 各成功一份。
3. UTF-8 BOM 可接受。
4. 首行日期/批次字段顺序变化时按形状正确识别。
5. 错前缀、错字段数、错声明行数、错数值、错日期、截断 gzip 均原子失败。
6. `MPT_CHANNEL_OTHERS` 被拒绝且提示 3.0.15。
7. OUTBOUND 分别覆盖 bankDebit、target、origin 三层金额/币种 fallback，并验证成对选择。

## 4. 临时批次生命周期

1. 不同批次追加。
2. 同文件同 hash 重导为 no-op。
3. 同文件名不同 hash 拒绝。
4. 同批次更高文件序号原子替换。
5. 同批次更低文件序号拒绝。
6. 替换失败后旧批次完整保留。
7. 重启数据库实例后批次仍可查询。
8. 删除单批次不影响其它批次；全部清空后为 0。
9. 主库 `linked_gateway_bill` 的行数与内容不受影响。
10. 临时链接表首页与既有链接表管理复用同一组 card/table/footer class，固定显示三列表库概览和 `删除 / 导入 / 退出`，且不出现 `账户映射管理`。
11. 首页固定显示 `临时中台入金网关账单表库`、`临时中台出金网关账单表库`；每行日期范围和更新时间只由自身 `sourceType` 批次计算。
12. 同一次多文件导入中，INBOUND/OUTBOUND 分别走对应 schema 并落为对应 `sourceType`，一类失败不污染另一类已成功文件。
13. 点击删除后与既有链接表删除框复用相同 card、表单字段顺序和按钮结构；目标表包含临时中台入金/出金网关账单两个逻辑表库。
14. 日期范围按所选 `sourceType + sourceDate` 闭区间统计和删除；删除一类时另一类批次及共享月侧库保留。
15. 跨月范围、边界日期、零命中、非法日期、范围外批次保留、空月库文件回收及相同范围幂等重跑均有覆盖。
16. 删除期间使用共享 mutation lock；删除后旧对账结果按来源快照判定失效，持久网关链接表不受影响。
17. 管理逻辑隔离不改变匹配池：INBOUND/OUTBOUND 临时行仍共同参与严格 1:1 对账。
18. 预统计和删除缺失/未知 `sourceType` 时在服务边界拒绝；删除最后一类前不得提前回收仍含另一类批次的共享月侧库。

## 5. 银行行派生

1. Credit 非零：CREDIT，Drawee 姓名/账号，金额绝对值。
2. Debit 非零：DEBIT，Payee 姓名/账号，金额绝对值。
3. 双边非零：整次运行失败并定位行号。
4. 双边零/空：跳过并计数。
5. 空 ReconciliationId：跳过匹配并告警，不进入不平结果。
6. OriginBillId 为空：同一文件行生成稳定且唯一的追溯 ID。

## 6. 1:1 匹配与重复

1. 非空 ID、渠道、金额、币种四项全部相同才成功；字符串 trim 后大小写敏感。
2. 对账 ID 相同但渠道不同：不平，不消费候选。
3. 对账 ID、渠道相同但金额不同：不平，不消费候选。
4. 对账 ID、渠道、金额相同但币种不同：不平，不消费候选。
5. 金额 `1`、`1.0`、`1.00` 视为数值等价。
6. 同 ID 第一候选要素不符、后续候选四项相同：跳过不符候选并消费后续精确候选。
7. 不做子串或日期兜底。
8. 两条银行完整匹配键相同、一条网关：第一条平账，第二条右单边。
9. 一条银行、两条完整匹配键相同但指纹不同的网关：只消费第一条稳定候选。
10. 临时和持久来源均满足完整匹配键：临时候选先消费。
11. 同 ID+同 10 字段指纹折叠为一个候选并告警；稳定第一条为保留记录，其余为被折叠记录。
12. 同 ID+不同指纹不折叠。
13. 十个指纹字段分别变化时均不得误折叠。
14. 参与银行行 = 平账 + 不平；网关候选 = 已消费 + 未使用。
15. 一个折叠组含 1 条保留记录和 N 条被折叠记录时，审计对象完整保存 1+N 条，各对象共享折叠记录ID但数据来源、数据位置和自身字段不串。
16. `对象类型` 仅为 `保留记录` / `被折叠记录`；折叠原因固定为 `reconciliationId+10字段指纹完全重复`，重复指纹与实际折叠键一致。
17. 保留记录和每条被折叠记录的原始 JSON 均保留；不得只记录被折叠侧或只记录计数。

## 7. 导出

1. 两个银行 Channel 生成两个文件，内容不串渠道。
2. 文件名使用本机实际导出日和安全渠道名。
3. 本渠道无完全重复记录时严格保持 5 个 sheet，名称和顺序为 `不平结果 / 平账结果 / 网关账单 / 渠道账单 / 订单修复`，不得生成空的重复审计 sheet。
4. 本渠道有完全重复记录时仅在末尾追加第 6 个 `重复网关账单`；前 5 个 sheet 的名称、顺序和列结构不变。
5. `重复网关账单` 表头严格为固定 22 列：折叠记录ID、对象类型、分片序号、分片总数、折叠原因、重复指纹、数据来源、数据位置、BillDate、Channel、MerchantId、OrderId、ReconBillBizId、reconciliationId、Currency、Amount、TradeType、name、cardNo、真实渠道、清算网络、原始数据JSON分片。
6. `不平结果` 20 列、`平账结果` 31 列，其余基线表头 31/16/14 列。
7. 原始 JSON 长度分别覆盖 2（最短合法对象 `{}`）、30000、30001、60000、60001，以及中英文、转义字符和 Unicode 字符恰好跨分片边界的场景；每片不超过 30000 字符且不得拆坏字符，分片序号从 1 连续，按 `折叠记录ID + 对象类型 + 数据来源 + 数据位置` 分组并按序拼接后与折叠前原文逐字符一致。
8. 同一原始对象的每个分片行重复填写其余 21 列；多个被折叠对象不得因对象类型相同而串片或合并。
9. 导出渠道集合为银行渠道与重复记录渠道并集：只有重复记录、没有银行行的渠道仍生成 6-sheet 文件，前 5 个 sheet 只有表头，第 6 个 sheet 有本渠道审计数据。
10. 某银行渠道没有重复、另一渠道有重复时，前者保持 5 sheet、后者为 6 sheet；两者的重复审计、平账和不平数据不得串渠道。
11. 0 不平仍生成文件，`不平结果` 只有表头，`平账结果` 有数据。
12. 不平结果只包含缺网关银行行，来源为 `导入银行对账单`，差错为 `右单边账`。
13. 渠道账单只包含相同的银行右单边行。
14. 网关账单、订单修复只有表头。
15. 模板列宽、表头样式和冻结等既有格式保留；动态第 6 sheet 的表头样式可读且列顺序固定。
16. 取消导出不改变结果；写入失败不留下伪成功文件。
17. 冲突检查后外部程序创建同名文件时，导出显式失败且不得覆盖或回滚删除该外部文件；已发布文件随后被外部替换/修改时也不得按路径盲删。
18. 目标目录不支持硬链接时使用 `COPYFILE_EXCL` 降级，普通/覆盖导出仍成功；降级路径遇到同名文件仍按 no-clobber 失败。

## 8. 兼容与性能

1. C4 接受旧 4-sheet/19-column `对账结果`。
2. C4 接受新 5-sheet/20-column `不平结果` 和 `平账结果`。
3. C4 接受末尾追加 `重复网关账单` 的 6-sheet 文件；第 6 sheet 存在时严格校验固定 22 列，校验后不读取数据行，订单修复/网关账单读取结果与对应 5-sheet 文件一致。
4. C4 对缺失或改名的必需 sheet、错误表头仍按既有结构校验拒绝；既有按名称读取和忽略无关未知 sheet 的行为不变。
5. 合成 10 万行 gzip 导入不出现与文件大小等量的多份内存副本。
6. 合成百万级持久网关表匹配通过迭代/投影完成；重复审计原始 JSON 随结果流式落侧库/写 Excel，不把全部分片常驻内存。
7. 运行中数据源变化后，旧结果不可导出。
8. 同进程第二次运行回收第一次结果 side DB，旧主库镜像标记 `superseded`，新结果仍可导出。
9. 应用重建 service 后旧成功结果标记 `expired` 并整文件回收，临时 MPT 批次仍保留。
