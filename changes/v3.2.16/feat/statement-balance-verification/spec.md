## 1. 背景

现状（v3.2.15）：

| 模板 | 处理 | 问题 |
| --- | --- | --- |
| 账单里的余额，当天只有一个余额值 | 直接采用，不查种子、不核对 | 余额与“上一日余额 + 当日收支”不符也不提示；结果回写成种子，成为下次导入的起点 |
| 账单里的余额，当天有多个余额值 | 用上一日余额 + 当日收支从候选中选；`+支出` 备选规则也算匹配 | 导入时金额已去掉正负号，`+支出` 等于把支出当收入，会掩盖收支方向映射错误 |
| 通过发生额计算 | 从种子逐日累加，有缺种子与断档检查 | 不读账单余额（本次不改） |

本分支为「账单里的余额」模板增加逐日余额校验。

## 3. 功能规则

### 3.1 校验口径

- 分组与日期：沿用现有口径，按银行账号 + 币种分组、按账单日期升序；参与计算的行与现状相同（收入、支出都为 0 或空的行已在此前剔除）。
- 锚点（上一日余额）：
  - 每组首日：同银行、同账号、同币种、账单日期早于首日的最近一条种子（任意生成方式）。生成的种子（账单里的余额 / 通过发生额计算）先扣回截至种子日的余额附加值，人工录入的种子按原值（沿用 v3.2.15 §3.5）。
  - 之后的日期：上一日的账单余额原值（不含余额附加值）。
- 候选余额：当天各行余额按两位小数去重；比较按两位小数，输出取选中候选的原值（沿用 v3.2.15 §3.6）。
- 结果：
  - 有候选与预期相符 → 采用该候选。
  - 只有一个候选且不符 → 余额不一致（3.3）。
  - 多个候选都不符 → 不允许继续（D7）：首日见 3.2，之后的日期报“期末余额无法根据收支金额推导”。
  - 当天没有任何余额 → 维持现状报错“未找到期末余额”。
- 余额附加值、种子回写、余额表格式不变。

### 3.2 缺种子

- 任一组首日之前没有种子：返回补录提示（`BALANCE_SEED_REQUIRED`，文案沿用“因首次导入余额，请导入上一个账单日余额用于余额校验”），补录后重新生成。
- 已有种子但首日多个余额都对不上（D7）：同样返回补录提示（`BALANCE_SEED_REQUIRED`），文案改为“上一账单日余额与账单对不上，请核对后重新补录”，并附上：
  - 已有种子的日期、金额、生成方式；用于计算的上一日余额（生成的种子扣回附加值后的原值）；
  - 首日收入合计、支出合计、预期余额、账单当日各余额。
- 补录弹窗标题为“核对上一账单日余额”，写明以上明细，预填已有种子的日期与金额；用户修改后提交，同日已有种子时沿用“该日期的余额已存在，确认覆盖吗？”。状态框标题“点击核对上一账单日余额”，活动日志写明对不上的明细。
- 背景：v3.2.15 用户反馈（KBANK-VN，首日两笔余额）：上一账单日余额误填 0 后，程序回到同一个空白补录框（看似关不掉），错误种子已落盘，重启后仍反复提示。

### 3.3 余额不一致确认

- 全部分组算完后，若有未确认的不一致，统一弹一次确认，逐条列出：
  - 银行账号、币种、账单日期；
  - 上一日余额的来源和日期：取自余额种子还是上一账单日；
  - 上一日余额、当日收入合计、当日支出合计、预期余额、账单余额、差额（账单余额 − 预期余额）；
  - 上一日与当日之间缺日期时，写明缺的日期区间。
- 按钮：
  - 「返回核查」：关闭弹窗，余额账单不生成；状态框仍可点开再处理。
  - 「确认继续生成」：以账单余额为准生成，种子照常回写。导入提示写“N处余额校验不一致，已按账单余额生成”，报错文件逐条列出差异；活动日志记一条警告。
- 不一致的那一天无论是否确认，都以账单余额作为下一日的上一日余额，因此一次能列全所有差异。
- 确认记在主进程账单会话的内存中，不落盘，重启后失效；与断档“不补录”同一口径，本次运行期间对完全相同的不一致有效（复用时导入提示仍带告警）。
- 确认键包含模板（输出名称）、银行账号、币种、账单日期、上一日余额的日期与金额、当日收入合计、当日支出合计、账单余额（金额按分）；其中任一变化视为新的不一致，需重新确认（D9）。
- 处理顺序：缺种子补录 → 发生额计算的断档确认 → 余额不一致确认。多个模板组的不一致合并为一次确认。

### 3.4 人工补录替换提醒（D10、D11）

- 时机：生成种子按同日覆盖写入；写入前，若同银行、同账号、同币种、同一账单日已有“人工录入”的种子（未写生成方式的旧记录按人工录入），且与本次日终余额按分不一致，先提醒。只认人工补录，不比对工具生成的种子。
- 比对口径：本次余额取原值（不含余额附加值），与人工补录同口径（沿用 v3.2.15 §3.5：人工补录按原值）。有附加值时提醒另写“另加余额附加值 X 后写入 Y”。
- 提醒逐条列出：银行账号、币种、账单日期、人工补录余额、账单余额（账单里的余额）或计算余额（通过发生额计算）、差额（本次 − 人工补录）。
- 「返回核查」：关闭弹窗，余额账单不生成，不写任何种子（含同一模板里不涉及替换的账户）；状态框仍可点开。「确认替换并生成」：按本次余额生成并覆盖人工补录；导入提示写“N处人工补录余额已按本次余额替换”，报错文件逐条列出，活动日志记一条警告。
- 顺序：缺种子补录 → 断档确认 → 余额不一致确认 → 人工补录替换确认。多个模板组合并为一次确认。
- 确认范围与失效同 3.3：本次运行期间对完全相同的项有效；确认键包含模板、账号、币种、账单日期、人工补录余额与本次余额（按分），任一变化需重新确认。
- 工具按同值回写会把人工补录改成工具生成（提交后 Codex 审查 P1）。本次运行内，这样的日期仍按人工补录保护：
  - 之后任一模板、任一入口以不同金额回写都要先确认。入口包括同批后续的组、返回核查后的重算、按文件名映射分批导入、导出全部。常见情形是多个模板共用同一份种子：同一银行前缀，如“中行-A”“中行-B”，同账号、同币种。按磁盘上的实际种子文件判断是否“同一份种子”：银行名写法不同，但解析到同一个文件时（空白、特殊字符；文件系统不区分时的大小写、Unicode NFC/NFD）共用保护；不同文件互不影响。
  - 按最新的人工值比对：运行中途补录或改过的值以改后为准，人工值变了，旧确认失效。
  - 确认替换并写入后，不再按旧人工值比对；用户删掉该日种子后也不再比对。
  - 重启后，此前工具回写的种子按 D10 只认人工补录，不比对。

### 3.5 导出全部余额的已接受风险告警（D12）

- 范围：「导出全部」余额（指定模板与按文件名映射两条路径，含部分模板已删除时的导出）。导出当前批次使用导入时生成的文件，告警已在导入时显示，不变。
- 导出成功后，若本次重算的告警含 `balance-gap-skipped`、`balance-mismatch-confirmed`、`balance-seed-replace-confirmed`，结果为告警：“文件导出成功，N处……，请点击状态框导出报错文件”（部分模板已删除时以“文件已导出，但数据不完整：……”开头），报错文件逐条列出，活动日志记警告。其他类型告警不带入。导出失败时保留原错误。
- 再次导出全部命中已生成的文件时，以及确认后重算、再导出时，告警同样带出：告警随文件一起保存（提交后 Codex 审查 P2）。

## 4. 非目标

- 「通过发生额计算」的余额校验（D1）。
- 在不一致弹窗内直接修改种子；需要修正时由用户核查账单或种子后重新导入。
- backlog B32（附加值跨导入重复叠加）。
- 不回溯、不改写已生成的历史余额表与种子。

## 5. 验收标准

- 单一余额与预期相符：正常生成，无提示。
- 单一余额不符（如种子 1,000、当日收入 100、账单余额 9,999）：弹余额不一致确认，列出预期 1,100、账单 9,999、差额 8,899。确认后余额表为 9,999，种子写 9,999，导入提示带告警；次日从 9,999 接着校验。
- 多日、多组同时不符：一次确认列全；确认后不再提示同一批差异。
- 首日无种子（单一余额）：要求补录；补录后按补录值校验。
- 跨周末等断档：缺的日期无净发生额时直接通过；有缺失交易时进入不一致确认并写明缺的日期。
- 多候选都不符：首日已有种子时提示“上一账单日余额与账单对不上”，列出种子与当日收支、账单当日余额，弹窗预填种子；改对后正常生成。非首日余额账单不生成并给出原因（与现状一致）。
- 当日只有支出、账单余额等于“上一日余额 + 支出”：不再算匹配。
- 差额 0.004 通过，0.006 提示。
- 带余额附加值：校验按账单原值链进行，输出与种子仍叠加附加值。
- 「通过发生额计算」模板的输出、提示与现状一致。
- 按文件名映射、导出全部、补录后重算等入口行为一致。
- 导出全部余额：确认第一批差异后导入第二批再导出全部，导出结果带“1处余额校验不一致，已按账单余额生成”告警并可导出报错文件；没有已接受风险时仍为“文件导出成功”。
- 人工补录替换：同日人工补录 5,000、账单余额 1,100 时先提醒并列出两个值；返回核查不生成、不写种子；确认后余额表为 1,100、种子替换为 1,100。发生额计算同样提醒（列出计算余额）。相符时不提醒。余额不一致与替换同时存在时先后两次确认。
- 共用种子：中行-A（与人工补录 5,000 相符）、中行-B（1,100）同批或分批导入，不论先处理哪组，B 都先提醒；返回核查后重算仍提醒；确认后 B 生成余额并带“已确认替换”告警。先导入、后补录 09-01=5,000 时同样提醒。确认 5,000→1,100 后人工值又改为 6,000，按 6,000→1,100 重新提醒。
- 导出全部再次导出（命中已生成文件）、确认后重算再导出：仍带已接受风险的告警。

## 6. 数据与资金影响

- 不改表结构、不改迁移、不改种子文件格式。
- 对现有用户的影响：
  1. 新账号首次用「账单里的余额」需补录一次种子。用过的账号已有工具回写的种子。
  2. 历史上未经核对就回写的种子如果本来就错，升级后首日会提示不一致；确认一次后从账单余额重新起算。
  3. 依赖 `+支出` 备选规则的模板（收支方向映射有误），会从静默通过变为提示或失败。
- ⚠️ 资金红线，请人工复核：确认继续后以账单余额为准并回写种子。确认后差异只在本次导入提示、报错文件和活动日志中留痕，种子本身不记录“曾不一致”。
- 人工补录替换（D10）改变了既有口径：v3.2.15 及以前，生成种子静默覆盖同日人工补录；现在不一致时须确认，两种模板都受影响。确认替换后人工补录值只在本次导入提示、报错文件和活动日志中留痕。
- ⚠️ 资金红线，请人工复核：两个模板共用种子，且对同一账号同一天给出不同余额时，种子取后写入的一组（v3.2.15 起既有）。这一点见 backlog B35。本次只保证本次运行内人工补录被替换前一定先提醒（§3.4）；重启后，此前工具回写的种子按工具生成处理，不再提醒。
