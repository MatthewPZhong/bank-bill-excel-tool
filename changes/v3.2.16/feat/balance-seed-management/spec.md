## 1. 背景

用户需求（2026-11-08，需求 2）：

> 余额种子可视化：模板管理页面左下角新增按钮【余额管理】，点击【余额管理】后弹出页面，页面左上角显示“余额管理”，“余额管理”右侧有文本“渠道”，“渠道”右侧存在单选下拉框，下拉框的枚举值为渠道。主页面需显示账户号、币种、日期、余额。支持修改和删除。

现有同名的【余额管理】（维护大账号弹窗左下角）维护的是余额附加值，用户要求改名为「余额附加值」。

## 2. 代码现状（基线 v3.2.15）

| 位置 | 当前行为 |
| --- | --- |
| `src/backend/balance-seed-store.js` | 种子存放在 `balance-seeds/<银行段>.json`，银行段为名称第一个 `-` 之前的部分；记录含 `merchantId / currency / billDate / endBalance / templateName / 生成方式 / updatedAt`，同一文件内以“账户号 + 币种 + 日期”为键 |
| 生成账单（`statement-generation*.js`、`main.js` `storeGeneratedBalanceSeeds`） | 按输出名（渠道名或普通模板名）的银行段读写整份文件，按“账号 + 币种”查找，与 `templateName` 无关；计算种子以 `overwrite: true` 覆盖同键记录 |
| 补录（`manual-balance-seed-preflight.js`） | 写入人工录入种子；确认前核对种子文件证据，期间文件变化则要求重新补录 |
| 维护大账号【余额管理】 | 维护余额附加值（`balance-adjustment-store.js`），与种子无关 |
| 用户查看或修改种子 | 只能直接编辑 JSON 文件 |

## 4. 功能规则

### 4.1 入口与布局

- 模板管理底栏左侧新增【余额管理】，右侧保留【导入模板文件】【导出模板文件】。
- 弹窗标题「余额管理」，其右侧为文本「渠道」与单选下拉；默认选中第一个渠道，没有渠道时选中第一个普通模板。
- 表格列：账户号、币种、日期、余额、生成方式、执行操作（【修改】【删除】）。按账户号、币种升序，同一账号日期从新到旧；超过 200 条分页。
- 提示行显示条数和种子文件名，说明种子按名称的银行段存放、生成账单时按账户号与币种读取、修改后的余额按「人工录入」处理。

### 4.2 可见范围（选中某个渠道 / 模板时显示哪些种子）

- 渠道读渠道名银行段的种子文件，普通模板读模板名银行段的文件（与生成时的输出身份一致）。
- 只隐藏“写入者属于另一个读同一文件的现有归属”的记录：渠道名与其子模板名归渠道（子模板名覆盖迁移前子模板写入、D5 未搬移的种子），普通模板名归该模板；归属的银行段按渠道名 / 模板名计算。被隐藏的记录不能经当前选项修改或删除。
- 写入者为空、已改名或删除、或其现在的归属读的是另一份文件（例如渠道改名后，旧文件里渠道和子模板写入的种子）的记录，在同一银行段的所有选项下都显示：生成时仍按账号读到它们，不能让它们在界面上消失。
- “同一文件”按实际文件名判断：与 `getBalanceSeedFilePath` 相同的规范化（非法字符、空白），再按 NFC 与忽略大小写比较（Windows / macOS 默认文件系统不区分大小写）。例如「招商银行 -深圳」与「招商银行-北京」都写 `招商银行.json`。
- 名称重合时的认领顺序：渠道名、普通模板名是当前输出身份，优先认领；子模板名只认领迁移前的旧记录，与某个渠道名重名时让给该渠道（渠道可改名为另一渠道的子模板名）。
- 渲染层只提交 `{ kind: 'channel' | 'template', id }`，名称与子模板由 Main 从主库解析；选中属于渠道的模板、渠道或模板已不存在时报错。

### 4.3 修改与删除

- 修改：只改余额，余额须为有限数字（允许千分位逗号；超出数值范围的输入会解析为 Infinity，写回时会被种子库当作无效记录过滤，等于删除，因此拒绝）。写入后该条生成方式为「人工录入」，`templateName` 为渠道名 / 模板名，`updatedAt` 为当前时间；余额未变化时不写文件。
- 删除：先弹确认（显示账户号、币种、日期、余额，并提示删除后下次生成若需要这一天的余额会提示补录），确认后只删这一条。
- 乐观并发：修改、删除都先重新读文件，按渲染层带回的原值（所在种子文件身份、余额、生成方式、写入者、更新时间）核对；文件身份随每条记录在列表中返回，防止列表读取后渠道 / 模板跨银行段改名时改到另一份文件里字段相同的记录；不一致、记录已不存在或对当前选项不可见时返回 `conflict`（“余额种子已变化，请刷新后重试”），不写文件，渲染层提示并重新读取。
- 同一文件同键出现多条记录时拒绝处理并提示检查文件。种子文件损坏时沿用原有提示。
- 审计：成功的修改与删除写活动日志，内容为所属、种子文件路径、账户号、币种、日期、原余额 → 新余额（删除为被删余额）、原生成方式、原写入者。

### 4.4 接口与登记

| 通道 | 类型 | 说明 |
| --- | --- | --- |
| `balance-seed:list` | 只读查询（TaskPolicy exclude `read-only-query`） | 入参 owner；返回 owner 描述（名称、银行段、种子文件名）与记录 |
| `balance-seed:update` | support-action（reason `balance-seed`） | 入参 owner、key、expected、endBalance |
| `balance-seed:delete` | support-action（reason `balance-seed`） | 入参 owner、key、expected |

G7 TaskPolicy 清单已冻结，写操作按 `channel:rename`、`bank-accounts:save-as` 的先例登记为 support-action。

## 5. 非目标

- 不新增种子（新增仍由生成写入或补录）；不改账户号、币种、日期。
- 不改变生成、补录、断档、月度余额读取种子的口径，也不搬移种子文件。
- 不处理同一银行段多个渠道 / 模板共用同一账号时的种子归属（backlog B35 的既有口径）。

## 6. 假设（低影响、可回退，交付时报告）

- A1：可见范围按记录的写入者（`templateName`）划分，见 4.2。生成时不区分写入者，因此同银行段其他现有渠道 / 模板写入的同账号种子同样会被本渠道生成读取，但只在其写入者的选项下显示（backlog B35 的共用口径）。
- A2：没有现有归属认领的记录（空写入者、改名或删除后遗留）在同一银行段所有选项下都显示，避免无法维护。
- A3：种子是某日的期末余额，生成账单时会以 `overwrite: true` 写入所生成日期的种子。修改或删除后再生成包含这一天的账单，这一天的种子会被生成结果覆盖；已生成未导出的账单不随之改变，需要重新生成。生成进行中修改种子同理（不阻断，与重新生成的覆盖口径相同）。

## 8. 数据与兼容影响

- 只改写 `balance-seeds/<银行段>.json` 中被修改或删除的那一条；写回时沿用种子库既有的规范化（与生成、补录写入相同），旧记录会补齐空写入者、人工录入与空更新时间。
- 修改把计算种子转为人工录入：断档检测会把它当作锚点；首日余额按种子推导时不再扣回附加值。这是 D3 的预期口径。
- 无迁移；新增 3 个 IPC 通道与 preload `balanceSeeds` 命名空间，配置弹窗边界 `allowedApiFields` 增加对应 API。
- 补录写入（`writeManualBalanceSeedPlan`）在写入前同步重读种子文件并核对确认时的证据，变化即以“余额种子在确认期间已变化，请重新补录”拒绝。补录在 `beforeStart` 核对之后、`execute` 写入之前有异步等待，【余额管理】是 support-action、不占 STATEMENT 任务位，可能在其间改写同一文件；不加这道核对，补录会用确认时的旧整文件计划覆盖这次修改或删除。正常界面下补录弹窗保存期间不能打开模板管理，属 IPC 层并发。
