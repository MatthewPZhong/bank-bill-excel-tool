## 1. 背景

用户需求（2026-11-08）：

部分渠道的原始账单只有币种，没有账户号，因此无法制作对应的明细和余额账单。前端改动：

1. 映射关系管理中，模板字段 `MerchantId` 的枚举值新增「原始账单仅有币种无账户号」。
2. `MerchantId` 选这一项时，下拉框右侧显示【映射管理】，样式与「自己输入」的【维护大账号】相同。
3. 点击【映射管理】弹出页面：左半边是币种及币种输入框，右半边是大账号及大账号输入框，右下角有【保存】和【返回】。

## 2. 代码现状（基线 `v3.2.15` / `5b5caf7b`）

| 位置 | 当前行为 | 与本次的关系 |
| --- | --- | --- |
| `MerchantId` 映射 | 取原始账单的某一列（再经账户映射转换），或「自己输入」：存为 `__FIXED__:__MULTI_BIG_ACCOUNT__`，Currency 行隐藏，大账号来自【维护大账号】 | 新增第三种：按币种查大账号 |
| 「自己输入」的大账号 | 存于 `template_big_accounts`；导入时按块识别，或弹窗选择大账号 / 币种（大账号 + 币种组合多于 1 个就弹窗）；渠道导入汇总全部子模板的大账号 | 新模式不经过识别和选择 |
| 余额 | 按 `MerchantId@@Currency` 分组成余额链；启用余额时 MerchantId 不能为空 | 新模式逐行回填 MerchantId 后沿用 |
| 月度余额导出 | 只纳入 `template_big_accounts` 里有大账号的普通模板 | 新模式本次不纳入（D3） |

## 3. 已确认决策（用户，2026-11-08）

| 编号 | 决策 |
| --- | --- |
| D1 | 生成账单时，输出行的币种为空、或该币种没在【映射管理】中配大账号：整批阻断，不生成任何文件。弹窗列出模板、文件名、币种和行号，提示先在【映射管理】中维护 |
| D2 | 【映射管理】弹窗逐行成对编辑：左半边币种，右半边大账号。每行最左侧是【新增】（在该行下方插入空行），行尾是【删除】，右下角【保存】在【返回】左侧 |
| D3 | 月度余额导出本次不纳入该模式，登记 backlog |
| D5 | （2026-11-09）使用本模式的渠道，原始账单币种列只会是币种代码（如 USD），不会是中文名称或 `RMB` 一类表外写法 |
| D4 | （2026-11-09，对账专项审查后）本模式下币种只认币种代码与币种映射表中的精确名称；“包含”式模糊命中（如「人民币离岸」被认成 CNY、「美元结算」被认成 USD）按未维护整批阻断 |

## 4. 功能规则

### 4.1 映射关系管理

- `MerchantId` 的下拉选项在「自己输入」之后新增「原始账单仅有币种无账户号」。
- 选中后，下拉框右侧显示【映射管理】；选其他值时隐藏。Currency 行保持可见。
- 选中后保存时：
  - 未启用「拆分/合并明细账单」时，Currency 必须映射到原始账单中的币种列，不能为空、固定值或拼接字段。
  - 启用「拆分/合并明细账单」时，Currency 行按现有互斥规则被禁用，币种取每条拆分行最终的币种。
  - 至少维护 1 组“币种 → 大账号”。
- 保存成其他 MerchantId 映射时，清空本模式的币种与大账号配置。

### 4.2 【映射管理】弹窗

- 标题「映射管理」。表格列依次为【新增】、币种、大账号、【删除】，币种和大账号各占一半宽度。
- 打开时显示已暂存的配置；没有配置时显示一行空行。
- 【新增】在当前行下方插入一行空行。【删除】删除当前行；只剩一行时，删除改为清空这一行，始终保留至少一行。
- 币种输入框按币种映射表做输入补全，失焦时转为大写。
- 【保存】校验通过后，把配置带回映射关系管理，并提示“点击【完成】后保存到模板”；在映射关系管理点【完成】时才写入模板。整行为空的行忽略。校验错误一次性弹窗列出：
  - 一组都没有：请至少维护 1 组币种与大账号；
  - 第 N 行：请填写币种 / 请填写大账号；
  - 第 N 行：币种「X」不在币种映射表中；
  - 币种「USD」重复（第 1、3 行），一个币种只能对应一个大账号。
- 一个大账号可以对应多个币种。
- 【返回】和右上角 × 放弃本次编辑，回到映射关系管理。

### 4.3 生成账单

- 每条输出行按最终的币种（大小写不敏感）查找大账号，结果写入 MerchantId；Currency 统一写成大写代码（如 `usd`、`美元` 都写为 `USD`）。
- 币种识别（D4）：英文代码不区分大小写；中文名称只认币种映射表中的精确名称（如「美元」→ USD），不做包含式模糊匹配。启用「拆分/合并明细账单」时沿用拆分行的现有口径，取原值不换算。
- 大账号原样写入 MerchantId，不再经过账户映射（网银账户号 → 清结算账号），与「自己输入」一致。
- 不识别大账号，不弹选择大账号窗口，也不按记住的顺序分配。
- 余额、余额种子、补录、余额调整、文件名都按回填后的 `MerchantId@@Currency` 沿用现有规则。一份文件含多个币种时，就有多条余额链。
- D1 阻断：
  - 只检查会输出的明细行，即收入、支出不全为空或 0 的行；合计行、零金额行不计入。
  - 一次导入的全部文件汇总后再报错。每组（模板 + 文件 + 币种）最多列 10 个行号，最多列 20 组。
  - 空币种显示为「（空）」。
  - 原始币种是无法换算成币种代码的英文词（如 `US Dollar`）时，同样按未维护阻断。

### 4.4 渠道

- 渠道内各子模板分别维护自己的币种与大账号配置。
- 同一批导入里，本模式的文件与需要选择大账号的文件（「自己输入」且有多个大账号 / 币种组合）混在一起时：阻断，提示分开导入。
- 只有一个大账号、不需要选择时照常生成，所选大账号只用于「自己输入」子模板的文件。

### 4.5 模板文件包

- 含本模式模板的模板包写版本 6，条目带 `currencyBigAccounts`；不含本模式（也不含同轮「字段筛选特征值」）时仍写 5，旧版照常可导入（合入 release/v3.2.16 时与「字段筛选特征值」统一为同一规则）。
- 读取版本不超过 6 的包；旧包按“无配置”读取。
- 旧版应用会整包拒绝版本 6 的包（“请升级应用后再导入”）。

## 5. 假设

| 编号 | 假设 |
| --- | --- |
| A1 | 【保存】只把配置带回映射关系管理，与【维护大账号】的【完成】一致；在映射关系管理点【完成】时才落库 |
| A2 | 大账号不经过账户映射，原样输出，与「自己输入」一致 |
| A3 | 命中行的 Currency 写成大写代码，以保证余额分组键与配置一致 |
| A4 | 从「自己输入」切换到本模式时，遗留的自有账号沿用现有 `preserveOwn` 行为，不额外删除 |
| A5 | 启用「拆分/合并明细账单」时允许本模式，按拆分行的最终币种查找大账号 |

## 6. 非目标

- 月度余额导出纳入本模式（D3，见 backlog）。
- 渠道混合批次中，本模式文件与需要选择大账号的文件同批选择大账号（见 backlog）。
- 【映射管理】弹窗不提供【余额管理】、【导入银行账号信息】。
- 不修改「自己输入」现有的识别、选择逻辑。

## 7. 验收标准

1. 选「原始账单仅有币种无账户号」后出现【映射管理】，Currency 行可见；改选其他值后按钮隐藏。
2. 弹窗布局符合 D2；【新增】【删除】【保存】【返回】的行为、校验提示符合 §4.2。
3. 保存模板后重新打开，选项、Currency 映射、币种与大账号配置都正确回显；改成其他模式保存后配置被清空。
4. 一份含 USD、EUR 的账单，USD、EUR 分别映射到两个大账号：明细 MerchantId 逐行正确；两条余额链分别正确；`usd`、`美元` 都按 USD 处理。
5. 有输出行币种为空或未维护时整批阻断，不生成文件，弹窗列出模板、文件、币种、行号；零金额行和合计行不阻断；多份文件汇总报错。
6. 渠道混合批次按 §4.4 处理。
7. 模板包 v6 导出、导入往返后配置一致；v5 包仍可导入。
8. 月度余额导出不包含本模式的模板（D3）。

## 8. 数据与资金影响

- 本模式决定每行的 MerchantId 和余额链归属：配错币种会把交易归入错误账号。D1 阻断未维护的币种；配置是否正确由用户负责，每个币种只能对应一个大账号。
- 新增表 `template_currency_big_accounts`，启动时幂等创建，删除模板时级联删除；不改动已有数据。
- 未改动「自己输入」与取列模式的输出。
