## 1. 背景

| 痛点 | 根因（排查结论） |
| --- | --- |
| 数据管理页面加载慢 | 存档关联同步每次在主进程统计全部月份有效行，并对每个来源开写事务；校验原表列表、导出预览、运行前预检在主进程同步执行；月份列表对有效行全表去重；每次打开重算全部归档月证据 |
| 存储数据过大 | 导入时每行原始 JSON 写入中转表与 raw fallback 后删除，生产上 fallback 永远读不到；主库不回收空闲页、导入后不截断 WAL |
| 解归档要求过严 | 只能从最新月逐月处理；任意月份导入都挡；只读操作也让预览失效；已调整位置解归档后不可再调；需勾选版本确认 |
| 导入和计算过久 | 每个文件完整解析 3 次、整文件 SHA-256 约 10 次；分类阶段多次全量扫描；worker 连接未设缓存；计算对当月全部行排序 |

另有新需求：通道明细对账字段为空或不合规的行，导入时由用户确认并补录。

## 3. 功能规则

### 3.1 级联解归档（D2、D6）

- 预览：选中 M 月后，若存在 M 月之后的已归档或已计算月份，预览列出这些月份、各自状态与人工调整条数，提示“这些月份的结果与调整将被删除，原表数据保留”，并出现删除确认勾选；勾选后才能执行。没有后续月份时与普通解归档相同，不出现勾选。
- 执行（单一事务）：写一条成功审计（`operation_type='unarchive_cascade'`）；删除后续月份的归档快照、结果及其明细、余额、Pending 汇总、币种合计与人工调整；后续月份数据集恢复为未处理；M 月按现有规则解归档（删除归档快照、结果恢复待确认、数据集恢复未处理）。
- 审计 evidence 记录：目标月、后续月份、被删结果 id 与状态、每条被删调整（主体、大类、分类、币种、调整值、原因、录入时间、程序版本）、各表删除条数、预期总变更数。
- 门禁：目标月归档不一致、有活动任务、目标月有导入中批次，仍禁止。后续月份的归档一致性不作为门禁（这些结果会被删除）。
- 成功后提示：请从 M+1 月起按顺序重新运行并归档。

### 3.2 解归档后再调整（D5）

- 每个结果有调整周期，首次计算为 0，每次解归档加 1；已有调整全部属于周期 0。
- 同一结果行同一币种，每个周期只能调整一次；不同周期的调整全部累加生效。
- 调整的金额、原因校验与 sequence、result_revision 规则不变。
- 导出中同一位置多条调整各占一行，Excel 血缘名不变。

### 3.3 预览失效与导入门禁（D3、D4）

- 写任务：导入、计算、初始化期初、修改结果、确认归档、解归档（含级联）、删除。只有这些任务结束才推进任务计数。
- 选文件预检、导出数据、导出结果表、导出审计、导出待确认表结束后，已打开的预览仍有效。
- 解归档预览与锁内复核的“导入中批次”只查目标月。

### 3.4 通道明细预检补录（D7–D10）

- 范围：已识别为 VCC 通道明细的 Sheet 中，渠道订单号有效、账单日期属于本次导入账期，且仅因可改字段为空或不合规而被判为格式异常的行。渠道订单号为空、账单日期不符等其他异常不列入，仍按现状过滤。
- 需要的币种与金额字段按现行规则：CITI 用交易币种、交易金额；其他通道 billdate 晚于账期月末用清算币种、清算金额，否则用结算币种、实际到账金额；改了通道名称或 billdate 后随之切换。
- 校验沿用导入规则：金额最多 2 位小数、15 位有效数字；币种为九币种标准大写，CNH 归一为 CNY；借贷方向取导入可识别的值；billdate 为有效日期。
- 用户可只改部分行；未修改或仍不合规的行按现状过滤。
- 导入时按修改后的整行值映射与计算内容哈希；同一文件同样修改重导为幂等跳过，不改重导仍被过滤，改法不同为幂等冲突。
- 导入时核对文件原值与预检一致，不一致则整次导入以“导入计划已失效”拒绝。
- 修改记录逐字段保存，删除原表数据时保留。
- 导出：校验原表导出、待确认表从存档原件重建行时套用修改记录，显示修改后的值；导入记录【导出明细】增加分类“人工补录”，说明为“原值 X → 新值 Y”。
- 状态框与导入记录显示人工补录行数。

## 4. 非目标

- 写保护比对范围（D1）。
- 不同月份导入与解归档并行（B88）、VCC 拆独立数据库与表瘦身（B85）、只读 worker 复用（B86）、旧写路径清理（B87）。
- 其他原表类型的补录。

## 5. 验收

- 金额、币种、幂等、计算结果、行序与导出内容在 A 部分前后一致（现有单测与集成脚本全部通过，合成数据前后对比一致）。
- 3.1–3.4 规则各有单测；级联解归档、通道补录各有集成链路。
- 对账专项审查（`reconciliation-blindspot-pass`）完成，资金红线发现经人工复核。
- `npm run release-check` 通过；Windows 真实数据回归登记 B84。
