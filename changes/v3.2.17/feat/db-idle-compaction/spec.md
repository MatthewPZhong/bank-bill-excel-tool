# Spec — v3.2.17 空闲时自动整理主库

> status: in-progress
> created: 2026-11-11
> 目标版本：v3.2.17（暂定）
> 适用分支：`feat/db-idle-compaction`
> 分支创建基线：`v3.2.16` 正式标签 → `8e027cb8`
> 依据：2026-11-10 VCC 财务OP校验“存储数据过大”排查与用户决策（backlog B82）；关联分支 `feat/vcc-financial-op-speed-unarchive`（导入不再撑大主库）

## 1. 背景

主库 `tool-data.sqlite` 未开启自动回收（`auto_vacuum=0`），删除或中转写入后留下的空闲页不会还给磁盘；v3.0.5 的一次性整理只在升级首启执行一次，v3.1.11 移除了 VCC【优化存储】入口。用户决定由软件在空闲时自动整理。

## 2. 已确认决策

| 编号 | 决策 | 来源 |
| --- | --- | --- |
| D1 | 空闲时自动整理主库；不在启动时运行（保持 v3.1.10“不在普通启动时偷偷压缩”的约定） | 用户，2026-11-10 |
| D2 | 用户一有操作（鼠标、键盘等）立即中止，数据库保持整理前状态，下次空闲再试 | 用户，2026-11-10（选项说明） |
| D3 | 整理期间新任务被拒绝并提示 | 用户，2026-11-10（选项说明） |

## 3. 规则

- 触发（每 2 分钟的空闲检查中判断，全部满足才执行）：用户 ≥ 30 分钟无操作；业务操作登记表无进行中的任务、收单 worker 不忙；可回收空间 ≥ max(1 GiB, 库大小 20%)；剩余磁盘 ≥ 库大小 × 2（无法判断时不整理）；距上次成功整理 ≥ 24 小时。
- 执行：持有业务过渡租约（新任务提示“正在整理存储空间，已自动停止整理，请再试一次。”）、暂停存档中心后台维护，在独立子进程中 `VACUUM` 并截断 WAL，完成后 `quick_check`。
- 中止：用户活动或退出应用时立即结束子进程，释放租约并恢复存档维护；退出流程等整理收尾后继续。
- 记录：活动日志 `database-maintenance` 记录整理前后大小、释放空间、耗时、失败原因；磁盘不足的跳过每 24 小时最多记一次。完成时间写入 `app_settings.db_idle_compaction_last_success_at`。

## 4. 非目标

- 侧库（`run-data/`）与 Pending 等其他数据库。
- 改为 `auto_vacuum=INCREMENTAL`。
- 界面入口或进度显示。

## 5. 验收

- 单测覆盖评估阈值、各跳过条件、成功路径（释放空间、记录时间、恢复存档维护、释放租约）、中止路径（数据与整理前一致、`quick_check` 通过）、退出等待、登记表提示文案。
- 真实环境：Windows 打包版大库上空闲整理与“一动鼠标即中止”（随 VCC B86 一并回归）。
