## 1. 背景

用户需求（2026-11-11）：

> 用户需要深色模式下的页面太黑了，所以需要新增深色模式的深浅度调节。外观设置页面开始时间的日期选定框下侧新增“深浅度调节”，文本“深浅度调节”右侧新增按钮【调节】，点击后打开一个主页面的页面，页面正下侧存在可以左右拖动的调节条，调节条最右侧存在【保存】按钮。

## 2. 代码现状（基线 v3.2.16）

| 位置 | 当前行为 |

| `src/styles-dark-mode.css` | `:root[data-theme="dark"]` 定义唯一一套深色变量（底色 `#111419`）；其他样式表没有 `data-theme` 选择器，组件只消费变量 |

| `src/renderer.js` | 深色且无自定义背景图时主背景写死 `#111419` |

## 3. 已确认决策（用户，2026-11-11）

| 编号 | 决策 |
| --- | --- |
| D1 | 调节页的“主页面”是真实主界面：暂时隐藏设置弹窗，露出当前模块主界面并以深色实时预览；预览期间主界面不可操作 |

## 4. 功能规则

### 4.1 入口

- 外观设置中「开始时间」时间框下方新增一行：文本「深浅度调节」，右侧按钮【调节】。外观设置未加载完成时随其他字段禁用。
- 深色未启用或当前处于浅色时段时【调节】仍可用：预览临时以深色显示，退出后恢复当时的有效主题。

### 4.2 调节页

- 页面正下方居中一条浮动调节条，从左到右：【取消】、「深」、可左右拖动的调节条、「浅」、当前数值、【保存】。
- 深浅度为 0–100 的整数。0 是 v3.2.16 及以前的深色（默认值，老用户升级后不变），越往右越浅，100 最浅。
- 拖动时整个主界面实时变化；保存前不写库，也不影响其他窗口状态。
- 【保存】：写入成功后关闭调节页、回到外观设置，新深浅度立即生效（当前处于深色时）；失败在调节条上方提示原因，保留调节页和拖动值，可重试或取消。保存进行中不能取消或关闭设置。
- 【取消】/ Esc：不保存，恢复原深浅度和原有效主题，回到外观设置。

### 4.3 生效范围

- 深浅度只作用于深色主题：底色、面板、输入框、分割线、表格悬停、标签、状态提示底色等表面颜色随之提亮；次要文字（说明、占位、禁用）同步提亮以保持可读。正文文字、主色和状态文字颜色不变。
- 浅色主题、定时开关与起止时间、自定义背景图片均不受影响。
- 启动和定时切换到深色时直接使用已保存深浅度，首屏不先闪现默认深色。

### 4.4 持久化

- 独立保存在主库 `app_settings.dark_mode_lightness`，不改动 `dark_mode_schedule` 的结构与校验；缺失或损坏读回 0，无迁移。
- 只接受 0–100 的整数，其他值拒绝且不改变已保存值和当前主题。

## 5. 验收

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| AC1 | 打开外观设置 | 开始时间下方显示「深浅度调节」与【调节】 |
| AC2 | 点击【调节】 | 设置弹窗隐藏，显示深色主界面与底部调节条，数值为已保存深浅度 |
| AC3 | 拖动调节条 | 主界面颜色实时变化，数值同步 |
| AC4 | 【保存】成功 | 回到外观设置；重启应用后深浅度保持 |
| AC5 | 【保存】失败 | 调节页保留并提示原因；已保存值与主题不变 |
| AC6 | 【取消】或 Esc | 回到外观设置，颜色恢复原深浅度；浅色时段恢复浅色 |
| AC7 | 未调节过的用户 | 深色外观与 v3.2.16 完全一致 |
| AC8 | 最浅档 | 正文、次要文字、主色在底色和面板上仍满足可读对比度 |
| AC9 | 浅色主题 | 不受深浅度影响 |

## 6. 非目标

- 不提供浅色主题的深浅调节，不新增多套主题。
- 不改变定时深色模式的判断规则、默认值与自动保存行为。
