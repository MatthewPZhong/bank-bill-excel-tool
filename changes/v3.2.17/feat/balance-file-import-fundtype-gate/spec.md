## 1. 背景

| 需求 | 现状 | 问题 |
| --- | --- | --- |
| 网银账单补录余额 | 首次导入时，主进程遇到第一个缺种子的账号就提示补录；补完一个整体重算，再提示下一个 | 多个账号只能逐个手输 |
| 资金对账「从银行对账单的信息里提取调拨订单对账ID」 | 自带写死场景，R2 阶段按 12 个 `包含 xFT`（OR）条件，从 CustomerRef / Extra Information / Payment Detail 提取 `[A-Z]FT\d{12}` 写入 ReconciliationId | 非调拨行的备注里出现 FT 号也会被写入调拨订单对账ID |

## 3. 功能规则

### 3.1 导入余额文件（D1、D2）

- **入口**：只出现在普通「补录上一账单日余额」弹窗（缺种子）。断档补录、「核对上一账单日余额」（已有种子但对不上）、余额不一致与人工补录替换确认都不出现。
- **待补录账号**：当前补录提示所在分组里，首个账单日之前没有任何种子的全部账号（银行账号 + 币种），顺序与逐个提示的顺序一致（先账号、后币种）。已有种子但对不上的账号不在内。按文件名映射时只覆盖当前分组（与「第 N 个账号，共 M 个」同口径），下一分组弹出补录时可再导入一次。
- **文件**：xlsx / xls / csv，读第一个工作表；前 10 行内需有一行同时包含四个列名（trim 后精确匹配），否则提示「余额文件缺少列：…」。
- **解析**：银行账号去首尾空格；银行账号单元格是数字时，只有显示文本与原值完全一致、且不超过 15 位整数才采用——达到 16 位（Excel 只保留 15 位有效数字，已被截断）、带小数、或数字格式改变了显示（如 `000000` 把 123 显示为 000123）的行按无效跳过，不参与匹配；币种不区分大小写；账单日期按现有日期解析口径（`2026-09-30`、`2026/09/30`、`20260930` 等），Excel 序列号形式的日期（数字单元格，或去掉时间后缀后的 `44835` 这类纯数字文本，范围与现有解析口径一致；6 位、8 位日历写法除外）按工作簿的日期系统（1900 / 1904）换算，CSV 没有日期系统、或读不出时这类日期按无效跳过；期末余额允许千分位，`0` 有效。账号为空、日期或金额无效的行跳过并在确认视图写明跳过行数。
- **匹配**：每个待补录账号取 银行账号、币种相同且 `账单日期 < 当前账单日期` 的行，取日期最新的一天：
  - 该日只有一个余额（按分去重）→ 来自文件，预填日期与余额；
  - 该日有多个不同余额 → 需手工录入，原因「文件中 {日期} 有多个不同余额」；
  - 没有早于当前账单日期的行 → 需手工录入，原因「文件中没有该账号早于 {当前账单日期} 的余额」；
  - 文件中没有该账号 → 需手工录入，原因「文件中没有该账号」。
  - 账号被 Excel 存成数字而丢了前导 0 等情况只会落到手工录入，不会错配。
- **确认视图**：标题「余额确认」；摘要「已从 {文件名} 提取 X 个账号的余额，Y 个需手工录入」（有跳过行时补充）；提示「余额按人工补录的原值保存（不含余额附加值）」。表格列：银行账号、币种、当前账单日期、上一账单日日期、上一账单日余额、来源（来自文件 / 需手工录入 + 原因）。需手工录入的行高亮；所有行的日期与余额都可修改。
- **【确认】**：
  - 先校验：每行日期与余额必填，日期早于当前账单日期；不通过的行标红并提示，不提交。余额数值合法性仍由主进程按现有补录规则判定。
  - 再逐个账号沿用现有补录保存：主进程每次只接受当前提示的账号，写入「人工录入」种子并重算，返回下一个提示；下一个仍是本弹窗分组（输出名称相同）、确认清单内、尚未保存成功的普通缺种子账号就继续，否则停下交给原有流程（断档确认、余额不一致、人工补录替换、清单外或下一分组的账号、校验失败、覆盖确认、报错或完成）。
  - 保存期间显示「正在保存第 i / N 个账号的余额…」，弹窗不能关闭、按钮不可点。
  - 中途出错后可再点【确认】：从最近一次主进程提示接着保存；已保存成功的行标为「已保存」并只读，不再提交。
- **账号核对**：所有补录请求（手工【完成】与确认后的连续保存）都带上界面所示的银行账号、币种与输出名称；与主进程当前待补录提示不一致时拒绝（`BALANCE_SEED_ACCOUNT_CHANGED`），不写种子，并带回当前提示，弹窗按当前账号重新打开、不带入原账号的草稿。
- **【返回】**：回到手工补录视图，手工输入的草稿保留；导入结果不写入任何种子。若已有账号保存成功（主进程提示已前进），按当前提示重建补录弹窗，不回到旧账号的表单。
- **留痕**：导入时活动日志记文件名、模板、待补录 / 从文件提取 / 需手工录入账号数与跳过行数；每个账号的种子写入沿用现有「补录上一账单日余额成功」日志。

### 3.2 提取调拨订单对账ID 限定 FundType（D3、D4）

- 自带写死场景「从银行对账单的信息里提取调拨订单对账ID」先判断前置条件，再走原有 12 个条件与提取规则：
  - `Channel` 去首尾空格后等于 `DBS` → 不受限（与 R3.5 渠道门控同口径，区分大小写）；
  - 否则 `FundType` 去首尾空格后恰好等于 `FundTransfer-in` 或 `FundTransfer-out`（区分大小写，与 R5 调拨回填同口径）才继续；`InternelFundTransfer-*`、`FundTransfer-in&FX`、`Fundtransfer-out&FX`、空值等都不算。
- 不满足前置条件的行：本场景不命中、不写 ReconciliationId、不锁定，后续 R2 场景仍可处理（first-match-wins 不变）；行数守恒不变。
- 用户自建的「提取对账ID」场景不受影响；场景配置（数据库）不变，不加迁移。
- 已知影响（用户已确认）：非 DBS 渠道里 FundType 不是调拨类型、但备注带 FT 号的行，不再由本场景获得对账ID，R4 资金性质校验等按对账ID的后续匹配也不会再命中这些行。

## 4. 非目标

- 批量一次写入多个账号的种子（仍逐个账号沿用现有写入与重算；见 backlog）。
- 解析银行原始余额报表、按模板映射识别余额文件。
- 扣回余额附加值、按「生成的种子」口径记录导入余额。
- 在 UI 展示或编辑自带写死场景的条件。

## 5. 验收标准

- 两个账号缺种子，余额文件含其中一个账号多日余额（含当前账单日及之后的行）：确认视图该账号预填早于当前账单日期的最近一天余额，另一个标为需手工录入并写明原因；补全后确认，两个账号依次写入人工种子，余额账单生成，期末余额以导入值为起点推导。
- 文件缺列：提示缺哪些列，弹窗停在手工补录视图。
- 确认视图返回：回到手工补录视图，草稿保留，未写入任何种子。
- 必填或日期不早于当前账单日期：行标红，不提交。
- 确认后中途出现断档、余额不一致、清单外账号或校验失败：停在对应的原有弹窗；已保存的账号种子保留。
- 断档补录、核对上一账单日余额、确认类弹窗不出现导入按钮；无待补录清单的旧提示不出现导入按钮。
- 部分账号保存成功后出错：【返回】显示当前待补录账号；再点【确认】不重提已保存账号；下一分组的同号账号不自动保存。
- 余额文件里零填充显示的数字账号（如显示 000123、原值 123）不匹配任何账号；小额余额（如 0.0000001）预填为普通小数且能保存。
- 非 DBS 渠道：FundType=FundTransfer-in / -out（含首尾空格）的行提取对账ID；Inbound、空值、InternelFundTransfer-in、FundTransfer-in&FX 等行不提取、不覆盖原对账ID，且仍可被后续场景命中。
- DBS 渠道：FundType=outbound / Charge 的行照常提取；R3.5 照常把同一调拨的手续费行归为 Charge。
- 用户自建「提取对账ID」场景结果不变。
