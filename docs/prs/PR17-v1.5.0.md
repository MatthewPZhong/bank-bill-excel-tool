# PR #17 — 映射字段列位置固定（消除选值后列平移）

## 改动文件

- `src/styles.css`（+21 行）
- `src/renderer-dialogs.js`（+14 / -16 行）

## 改动内容

### 问题

映射关系管理对话框中，映射字段列的位置会随下拉值变化发生平移：
- 选"需要拼接字段"时，`.concat-field-picker` 从 `hidden`（`display: none`）变为可见，列宽突增
- "是否拆分/合并明细账单"选"是"、"复用模块字段的映射关系"选"否"时，右侧按钮从隐藏变为可见，同样导致列平移

### 修法

1. **CSS 层**（`styles.css`）：对 `.concat-field-picker[hidden]`、`.mapping-field-editor > button[hidden]`、`.bill-split-group-btn[hidden]` 统一覆盖全局 `[hidden] { display: none }` 规则，改为 `visibility: hidden + pointer-events: none`，隐藏时仍保持占位空间。

2. **JS 层**（`renderer-dialogs.js`）：账单拆分组行的按钮文本始终填充（"拆分/合并账单映射关系管理" / "拆分/合并账单映射关系设置"），不再在隐藏时清空 `textContent`。确保 `visibility: hidden` 状态下按钮有正确宽度可占位。

### 覆盖范围

| 模块 | 元素 | 修复 |
|---|---|---|
| 映射关系管理主表格 | `.concat-field-picker` | CSS 占位 |
| 映射关系管理主表格 | 维护大账号 / 发生额管理等按钮 | CSS 占位 |
| 账单拆分组行 | "拆分/合并账单映射关系管理" 按钮 | CSS 占位 + JS 保留文本 |
| 账单拆分组行 | "拆分/合并账单映射关系设置" 按钮 | CSS 占位 + JS 保留文本 |
| 弹框 1（拆分/合并账单映射关系设置） | `.concat-field-picker` | CSS 占位（同规则） |

弹框 2（六列表格）无此问题，不涉及。

### 追加：按正负号拆分的发生额互斥补全

#### 问题

映射关系管理的发生额互斥只实现了单向：`按字段区分发生额 = 是` → 禁用 Credit/Debit/按正负号。但反方向缺失：`按正负号拆分的发生额` 有值时，Credit/Debit/按字段区分发生额 没有被禁用。

#### 修法

重写 `applyAmountSplitMutualExclusion` 为完整的 3 选 1 互斥：

| 激活模式 | 禁用 |
|---|---|
| 按字段区分发生额 = 是 | Credit / Debit / 按正负号 |
| 按正负号有值 | Credit / Debit / 按字段区分 |
| 无 | 全部启用 |

Credit/Debit 直接映射是默认状态，不算独立模式，不触发互斥锁。

#### Bug fix

原实现用 `getSelectValues(select)[0] !== ''` 判断按正负号是否有值。`getSelectValues` 在 select 为空时返回 `[]`，`[][0]` 是 `undefined`，`undefined !== ''` 为 `true`——导致空值时也被误判为已激活。改为 `signedAmountSelect.value !== ''` 直接取值。

### 追加：映射字段下拉框宽度固定

#### 问题

映射字段下拉框选中值文本过长时（例如源文件 header 名很长），`<select>` 元素被撑宽，导致映射字段列宽度增长、布局偏移。

#### 修法

`styles.css` 的 `.mapping-select` 新增 `max-width: 260px`（与 `min-width: 260px` 一致），宽度完全固定。长文本在下拉框内截断显示，展开下拉面板时可看到完整文本（浏览器原生行为）。

---

### 追加：拼接字段预览文本截断过早

#### 问题

映射字段选"需要拼接字段"后，"当前拼接顺序"下方的预览文本被过早截断——明明右侧有大量空间，文本却显示为省略号。

两层截断叠加导致：
1. **CSS**：`.concat-preview { max-width: 200px }` 硬限 200px
2. **JS**：`previewText.length > 40` 超 40 字符就截断加 `......`

#### 修法

1. CSS：移除 `.concat-preview` 的 `max-width: 200px`，让预览文本自然占满可用空间（`overflow: hidden; text-overflow: ellipsis` 仍保留作为最终兜底）
2. JS：截断阈值从 40 → 120 字符（`renderer-dialogs.js` 两处，主表格 + 弹框 1 各一处）

### 追加：弹框 2 六列表格 UI 优化 4 项

#### 1. 账单序号表头不换行

`styles.css` 的 `.bill-split-rows-table th, td` 加 `white-space: nowrap`，"账单序号"不再折成两行。

#### 2. 完成后行数据文本化

点击行级「完成」后，该行的 4 个 select 隐藏，改为显示纯文本 `<span class="bill-split-row-view-text">`（与维护大账号的完成/编辑交互形式一致）。点「编辑」后恢复 select。配套 CSS：
- `.bill-split-row-view-text`：`min-height: 44px; line-height: 44px; font-size: 14px`（匹配 select 高度，字体比抬头字段稍小）
- `.bill-split-rows-table`：`table-layout: fixed`（列宽固定，切换完成/编辑时表格不抖动）

#### 3. 账单序号列排版

- `th:first-child`：`padding-left: 1em`（"账单序号"标题右移一个字宽）
- `td:first-child`：`padding-left: 2em`（数字再右移一个字宽，左对齐到标题文本左侧偏右）
- `td:first-child`：`font-size: 14px; min-height: 44px; line-height: 44px`（垂直居中）

#### 4. 维护大账号币种校验改为弹框提醒

原来币种校验失败只在底部状态栏显示错误文本（`setStatus`），用户容易忽略。改为 `openModal(createAlertDialog(...))` 弹出提醒框，用户点确认后回到编辑状态。
