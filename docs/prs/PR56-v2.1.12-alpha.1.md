## 改动主线

### 需求1 第 6 模块「VCC业务OP计算」（新功能 · 🔴资金红线 · `module.id=vcc-op-calc`）
- **业务**：仅导入流水对账单（28 列，复用第 5 模块 `FLOW_COLUMN_DEFS`）→ 按「出入方向」对「对账金额」求和 → `期末OP = 期初OP(用户手填上月OP) + 发生额(入−出)`；月份取「账单日期」。UI 复用第 4 模块面板，「导出差异」→「显示余额」。
- **持久化**：2 张新表 + FK（`vcc_op_calc_runs` 按月汇总 + `vcc_op_calc_run_files` 逐文件明细，金额列 TEXT，**不落流水原始行**，同月多 run 取最新）+ 2 索引；幂等 migration 不动现有表。
- **JSZip 流式 reader（弃 SheetJS/exceljs）**：实测 78.7 万行 / 811MB worksheet——SheetJS 超 V8 单字符串 512MB 上限静默返回空、exceljs 因 zip data descriptor 报 `invalid signature`；改 JSZip 走 central directory + SAX 扫 `<row>` + 多 sheet 定位 + 损坏提示 + 进度回调（7.8s/778MB 优于 exceljs 16.9s/2GB）。
- **session 流式聚合**：合并 scan+compute 一次读、内存恒定；6 IPC（资金类 `trackedIpcHandle`）+ 进度事件（每 5 万行）。
- 🔴 护栏：整数分精度（乘 100 求和除回）+ 混币种全量合并求和（跨币种合计、非货币余额，已确认口径）+ 整批拒绝（方向非法 / 多月份混杂 / 非数字行）。

### 需求5 C3「提取ReconId-From 网关」extra fee 额外费用匹配（🔴资金红线）
- 弹窗加勾选框「网关对账单金额与银行对账单不一致」→「网关金额 + [fee] = 银行金额」；config 新增 `extraFee:{enabled,amount}`。
- 🔴 方案 A1：fee **仅作用于「银行侧=发生额绝对值」(`BANK_STATEMENT_VIRTUAL_AMOUNT_ABS`) 字段对**（零歧义、避免多金额对错配）；`gw+fee` 后比 bank，其余 reconField 不变。
- 🔴 允许正负小数 + `Math.round((gw+fee)*100)/100` 归一到分；undefined→null 双防御（防旧调用 `gwNum+undefined=NaN` 大面积回归）；旧场景惰性兜底无 migration。
- 🔴 绝对不变量：fee 未勾 / =0 时与 v2.1.11 **byte-for-byte 一致**，1v1 严格消费红线（`usedGwRowIdx`）不动。

### 需求6 资金对账不平跳过提示数据侧候选行预检
- 两处 C3 提示弹窗（`maybePromptGatewayReconImport` / `shouldPromptGatewayReconAtRun`）现状只判"启用 C3 场景"（场景维度），启用但本次数据无命中行时仍弹「将跳过」；修复 = 追加"数据侧候选行存在性"判断（启用 C3 **AND** ≥1 命中 `gateway-recon-join` conditions 的行才弹）。
- 新增只读 helper `countC3BankCandidates`（与 C3 引擎 conditions 语义一致）+ 1 IPC（main 查 session C3 候选行数）+ renderer 双 gate；不碰资金红线、不改 C3 匹配结果。
