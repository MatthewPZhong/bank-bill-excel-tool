## 关键技术决策

1. **Reader 选型（v0.5 fix2 修订）**：v0.3 尝试 SheetJS dense（单文件全 load 100w 行 1-1.5GB）；用户实测真实清结算导出 = **POI 流式写 ZIP（data descriptor 模式）+ inlineStr cell + 单文件 30w 行 / 832MB 解压**，SheetJS fflate 严格校验 `local file header.uncompressedSize` 拒解（`Bad uncompressed size: N != 0`），ExcelJS streaming（unzipper）同样拒解（`invalid signature 0x41d`）。**v0.5 fix2 改 yauzl + sax 流式**：yauzl 纯 JS ZIP 流式支持 data descriptor + ZIP64；sax 纯 JS SAX 流式 XML；单文件 RAM < 50MB；peek 早退出 O(1) < 100ms；跨平台无 native 编译。**实测 30w 行 / 832MB / 48 列 inlineStr xlsx：peek 8ms / 完整导入 55.4s / 内存峰值 210MB**
2. **大事务包多 xlsx**：用户多选 N 个 xlsx 视为 1 次导入，任一文件失败 → 整批 ROLLBACK（spec §3.3 "整批拒绝"）
3. **diff 表仅含差异行**：原 v0.1 设计是 28 列全表（含一致行高亮差异），用户反馈"500w 全表文件巨大"→ v0.2 改 30 列仅差异行 + 4 列对比区 → v0.3 去掉单据_对账金额 copy → 末尾 3 列（29 列）
4. **币种归一**：入库时 `currency_norm = LOWER + TRIM`，SQL JOIN 直接比较 currency_norm（避免每行算函数）
5. **金额 ABS**：入库时 `recon_amount_abs = ABS(parseFloat(对账金额))`，writer 直接读列，不二次 ABS
