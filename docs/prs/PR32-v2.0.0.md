## 关键决策

- **D1 exceljs vs SheetJS 共存**：exceljs 仅用于本模块写出（标黄 + error-report），读入仍用 SheetJS（复用现有 readers.js 解析能力）；其他 3 模块（statementGenerator / newAccountGenerator / pendingReconciliation）不变
- **D2 dispatcher 数据结构**：`lockedRowIds` 来自算法层不改语义；C2 双锁 PR #31 已保证；modifications 在 dispatcher 层补 scenarioId/scenarioName
- **D3 文件路径独立目录**：`~/Documents/网银账单生成小助手/bank-statement-process/{date}/`，与现有 `exports/` / `error-reports/` 解耦
- **D4 _rowId 生成时机**：import 阶段（readBankStatement）就给每行加 `row_${index}`；算法层 ensureRowId 作为 fallback
- **D5 IPC 命名规范**：沿用 `xxx-yyy:zzz` 格式（与现有 templates / scenarios 一致）
- **Q-A1 C3 启用 + 未导入 gwRows**：dispatcher 直接按 gwRows=null 跳过 C3 类，IPC 返回 `stats.skippedC3Count` 让 renderer 提示（避免后端塞 dialog 逻辑）
- **Q-A2 modifiedRows 写出**：剥离内部字段（_rowId / _modifiedColumns / _hitScenarioName），仅写 originalHeaders 44 列；_modifiedColumns 转换为 cell.fill 信息
