## 概述

v2.1.11-beta.1，3 个用户需求 + self-review / SR-FIX 质量收尾。基于 main(2.1.10) 新建 `v2.1.11` 分支。

## 改动主线

### T1 单元测试运行日志
- `npm run test:unit`（`scripts/run-unit-tests.js`）从"仅透传退出码"增强为：终端输出 `==== N/N PASS ====` + 每文件用例数/耗时汇总（仿 integration-runner），并落盘带时间戳日志 `logs/unit-tests/unit-*.log`（元信息 + 原始输出 + 汇总）；**退出码透传不变**（release-check 真理来源）；三平台兼容（无 shell）。
- `parseTapSummary` 抽为可测纯函数（兼容 spec/TAP 双 reporter）。
- 顺带更正 `CLAUDE.md` 过时表述「No unit test framework」→ 三层测试描述。

### T2 pending 月度移除核对（新功能 · 🔴 资金/对账红线）
- **流程**：导入某月 pending 数据后弹「是否核对移除pending数据」→ 选是导入「移除归档Pending账单」文件入库（关联该月）→ 跑对账后**自动**用对账规则把移除数据与 `missing`（消失）行匹配。
- **共用对账规则**：matchFields 配对（多轮 fallback，复用 engine 语义）+ **compareFields 内容核对**（与 pending 对账 changed 同源）。
- **导出**（仅单 run）：新增 sheet「missing核对移除」末列「移除核对状态」**三态** —— `核对无误` / `核对有差异：字段(missing值≠移除值)` / `missing有_移除无`；条件 sheet「移除有_missing无」。
- **新表**：`removed_pending_rows`（raw_json + 索引列）+ `pending_removal_matches`（幂等 migration，不动现有表）。
- 🔴 数值红线：金额等数值字段比对复用数值归一化（`"100"` vs `"100.00"`、`"1,234.50"` vs `"1234.5"` 判一致，不误报；差异文字展示原始值）。

### T3 C2「银行对账单字段赋值」增强（业务规则 · 🔴 赋值引擎红线）
- 账单类型支持**多筛选条件（AND 全满足）**，每条件行可「新增」插空白条件行（子序号 `#1.1/#1.2`）；删除/分组渲染配套。
- 筛选字段 = `FundType` 时值改**严格单选下拉**（枚举运行时读 `assets/FundType枚举值.xlsx`，经 `scenarios:fund-type-enum` IPC），赋值行同；文件缺失降级文本输入。
- 对账字段**可留空 / 删到 0 行**（引擎走无条件赋值）。
- 旧版单条件场景打开时**自动惰性迁移**为多条件 `conditions` 结构（repository 读取 + 引擎入口 + dialog 三处归一化对齐，向后兼容、配置不丢）。
