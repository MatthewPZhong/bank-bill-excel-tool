## 三、对抗式矩阵验证（资金红线）🔴

实现后用多 agent 矩阵工作流**真跑引擎逐格对比 PRD §5.2**，发现引擎初版「逐 bank 行顺序消费」收敛模型与决策矩阵 3 处不等价（会把该人工介入的行静默标成提示 / 错回填）：

| Bug | 现象 | 修复（用户拍板 Q13/Q14/Q15）|
|---|---|---|
| 反向多笔 | N 银行行命中同 1 refund → 回填最早一条+提示其余 | Q14：涉事银行行全部报错-人工介入、不回填、refund 锁定 |
| S4 顺序依赖 | 超 10 天的行排在被消费后静默降级成提示 | Q13：按冻结候选集 + minDayDiff 判，去顺序依赖；每条超容差各一行报错 |
| 报错后复用 | S1~S3 多笔报错卷入的 refund 被其他行经 S4 吃掉 | Q15：报错链路 refund 锁定退出 S4 |

引擎重构为「按策略批量解析双向冲突」（仅严格 1↔1 互配才回填），补 10 针对性单测，三组复现输入实跑全部修复。PRD §九 bis 已回写 Q13/Q14/Q15。

> 验证副产物：推翻一份子报告对 `resolveHits` 正向分支的误判，避免改坏正确代码。

## 四、⚠️ 关联功能 review（/check-vars）

本次触及 `rules/important-variables.md`：

**Critical**
- `_rowId`（全局唯一不变量）：引擎用 `bank._rowId` 做 1v1 消费 + 反向聚合；依赖上游全局唯一重编号（`main.js:11204`）。只读不注入，独立池不串 dispatcher rowLockSet。
- `runReconciliation` / `unmatchedRows` 行数守恒契约：场景4 **只读 bankRows、不进 modColsByRowId、不 mergeMods**，`refundBackfillRows`/`refundUnmatchedRows` 是独立产物、不参与 `modifiedRows+unmatchedRows=bankRows` 守恒。现有 orchestrator 单测 + 集成全过。

**Runtime-state**
- `processingResult`：新增 `refundBackfillRows`/`refundUnmatchedRows`，独立于现有字段、本轮恒 []、export 前有 Array.isArray 守卫；清空路径未改。新增模块级 `refundOrderSession=null`（Layer2 占位，不改 `bankStatementSession`）。

**Risk-sensitive**
- `FundType`：引擎按 `Ach Return` + `isFundTypeChanged`（读 R4 改写痕迹 modColsByRowId）筛选；只读。
- scenarios seed：refund 场景默认 **enabled=0**（休眠），既有 7 条仍 enabled=1（单测断言）；INSERT enabled 参数化、独立 marker。

**必跑**：`npm run release-check` 全绿（含 smoke）✅
