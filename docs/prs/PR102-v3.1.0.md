# [v3.1.0] 平盘资金性质校验

PR：https://github.com/MatthewPZhong/bank-bill-excel-tool/pull/102 ｜ 分支 `codex/v3.1.0-position-reconciliation` → `main`。

## 一、交付内容

1. 将「平盘对账数据处理」从占位模块升级为第一期可用的「平盘资金性质校验」。
2. 增加平盘银行对账单、五类链接原始表/对账表、独立账户映射、数据管理和差异管理。
3. 十组 FundType 使用可审计规则判断，订单类执行单次及跨已确认运行的双向严格 1:1。
4. 增加固定 49 列结果、实际修改标黄、回导防篡改、最终确认和状态更新。
5. 批量明细只进入独立持久 side DB；输入使用不可变暂存副本，并接入存档中心。
6. 存档失败暂存副本可跨重启重试；跨批次共用源路径在最后一个未完成 artifact 解决前不会释放；业务成功返回前完成本次存档或形成正式失败批次/持久 outbox，银行及管理页恢复错误展示文件级明细。
7. 草稿绑定数据 revision 和规则版本，数据、映射或规则变化后禁止继续导出、回导或确认。
8. 首次启动由主库先保存 generation 0 bootstrap，再创建完全绑定的侧库；已有侧库但主库无绑定、仅旧 initialized marker、缺失、空库、旧库回滚、同代及更高代次分叉均阻断。
9. 平盘 IPC 全局互斥，待完成记录、checkpoint 同步和清理均校验 operation token 所有权；异常退出或同进程部分提交失败后，可从侧库推进、业务成功标记或已发布输出恢复持久存档意图。
10. 运行来源由原始行推导，消费冲突由逐行血缘重算；每条运行行保存完整性 hash，并核对结果、差异、消费、血缘和当前银行/链接引用；已确认血缘与持久消费表双向一致。
11. 静态模板与运行时 writer 复用标识符文本列判定，空表仍保留 ID、账号、卡号、ReconID、CustomerRef、客户编号、客户号、Account Reference、大额行号和 VA 格式。
12. 清结算银行账户表的 prepare 待确认阶段不建立空存档批次，确认 apply 后才提交侧库与输入存档。
13. 消费关系历史 owner 必须由已确认运行的完整行血缘证明；无关更早 owner、未来 owner 和额外关系均 fail closed。
14. 平盘 pending、存档和 checkpoint 状态机增加行为级 harness，覆盖正式批次、outbox、输出发布后状态失败及双失败。
15. outbox 仅在所有文件完成正式 artifact 登记后删除；附件元数据登记前失败继续保留任务与源文件。
16. 启动暂存清理纳入主库 pending 文件保护，停机超过 7 天也不会先删除恢复输入。

  - 49 列名称和顺序不变；新增列级文本格式只影响 Excel 单元格类型，零数据、正常数据、回导表头和 FundType 标黄均已回归。
