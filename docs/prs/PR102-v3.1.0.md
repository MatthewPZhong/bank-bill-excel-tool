# [v3.1.0] 平盘资金性质校验

PR：https://github.com/MatthewPZhong/bank-bill-excel-tool/pull/102 ｜ 分支 `codex/v3.1.0-position-reconciliation` → `main`。

## 一、交付内容

1. 将「平盘对账数据处理」从占位模块升级为第一期可用的「平盘资金性质校验」。
2. 增加平盘银行对账单、五类链接原始表/对账表、独立账户映射、数据管理和差异管理。
3. 十组 FundType 使用可审计规则判断，订单类执行单次及跨已确认运行的双向严格 1:1。
4. 增加固定 49 列结果、实际修改标黄、回导防篡改、最终确认和状态更新。
5. 批量明细只进入独立持久 side DB；输入使用不可变暂存副本，并以解析时 snapshot、size 和 SHA-256 绑定 token、pending、outbox 与正式存档。
6. 存档失败暂存副本可跨重启重试；跨批次共用源路径在最后一个未完成 artifact 解决前不会释放；业务成功返回前完成本次存档或形成正式失败批次/持久 outbox，银行及管理页恢复错误展示文件级明细。
7. 草稿绑定数据 revision 和规则版本，数据、映射或规则变化后禁止继续导出、回导或确认。
8. 首次启动由主库先保存 generation 0 bootstrap，再创建完全绑定的侧库；已有侧库但主库无绑定、仅旧 initialized marker、缺失、空库、旧库回滚、同代及更高代次分叉均阻断。
9. 平盘 IPC 全局互斥，待完成记录、checkpoint 同步和清理均校验 operation token 所有权；异常退出或同进程部分提交失败后，可从侧库推进、业务成功标记或已发布输出恢复持久存档意图。
10. 运行来源由原始行推导，消费冲突由逐行血缘重算；每条运行行保存完整性 hash，并核对结果、差异、消费、血缘和当前银行/链接引用；已确认血缘与持久消费表双向一致。
11. 静态模板与运行时 writer 复用标识符文本列判定，空表仍保留 ID、账号、卡号、ReconID、CustomerRef、客户编号、客户号、Account Reference、大额行号和 VA 格式。
12. 清结算银行账户表的 prepare 待确认阶段不建立空存档批次，确认 apply 后才提交侧库与输入存档。
13. 消费关系历史 owner 必须由已确认运行的完整行血缘证明；无关更早 owner、未来 owner 和额外关系均 fail closed。
14. 平盘 pending、存档和 checkpoint 状态机增加行为级 harness，覆盖正式批次、outbox、输出发布后状态失败及双失败。
15. 正式建批、追加和 outbox 重放共享 artifact 完整性门禁；附件元数据登记前失败会转入或保留同一 operation key 的 outbox，正式批次与 outbox 双失败时不推进 checkpoint。
16. 启动暂存清理纳入主库 pending 文件保护；pending 文件清单缺失/损坏、存档保护 provider 返回非数组或抛异常时均跳过清理。恢复登记和同进程 checkpoint 完成均在所有 archive 状态判断前复用同一校验；损坏清单不写错误 outbox、不清 pending，连续重启也不会删除真实恢复输入。
17. 恢复 input 不再重新抓取当前文件作为可信基准；暂存字节变化时保留 pending、阻断 checkpoint，并由正式存档再次校验预期 SHA-256。
18. 结果回导对 BillDate/ValueDate 区分纯日期和业务时间；纯日期接受等价 Excel 日期，包含时分秒时拒绝同日修改、跨日及非法值。
19. side DB 在银行、普通来源、账户确认和结果回导的业务事务内写入文件级提交凭证；多文件异常恢复只存档 pending 与已提交凭证的交集，未提交文件不会进入正式批次或 outbox。
20. 存档重试已有预期 SHA 时允许 inode/mtime/ctime 不同的同字节副本；当前读取前后 stat、大小与 SHA 仍必须全部通过，不同字节或读取中变化继续拒绝。
21. 存档中心区分原路径重试、选择原文件重试和必须重跑业务；替代文件摘要不暴露给页面，错误副本由后端 SHA 门禁拒绝。
22. 多文件恢复中未提交的 prepared 输入在 checkpoint 同步和 pending 清除后立即按全局保护集清理，不再等待过期回收。

## ⚠️ 关联功能 review

- **Important-skeleton**：`ipcRenderer`、`ArchiveCenterController / archiveCenter IPC`
  - 新增 `selectRetrySources` 后 controller、main handler、preload 和 renderer 已同步为 11 个方法；取消选择不调用重试，替代路径按 artifact ID 白名单传递。
  - renderer 不接收存档 Blob 路径、已登记源路径、预期 SHA 或预期大小；真实 ArchiveService 已验证错误副本拒绝、同字节副本成功。
- **Risk-sensitive**：`POSITION_BANK_HEADERS`
  - 49 列名称和顺序不变；新增列级文本格式只影响 Excel 单元格类型，零数据、正常数据、回导表头和 FundType 标黄均已回归。
  - position side DB 的来源/冲突/scope/snapshot/summary 与明细交叉校验、跨库 checkpoint+operation token、跨运行 1:1、原始值不变和确认事务已完成定向及 parity 检查。
- **Runtime-state**：`archiveOperationTracker`
  - 模块支持范围、批次归属和失败隔离不变；平盘业务现在等待本次存档处理，并区分“已持久登记重试”与“完全无法登记”。正式批次失败时的 outbox、启动重放、同进程部分提交恢复、部分失败源文件保护、退出等待和重复 operation key 均已测试。
- **Runtime-state**：`dialog`
  - 替代源选择使用统一目录记忆入口和单文件原生对话框；用户取消时返回 `cancelled`，不调用 ArchiveService、不修改 artifact。
- **Minor**：`getSetting`、`setSetting`
  - 沿用平盘侧库首次 bootstrap、checkpoint 和待完成 operation 设置键；每次操作前先登记、完成后同步并清理，侧库领先时还须逐代 operation token 一致才能追平，未改变通用 settings 语义。
