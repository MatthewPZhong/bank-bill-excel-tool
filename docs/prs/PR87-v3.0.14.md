# [v3.0.14] 前置资金对账与命中场景口径收紧

PR：https://github.com/MatthewPZhong/bank-bill-excel-tool/pull/87 ｜ 分支 `codex/v3.0.14-pre-fund-reconciliation` → `main`。

## 一、交付内容

1. 「命中场景」只认用户字段实际改值；异常说明只在实际改值行上检测和输出。锁定 no-op、同值赋值和 note-only 行进入未命中结果，命中+未命中行数守恒不变。
2. 新增「前置资金对账」，3.0.14 只交付「缺网关账单」：标准银行账单联合临时 MPT 和持久网关账单，按非空对账 ID、渠道、精确十进制金额、币种做临时来源优先的稳定 1:1 对账。
3. 支持 `MPT_INBOUND_GATEWAY` / `MPT_OUTBOUND_GATEWAY` txt/gz 流式解析、强校验和 side DB 落库；两个逻辑表库独立汇总和按 `sourceType` 删除，运行时共同参与候选池。
4. 完全重复仍只按 `reconciliationId + 10 字段指纹` 折叠；每组审计一个保留对象和全部被折叠对象，保存来源、位置、规范字段、姓名、卡号和原始 JSON。
5. 按渠道动态导出 5/6-sheet：无重复保持 5 个基线 sheet；有重复时末尾追加固定 22 列「重复网关账单」。渠道集合取银行渠道与重复渠道并集，重复专属渠道也生成隔离文件。
6. 原始 JSON 每片最多 30,000 个 UTF-16 code unit，不拆代理对；C4 兼容旧 4-sheet、当前 5-sheet 和新增 6-sheet，第 6 sheet 校验表头后不读取数据行。

## 二、关键保护

- 正式 Electron 应用持有单实例锁，防止两个实例同时回收同一结果 side DB。
- 保留对象原始 JSON 回读使用 SHA-256 身份校验；候选、审计、结果、汇总和成功状态在同一事务完成。
- 结果 JSON 损坏、快照缺失、Excel 单 sheet 超过 1,048,575 条数据行时显式失败。
- C4 先用 `sheetRows:1` 校验审计 sheet，再只读取业务 sheet，避免大审计页进入内存。
- 导出采用 no-clobber 发布：优先硬链接，不支持时降级 `COPYFILE_EXCL`；只回滚本次实际发布且身份未变化的文件，不覆盖或误删外部同名文件。
- 银行重导、临时来源变化、持久链接表 meta 变化、结果库丢失或损坏后，旧结果立即失效并禁止导出。
