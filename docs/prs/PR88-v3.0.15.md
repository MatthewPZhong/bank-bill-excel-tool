# [v3.0.15] 重复入金匹配

PR：https://github.com/MatthewPZhong/bank-bill-excel-tool/pull/88 ｜ 分支 `codex/v3.0.15-duplicate-inbound-match` → `main`。

## 一、交付内容

1. 新增独立「重复入金匹配」模块，一次原子导入标准 46 列银行对账单和标准 26 列单据对账单，提供导入、运行和另存为导出。
2. 银行 Reversal 使用 Debit Amount、Inbound 使用 Credit Amount，以精确十进制金额、双方姓名/卡号、Channel、Currency 七元组分组；仅严格 1 Reversal + 2 Inbound 进入自动匹配。
3. 每条银行 Inbound 按非空 `Channel + MerchantId + ReconciliationId` 精确查询全部保留月份的 `MPT_INBOUND_GATEWAY + Inbound-VA`；零/多候选、组内同记录、跨组复用或 `oppBu` 异常均整组转人工。
4. 两条非空 MPT `orderId` 必须分别唯一命中不同单据；单据用户编号、账户号、业务部门须非空一致，业务部门还须等于 MPT `oppBu`。
5. 邮件业务来源取 MPT `oppBu`，客户号/账户号取单据；导出固定为「邮件模板」「匹配不成功需人工判定」两个 sheet，Debit Amount 使用常规格式。
6. 银行、单据、结果和三方血缘仅保存在当前启动周期 side DB；主库只保存轻量运行镜像。新导入、新运行、INBOUND MPT 变化或重启后旧结果禁止导出。

## 二、Self-review 收紧

- 空 `ReconciliationId` 固定不进入候选池，避免空 ID 被误认为精确命中。
- 多候选保留精确总数，只物化稳定前 2 条审计样本；相同查询键共享有界结果，避免 N×K 内存放大。
- 导入前后校验文件 hash；镜像失效与 side DB 回收分别执行，任一失败均显式报错且不恢复旧结果。
- 成功 run 的邮件行、人工行、审计组和汇总计数必须守恒；缺行或损坏时标记 `invalid-side-db` 并禁止导出。
- Excel 临时文件通过 sheet、表头和行数回读后才能发布；覆盖失败恢复原目标，备份删除失败向用户显示警告。
- main IPC handler、进度发送、锁释放、detailLines 和 renderer 警告展示均补行为测试。
