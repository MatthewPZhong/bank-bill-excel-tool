# PR #22 — v1.5.3：模式下拉 + 月度余额导出 + 自有账号合并 + Courier New 表头 + 浮点精度 hotfix

## 背景

用户需要三件事 + 一个 hotfix：

1. **R1** 月末给财务交余额报告，操作从"制作网银账单→导入→生成"长链路降到"点两下"。
2. **R2** 自有账号 json 文件与大账号表分离，无法统一管理；需要合并到大账号表，同时保持"自有账户不参与制作网银账单流程"的业务语义。
3. **R3** 导出 xlsx 的表头（跟模板走的宋体/系统默认）不便于阅读数字，要求**表头行**改为 Courier New 等宽字体。
4. **R4**（发版前回归发现的 hotfix）账单拆分合并求和的浮点噪声（如 `2377.49 + 178.31 = 2555.7999999999997`）会泄露到导出 xlsx，需要在 1.5.3 窗口内顺手修。

## 需求详述

### R1 主页面「模板」→「模式」+ 月度余额导出

- 主页面顶部 `index.html:48` 的 `<label>` 文本改为「模式」；下拉值域收窄为 `制作网银账单`（默认，内部隐式 `__FILENAME_MAPPING__`）+ `导出月度余额账单`
- 真实模板 / 虚拟 ID 从主页面下拉消失，仅出现在「导出月度余额账单」模式的弹窗里
- 弹窗（`createMonthlyBalanceExportDialog`）：
  - 左上标题「请选择需要导出月度余额账单的银行渠道」
  - 模板下拉（默认选 `全部银行渠道`，其余为普通模板）+ 年月选择器（近 10 年~今年+1；月份必须主动选）
  - 完成按钮 → 后端 `monthly-balance:assemble` 装配 → 写入临时 xlsx → `monthly-balance:export` 弹系统 SaveDialog 另存
- **Q2 最新余额定义**：对每个大账号 × 币种，优先取 `billDate === 月末最后一日` 的 seed；无则按 `billDate ≤ 月末最后一日` 取最大的一条；全部 seeds `billDate > 月末` 或完全无 seed → **跳过该大账号**
- **Q4 单文件单 sheet**：所有模板 / 大账号 / 币种 records 合并到同一 sheet
- 文件命名：`月度余额账单-{模板名 or "全部银行渠道"}-{YYYY-MM}.xlsx`
- 按钮矩阵：月度余额模式下 `导入文件 / 导出明细 / 账户映射` 置灰禁用；`导入模板 / 模板管理 / 导出余额` 可用

### R2 自有账号合并入大账号表

- `template_big_accounts` 表新增列 `account_nature TEXT NOT NULL DEFAULT 'client'`（取值 `'client' | 'own'`）
- 维护大账号对话框 tbody 现同时渲染 `clientAccounts + ownAccounts`，`own` 行 merchantView 前加 `[自有] ` 前缀（input 值保持裸 merchantId）
- `saveMappings` 透传每条 `accountNature` 入库，白名单校验 `'client' | 'own'`，非法/缺省默认 `'client'`
- **§3.1 跨需求一致性约束**：自有账户**仅在 R1 月度余额导出场景参与**，其它场景一律过滤。实现：`getTemplateBigAccounts(db, templateId, { includeOwn = false })` 默认不含 own；R1 装配显式传 `{ includeOwn: true }`；`listTemplates / getTemplate / listChildTemplates` 的 `bigAccountCount` 子查询统一加 `AND ba.account_nature = 'client'`
- 维护大账号对话框初始化走独立 IPC `big-account:get-with-own` 拿含自有的完整列表（仅用于 UI 展示）
- **D15 迁移失败不阻塞启动**：`runOwnAccountsMigration` 外层 try/catch，返回 `{ status: 'failed' }` 时不抛异常，缓存失败文案由 renderer `setStatus` 以 error tone 显示
- **D16 orphan bankName 跳过**：json 对应 bankName 数据库无模板 → 跳过 + `[WARN]` 日志，不触发 D15 告警
- 历史 `own-accounts/*.json` 保留不删除（Q6 过渡兼容）；迁移幂等 flag `app_settings.own_accounts_migration_v1_5_3_done='1'`；迁移日志 `{storageRoot}/own-accounts-migration-v1.5.3.log`
- Bundle v3 格式向后兼容：`bigAccounts[]` 新增可选 `accountNature` 字段，旧 bundle 缺此字段时默认 `'client'`

### R3 导出表头字体 Courier New（D14）

- 新增依赖 `xlsx-js-style@^1.2.0`，**仅** `src/backend/file-service/writers.js` 局部切 `require('xlsx')` → `require('xlsx-js-style')`，其它文件保持 `xlsx`，减少打包体积
- 新增工具 `applyHeaderRowFont(worksheet, headerRowIndex = 0)`：遍历表头行每个 cell 补 `s.font.name = 'Courier New'`，保留原有 `bold / sz / color / fill / border`
- `writeWorkbookRows` + `writeBalanceWorkbook` 各注入一次；数据区字体不变；**不加 CJK 回退链**（Q10，渲染依赖系统字体替换）
- 合并文件 `mergeGeneratedXlsxFiles`：实测社区版 `xlsx` 读回 `cell.s` 会丢 `font.name`，需要在出口局部 shadow `xlsx-js-style` 再补调 Courier New（TechDoc §4.3.2 fallback）
- **D14 副作用**：明细 / 余额 / 月度余额 / 合并 / **新开账户模块**五条路径表头都会变 Courier New（新开账户模块是副作用，用户已知情并接受）；报错 xlsx（错误报告实际是 txt）不改

### R4 账单拆分合并浮点精度 hotfix（D17）

- **Bug 位置**：`src/backend/file-service.js:buildMappedRows` 合并分支 `const net = sumCredit - sumDebit`
- **根因**：JS 浮点 `+` / `-` 噪声（`2377.49 + 178.31 = 2555.7999999999997`），`sanitizeAmountValue` 只字符串清理不 round
- **修复**：`const net = roundAmount(sumCredit - sumDebit)`（`Number(value.toFixed(2))`），2 位小数对资金字段是精确而非降精度
- **关键**：初稿方案 `roundAmountHighPrecision`（`toFixed(12)`）对样本 `65572.01 + 4917.90 = 70489.90999999999` **不收敛**（IEEE 754 在 12 位处仍保留噪声），改 `roundAmount`（`toFixed(2)`）后覆盖全部 3 条用户样本
- 影响：所有"账单拆分合并"模式下 ≥2 行且含多位小数的合并组；属 v1.5.2 已有 bug

## 风险

1. **R2 数据迁移**（资金字段 merchant_id）：一个 bankName 对多模板时"全部写入"策略；orphan / conflict 三态全部有日志兜底；失败不阻塞启动 + 状态栏告警（D15）
2. **§3.1 过滤约束**：跨 SQL 层 + repository 层 + 前端层 + IPC 层的一致性；漏改一处自有账号就会渗透到制作账单流程
3. **R4 资金字段精度**：2 位小数强制 round 在项目模板库范围内无信息损失（未使用 3 位小数货币）
4. **D14 副作用**：新开账户模块表头会变 Courier New（用户已确认接受）
5. **R3 xlsx-js-style 打包**：新依赖需 electron-builder 验证；当前 smoke + regression 均通过
