## 2. 平盘对账前端契约

- 主模块 ID 为 `position-reconciliation-process`，登记在模块全集但不加入默认启用列表，由用户从功能收纳中手动启用。
- 页面提供「平盘资金性质校验 / 平盘数据信息回填 / 平盘订单销账处理」三项功能选择。
- 「开始运行 / 对账表管理 / 链接表管理 / 对账配置管理 / 导出文件」五个按钮仅显示后续开放提示，不调用业务 IPC 或读写业务数据。
- 仅「开始运行」使用蓝色主按钮，其余使用白色次按钮；开始运行与导出文件宽度均为 `140px`。
- 本版不持久化功能选择，不新增数据库、业务 IPC、Excel 或存档中心契约。

## 3. Payment 多大账号契约

- `config.paymentOfflineBackfill.bigAccount` 保持字符串 schema，以中文顿号 `、` 保存多个 trim 后账号；首尾/连续顿号、空段、重复账号及中英文逗号均拒绝保存。
- 银行行 `MerchantId` 与订单 `收款账户（卡号）` 必须属于配置集合，并在每一匹配对中 trim 后大小写敏感相等。
- R1/R2 按账号与周隔离，R3 全池兜底也不得跨账号取候选；账号配置顺序不改变既有排序和赢家。
- 多账号共享既有银行行、订单行全局 1:1 消费集合；金额、币种、日期、回填字段、matchedPairs 和 Excel 契约不变。
- 非法历史配置不匹配任何行，并产生可见配置 warning。

## 4. 兼容性与失败行为

- 旧单账号字符串直接视为一个账号，无数据库迁移。
- 新模块默认不启用，不改变既有用户模块顺序或现有业务入口。
- 平盘按钮不得触发文件选择、运行、导出、数据库写入或存档批次。
- 多账号解析失败时安全 no-op，不降级为合池或模糊匹配。
