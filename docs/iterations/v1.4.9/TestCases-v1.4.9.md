## 三、测试数据准备

### 3.1 测试模板

**模板 T1 — 多币种单行源（拆分场景）：**
- `template.headers` = `['DATE', 'AMT1_CUR', 'AMT1_C', 'AMT1_D', 'AMT2_CUR', 'AMT2_C', 'AMT2_D', 'MERCHANT', 'DESC']`
- 用于配置 2 份拆分账单（Row1 取 AMT1_*，Row2 取 AMT2_*）

**模板 T2 — 单金额列源（合并场景）：**
- `template.headers` = `['DATE', 'CURRENCY', 'AMOUNT', 'TXN_TYPE', 'DESCRIPTION']`
- 用于配置 N 份拆分 + 多组合并

**模板 T3 — 直接映射已配置模板：**
- `template_mappings` 中 `Credit Amount` / `Debit Amount` / `Currency` 已分别映射到独立列
- 用于 4 方互斥（AC1-65 ~ AC1-68）校验

**模板 T4 — v1.4.8 的「按字段区分发生额」模板：**
- `template_mappings` 中「按字段区分发生额」= `是`
- `template_amount_split_rules` 表含 2 行规则
- 用于 4 方互斥（AC1-70）+ 独立表数据隔离（AC1-48）校验

**模板 T5 — v1.4.7 旧模板（无 bill split 配置）：**
- 4 张 bill split 新表中**无记录**
- 用于 AC1-75 兼容性

### 3.2 测试 CSV / XLSX

**文件 F1（多币种单行源）：** 列 `DATE, AMT1_CUR, AMT1_C, AMT1_D, AMT2_CUR, AMT2_C, AMT2_D, MERCHANT, DESC`，5 行数据。示例行：`2026-04-01, CNY, 100, 0, USD, 14, 0, SHOP1, item1`。

**文件 F2（合并场景 — 连续两行属同一笔）：** 列 `DATE, CURRENCY, AMOUNT, TXN_TYPE, DESCRIPTION`，6 行数据，每 2 行为一组（第 1 行手续费 +10，第 2 行本金 -210，合并后净值 = -200）。

**文件 F3（合并组 Currency 不一致）：** 基于 F2 结构，合并组内两行 `CURRENCY` 分别为 `CNY` / `USD`，用于 ACI-6 报错验证。

**文件 F4（合并后净值 = 0）：** 基于 F2 结构，合并组内两行 `AMOUNT` 一正一负且绝对值相等，用于 ACI-7 **静默过滤**验证（**2026-04-08 fix2 override**：原为"报错验证"，现为"静默跳过整个合并组"验证）。

**文件 F5（列不存在）：** 列 `DATE, AMOUNT`，缺少弹框 2 配置中引用的 `CURRENCY` 列，用于 ACI-10 报错验证。

**文件 F6（全部未命中）：** 列同 F2，所有行的金额均为空字符串，用于 ACI-12 多文件聚合告警验证。

**文件 F7（多文件批量）：** F1 / F2 / F6 三个文件，用于多文件聚合告警场景。

**文件 F8（性能用，1500+ 行）：** 基于 F1 结构 1500 行。

### 3.3 测试 Bundle JSON

**Bundle B1（v1.4.7 旧 bundle）：** 顶层无 `bundleVersion` 字段，无 `billSplitRows` 等新字段。
**Bundle B2（v1.4.8 bundle）：** 顶层 `bundleVersion = 2`，包含 `amountSplitRules`，无 `billSplitRows`。
**Bundle B3（v1.4.9 bundle）：** 顶层 `bundleVersion = 3`，包含 `billSplitMappings` / `billSplitRows` / `billSplitAmountRules` / `billSplitMergeEnabled` / `reuseModuleMapping`。
**Bundle B4（人为伪造高版本）：** 顶层 `bundleVersion = 99`。
