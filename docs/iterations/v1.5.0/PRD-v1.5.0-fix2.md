## 一、需求概述

本次 fix2 包含 8 项需求：

1. **模块名称变更** —— "新开账户生成网银账单" 改为 "新开账户余额账单生成"。
2. **英文日期格式解析** —— 支持 `DD Mon YYYY, HH:MM:SS AM/PM`、`Month DD, YYYY` 等常见英文日期变体，只取日期部分。
3. **导入模板包同名覆盖确认** —— 导入 JSON bundle 时，如果存在同名模板，覆盖前弹出确认框。
4. **使用手册导出格式扩展** —— 从仅支持 PDF 扩展为支持 txt、md、html 三种格式，导出后展示确认效果。
5a. **提取大账号顺序弹框 — 单滚动条** —— 提取大账号顺序弹框改为单滚动条控制两侧同步滚动。
5b. **大账号选择对话框 — 条件单滚动条 + 文本化** —— 勾选"记住顺序"时切为单滚动条 + 右面板文本化显示。
6. **按正负号下拉框宽度修复** —— "按正负号拆分的发生额"下拉框宽度与"按字段区分发生额"下拉框保持一致。
7. **指定账单实现功能** —— 在"拆分/合并账单——发生额映射关系管理"中新增"指定账单实现功能"勾选框和多选下拉框。

## 二、背景与目标

### 2.1 背景

**需求 1**：当前模块切换中"新开账户生成网银账单"名称与实际功能不匹配——该模块的核心功能是生成新开账户的余额账单，而非网银账单。

**需求 2**：当前日期解析函数 `parseEnglishMonthDateCandidate`（normalizers.js:358）支持 `DD-Mon YYYY`、`Mon-DD YYYY` 等以连字符或空格分隔的英文月份日期，但不支持带逗号分隔和 AM/PM 时间后缀的格式（如 `09 Apr 2026, 06:26:26 PM`），也不支持完整英文月份名 + 逗号格式（如 `April 9, 2026`）。部分银行的原始账单使用这些格式。

**需求 3**：当前 `template:import-bundle` handler（main.js:3501-3654）在导入模板包时，对同名模板直接执行 `database.upsertTemplate` 覆盖写入，没有任何确认环节。用户误导入同名模板包时会静默覆盖已有配置，造成数据丢失。

**需求 4**：当前使用手册另存为仅支持 PDF 格式导出（main.js:2419-2526）。用户需要 txt、md 和 html 格式的选项。

**需求 5a**：当前提取大账号顺序弹框（renderer-dialogs.js:917-930）左右面板各有独立滚动条，通过 `scrollTop` 事件双向同步。但存在滚动延迟和视觉不一致——两侧各显示一个滚动条，用户体验不佳。

**需求 5b**：当前大账号选择对话框（renderer-dialogs.js:624-637）左右面板同样采用双滚动条同步方案。当用户勾选"记住顺序"时，应当切为单滚动条并将右面板大账号信息变为只读文本化显示。

**需求 6**：在"拆分/合并账单映射关系管理"的"发生额映射关系管理"区域中，"按正负号拆分的发生额"的下拉框 CSS（`.bill-split-sub-row .mapping-select`，styles.css:2042）只设置了 `min-width: 200px`，没有 `max-width`。而全局 `.mapping-select` 有 `min-width: 260px; max-width: 260px`。导致两个下拉框宽度不一致。v1.4.9 fix3 做了部分修复但不彻底。

**需求 7**：当前"拆分/合并账单——发生额映射关系管理"中，"按正负号拆分的发生额"和"按字段区分发生额"的功能作用于全部账单序号。需要支持"指定账单实现功能"——让用户可以指定某些功能模块仅作用于特定的账单序号。

### 2.2 目标

- 需求 1：模块切换中显示的名称与模块实际功能一致。
- 需求 2：常见英文日期格式均可被正确解析为 `YYYY-MM-DD`。
- 需求 3：导入模板包覆盖同名模板前，用户有机会确认或取消。
- 需求 4：使用手册可导出为 txt、md、html 三种格式，导出后可预览确认。
- 需求 5a：提取大账号顺序弹框始终使用单滚动条。
- 需求 5b：勾选"记住顺序"时大账号选择对话框切为单滚动条 + 右面板文本化。
- 需求 6："按正负号拆分的发生额"下拉框宽度与"按字段区分发生额"下拉框视觉一致。
- 需求 7：支持将"按正负号拆分的发生额"或"按字段区分发生额"的功能指定到特定账单序号。

### 4.2 需求 2：英文日期格式解析

#### 4.2.1 新增支持的日期格式

| 格式 | 示例 | 说明 |
|------|------|------|
| `DD Mon YYYY, HH:MM:SS AM/PM` | `09 Apr 2026, 06:26:26 PM` | 日+缩写月+年，后接时间和 AM/PM |
| `Month DD, YYYY` | `April 9, 2026` | 完整月份名+日+年 |
| `DD Month YYYY` | `9 April 2026` | 日+完整月份名+年 |
| `Mon DD, YYYY` | `Apr 9, 2026` | 缩写月+日+年 |
| `DD Mon YYYY` | `09 Apr 2026` | 日+缩写月+年（无时间） |

#### 4.2.2 处理规则

- 只取日期部分，时分秒及 AM/PM 后缀**丢弃**。
- 输出为标准 `YYYY-MM-DD` 格式。
- 英文月份名支持完整拼写（January~December）和三字母缩写（Jan~Dec），大小写不敏感。

#### 4.2.3 不变的行为

- 现有支持的日期格式（`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYYMMDD`、中文年月日、`DD-Mon YYYY` 等）保持不变。
- `dateParseOrder` 配置（MDY / DMY / auto）对英文月份格式不产生影响（月份名称本身无歧义）。

---

### 4.3 需求 3：导入模板包同名覆盖确认

#### 4.3.1 触发条件

用户通过"导入模板包"功能导入 JSON bundle 时，如果 bundle 中的某个模板在当前数据库中已存在同名模板（按 `templateKey` 或 `name` 匹配）。

#### 4.3.2 交互流程

1. 解析 bundle 中的模板列表。
2. 逐个检查是否存在同名模板。
3. 如果存在至少一个同名模板 → 弹出确认框：
   - 提示文本：列出将被覆盖的模板名称
   - 确认按钮：确认覆盖，继续导入流程
   - 取消按钮：取消整个导入操作
4. 如果不存在同名模板 → 直接执行导入（行为不变）。

#### 4.3.3 确认框设计

```
+------------------------------------------------------------------+
|  以下模板已存在，导入将覆盖现有配置：                                  |
|                                                                    |
|  • 模板A                                                           |
|  • 模板B                                                           |
|                                                                    |
|  是否确认覆盖？                                                      |
|                                                                    |
|               [取消]           [确认覆盖]                             |
+------------------------------------------------------------------+
```

### 4.4 需求 4：使用手册导出格式扩展

#### 4.4.1 支持的导出格式

| 格式 | 扩展名 | 说明 |
|------|--------|------|
| 纯文本 | `.txt` | 去除 Markdown 标记的纯文本内容 |
| Markdown | `.md` | 原始 Markdown 内容直接写出 |
| HTML | `.html` | Markdown 渲染为 HTML 后导出 |

#### 4.4.2 文件保存对话框

将当前固定 PDF 格式的 `showSaveDialog` filters 扩展为三种格式：

```
filters: [
  { name: '纯文本文件', extensions: ['txt'] },
  { name: 'Markdown 文件', extensions: ['md'] },
  { name: 'HTML 文件', extensions: ['html'] }
]
```

默认文件名保留 `使用手册`，扩展名随用户选择的格式变化。

#### 4.4.3 导出后确认效果

导出完成后，弹出提示框告知用户导出成功，并提供文件路径信息。用户可据此打开文件确认导出效果。

### 4.5 需求 5a：提取大账号顺序弹框 — 单滚动条

#### 4.5.1 现状

提取大账号顺序弹框的左侧文件列表（`.extract-file-list`）和右侧提取结果列表（`.extract-order-list`）各有独立滚动条，通过 `scrollTop` 事件双向同步（renderer-dialogs.js:917-930）。

#### 4.5.2 目标

改为**单滚动条**方案：
- 左右面板放入同一个可滚动外层容器中
- 外层容器设置 `overflow-y: auto`
- 左右面板自身取消 `overflow-y`
- 两侧始终由外层容器的单个滚动条一起控制滚动
- **无条件生效**，不依赖任何 checkbox 状态

#### 4.5.3 UI Mockup

```
+----------------------------------------------------------------+
| 确认大账号顺序                                              [×] |
+----------------------------------------------------------------+
| +---------------------------------------------------------+  ▲ |
| | 文件顺序：          | 大账号信息：                         |  █ |
| | 1. file_a...csv    | 1. 62001234567890 CNY   [编辑]   |  █ |
| | 2. file_d... 第3行  | 2. 62009876543210 USD   [编辑]   |  █ |
| | 3. file_g...csv    | 3. 44001234567890 HKD   [编辑]   |  ▼ |
| +---------------------------------------------------------+    |
|                                                       [完成]   |
+----------------------------------------------------------------+
            ↑ 单滚动条控制左右两侧
```

### 4.6 需求 5b：大账号选择对话框 — 条件单滚动条 + 文本化

#### 4.6.1 未勾选"记住顺序"时

保持现有行为不变：
- 左右面板各有独立滚动条
- 右面板大账号列表为可交互的 checkbox 列表

#### 4.6.2 勾选"记住顺序"时

切换为：
- **单滚动条**：与 5a 方案一致，左右面板放入同一个外层容器，由单个滚动条控制
- **右面板文本化**：右面板的大账号信息从 checkbox 列表变为纯文本只读显示（仅展示已勾选的大账号信息及其序号）

#### 4.6.3 切换时机

- 勾选"记住顺序" → 立即切为单滚动条 + 右面板文本化
- 取消勾选"记住顺序" → 立即恢复双滚动条 + 右面板恢复 checkbox 列表

### 4.7 需求 6：按正负号下拉框宽度修复

#### 4.7.1 现状

在"拆分/合并账单映射关系管理"弹框的"发生额映射关系管理"区域：

| 元素 | 当前 CSS | 实际宽度 |
|------|---------|---------|

| "按字段区分发生额" 下拉框 | 同上 | 可能超过 260px |
| 全局 `.mapping-select` | `min-width: 260px; max-width: 260px` | 固定 260px |

#### 4.7.2 目标

"按正负号拆分的发生额"的下拉框宽度应与"按字段区分发生额"的下拉框**保持一致**，且视觉上与全局 `.mapping-select` 对齐。

### 4.8 需求 7：指定账单实现功能

#### 4.8.1 功能位置

在"拆分/合并账单——发生额映射关系管理"区域中：

- "按正负号拆分的发生额"下拉框的**右侧**
- "按字段区分发生额"的"发生额映射关系管理"按钮的**右侧**

#### 4.8.2 出现条件

- 当"按正负号拆分的发生额"下拉框**有值**时，在该行右侧出现"指定账单实现功能"勾选框
- 当"按字段区分发生额"下拉框**有值**（即选择了"是"）时，在"发生额映射关系管理"按钮右侧出现"指定账单实现功能"勾选框

#### 4.8.3 勾选框交互

1. 勾选"指定账单实现功能" → 勾选框右侧出现**多选下拉框**
2. 点击多选下拉框 → 展开账单序号列表（来自当前拆分/合并账单的序号列表）
3. 用户多选账单序号
4. 点击下拉框外其他区域 → 多选下拉框收起，选中结果**立即落库**（自动保存）
5. 取消勾选"指定账单实现功能" → 多选下拉框隐藏，清除已选账单序号并落库

#### 4.8.4 对账单序号行数据的影响

当副区域（发生额映射关系管理）有值时：
- 若未勾选任何"指定账单实现功能" → 所有账单序号行的 Credit/Debit 下拉框**全部禁用**
- 若勾选了"指定账单实现功能"并选定了账单序号 → 被选定的账单序号行的 Credit/Debit 下拉框**禁用**，未被选定的账单序号行的 Credit/Debit 下拉框**可用**

#### 4.8.5 UI Mockup

```
拆分/合并账单——发生额映射关系管理
+----------------------------------------------------------------------+
| 按正负号拆分的发生额  [▾ 字段A ]  [✓] 指定账单实现功能 [1, 3 ▾]      |
| 按字段区分发生额      [▾ 是    ]  [发生额映射关系管理]               |
|                                   [✓] 指定账单实现功能 [2 ▾]         |
+----------------------------------------------------------------------+

说明：
  - "[1, 3 ▾]" 表示多选下拉框，已选中账单序号 1 和 3
  - "[2 ▾]" 表示多选下拉框，已选中账单序号 2
  - 账单序号 1、2、3 行的 Credit/Debit 下拉框被禁用，其余行可用
```

注意：账单序号行数据表格为五列（不含"发生额"列），列为：序号、日期、Credit、Debit、余额。
