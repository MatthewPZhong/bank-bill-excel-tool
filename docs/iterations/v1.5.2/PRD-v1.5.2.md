## 一、需求概述

本版本包含 3 项核心需求和 2 项新增功能：

1. **主/子模板的模板名校验** —— 在映射关系管理页「完成」时，若勾选「设为子模板」且选中了主模板，需校验"子模板名包含主模板名字符串"，不通过则弹提醒并拦截落库。
2. **大账号确认页：单个账号匹多个文件** —— 在「提取大账号顺序」按钮右侧新增勾选框（默认不勾选）与 toggle 按钮，允许将多个文件映射到同一个大账号。UI 改动包括：编辑/完成合并为 1 个 toggle 按钮、完成后排序、编辑还原保留映射、左侧新增字母列、按钮文案更新等。
3. **主页面模板新增「按表头自动识别模板」** —— 主页面模板下拉新增枚举值「按文件名映射模板」（并设为默认）；导入文件时系统**直接遍历所有模板按表头匹配**（用户无需配置任何字段，原映射管理对话框中的「文件名固定字段」输入框模块已删除），唯一命中则按该模板输出，否则报错截断。
4. **表头唯一性校验**（新增） —— 导入模板文件时校验新表头与已有模板不重复；Bundle 导入时逐 entry 校验，重复跳过。
5. **多模板合并导出**（新增） —— 多个文件匹配到不同模板时，按各自模板独立生成后合并为汇总文件。

## 二、背景与目标

### 2.1 背景

**需求 1**：v1.5.1 引入主/子模板机制（`src/backend/database/migrations.js:282` `ensureParentTemplateSupport`、`src/renderer-dialogs.js:1886` 映射关系管理 header 的两个勾选框）。当前用户勾选「设为子模板」+ 选中一个主模板之后直接落库（`src/renderer-dialogs.js:2581-2585`），**不检查**子模板名与主模板名之间的从属关系。导致：子模板可能挂在完全无关的主模板下，导入文件时子模板匹配会错乱。

**需求 2**：v1.5.0 的大账号确认页（`src/renderer-dialogs.js:581-614` `createBigAccountSelectionDialog`）基于"一个 block（文件一段）对应一条 assignment"的 1:1 语义（`src/main.js:881` `applyBigAccountAssignmentsToFileEntries` / `src/main.js:6658` `assignments.length !== expectedRows.length` 校验），**每个文件/block 独立勾选一个大账号**。当实际业务里多个文件本来就属于同一个大账号（例如同一客户按月拆成 3 个文件）时，用户必须对同一大账号重复勾选 3 次，操作繁琐且容易漏选。

**需求 3**：目前主页面「模板」下拉要求用户**先选定一个具体模板再导入**。当用户有几十个模板、或需要批量导入不同银行的文件时，手动切换模板不现实。需要一种按表头自动识别模板的默认模式。

> **方案演变**：初稿设计为"在映射管理里为每个模板配置「文件名里的固定字段」，导入时按 `basename.includes(filenameFixedField)` 匹配"。最终实现改为**直接按表头自动识别**——用户无需配置任何字段，映射管理对话框中的输入框模块已删除。`filenameFixedField` 数据层保留不动（DB 列、Repo/IPC/Bundle 透传均在），以便未来可能重新启用。

### 2.2 目标

- 需求 1：在子模板入库前加一层"子模板名必须包含主模板名字符串"的校验，拦截错配主模板的情况。
- 需求 2：大账号确认页支持"多文件共享一个大账号"的 M:1 映射，并在"完成"按钮处一次性生效。未被多对一映射的文件走原有 1:1 流程。UI 交互细节包括：默认不勾选、toggle 按钮、完成排序、编辑还原保留映射、左侧字母列、按钮文案更新。
- 需求 3：新增「按文件名映射模板」枚举作为默认模板，导入文件时**按表头自动识别匹配**唯一模板（用户无需配置字段），唯一命中则按该模板输出；否则整批截断。
- 表头唯一性校验：确保不同模板不会有完全相同的表头，防止按表头自动识别时多命中。
- 多模板合并导出：多文件匹配不同模板时合并输出汇总文件。

### 2.3 明确不做

- 需求 1：不对"普通模板"之间做任何名称校验；不对主模板自身名称做前缀限制。
- 需求 1：不调整"模糊匹配"算法（仅用"子包含主"字符串包含）；不做大小写不敏感或去空格等增强。
- 需求 2：不在映射结果持久化——仅影响本次导入会话中对大账号的绑定关系，不写回数据库（不修改 `big_account_order` 等配置）。
- 需求 2：不改变"固定顺序模式（fixed）"里"记住顺序"的保存格式；多对一仅作为不固定模式和固定模式下的一次性勾选辅助。
- 需求 3：不做"多个候选集 fallback"的兜底；命中非唯一直接报错。
- 需求 3：不自动保存/清空用户已选的具体模板；选择"按文件名映射模板"时只影响本次导入动作。
- 需求 3：~~原设计的"文件名固定字段"输入框 UI~~ 已删除；按表头自动识别不需要用户配置。

## 六、功能详细描述

### 6.1 需求 1：主/子模板的模板名校验

#### 6.1.1 说明

**触发条件**：在「映射关系管理」对话框点击「完成」按钮（`src/renderer-dialogs.js:2542` 的 `data-action="done"` 点击 handler）。

**校验规则（决策 D1）**：子模板名**包含**主模板名字符串（`子模板名.includes(主模板名)`）。

**流程**：
1. 点「完成」时，若当前模板勾选了「设为子模板」并在主模板下拉中选中了某个主模板 → 取该主模板的 `name`，调用 `当前模板.name.includes(主模板.name)` 判断：
   - **通过** → 继续原有的保存流程（保存 mappings → `setChildParent` → 刷新模板 → 返回模板管理页）。
   - **不通过** → 弹出提醒框「子模板与主模板模板名匹配不上，请检查。」；用户点提醒框的「确认」后**不落库**，重新打开"映射关系管理"对话框（保留当前已编辑内容）。
2. 若**未**勾选「设为子模板」或**未选**主模板 → 不触发本次校验，走原有逻辑。

**输入**：
- 当前模板的 `name`（String）
- 主模板下拉框 `data-role="parent-select"` 的 `selectedOption.textContent`（即主模板 `name`）

**输出**：
- 通过时：正常落库（等同现有 `src/renderer-dialogs.js:2578-2588` 的 `setParentStatus` / `setChildParent` 调用链）
- 不通过时：弹警告对话框（`createAlertDialog`），拦截落库；提醒框内文案固定为「子模板与主模板模板名匹配不上，请检查。」

**边界条件**：
- 主模板名 `""` 或 `null` 不应出现（parent-select 下拉只列出 `isParent=true` 的模板，其 `name` 必然非空）。若异常出现，按"不通过"处理并提醒。
- 主模板名为 `"中行001"`、子模板名为 `"中行001"` → 通过（`includes` 允许相等）。
- 主模板名含特殊字符（中文标点、空格）：仍按原始字符串 `includes`，不做规范化。
- 前端拦截不通过时，`templates.setChildParent` / `templates.setParentStatus` **都不调用**，mappings 本身也不落库（整体"完成"操作取消），避免出现"mappings 存了但主/子关系没存"的不一致。
  - 实现建议：校验放在 `saveMappings` 调用之前（即 `src/renderer-dialogs.js:2542` `click` handler 的第一步，优先于 `saveMappings(draftMappings)`）。
- 当前模板本身是主模板（`templateIsParent=true`）时：由于不能同时是主模板和子模板（UI 互斥 `src/renderer-dialogs.js:1943-1954`），该分支不触发校验。

#### 6.1.2 影响范围

- **前端**：仅修改 `src/renderer-dialogs.js:2542` 的「完成」按钮 handler，新增一段前置校验。
- **后端 / DB / 接口**：**无变更**。

### 6.2 需求 2：大账号确认页支持「单个账号匹多个文件」

#### 6.2.1 说明

**触发条件**：打开「网银账单解析大账号确认」对话框（`src/renderer-dialogs.js:581` `createBigAccountSelectionDialog`）后即生效。

**UI 变更**：
1. 「提取大账号顺序」按钮右侧新增：
   - 勾选框「单个账号匹多个文件」（`<input type="checkbox">` + 标签），**默认不勾选**
   - 编辑和完成**合并为 1 个 toggle 按钮**（非两个独立按钮）
2. 勾选时不发生文本平移（visibility 占位），编辑态勾选 block 位置不变。
3. **左侧文件名左边新增字母列**标识组归属。
4. "导出当前文件"按钮更名为"导出**当前批次文件**"；"导出所有"按钮更名为"导出**所有批次文件**"。

**勾选粒度（已决策 2026-04-16：B 语义）**：
- 现有大账号确认页的左侧列表本来就**按 block 渲染**（一个文件可能产生多个 block，每 block 一行；见 `src/renderer-dialogs.js:652-664` + `src/main.js:857-879` `buildBigAccountSelectionRows`）。
- v1.5.2 的 M:1 映射**勾选粒度 = block**：用户在左侧勾的是"某文件的某个具体 block"，而**不是**"整个文件"。同文件的其他未被勾选 block 保持原处理（由用户在剩余 1:1 流程中单独勾选或沿用旧逻辑）。
- 这是决策 ①B 的直接体现：**只覆盖被勾选的那个 block**，同文件其他 block 的 MerchantId/Currency 不被本次 M:1 映射触及。

**编辑状态下的 UI 细节**：
- 左侧"文件顺序"的每个 **block 条目**：左边新增字母列标识组归属（如 `a`、`b`），勾选单位始终是 block，不是文件。
- 勾选时不发生文本平移（visibility 占位），编辑态勾选 block 位置不变。
- 右侧"大账号顺序"的每个条目：保留原勾选框，按组分配。
- **完成后排序**：uncovered block 在前保持原序，covered block 在后按组 a→z 排（组内按原文件顺序）。
- **编辑还原**：点编辑恢复原排序，**保留已有映射**供修改（不清空 multiGroups）。
- **已映射 block 不参与「提取大账号顺序」**，确认弹窗不显示已映射 block。

**映射生成规则（决策 D2 / D3 + ①B block 粒度）**：
- 用户进入编辑状态后，每一次"配对事件"形成**一组** M:1 映射，组序号 = 英文字母 `a, b, c, ...`；每组内勾选的左侧 N 个 **block** 共享右侧那一个大账号（MerchantId + Currency）。
- 两种操作顺序（任选其一，语义对称）：
  1. **先左后右**：先勾左侧 N 个 block（同组 N ≥ 1；可来自同一文件的不同 block，也可来自不同文件）→ 再勾右侧一个大账号 **或** 再点击另一个右侧勾选框（开始下一组）**或** 点击"完成"（结束）→ 当前组成立，组序号落位 `a`，下次 +1 为 `b`。
  2. **先右后左**：先勾右侧一个大账号 → 再勾左侧 N 个 block **或** 再点击另一个右侧勾选框（开始下一组）**或** 点击"完成"（结束）→ 当前组成立，组序号 `a`，下次 +1 为 `b`。
- **组序号跳转触发器（无论顺序）**：只要满足"当前组至少一条左侧 + 一条右侧"，下一次"切换到新组"的动作即视为上一组闭合；切换触发器为：
  - 开始勾新的右侧大账号（先右后左场景下开启新组）；
  - 开始勾新的左侧 block（需已有右侧绑定；否则视为同组追加）；
  - 点击"完成"按钮（触发整体闭合）。
- **同一左侧 block 不能属于多个组**（勾选互斥），如需改组需先取消当前组勾选。**同一文件的不同 block 可以归属不同组或不归属任何组**（决策 ①B 核心）。
- **同一大账号可以出现在多组吗？** 不允许同一 MerchantId+Currency 同时对应两组；一个大账号最多进一组（用户如果需要全部 block 都映射到同一大账号，也仍只有一组）。
- **编辑中不立即生效**：用户可随时取消勾选或切换；只有点击"完成"后，当前所有组才被"冻结"并用于后续"完成选择"。
- **"完成"按钮**（组闭合按钮，**非对话框的主完成按钮**）：
  - 清除所有英文序号，隐藏勾选框（进入"已完成"态）；
  - 左侧未参与多对一的 block、右侧未参与多对一的大账号 → **沿用旧 1:1 逻辑**（决策 D4），即用户仍可单独勾选（此时序号重新用原来的数字序号渲染）。
- **对话框主完成**（即 `src/renderer-dialogs.js:1105` 的 `doneBtn` 点击事件）：将多对一映射**按 block 粒度展开**为多条 `assignments`——每被勾选的 block 一条，共享组内大账号的 MerchantId+Currency，**精确定位 key = `(fileIndex, blockIndex)` / 即 `rows[i].index`**；未入组的 block 再用 1:1 assignments 补齐；合并后发给后端 `file:complete-big-account-selection`。

**边界条件**：
- 若取消"单个账号匹多个文件"勾选框 → 清空所有正在编辑的多对一勾选，回到旧 1:1 UI。
- 若左侧 block 总数 = 1 → 编辑态下也允许 M:1，但实质等于 1:1，不强制拦截（用户随意）。
- 若某组只有左侧勾选、没有右侧大账号就触发"完成" → 该组无效丢弃；只触发一次警示（可在状态栏提醒"有 N 个未配对的 block，已忽略"）。对话框主"完成"仍要求**所有 block 都有归属**（左侧 block 全部被覆盖），否则沿用原校验的错误提示。
- **同文件多 block 分别归属不同组或未归属**（决策 ①B 边界）：例如文件 X 有 3 个 block，用户可能把 block1 放到组 a（大账号甲）、block3 放到组 b（大账号乙）、block2 不入任何组留给 1:1 单独勾选；最终导出时 block1 写甲、block3 写乙、block2 写用户 1:1 勾选的值；同文件的 3 个 block 可各自不同。
- 固定模式（`mode === 'fixed'`）下"记住顺序"与多对一交互：v1.5.2 暂定**两者互斥**——勾上"单个账号匹多个文件"时，"记住顺序"勾选框禁用；反之亦然。持久化格式不变。
- 后端收到展开后的 assignments 数组长度 = 左侧 block 总数（与现有 `src/main.js:6658` 的 `expectedRows.length` 校验一致），对后端零侵入。

**导入流程（最终实现）**：
当主页面选中「按文件名映射模板」时，点击「导入文件」：
1. 弹出系统文件选择对话框，用户多选若干文件。
2. 对**每一个文件** `filePath`：
   - 遍历**所有模板单元**（主/子/普通，全量 templates），用 `matchesTemplateHeaders(filePath, template)` **逐个试表头**。
   - 令 `matches` = 表头匹配成功的模板列表。
3. **匹配结果分支**：
   - `matches.length === 1`（**唯一命中**）：直接按该模板解析（不再有额外的表头二次校验，因为 `matchesTemplateHeaders` 本身就是表头校验）。
   - `matches.length === 0`：弹报错"无法通过表头匹配任何模板"（`FILENAME_MAPPING_NO_MATCH`）→ **整批截断**。
   - `matches.length >= 2`：弹报错"表头匹配到多个模板"（`FILENAME_MAPPING_AMBIGUOUS`）→ **整批截断**。
4. 所有文件都通过 → 按各自 `matchedTemplate` 独立解析，后续大账号确认、导出流程沿用现有分模板流水线。
5. **多个文件匹配到不同模板时** → 走多模板合并导出逻辑（见 §6.5）。

**报错文案**：
- 0 命中："无法通过表头匹配任何模板，已取消本次导入。"
- 多命中："表头匹配到多个模板：模板A、模板B；请调整配置使表头唯一。已取消本次导入。"

**边界条件**：
- 整批截断语义不变：对话框报错确认后本次导入直接返回，不保留已校验通过的部分。
- 不再有 `FILENAME_MAPPING_HEADER_MISMATCH` 报错（因为匹配本身就是试表头，通过即命中，不通过即不命中）。
- `filenameFixedField` 数据层保留但 UI 不再使用。

### 6.4 表头唯一性校验（新增功能）

#### 6.4.1 说明

**目的**：确保按表头自动识别不会命中多个完全相同的模板。

**触发场景**：
1. **导入模板文件时**：新模板的表头（headers）与已有模板全量比较，完全相同（字段名、顺序一致）则拒绝导入，返回错误码 `TEMPLATE_HEADERS_DUPLICATE`。
2. **Bundle 导入时**：每个 entry 的表头与已有模板全量比较，重复则**跳过该 entry**（不阻断其他 entry），同时在 activity log 写入警告。

**边界条件**：
- 只比较表头字段名和顺序，不比较模板名称或其他配置。
- 表头只差一列即视为不同，不触发校验。
- 该校验独立于按表头自动识别逻辑，是一个入口层面的前置防护。

#### 6.4.2 影响范围

- **后端**：模板导入逻辑（`template:import` / `template:import-bundle`）新增表头比对检查。
- **前端**：无。
- **DB**：无。

### 6.5 多模板合并导出（新增功能）

#### 6.5.1 说明

**触发条件**：多个文件通过按表头自动识别匹配到**不同模板**时。

**行为**：
1. 每组文件按各自��配的模板独立生成明细和余额账单（银行名称 / 所在地各自正确）。
