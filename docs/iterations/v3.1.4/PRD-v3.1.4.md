## 1. 版本目标

修复平盘链接原始表因为少量、可明确判定为无效证据的调拨或测试付款行而整文件
0 行落库的问题。白名单异常自动过滤，正常行继续落库和派生；过滤行不参与匹配，
但必须通过墓碑、不可变异常报告、存档和运行快照保持完整审计链。

## 2. 用户流程

固定流程为：

`链接表管理 → 导入原始表 → 文件解析/校验 → 发现过滤行并自动过滤 → 写数据库`

- 写库前不增加确认页面；完成后展示物理、正常、过滤、重复和链接行数。
- 有过滤行时可立即导出异常报告，之后也可在存档中心下载同一字节文件。
- 资金校验选择 Channel 和月份后直接运行；结果确认页始终显示“过滤数据导出”，
  无过滤数据时按钮禁用。

## 3. 业务与数据契约

1. 白名单只覆盖非付款成功调拨的证据缺失，以及目标证据完整但源金额/币种缺失的
   测试付款；付款成功调拨缺证据和其它硬错误继续整文件拒绝。
2. 正常行继续使用 `source_type + row_hash` 技术身份并按既有规则派生链接；过滤行
   不进入来源表、链接表、候选、多候选或严格 1:1 消费。
3. 过滤业务键与正常记录碰撞时拒绝过滤文件，不删除旧数据；同一精确异常重导保持
   一条活动墓碑并保留历史审计。
4. preflight/apply 逐行复算 sealed ledger；报告、哈希、归档意图、revision 或事务
   证据不完整时失败关闭。
5. 运行冻结目标月份内的活动墓碑、报告引用和来源 revision；必要来源全量过滤且有效
   行为 0 时阻断运行。
