## 一、需求概述

本版本包含 5 项需求：

1. **模板管理 — 主/子模板** —— 映射关系管理页面新增「设为主模板」和「设为子模板」勾选框，支持主模板下挂子模板，主页面选择主模板后可导入并解析子模板对应格式的文件。
2. **账户映射页面改动** —— 新增模板下拉框（含子模板），表头文案变更，新增「执行操作」列（编辑/删除），币种列增 tooltip 说明，「有账户号无币种」checkbox 改为自动检测，编辑/完成按钮左对齐，迁移分配对话框，多币种桥接提醒。
3. **模板管理页面标题** —— 模板管理页面左上角新增「模板管理」标题文本。
4. **模板导出/导入增强** —— 导出主模板时自动包含子模板数据及对应账户映射数据，Bundle 版本号升级为 v4。
5. **导入文件重复判定规则增强** —— 重复判定扩展为同路径/同文件名/同文件内容三种维度，重复提示框显示重复原因，去掉「保留两份」按钮。

## 二、背景与目标

### 2.1 背景

**需求 1**：当前映射关系管理页面（`src/renderer-dialogs.js:1761` `createMappingDialog`）每个模板是独立平级的。实际业务中，同一银行的不同账单格式（如明细账单 vs 汇总账单）有共同的上下游关系，用户需要在选择一个主模板后，能同时导入该主模板及其子模板对应的多种文件格式，一次性完成账单解析和导出。当前缺乏主/子模板关联机制，用户必须手动切换模板逐个导入。

**需求 2**：当前账户映射页面（`src/renderer-dialogs.js:3958` `createAccountMappingDialog`）是全局共用的，所有模板共享同一份账户映射数据（`account_mappings` 表无 `template_id` 字段）。不同银行/模板的账户映射实际是不同的，需要按模板隔离。同时表头文案不够准确（「网银大账号ID」/「清结算系统大账号ID」需更新），且行缺乏编辑/完成切换交互。

**需求 3**：当前模板管理页面（`src/renderer-dialogs.js:1695` `createTemplateManagerDialog`）dialog-header 只有关闭按钮，无标题文本，不符合 UI 规范。

**需求 4**：当前模板导出（`src/main.js:3411` `template:export-bundle`）的 bundle（bundleVersion: 3）不包含主/子模板关系数据和账户映射数据。新增主/子模板后，需要在导出/导入时携带这些数据，以实现完整的模板迁移。

**需求 5**：当前文件重复判定（`src/main.js:4940` `resolveImportFileSelection`）仅按 `path.resolve` 全路径判重。用户从不同目录选择同名或内容相同的文件时不会被识别为重复。且重复提示框提供「保留两份」选项，可能导致数据混乱。

### 2.2 目标

- 需求 1：实现主/子模板关联机制，主页面选择主模板后可导入子模板文件并自动匹配对应子模板进行解析。
- 需求 2：账户映射按模板隔离，表头文案更新，新增编辑/完成交互和执行操作列。
- 需求 3：模板管理页面显示「模板管理」标题。
- 需求 4：Bundle v4 包含主/子模板关系和账户映射数据，支持完整导出/导入。
- 需求 5：增强重复判定维度（路径/文件名/内容），显示重复原因，移除「保留两份」按钮。

### 2.3 明确不做

- 不做子模板之间的嵌套（子模板下再挂子模板）。
- 不做主模板的批量创建/删除子模板 UI。
- 不做 bundleVersion 3 → 4 的自动在线升级（仅导入时升级）。
- 不做文件内容哈希的持久化缓存（每次导入时实时计算）。

## 五、功能详细描述

### 5.1 需求 1：模板管理 — 主/子模板

#### 5.1.1 说明

**输入**：用户在映射关系管理页面勾选「设为主模板」或「设为子模板」。

**输出**：
- 勾选「设为主模板」后，模板管理页面中该模板左侧出现三角形展开按钮（`▶`），点击展开显示所属子模板列表，箭头由右转向下（`▼`）。
- 勾选「设为子模板」后，右侧出现「主模板」文本和单选下拉框，下拉框值为所有已勾选「设为主模板」的模板。子模板在主页面模板下拉框中不显示。

**边界条件**：
- 「设为主模板」和「设为子模板」互斥，不可同时勾选。
- 一个子模板只能属于一个主模板（一对多关系，`parent_template_id` 外键）。
- 主模板自身也有映射规则，可直接解析文件。
- 取消子模板身份后恢复为普通独立模板（`parent_template_id` 置为 null）。
- 取消主模板身份时，若该主模板下有子模板，需提示用户确认（子模板将恢复为普通模板）。
- 主页面选择主模板后，导入文件时自动匹配子模板（通过文件表头与子模板 headers 比对），不需用户手动选择子模板。
- 如果导入文件的表头与主模板自身匹配，则用主模板解析；如果与某个子模板匹配，则用该子模板解析；如果都不匹配，报错。

#### 5.1.2 影响范围

- **数据库**：`templates` 表新增 `parent_template_id` 字段（INTEGER, NULLABLE, 外键指向 templates.id）。
- **前端 — 映射关系管理页面**：dialog header 区域新增两个勾选框。
- **前端 — 模板管理页面**：子模板行需缩进显示在主模板下方，主模板行有展开/折叠按钮。
- **前端 — 主页面模板下拉框**：过滤掉子模板（`parent_template_id IS NOT NULL` 的模板不显示）。
- **后端 — 文件导入解析**：选择主模板导入文件时，需自动匹配主模板或子模板。

### 5.2 需求 2：账户映射页面改动

#### 5.2.1 说明

**输入**：用户打开账户映射页面。

**输出**：
1. 左上角新增「模板」文本 + 单选下拉框，下拉框值取自主页面「模板」的当前选中值（默认选中当前模板），用于切换查看/编辑不同模板的账户映射。
2. 表头文案变更：「清结算系统大账号ID」→「清结算系统银行账号」，「网银大账号ID」→「网银账单账户号」。
3. 新增「执行操作」列（最右侧），含「编辑」和「删除」按钮。
   - 初始状态：行以文本形式展示（只读），「执行操作」列显示「编辑」和「删除」按钮。
   - 点击「编辑」→ 行内文本变为输入框，「编辑」按钮变为「完成」按钮。
   - 点击「完成」→ 行内输入框变回文本（保存数据），「完成」按钮变回「编辑」按钮。
   - 「删除」按钮始终可用，点击删除该行。
   - 编辑/完成按钮左对齐，与「执行操作」表头文本对齐。
4. 导入多文件时，按（子）模板自动查找对应账户映射。若某个（子）模板完全没有账户映射记录，不阻断导入（已移除截断检查）。
5. **币种 tooltip**：「币种」表头右侧新增 ⓘ 图标，hover 显示说明文本：「当账户映射中填写了币种时，导出账单时会自动使用此币种覆盖文件中缺失的币种信息。适用于网银文件中有账户号但无币种列的场景。」
6. **「有账户号无币种」checkbox 去掉**：原先需手动勾选的 `noCurrency` checkbox 改为自动检测——币种字段有值时自动启用该功能，无需用户额外操作。
7. **迁移分配对话框**：数据库迁移后首次打开账户映射页面时，检测 `account_mapping_migration_pending` flag，弹出分配对话框引导用户将旧数据分配到各模板。
8. **多币种桥接提醒**：提取大账号顺序时，若通过账户映射桥接匹配到的大账号存在多个币种，弹出提醒框提示用户"以下文件的大账号币种可能不准确，请检查并编辑"。
9. **模板下拉框含子模板**：账户映射页面的模板下拉框包含所有模板（含子模板），可选择子模板单独配置其账户映射。

**边界条件**：
- 每个模板有独立的账户映射列表。
- 切换模板下拉框时，加载对应模板的账户映射数据。
- 新增行默认进入编辑状态（输入框）。
- 空行（bank_account_id 和 clearing_account_id 均为空）不保存。
- 导入文件时，若匹配到的（子）模板没有任何账户映射记录，直接截断本次导入并报错，不弹出账户映射页面。

#### 5.2.2 影响范围

- **数据库**：`account_mappings` 表新增 `template_id` 字段（INTEGER, NOT NULL, 外键指向 templates.id）。需要数据迁移：现有无 template_id 的记录需要处理（详见 §八）。
- **前端 — 账户映射页面**：布局变更（新增模板下拉框、执行操作列、编辑/完成交互）。
- **后端 — 账户映射 CRUD**：所有查询和写入需带上 template_id。

### 5.4 需求 4：模板导出/导入增强

#### 5.4.1 说明

**输入**：用户点击「导出模板文件」或「导入模板文件」。

**输出**：

**导出时**：
1. Bundle 文件包含主模板和其所有子模板的数据（导出主模板时自动包含子模板）。
2. 每个模板（含子模板）的账户映射数据也一并导出。
3. bundleVersion 升级为 4。

**导入时**：
1. 支持 bundleVersion 4 的解析（包含主/子关系和账户映射）。
2. 导入主模板时自动还原其子模板和各自的账户映射。
3. bundleVersion 3 的旧 bundle 仍可导入（无主/子关系和账户映射，按现有逻辑处理）。
4. bundleVersion 5+ 拒绝导入。

**边界条件**：
- 导出普通模板（非主模板）时不包含子模板数据，但包含该模板自身的账户映射。
- 导入时若目标数据库中已有同名模板，沿用现有冲突处理逻辑。
- 子模板的 parent_template_id 在导入时需通过 template_key 或 name 重新关联到对应主模板。

#### 5.4.2 影响范围

- **后端 — Bundle 常量**：`src/main.js:116` `SUPPORTED_BUNDLE_VERSION` 从 3 升至 4。
- **后端 — 导出**：`src/main.js:1040` `buildTemplateLibraryPayload` 需包含子模板数据和账户映射数据。
- **后端 — 导入**：`src/main.js:1074` `readTemplateBundleFile` 需解析 v4 格式，还原主/子关系和账户映射。

### 5.5 需求 5：导入文件重复判定规则增强

#### 5.5.1 说明

**输入**：用户在导入文件时选择了与已导入文件重复的文件。

**输出**：
1. 重复判定扩展为三个维度（按优先级顺序判定，命中第一个即判为重复）：
   - **同路径**：`path.resolve` 后路径完全相同（现有逻辑）。
   - **同文件名**：`path.basename` 相同但路径不同。
   - **同文件内容**：文件二进制内容的哈希值（如 SHA-256）相同。
2. 重复提示框显示重复原因（不同维度显示不同文案）。
3. 按钮从三个改为两个：「覆盖旧记录」和「取消本次导入」（移除「保留两份」）。

**边界条件**：
- 同一批次内的重复和已导入会话中的重复都需要检测。
- 文件内容哈希每次导入时实时计算，不做持久化缓存。
- 重复原因文案：
  - 同路径：`"同一文件路径"`
  - 同文件名：`"同名文件"`
  - 同内容：`"文件内容相同"`

#### 5.5.2 影响范围

- **后端 — 重复判定**：`src/main.js:4940` `resolveImportFileSelection` 函数需扩展判重逻辑。
- **后端 — 哈希计算**：需新增文件内容哈希计算（`crypto.createHash`）。
- **前端 — 提示框**：按钮从 3 个减少为 2 个，detail 文案增加重复原因。

## 八、数据 / 状态 / 安全影响

| 类别 | 说明 |
|------|------|
| 数据结构变更 — `templates` 表 | 新增 `parent_template_id` 字段（INTEGER, NULLABLE, FOREIGN KEY → templates.id ON DELETE SET NULL）。默认 NULL 表示非子模板。迁移脚本需幂等（`ALTER TABLE IF NOT EXISTS` 或先检查列是否存在）。 |
| 数据结构变更 — `account_mappings` 表 | 新增 `template_id` 字段（INTEGER, NOT NULL, FOREIGN KEY → templates.id ON DELETE CASCADE）。**数据迁移（已确认方案 B）**：现有无 template_id 的记录**复制给每个模板**——遍历所有已有模板，为每个模板各复制一份完整的旧账户映射记录。同时需移除 `bank_account_id` 字段的 UNIQUE 约束，改为 `UNIQUE(template_id, bank_account_id)` 联合唯一约束。 |
| 状态流转变更 | 无新的状态机。主/子模板关系通过 `parent_template_id` 外键管理，删除主模板时子模板的 `parent_template_id` 置为 NULL（`ON DELETE SET NULL`），子模板恢复为普通模板。 |
| 权限 / 安全 | 无鉴权变更。文件内容哈希使用 SHA-256，仅用于去重比对，不涉及安全敏感操作。 |
| 回滚策略 | 数据库迁移为 `ALTER TABLE ADD COLUMN`，回滚可通过版本回退（SQLite 会忽略未使用的列）。Bundle v4 导出的文件在旧版本（v3 only）导入时会被拒绝（版本号检查）。 |

> **风险提醒**：`account_mappings` 表新增 `template_id` 涉及现有数据迁移，需 Dev 在 TechDoc 中详细设计迁移脚本。此变更影响所有账户映射的读写操作，属于**数据迁移**范畴，建议人工复核迁移逻辑。
