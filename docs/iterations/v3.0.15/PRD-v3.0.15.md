## 1. 需求概述

本次仅包含 1 项需求：

1. **重复入金匹配** —— 一次导入一份标准银行对账单和一份标准单据对账单，按已确认的七字段键识别严格的 1 Reversal + 2 Inbound 组，查询全部保留月份 MPT INBOUND，再以 MPT `orderId` 唯一匹配单据，生成两 sheet Excel。

## 2. 背景与目标

### 2.1 背景

- 重复入金后被银行 Reversal 的场景，需要定位两笔 Inbound 对应的 MPT 加款单号，并形成业务召回邮件数据。
- 同一金额可能跨客户、渠道、币种或月份重复出现；按金额抢占第一个候选会产生误召回和资金风险。
- 未能自动确认的 Reversal 相关行必须完整进入人工判定，不能被纯统计口径吞掉。

### 2.2 本版目标

- 新增独立“重复入金匹配”模块，完成导入、运行、状态展示和另存为导出。
- 银行输入限定为标准 46 列，且每行 `BizId` 非空、全文件唯一。
- Reversal 与 Inbound 按“方向金额 + 双方姓名卡号 + Channel + Currency”分组，仅 1+2 组进入 MPT 候选匹配。
- 每条银行 Inbound 按 `Channel + MerchantId + ReconciliationId + TradeType=Inbound-VA` 查询全部保留月份 MPT INBOUND。
- 自动成功必须同时满足 MPT 候选唯一、组内不重复、跨组不复用、`oppBu` 一致，以及两条单据唯一且身份字段一致。
- 导出固定两 sheet，并保留银行 BizId、MPT 月份/行 ID 等内部血缘以供审计。
- 运行数据只在当前应用启动周期有效；MPT 保留月份仍按 v3.0.14 生命周期持久化。

### 2.3 明确不做

- **不做 `MPT_CHANNEL_OTHERS`。** v3.0.14 文档中原顺延到 3.0.15 的该项改为顺延 **3.0.16**。
- **不做临时银行对账单。** 改为顺延 **3.0.16**。
- **不做缺渠道账单场景。** 改为顺延 **3.0.16**；前置资金对账场景仍只有现有“缺网关账单”。
- 不改变 v3.0.14 前置资金对账匹配、导出和持久批次语义。
- 不读取持久“已链接网关账单”作为本需求候选池，不写回或删除 MPT 批次。
- 不自动发送邮件、不接入邮箱、不生成邮件正文；本版只输出 Excel。
- 不支持多银行文件合并、不支持非标准表头、不支持手工编辑匹配结果后回写。
- PR #88 按用户指示在自动门禁全绿且 P0-P4 Finding 归零后合并；本次不打 tag、不创建 GitHub Release。

## 4. 术语与规范化规则

| 术语 | 定义 |
|------|------|
| 相关银行行 | `FundType` 经 `String(value).trim()` 后严格等于 `Reversal` 或 `Inbound` 的行；大小写敏感。其它值为忽略行。 |
| Reversal 方向金额 | 仅取该行 `Debit Amount`；不读取、校验其 `Credit Amount`。 |
| Inbound 方向金额 | 仅取该行 `Credit Amount`；不读取、校验其 `Debit Amount`。 |
| 规范金额 | 十进制字符串规范化后的精确值；去前导零和无效尾零，`.5` 等价 `0.5`，负零等价 `0`；禁止逗号和科学计数法，不经 JS 浮点数。 |
| 分组文本 | `null`/`undefined` 归为 `""`，其它值使用 `String(value)` 原值；**不 trim、大小写敏感**。 |
| 银行分组键 | 结构化七元组：`[规范方向金额, Payee Name, Payee CardNo, Drawee Name, Drawee CardNo, Channel, Currency]`。 |
| 1+2 候选组 | 分组内恰好 1 条 Reversal 且恰好 2 条 Inbound。 |
| MPT 查询键 | 对每条银行 Inbound，将 `Channel`、`MerchantId`、`ReconciliationId` 分别转字符串并 trim 后，与 MPT 同名语义字段精确、大小写敏感比较，同时 `tradeType` 必须严格为 `Inbound-VA`；`ReconciliationId` 为空时不进入候选池，按零候选转人工。 |
| MPT 候选 ID | 至少由“保留月份标识 + 该月份侧库行 ID”组成的全局稳定 ID；同一持久行在任何查询中必须得到同一 ID。 |
| MPT 业务来源字段 | 只使用 `oppBu`；trim 后必须非空，且两条 MPT 候选大小写敏感一致。MPT `clientId`、`accId`、`business` 不参与成功判定或客户/账户输出。 |
| 单据匹配键 | MPT `orderId` 与单据 `业务订单号` 分别转字符串并 trim 后大小写敏感精确匹配；不做模糊匹配或 fallback。 |
| 单据身份字段 | 单据 `用户编号`、`账户号`、`业务部门` 分别 trim；三项必须非空且在两条单据间一致，`业务部门` 还必须等于 MPT `oppBu`。 |
| 当前启动周期 | 从本次应用主进程启动到退出；重启后银行导入和匹配结果失效，MPT 保留月份不失效。 |

> 分组文本与 MPT 查询键有意采用不同规范化规则：前者保留银行原始空格以防扩大资金分组，后者按 MPT 导入既有 trim 语义查询。实现不得混用两个规则。

## 5. 功能详细描述

### 5.1 模块入口与 UI

- 新模块名称：`重复入金匹配`；module id：`duplicate-inbound-match`。
- 入口由现有功能柜控制，默认关闭；启用后显示独立面板，不嵌入“前置资金对账”场景下拉。
- 面板最少包含：`导入文件`、`开始运行`、`导出文件`、状态/进度区域。
- 初始仅可导入；有效导入后可运行；成功运行且快照未失效后可导出。
- 导入、运行、导出进行中，相关按钮防重复触发；进度文本不得输出姓名、卡号或完整原始行。
- 状态摘要至少展示：输入总行、Reversal 行、Inbound 行、忽略行、分组数、1+2 候选组、自动成功组、人工组/行、纯 Inbound 组/行，以及 MPT 零候选、多候选、复用、身份冲突计数。

### 5.2 银行与单据对账单双文件导入

#### 5.2.1 输入契约

- 每次通过同一个文件选择框恰好选择 2 个文件：一份 `.xls/.xlsx` 银行对账单和一份 `.xlsx` 单据对账单。
- 银行文件必须存在 `渠道对账单` sheet，表头与标准 46 列全集及顺序一致；单据文件第一工作表表头必须与既有 `BILL_HEADERS` 26 列全集及顺序一致。
- 两份文件按 sheet/表头契约自动识别；数量不符、同类型、类型不明或任一文件结构非法时整批拒绝。
- 空数据文件可导入并运行；若最终没有成功邮件行和人工判定行，则禁止导出。
- 每个数据行的 `BizId` 按 `String(value ?? '').trim()` 校验：不得为空，且在整份文件内唯一；唯一性大小写敏感。原始 46 列值不因校验而改写。
- 重复错误必须报告重复值及所有相关 Excel 行号；空值错误必须报告行号。任一错误使本次导入整体失败。

#### 5.2.2 替换与失败语义

- 用户取消文件选择时不改变当前输入和运行结果。
- 一旦用户选中新文件对，先使上一组输入和上一轮结果失效；随后任一文件读取、结构校验、BizId 校验或事务落库失败时保持“未导入/不可运行/不可导出”，不恢复旧结果，也不产生半份新数据。
- 原始 46 列及稳定来源序号进入本模块侧库；来源序号以文件中的数据行顺序为准。
- 单据文件流式读取；侧库只保存来源文件/行号、业务订单号、用户编号、账户号、业务部门及匹配索引。空或重复业务订单号不阻断导入，只在被当前分组引用时按零/多候选处理。
- 不将银行明细、单据明细、姓名、卡号、账号或 BizId 列表写入主 SQLite 或常规日志。

### 5.3 银行分组与候选分类

#### 5.3.1 行分类与金额

1. `FundType` trim 后严格为 `Reversal`：读取并规范化 `Debit Amount`。
2. `FundType` trim 后严格为 `Inbound`：读取并规范化 `Credit Amount`。
3. 其它值（包括 `reversal`、`INBOUND`、空值）：只计入忽略行统计，不进入分组、人工 sheet 或邮件 sheet。
4. 相关行的方向金额为空、含逗号、科学计数法或不是合法十进制时，整次运行失败；错误必须含 BizId/源行号和字段名。非方向金额即使非法也不得导致失败。

#### 5.3.2 精确分组

- 使用第 4 节定义的结构化七元组，不可用未经转义的分隔符拼接，以免字段内容碰撞。
- `BizId`、`MerchantId`、`ReconciliationId` 不进入银行分组键。
- 组按最早来源序号排序；组内行保持原文件顺序。
- 分组后的处置：
  - 恰好 1 Reversal + 2 Inbound：进入 MPT 匹配。
  - 包含 Reversal 但不是 1+2：组内全部相关行进入人工判定；原因包含 Reversal 或 Inbound 数量不符。
  - 不含 Reversal、仅含 Inbound：只进入纯 Inbound 统计，不导出到两个结果 sheet。

### 5.4 全保留月份 MPT 查询

- 候选池只包含前置资金对账侧库中**全部保留月份**的 `MPT_INBOUND_GATEWAY` 行；没有账期窗口，也不以银行 BillDate 限制月份。
- 必须额外检查原始/规范 MPT 行的 `tradeType === 'Inbound-VA'`；OUTBOUND、其它 tradeType、持久已链接网关账单均不得成为候选。
- 对 1+2 组内的每条银行 Inbound，按第 4 节 MPT 查询键检索。
- 不按月份新旧、导入时间或行顺序择优，不去重 MPT 重复行；每条持久行都是独立候选。
- 单条 Inbound 的候选数必须恰好为 1：0 条或多于 1 条均使整个 1+2 组进入人工判定。
- 查询结果必须保留精确候选数；为保持大批量内存有界，候选数大于 1 时只需物化稳定排序后的前 2 条审计样本。零/一/多裁决必须使用精确候选数，不得把样本数当成总数。
- 查询实现应批量收集银行 `ReconciliationId`，每个保留月份只打开/扫描一次，避免“银行行数 × 月份数”的重复全表扫描。
- MPT 原始 JSON 无法解析或顶层不是对象属于存储完整性错误，整次运行失败，不降级为人工匹配。

### 5.5 唯一、不复用与字段一致

对所有 1+2 组采用先解析、后全局裁决的两阶段算法，不允许遍历时 first-wins：

1. 分别解析两条银行 Inbound 的候选集合。
2. 两条 Inbound 均为单候选后，两个 MPT 候选 ID 必须不同；相同则整组人工。
3. 汇总所有组的单候选 ID。任一 ID 被不同组引用时，**所有受影响组**均进入人工判定，不得只保留先处理的组。
4. 未触发上述失败后，两条 MPT 的 `oppBu` trim 后都必须非空且大小写敏感一致。MPT `clientId`、`accId`、`business` 不再参与一致性判定。
5. 两条 MPT `orderId` trim 后都必须非空；为空时整组转人工。
6. 只有全部条件成立的组才进入单据匹配；一个 MPT 成功组严格消费 1 Reversal、2 Inbound 和 2 个互异且全局未复用的 MPT 候选。

### 5.5.1 单据唯一匹配与校验

1. 两个非空 `orderId` 分别查询当前导入单据的 `业务订单号`；每个必须恰好命中 1 行，零候选或多候选均整组人工。
2. 两个 `orderId` 必须命中不同单据行；命中同一行时整组人工。
3. 两条单据的 `用户编号`、`账户号`、`业务部门` trim 后都必须非空且逐项一致；任一为空或冲突均整组人工。
4. 一致后的单据 `业务部门` 必须与 MPT `oppBu` 大小写敏感精确相等；否则整组人工。
5. 单据失败只影响当前分组；其它分组继续运行。禁止退回 MPT `clientId/accId` 作为客户号或账户号。

人工原因采用稳定顺序并可组合，以中文 `；` 连接；同组每行写同一原因：

1. Reversal 数量不是 1；
2. Inbound 数量不是 2；
3. 某银行 Inbound 的 MPT 候选为 0；
4. 某银行 Inbound 的 MPT 候选多于 1；
5. 组内两条 Inbound 指向同一 MPT 候选；
6. MPT 候选被跨组复用；
7. MPT `oppBu` 为空或不一致；
8. MPT `orderId` 为空；
9. 单据零候选、多候选或两单号命中同一行；
10. 单据身份字段为空、不一致或业务部门不等于 `oppBu`。

### 5.6 结果守恒、顺序与血缘

- 相关银行行必须满足：
  `相关行数 = 自动成功组数 × 3 + 人工行数 + 纯 Inbound 行数`。
- 包含 Reversal 的组必须满足：
  `Reversal 相关组数 = 自动成功组数 + 人工组数`。
- 1+2 候选组必须满足：
  `1+2 候选组数 = 自动成功组数 + MPT 阶段失败人工组数 + 单据阶段失败人工组数`。
- 成功结果选用的 MPT 候选数必须等于 `自动成功组数 × 2`，且候选 ID 全局唯一。
- 自动成功组和人工组都按组内最早来源序号输出；人工组内按原文件顺序输出。
- 内部结果必须记录：Reversal BizId/来源序号、两条 Inbound BizId/来源序号、两条 MPT 候选 ID（月份 + 行 ID）、两条单据文件/行号及匹配原因/判定。Excel 固定列不额外暴露这些内部字段。
- 任一守恒断言不成立时运行失败，不保存为“成功”结果。

### 5.7 两 sheet Excel 输出

- 一次导出生成 1 个 `.xlsx`；默认文件名为本地日期 `YYMMDD_重复入金召回邮件模板.xlsx`。
- 工作簿必须且只能有以下两个 sheet，顺序固定：
  1. `邮件模板`
  2. `匹配不成功需人工判定`
- 只有成功邮件行或人工判定行至少一类非空时才允许导出；仅纯 Inbound、仅忽略行或完全空结果时禁止导出。

#### 5.7.1 `邮件模板`

固定 10 列及映射：

| 列 | 取值 |
|----|------|
| `BillDate` | 成功组 Reversal 的 `BillDate` |
| `Channel` | 成功组 Reversal 的 `Channel` |
| `MerchantId` | 成功组 Reversal 的 `MerchantId` |
| `Currency` | 成功组 Reversal 的 `Currency` |
| `Debit Amount` | 成功组 Reversal 的 `Debit Amount` 原值；Excel 数据格式固定为“常规”，不得继承模板说明行的日期格式 |
| `加款单号` | 两条银行 Inbound 按来源顺序取非空 MPT `orderId`，用中文顿号 `、` 连接 |
| `业务来源` | 两条 MPT 一致后的 `oppBu` trim 值 |
| `客户号` | 两条唯一单据一致后的 `用户编号` trim 值，按文本写入 |
| `账户号` | 两条唯一单据一致后的 `账户号` trim 值，按文本写入 |
| `备注` | 固定文本 `重复入账后被Reverse` |

- 每个自动成功组输出 1 行；模板说明行不得出现在结果中。
- 样式以 `assets/重复入金召回邮件模板.xlsx` 的表头/示例行为基准；业务值不得被公式或自动数值转换破坏。模板说明行的单元格格式不能覆盖业务列语义，`Debit Amount` 数据行必须显式使用“常规”格式。

#### 5.7.2 `匹配不成功需人工判定`

- 表头为标准 46 列原顺序，末尾追加 `人工判定原因`。
- 每个人工组输出该组全部相关银行行；46 列保持导入原值，同组每行追加相同的稳定中文原因。
- 自动成功组、纯 Inbound 组和忽略行不进入该 sheet。
- 样式以 `assets/银行对账单.xlsx` 的 `渠道对账单` 为基准。

#### 5.7.3 保存语义

- 使用系统另存为；用户取消不报错、不改变可导出结果。
- 文件先写同目录临时文件，完整生成并校验 sheet/行数后再原子发布；失败不得留下伪装成成功的目标文件。
- 已存在目标文件时遵循系统确认语义，不静默覆盖。
- 任一 sheet 超过 Excel 行数上限时整次导出失败，并提示拆分输入；本版不自动拆多文件。

### 5.8 当前启动周期与状态机

状态流转：

```text
未导入
  └─成功导入→ 可运行（导入快照有效）
                    └─开始运行→ 运行中（导出立即禁用）
                                   ├─成功→ 可导出
                                   └─失败→ 可重试运行、不可导出
任意状态 ─取消选择→ 状态不变
任意状态 ─选中新文件→ 旧输入/结果立即失效
                         ├─导入成功→ 可运行
                         └─导入失败→ 未导入
可导出 ─相关 INBOUND MPT 快照变化→ 结果过期、需重跑
应用重启→ 未导入
```

- 银行/单据导入、当前结果和详细血缘只存本模块侧库，服务当前启动周期。
- 主库只允许保存轻量运行镜像：状态、时间、两份文件名/hash、输入/MPT 快照摘要、计数、侧库路径与错误摘要；不得保存原始银行/MPT/单据业务字段。
- 应用启动时清理上次启动周期的本模块侧库及孤立 `-wal/-shm` 旁文件；目录扫描或删除失败必须显式阻断。遗留 `running` 标记为 `interrupted`，其它不可用镜像标为 `expired`/`missing-side-db`/`invalid-side-db`，不得恢复可导出状态。
- 确认选择新的银行+单据文件即删除旧导入和旧结果；开始新运行即使旧结果曾成功，也先使其不可导出。导入或运行失败均不回退到旧结果。
- 运行结果必须绑定同一双文件 import（银行/单据文件名与 hash）以及所有保留月份 INBOUND 批次的月份、批次 ID/hash/行数。相关 INBOUND 导入、替换、删除后旧结果变为 stale；仅 OUTBOUND 变化不应使结果 stale。
- 运行/导出与 MPT INBOUND 导入、替换、删除使用同一互斥边界或等效事务快照，避免“查询一半时批次变化”。
- 导出只读取当前启动周期“最新、成功、快照未过期”的完整结果。

### 5.9 错误分级

| 类型 | 示例 | 行为 |
|------|------|------|
| 导入硬错误 | 文件数量/类型不符、非标准 46/26 列、BizId 空/重复、读取失败 | 双文件整批导入失败；因文件已经确认选择，旧会话保持失效。 |
| 运行硬错误 | 方向金额非法、MPT 原始 JSON 损坏、守恒断言失败、侧库不可用 | 本次运行失败；不可导出旧结果；显示可定位但脱敏的错误。 |
| 业务不确定 | 非 1+2、MPT 0/多候选/复用/oppBu 异常、单据 0/多候选或身份字段异常 | 相关整组进入人工判定；运行本身可成功。 |
| 统计处置 | 纯 Inbound、忽略 FundType | 仅计数，不进入结果 sheet。 |
| 导出硬错误 | 结果 stale、行数超限、写盘失败、临时文件回读契约失败、目标替换失败 | 不发布目标文件；保留当前成功结果供重试。 |

## 7. 技术方案与决策

### 7.1 数据流

```text
标准 46 列银行账单 + 标准 26 列单据对账单
  → 双文件原子导入 + BizId/表头校验 → 当前会话侧库
  → 行分类 + 精确金额规范化 + 七元组分组
  → 非 1+2 Reversal 组：人工；纯 Inbound：统计
  → 1+2 组批量查询全部保留月份 MPT INBOUND
  → MPT 单行唯一 → 组内 ID 不同 → 跨组无复用 → oppBu 非空一致
  → 两 orderId 唯一命中不同单据 → 单据身份字段非空一致 → 业务部门等于 oppBu
  → 成功行 / 人工行 + 守恒断言 → 当前会话侧库
  → 快照复核 → 两 sheet xlsx 原子导出
```

### 7.2 关键实现决策

| 决策 | 选择 | 未选择方案及原因 |
|------|------|------------------|
| 模块边界 | 独立 `duplicate-inbound-match` 模块，只读复用 MPT 保留月份。 | 不塞入前置资金对账场景，避免扩大 3.0.14 状态机与导出契约。 |
| 金额 | 十进制字符串精确规范化。 | 不用 `Number`/浮点，避免大金额和长小数误分组。 |
| 分组键 | 结构化七元组。 | 不用分隔符拼接，避免姓名/卡号含分隔符碰撞。 |
| MPT 匹配 | 每条 Inbound 恰好一个候选，随后做全局复用图裁决。 | 不按月份优先、不 first-wins，避免同一 MPT 行被多组消费。 |
| 未决组 | 整组人工。 | 不部分成功，因为 1 Reversal + 2 Inbound 是最小业务闭环。 |
| 批量数据 | 当前周期侧库。 | 不放内存（大文件风险），不放主库（敏感批量数据和生命周期不符）。 |
| 结果有效性 | 输入 + INBOUND MPT 快照绑定。 | 不允许数据库变化后直接导出旧结果。 |
| 输出 | 固定两 sheet、单工作簿。 | 不追加内部血缘列，保持业务模板契约；血缘留侧库。 |

### 7.3 技术风险与控制

| 风险 | 控制 |
|------|------|
| 同一 MPT 候选跨组抢占 | 两阶段全局复用检测，所有冲突组人工；测试输入顺序置换。 |
| 金额浮点/字段空格扩大或缩小分组 | 独立 amount/text/query normalizer，并以反例单测锁定。 |
| 查询期间 MPT 批次变化 | 共享锁或一致性快照；运行完成前后校验 INBOUND snapshot。 |
| 结果静默丢行 | 三条守恒公式 + 每行唯一 disposition + 硬失败。 |
| 主库/日志泄露姓名卡号 | 批量明细只进侧库，错误和进度脱敏，镜像仅摘要。 |
| 大月份池性能退化 | reconciliationId 批量条件、每月份一次读取、进度/yield、真实大数据基准。 |
| Excel 截断或半文件 | 行数上限预检、临时文件 + 原子发布、写后结构校验。 |

## 8. 数据 / 状态 / 安全影响

| 类别 | 说明 |
|------|------|
| 数据结构变更 | 新增模块侧库表保存当前周期银行导入、运行、邮件行、人工行及血缘；主库新增轻量 run mirror。不得复制 MPT 全量。 |
| 状态流转变更 | 新增“未导入 → 可运行 → 运行中 → 可导出/失败 → stale”的模块状态；重启统一失效。 |
| 权限 / 安全 | 本地文件处理，无新增远程权限；姓名、卡号、账号、BizId 属敏感数据，只允许侧库和用户选择的输出文件。 |
| 幂等性 | 同一输入与同一 MPT 快照重跑结果、顺序和原因必须一致；新 run 取代旧 run，不追加重复导出行。 |
| 审计 | 成功与人工处置均保留银行 BizId/源序号；成功额外保留两个 MPT 全局候选 ID。 |
| 回滚策略 | 关闭/移除模块入口和 IPC；旧版本忽略新增主表及侧库。回滚不删除用户 MPT 保留月份；必要时只清理本模块当前周期侧库。 |

| AC-24 | 新导入/新运行、INBOUND MPT 变化和 OUTBOUND-only 变化分别按 §5.8 正确使结果替换、失效或保持有效。 |
| AC-25 | 运行/导出与 MPT 批次变更不存在混合快照；主库不落银行/MPT 明细、姓名、卡号。 |
| AC-26 | 完整单元、集成、smoke、release-check 通过；大文件/多月份基准无明显阻塞或非线性重复扫描。 |
| AC-27 | 资金人工复核签字确认分组、金额/币种、候选唯一不复用、全月份边界、守恒、输出血缘和回滚；未签字不得发布。 |
