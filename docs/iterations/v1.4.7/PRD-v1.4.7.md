## 一、需求概述

本版本包含 2 项需求：

1. **大账号选择对话框重构** -- 移除"固定"按钮，新增"多账号账单导入解析模式"下拉框，重新设计左右分栏布局（文件顺序 vs 大账号顺序），支持勾选序位映射、定位搜索、记住选择顺序
2. **新开账户余额账单命名规则** -- 单账号输出账户号后四位+币种，两个以上账号输出"多账号-多币种"

## 二、需求详细描述

### 需求 1：大账号选择对话框重构

#### 1.1 功能说明

**做什么：**

对 `createBigAccountSelectionDialog` 的多行模式（`payload.rows` 分支，即 `renderer-dialogs.js:521-797`）进行全面重构，适用于 MerchantId="自己输入"时多文件/多行模板字段触发的大账号选择场景。

**变更点一：移除"固定"按钮，新增"多账号账单导入解析模式"下拉框**

- 移除右上角现有的"固定"按钮（`big-account-fixed-toggle`，`renderer-dialogs.js:646-649`）。
- 在原"固定"按钮位置新增一个标签为"多账号账单导入解析模式"的单选下拉框（`<select>`），包含两个选项：
  - `账号顺序不固定`（默认值）：无数据行的模板字段不参与编排——即只有实际包含交易数据的块（block）才会出现在左侧文件顺序列表中。
  - `账号顺序固定`：无数据行的模板字段参与编排——即文件中所有被识别为账号块的区域（含无交易数据的空块）都会出现在左侧文件顺序列表中，可被映射大账号。
- 关闭对话框后再次打开时，保留上次选择的模式（按模板区分存储，使用模板 ID 作为 key）。

**为什么：**

- 原"固定"按钮的功能是将选择结果持久化到模板的 `fixedAssignments`，在新设计中由"记住大账号选择顺序"勾选框替代（见变更点五）。
- 新增的"解析模式"解决了不同银行账单格式差异的问题：部分银行账单的多账号区块之间存在无交易数据的分隔行/表头行，在"账号顺序固定"模式下需要保留这些空块以确保文件行与大账号的一一对应关系。

**"空块"定义：** 空块是指在文件中由 `headerBreaks` 分隔出的区域，该区域内所有数据行的 Credit Amount 和 Debit Amount 列均为空（即 `isTransactionRow` 判定为 false）。当前 `identifyAccountBlocks` 的 `trimBlock` 逻辑会裁剪掉这些空块（`startIndex > endIndex`），在"账号顺序固定"模式下需要保留空块作为占位项参与编排。

**变更点二：左右分栏布局**

将对话框内容区重新设计为按物理中线分左右两个模块：

- **左侧模块 -- "文件顺序"**：
  - 标题行显示"文件顺序"。
  - 列表项格式：`{序号}. {文件名.格式}+第{X}行`，其中序号从 1 开始连续编号，文件名为原始文件名（含扩展名），X 为该账号块在源文件中的起始行号。
  - 文本过长时省略显示（CSS `text-overflow: ellipsis`），鼠标悬停显示完整内容（`title` tooltip）。
  - 列表项按导入文件的原始顺序排列，每个文件内的多个块按块起始行号从小到大排列（与现有 `buildBigAccountSelectionRows` 的输出顺序一致）。
  - 列表项为只读，不可点击或拖拽。

- **右侧模块 -- "大账号顺序"**：
  - 标题行显示"大账号顺序"。
  - 列表项格式：`[勾选框] {大账号}+{币种}`，其中大账号为 `merchantId`，币种为该大账号下已配置的币种（若大账号有多个币种，每个币种独立一行，如 `ACC001+HKD`、`ACC001+USD`）。
  - 数据源：当前模板已维护的 `bigAccounts` 数组，经 `expandBigAccountConfigurations`（`main.js:841-863`）展开为 `merchantId+currency` 的扁平列表。
  - 勾选后，在勾选框右侧显示数字序位（从 1 开始连续编号），表示该大账号+币种映射到左侧相同序号的文件行。
  - 序位数字的最大值不得超过左侧最末序号（即左侧有 N 个文件行，右侧最多勾选 N 个大账号+币种）。
  - 序位的交互逻辑复用现有"币种多选序位"的模式：按勾选先后顺序自动编号，取消勾选后重排。

**为什么：**

- 现有设计是每一行分别用下拉框选择大账号+输入币种，当文件行数多时操作繁琐且容易出错。新设计将"文件行"和"大账号"分开展示，用户通过勾选序位建立映射关系，更直观高效。

**变更点三：映射逻辑**

- 用户在右侧勾选大账号+币种并建立序位后，系统根据序位将大账号+币种映射到相同序号的左侧文件行数据。
- 例如：左侧序号 1 对应文件 A 第 3 行，右侧序位 1 对应大账号 `ACC001+HKD`，则文件 A 第 3 行的 MerchantId 填充为 `ACC001`，Currency 填充为 `HKD`。
- 点击"完成"时，收集所有序位映射，构建 `assignments` 数组传递给 `file:complete-big-account-selection` IPC handler。
- 若右侧勾选的序位数量不等于左侧文件行数量，点击"完成"时提示错误"请为每一行文件数据选择对应的大账号和币种"。

**变更点四：左下角"定位大账号"输入框**

- 在对话框左下角新增一个文本输入框，placeholder 为"定位大账号"。
- 用户输入文本后按回车键，在右侧大账号列表中进行子串匹配搜索（匹配 `merchantId` 文本是否包含输入内容，大小写不敏感）。例如输入 "001" 可匹配到 "ACC001"。
- 匹配到的项高亮显示（添加高亮样式类），并滚动到可视区域。
- 若存在多个匹配项（同一大账号的不同币种，或不同大账号包含相同子串），每次按回车循环定位到下一个匹配项。
- 无匹配时不做任何操作，输入框边框短暂闪烁红色提示未找到（500ms 后恢复）。

**变更点五：右下角"记住大账号选择顺序"勾选框**

- 在对话框右下角新增一个勾选框，标签为"记住大账号选择顺序"。
- **仅在"账号顺序固定"模式下可用**：当解析模式为"账号顺序不固定"时，该勾选框 disabled（灰显不可勾选）。
- 勾选后，点击"完成"时，将当前的序位映射顺序保存到本地 JSON 文件（按模板 ID 区分）。
- 未勾选"记住"时点击"完成"，若该模板已存在已保存的顺序 JSON，则清除该文件（清空 assignments），避免下次仍预填充旧数据。
- 下次打开该模板的大账号选择对话框时，如果解析模式为"账号顺序固定"且存在已保存的顺序，自动预填充右侧的勾选序位。预填充时做容错处理：跳过当前大账号列表中不存在的 assignment 项（如大账号配置已变更导致 merchantId+currency 不匹配），仅预填充仍然有效的序位。
- 保存格式：

```json
{
  "templateId": "xxx",
  "assignments": [
    { "rowIndex": 0, "merchantId": "ACC001", "currency": "HKD" },
    { "rowIndex": 1, "merchantId": "ACC002", "currency": "USD" }
  ]
}
```

- 存储路径：`{storageRoot}/big-account-orders/{templateId}.json`（storageRoot 即 `getStorageRoot()` 返回的 `~/Documents/网银账单生成小助手`）。

**为什么：**

- 替代原"固定"按钮的功能。"账号顺序固定"模式下文件行与大账号的映射关系是稳定的（每次导入同结构文件都应选择相同的大账号顺序），因此允许记住选择。"账号顺序不固定"模式下每次导入的文件行可能不同，记住选择没有意义。

#### 1.2 交互流程

1. 用户在 MerchantId="自己输入"的模板下导入文件，触发多文件/多行模板字段场景。
2. 系统弹出重构后的大账号选择对话框。
3. 对话框右上角默认显示"账号顺序不固定"模式。
4. 左侧"文件顺序"列显示所有需要映射的文件行（含序号、文件名、行号）。
5. 右侧"大账号顺序"列显示所有可选的大账号+币种（展开后的扁平列表）。
6. 用户在右侧逐个勾选大账号+币种，系统自动按勾选顺序编号。
7. 用户可在左下角"定位大账号"输入框中输入大账号文本，按回车快速定位到右侧对应项。
8. 用户确认映射关系后点击"完成"：
   a. 若序位数量与左侧文件行数量一致，执行映射并处理文件。
   b. 若不一致，提示错误。
9. 用户切换解析模式时：
   a. 清空右侧所有已勾选的序位（避免新旧模式下左侧行数不一致导致序号错乱）。
   b. 左侧文件顺序列表根据新模式重新渲染（"账号顺序固定"含空块，"账号顺序不固定"不含空块）。
   c. 若切换到"账号顺序固定"模式：右下角"记住大账号选择顺序"勾选框变为可用；若存在已保存的顺序，自动预填充右侧勾选序位（覆盖手动勾选）。
   d. 若切换到"账号顺序不固定"模式：右下角"记住大账号选择顺序"勾选框变为 disabled。
10. 用户勾选"记住大账号选择顺序"后点击"完成"，系统保存序位到本地 JSON。
11. 用户点击 [x] 关闭对话框时，取消本次导入操作。

### 需求 2：新开账户余额账单命名规则

#### 2.1 功能说明

**做什么：**

修改新开账户余额账单（`new-account:generate`）的导出文件命名规则：

- **单账号**（`accounts.length === 1`）：
  - 文件名中输出银行账号后四位 + 币种信息。
  - 币种信息：若账号有多个币种，输出"多币种"；若只有单个币种，输出该币种代码。
  - 格式：`{银行名称}-{所在地}-{账户号后四位}-{币种标签}-NEW_BALANCE.xlsx`
  - 示例：`CNCB-CN-7890-HKD-NEW_BALANCE.xlsx`（单币种）
  - 示例：`CNCB-CN-7890-多币种-NEW_BALANCE.xlsx`（多币种）

- **两个以上账号**（`accounts.length >= 2`）：
  - 文件名中输出"多账号-多币种"。
  - 格式：`{银行名称}-{所在地}-多账号-多币种-NEW_BALANCE.xlsx`
  - 示例：`CNCB-CN-多账号-多币种-NEW_BALANCE.xlsx`

**当前实现：**

- 文件：`src/main.js` 约第 4695-4699 行。
- 当前逻辑：无论账号数量，统一使用 `{primaryAccount.bankName}-{primaryAccount.location}-多账号-{currencyLabel}-NEW_BALANCE.xlsx`。
- 其中 `currencyLabel` 为 `generated.currencies.length > 1 ? '多币种' : generated.currencies[0]`。

**目标行为：**

- 根据 `accounts.length` 区分单账号和多账号场景，生成不同的文件名。
- 单账号时：文件名包含该账号银行账号后四位（若账号长度 <= 4 位则原样输出），以及币种标签（多币种输出"多币种"，单币种输出币种代码）。
- 多账号时：文件名使用"多账号-多币种"（不区分实际币种数量，统一输出"多币种"）。

**为什么：**

- 当前命名规则在单账号场景下缺少辨识度（无法从文件名看出是哪个账户号），且多账号场景下的币种标签不够统一。新规则使文件名在不同场景下都更具辨识度，同时保持简洁。

#### 2.2 交互流程

1. 用户在新开账户模块中填写信息并点击"生成"。
2. 系统根据账号数量和币种信息生成对应的文件名。
3. 用户点击"导出"时，使用生成的文件名导出 Excel 文件。
4. 对用户而言无额外操作，仅导出的文件名发生变化。

#### 2.3 UI 说明

无界面变更。仅影响导出文件的文件名。

**文件名格式变更：**

```
变更前（统一格式）：
  {银行名称}-{所在地}-多账号-{币种标签}-NEW_BALANCE.xlsx

变更后：
  单账号：{银行名称}-{所在地}-{账户号后四位}-{币种标签}-NEW_BALANCE.xlsx
  多账号：{银行名称}-{所在地}-多账号-多币种-NEW_BALANCE.xlsx

示例：
  单账号+单币种：
    变更前: CNCB-CN-多账号-HKD-NEW_BALANCE.xlsx
    变更后: CNCB-CN-7890-HKD-NEW_BALANCE.xlsx

  单账号+多币种：
    变更前: CNCB-CN-多账号-多币种-NEW_BALANCE.xlsx
    变更后: CNCB-CN-7890-多币种-NEW_BALANCE.xlsx

  多账号（>=2个，含恰好2个）：
    变更前: CNCB-CN-多账号-HKD-NEW_BALANCE.xlsx
    变更后: CNCB-CN-多账号-多币种-NEW_BALANCE.xlsx

特殊情况：
  - 账户号长度 <= 4 位时，原样输出（不截取）
  - 账户号为空时，省略账户号段
```

#### 2.4 验收标准

| AC 编号 | 验收条件 |
|---------|---------|
| AC2-1 | 单账号+单币种时，导出文件名格式为 `{银行名称}-{所在地}-{账户号后四位}-{币种代码}-NEW_BALANCE.xlsx` |
| AC2-2 | 单账号+多币种时，导出文件名格式为 `{银行名称}-{所在地}-{账户号后四位}-多币种-NEW_BALANCE.xlsx` |
| AC2-3 | 多账号（>=2，含恰好 2 个）时，导出文件名格式为 `{银行名称}-{所在地}-多账号-多币种-NEW_BALANCE.xlsx` |
| AC2-4 | 单账号银行账号长度 <= 4 位时，账户号原样输出。示例：账号 "12"（2位）输出 "12"，账号 "1234"（4位）输出 "1234"，账号 "12345"（5位）输出 "2345" |
| AC2-5 | 单账号银行账号为空时，文件名中不包含账户号段（格式变为 `{银行名称}-{所在地}-{币种标签}-NEW_BALANCE.xlsx`） |
| AC2-6 | 导出的 Excel 文件中银行账号仍显示完整值，文件名截取不影响文件内容 |
| AC2-7 | 多账号场景下，银行名称和所在地取第一个账号（`primaryAccount`）的值（与现有逻辑一致） |
| AC2-8 | 银行账号假设为纯数字或字母，不做文件名特殊字符清理（账户号经 `sanitizeFileName` 处理后已安全） |
| AC2-9 | `NEW_ACCOUNT_EXPORT_NAME` 常量值为 `'NEW_BALANCE'`，文件名中保持使用此常量（与代码一致） |
