# v3.1.0 技术设计

## 数据边界

- 批量银行、链接、运行和差异数据保存在独立 `position-data.sqlite`。
- 主库只保留既有应用配置和轻量运行能力，不保存平盘批量明细或个人信息。
- 主库记录侧库已初始化状态，侧库保存身份标记；已初始化后文件缺失或被替换为空库时 fail closed，避免丢失跨运行消费关系后静默重建。
- 备份恢复以完整应用数据目录为单位，主库与 `run-data/` 不得混用不同批次。
- 银行、账户确认导入和结果回导使用应用私有暂存副本，保证解析、写库和存档来源一致；未完成存档引用的副本跨重启保留，直至重试成功或批次删除。

## 状态与失效

- 银行数据按 `Channel + 月份` 原子替换，BizId 不允许跨范围迁移。
- 运行草稿绑定银行、来源、映射 revision 和规则版本。
- 银行、链接、映射或规则变化后，旧草稿禁止导出、回导和确认。
- 草稿 scope、snapshot、summary 采用严格结构校验，并与运行行范围、来源和汇总计数交叉核对。

## 匹配与确认

- 订单类匹配执行单次运行及跨已确认运行的双向严格 1:1。
- 匹配金额使用十进制字符串计算，不使用 JavaScript 浮点数。
- 回导固定 49 列，只允许在原 FundType 基础/FX 二元组内修改。
- 结果、链接和原始表的标识符格式写到列定义，零数据工作簿仍保持文本列。
- 未解决差异确认不认领链接来源，只有唯一成功匹配血缘写入消费表。

## 存档与退出

- 成功输入、回导和每次结果导出均独立立即接入存档中心，跨重启不依赖进程内批次。
- 退出先禁止新业务并等待活动业务结束，再排空存档任务，最后关闭 side DB。
