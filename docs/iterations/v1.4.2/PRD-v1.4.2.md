## 需求概述

本次迭代包含 6 项功能变更，涵盖以下方面：

1. **账号映射对话框优化** -- 表头文案修正 + 新增"有账户号无币种"勾选框与单币种输入
2. **导出文件命名规则变更** -- 账户号仅输出后四位
3. **币种输入框简化** -- 取消文本+下拉组合，仅保留文本输入框
4. **MerchantId 自己输入模式增强** -- 多文件/多行模板字段时弹出大账号/币种选择框
5. **映射字段新增"需要拼接字段"** -- 支持多选字段并按序拼接
6. **映射关系管理间距调整** -- 模板字段与映射字段间距缩短

## 需求一：账号映射对话框优化

### 1.1 功能说明

**做什么：**
- 将账号映射对话框（`createAccountMappingDialog`）中的表头"清结算系统大账户ID"改为"清结算系统大账号ID"（"户"改为"号"）。
- 在"清结算系统大账号ID"输入框右侧新增一个勾选框，标签为"有账户号无币种"。
- 勾选后，勾选框右侧弹出一个币种输入框，仅支持输入单个币种（复用现有币种输入框的自动补全能力）。

**为什么：**
- 文案统一：现有系统中"大账号"和"大账户"混用，统一为"大账号"以避免歧义。
- 业务场景补充：存在部分账户有银行账号但原始文件中缺少币种信息的情况，需要在映射时手动补录币种。

**数据模型变更：**
- 当前数据结构：`{ bankAccountId: string, clearingAccountId: string }`
- 变更后结构：`{ bankAccountId: string, clearingAccountId: string, noCurrency: boolean, currency: string }`
- `noCurrency` 默认 `false`，`currency` 默认 `''`；旧数据加载时按此默认值兼容。

**币种字段的下游消费逻辑：**
- 当 `noCurrency=true` 且 `currency` 有值时，在导入文件生成明细/余额账单的过程中，若源文件中匹配到该 `bankAccountId` 但缺少币种信息，则自动使用此处配置的 `currency` 值填充 Currency 字段。
- 具体影响 `buildStatementGenerationConfig` 中 `accountMappingByBankId` 的构建逻辑，需将币种信息一并传递至 `file-service.js` 的数据处理流程。

### 1.2 交互流程

1. 用户点击"账号映射"按钮，弹出账号映射对话框。
2. 对话框表头显示为："网银大账户ID" | "清结算系统大账号ID"。
3. 每行"清结算系统大账号ID"输入框右侧显示勾选框"有账户号无币种"。
4. 用户勾选后，勾选框右侧弹出币种输入框：
   - 输入时支持自动补全（与现有币种输入框行为一致，使用 `getCurrencySuggestion` 匹配）。
   - 按右方向键可接受补全建议。
   - 仅支持输入单个币种代码。
5. 用户取消勾选后，币种输入框隐藏，已输入的币种值清空。
6. 用户点击"完成"按钮时，将映射数据（含币种信息）一并保存。

### 1.3 UI 说明

```
+----------------------------------------------------------+
| 账号映射                                            [x]  |
+----------------------------------------------------------+
| 网银大账户ID    | 清结算系统大账号ID                       |
|-----------------|------------------------------------------|
| [输入框]        | [输入框] [ ] 有账户号无币种 [币种输入框]  |
| [输入框]        | [输入框] [ ] 有账户号无币种               |
|   新增          |                                          |
+----------------------------------------------------------+
|                                            [完成]        |
+----------------------------------------------------------+

注：勾选"有账户号无币种"后，右侧出现币种输入框。
    未勾选时，币种输入框隐藏。
```

## 需求二：导出文件命名规则变更

### 2.1 功能说明

**做什么：**
- 明细和余额文件导出时，文件名中的账户号（merchantId）仅输出后四位。
- 例如原文件名 `模板名-1234567890-DETAIL-2026-03-01~2026-03-31.xlsx` 变为 `模板名-7890-DETAIL-2026-03-01~2026-03-31.xlsx`。

**为什么：**
- 出于信息安全考虑，导出文件名中不应暴露完整账户号，仅保留后四位用于辨识。

### 2.2 交互流程

1. 用户导入文件并完成映射。
2. 用户点击"导出明细"或"导出余额"按钮。
3. 系统生成文件时，文件名中的账户号自动截取后四位。
4. 对用户而言无额外操作，仅导出的文件名发生变化。

### 2.3 UI 说明

无界面变更。仅影响导出文件的文件名。

**文件名格式变更：**
```
变更前：{模板名}-{完整账户号}-{DETAIL|BALANCE}-{日期范围}.xlsx
变更后：{模板名}-{账户号后四位}-{DETAIL|BALANCE}-{日期范围}.xlsx

示例：
  变更前: CNCB-CN-3973-1234567890-DETAIL-2026-03-01~2026-03-31.xlsx
  变更后: CNCB-CN-3973-7890-DETAIL-2026-03-01~2026-03-31.xlsx

特殊情况：
  - 账户号长度 <= 4 位时，原样输出（不截取）
  - 账户号为空时，文件名中不包含账户号段（与现有逻辑一致）
  - 多账户导出时后四位相同：本版本不做额外处理，因导出文件按日期目录分隔且含内部后缀区分，不会产生文件覆盖
```

### 2.4 验收标准

| AC 编号 | 验收条件 |
|---------|---------|
| AC2-1 | 导出明细文件时，文件名中账户号仅显示后四位 |
| AC2-2 | 导出余额文件时，文件名中账户号仅显示后四位 |
| AC2-3 | 账户号长度不足 4 位时，原样输出 |
| AC2-4 | 账户号为空时，文件名中不包含账户号段 |
| AC2-5 | 导出的 Excel 文件中 MerchantId 对应的单元格仍显示完整账户号，文件名截取不影响文件内容 |

### 2.5 影响范围

| 模块/文件 | 影响说明 |
|-----------|---------|
| `src/main.js` | `buildStatementOutputFilePath` -- 在拼接 `publicFileName` 时对 `merchantId` 取后四位 |
| `src/main.js` | 导出流程中传入 `outputMerchantId` 的位置需确认是否需同步处理 |

## 需求三：币种输入框简化

### 3.1 功能说明

**做什么：**
- 取消现有的"文本输入框 + 下拉框"组合的币种输入方式。
- 仅保留文本输入框（即去掉下拉按钮和下拉面板）。
- 保留文本输入框的自动补全（ghost input）能力。

**为什么：**
- 简化 UI 交互，减少用户操作步骤。文本输入框的自动补全已足够满足币种选择需求，下拉框显得冗余。

### 3.2 交互流程

1. 用户在需要输入币种的位置，直接在文本输入框中输入。
2. 输入时自动补全提示（灰色幽灵文字）仍然有效。
3. 按右方向键接受补全建议。
4. 不再显示下拉按钮和下拉选项面板。

### 3.3 UI 说明

```
变更前：
  [HKD___________] [▾]     <- 文本输入框 + 下拉按钮
                   +---------+
                   | CNY     |  <- 下拉面板
                   | HKD     |
                   | USD     |
                   +---------+

变更后：
  [HKD___________]          <- 仅保留文本输入框（含自动补全）
```

**适用范围：** 所有使用币种输入的场景，包括：
- 新开账户模块的单币种输入
- 大账号/币种选择对话框中的币种输入
- 大账号管理对话框（`createBigAccountManagerDialog`）中的币种输入

## 需求四：MerchantId 自己输入模式 -- 大账号/币种选择框增强

### 4.1 功能说明

**做什么：**
- 当映射关系中 MerchantId 设定为"自己输入"模式时，在以下两种情况下弹出大账号/币种选择对话框：
  1. **导入了多个文件**：每个文件需要单独选择大账号和币种。
  2. **导入的文件中存在多行模板字段**：每行需要单独选择大账号和币种。

**为什么：**
- 当前实现中，多文件导入或文件内含多行模板字段时，需要明确每个文件/每行对应的大账号和币种，否则无法正确生成账单。

### 4.2 交互流程

#### 场景 A：导入了多个文件

1. 用户在"MerchantId"映射设为"自己输入"的模板下，导入了多个文件。
2. 系统弹出大账号/币种选择对话框。
3. 对话框按文件名排序列出每个文件：

```
+----------------------------------------------------------+
| 请选择本次使用的大账号 / 币种                        [x]  |
+----------------------------------------------------------+
| 1. 文件1.xlsx                                            |
|    大账号              币种                               |
|    [下拉选择]          [文本输入+自动补全]                 |
|                                                          |
| 2. 文件2.xlsx                                            |
|    大账号              币种                               |
|    [下拉选择]          [文本输入+自动补全]                 |
|                                                          |
| 3. 文件3.xlsx                                            |
|    大账号              币种                               |
|    [下拉选择]          [文本输入+自动补全]                 |
+----------------------------------------------------------+
|                                            [完成]        |
+----------------------------------------------------------+

注：大账号使用下拉选择（从已维护的大账号列表中选择）。
    币种使用文本输入框+自动补全（与需求三一致，不使用下拉框），
    可选范围根据所选大账号的币种列表过滤。
```

4. 用户为每个文件选择大账号和币种后，点击"完成"。
5. 系统使用对应的大账号/币种处理各个文件。

#### 场景 B：文件中存在多行模板字段

1. 用户导入的文件中存在多行模板字段（一行对应一个账号）。
2. 系统识别后弹出大账号/币种选择对话框。
3. 对话框按行号列出每一行：

```
+----------------------------------------------------------+
| 请选择本次使用的大账号 / 币种                        [x]  |
+----------------------------------------------------------+
| 1. 第3行的账号为：                                        |
|    大账号              币种                               |
|    [下拉选择]          [文本输入+自动补全]                 |
|                                                          |
| 2. 第7行的账号为：                                        |
|    大账号              币种                               |
|    [下拉选择]          [文本输入+自动补全]                 |
|                                                          |
| 3. 第11行的账号为：                                       |
|    大账号              币种                               |
|    [下拉选择]          [文本输入+自动补全]                 |
+----------------------------------------------------------+
|                                            [完成]        |
+----------------------------------------------------------+
```

4. 用户为每一行选择大账号和币种后，点击"完成"。

### 4.3 UI 说明

复用现有 `createBigAccountSelectionDialog` 的多行模式（`payload.rows` 模式）。

**关键变更：**
- 多文件场景：`row.label` 格式为 `"1."、"2."...`，`row.fileName` 为文件名。
- 多行模板字段场景：`row.label` 格式为 `"1."、"2."...`，提示文字为 `"第XX行的账号为："`。
- 大账号列使用下拉选择框（从已维护的大账号列表中选择）。
- 币种列使用文本输入框+自动补全（与需求三一致，不再使用下拉框），可选范围根据所选大账号的币种列表过滤自动补全建议。

**"多行模板字段"的判定规则：**
- 指文件中依照模板字段取读表后，存在多行数据行，每行对应一个独立的账号。即 MerchantId 映射为"自己输入"（`isMultiBigAccountTemplate=true`），且 `buildMappedRowsForFile` 返回的数据行数 > 1 时触发。
- 当前代码中 `buildPendingBigAccountFileEntries` + `buildBigAccountSelectionRows` 已具备此判定能力，本需求复用此逻辑。

**场景 A 的触发时机：**
- 在用户单次"导入文件"操作中选择了多个文件时触发（即 `selectionResult.filePaths.length > 1`）。不是 session 累计文件数。每次导入操作独立判定。

**大账号下拉框的数据源：**
- 来自当前模板已维护的 `bigAccounts` 数组（通过"维护大账号"功能管理）。
- 如果模板未维护大账号（`bigAccounts` 为空数组），则下拉框无可选项，用户需先通过映射关系管理中的"维护大账号"按钮添加大账号后再导入。

### 4.4 验收标准

| AC 编号 | 验收条件 |
|---------|---------|
| AC4-1 | MerchantId 为"自己输入"且导入多个文件时，弹出大账号/币种选择对话框 |
| AC4-2 | 对话框按文件名排序显示每个文件的选择行 |
| AC4-3 | 每行包含大账号下拉选择框和币种文本输入框（文本输入+自动补全，与需求三一致） |
| AC4-4 | 选择大账号后，币种输入框的自动补全建议根据该大账号的币种列表过滤 |
| AC4-5 | 大账号仅一个币种时，币种自动填充且不可编辑 |
| AC4-6 | 未为所有行选择大账号和币种时，点击"完成"提示错误"请先为每一行选择大账号和币种" |
| AC4-7 | MerchantId 为"自己输入"且文件中存在多行模板字段（即源文件依照模板字段取读后有多行数据行）时，弹出大账号/币种选择对话框 |
| AC4-8 | 多行模板字段场景中，每行标签显示对应的源文件行号（如"第3行的账号为："） |
| AC4-9 | 完成选择后，系统正确使用对应的大账号/币种处理各文件/各行 |
| AC4-10 | "固定"开关功能正常，可固定选择以供后续复用 |
| AC4-11 | 多文件导入且部分文件含多行模板字段时，弹出一个综合对话框，按文件+行号统一列出所有需选择的行 |
| AC4-12 | 用户点击 [x] 关闭对话框时，取消本次导入操作，不进行处理 |

### 4.5 影响范围

| 模块/文件 | 影响说明 |
|-----------|---------|
| `src/main.js` | 导入文件流程中，MerchantId 为自己输入时，构建 `rows` 数据传递给前端弹窗 |
| `src/renderer-dialogs.js` | `createBigAccountSelectionDialog` -- 确认多文件/多行场景下的 `rows` 数据结构和展示 |
| `src/renderer.js` | 导入文件的回调逻辑中，处理 `big-account-selection-required` 状态 |

## 需求五：映射字段新增"需要拼接字段"值

### 5.1 功能说明

**做什么：**
- 在映射关系管理中，映射字段的下拉框新增一个可选值："需要拼接字段"。
- 用户选定该值后，在该映射字段右侧显示一个下拉式多选框，可选值为映射字段的所有候选值（即文件表头）。
- 下拉式多选框支持按点击顺序标记序号，收起后按序拼接字段值。

**为什么：**
- 部分模板字段需要由多个源文件列拼接而成（如"户名"由"姓"+"名"拼接），需要提供更直观的拼接字段选择和排序方式。

**与现有多选机制的关系：**
- 现有多选（`mapping-multi-select`）：用户在 `<select multiple>` 中按 Ctrl/Shift 选择多个字段，保存时弹出 `createMappingOrderDialog` 确认拼接顺序。
- 新增"需要拼接字段"：用户先选择此选项，再在专门的多选面板中按点击顺序选择字段，点击即确定顺序，无需额外排序确认。
- **两种机制并存**，用户可选择任一方式。"需要拼接字段"提供更直观的交互体验，适合明确知道需要拼接哪些字段的场景。

**数据结构：**
```json
{
  "templateField": "AccountNo",
  "mappedField": "需要拼接字段",
  "mappedFields": ["账号前缀", "账号主体", "校验位"],
  "concatSeparator": ""
}
```
- `mappedField` 存储 `"需要拼接字段"` 标识。
- `mappedFields` 存储有序的子字段数组。
- `concatSeparator` 本版本默认为空字符串（直接连接），预留后续扩展。

**拼接字段的可选值范围：**
- 仅展示文件表头（即 `payload.template.headers`），不包含高级映射字段（`ADVANCED_MAPPING_FIELDS`）。

### 5.2 交互流程

1. 用户在映射关系管理中，为某个模板字段的映射字段选择"需要拼接字段"。
2. 选定后，该行右侧出现一个下拉式多选框。
3. **未点击前**：呈现普通下拉框样式（按钮样式）。
4. **点击后**：展开下拉面板，面板中列出所有映射字段候选值：
   - 每个选项前方有两个字符位的勾选框。
   - 勾选框右侧有两个字符位的数字序列位。
5. 用户逐个点击勾选字段：
   - 按点击的先后次序，在数字序列位填写位次，格式为 `1.`、`2.`、`3.` ...
   - 再次点击已勾选的字段可取消勾选，后续字段序号自动重排。
6. **下拉框收起时**：完成次序排列。
7. 在映射字段对应的输入框右侧显示拼接预览：
   - 按次序从左到右排列已选字段名，字段间用空格隔开。
   - 内容过多时末尾用"......"省略。
   - 鼠标悬停时显示完整内容（tooltip）。


## 需求六：映射关系管理间距调整

### 6.1 功能说明

**做什么：**
- 在映射关系管理对话框中，缩短"模板字段"列和"映射字段"列之间的间距（即表格列间距）。

**为什么：**
- 当前间距过大，视觉上两列之间显得过于松散，影响信息密度和可读性。

### 6.2 交互流程

无交互变更。纯 UI 样式调整。

### 6.3 UI 说明

```
变更前（间距较大）：
+----------------+                  +-------------------------+
| 模板字段       |                  | 映射字段                 |
+----------------+                  +-------------------------+
| Date           |                  | [交易日期           [v]]|
| MerchantId     |                  | [自己输入           [v]]|
+----------------+                  +-------------------------+

变更后（间距缩短）：
+----------------+  +-------------------------+
| 模板字段       |  | 映射字段                 |
+----------------+  +-------------------------+
| Date           |  | [交易日期           [v]]|
| MerchantId     |  | [自己输入           [v]]|
+----------------+  +-------------------------+
```

### 6.4 验收标准

| AC6-2 | 缩短间距后，模板字段和映射字段内容无截断、无溢出 |
| AC6-3 | 表格整体布局协调，不影响其他元素的显示 |

## 风险与依赖

| 编号 | 风险/依赖 | 说明 | 缓解措施 |
|------|-----------|------|----------|
| R-1 | 数据兼容性 | 需求一和需求五引入新的映射字段类型，需确保旧模板/旧映射数据在升级后仍可正常加载 | 在数据加载时做默认值兼容处理 |
